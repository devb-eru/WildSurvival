# WildSurvival DAY 진행 및 스킵 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 ID | `DAY-001` |
| 역할 | Day 수명주기, 과반 스킵 투표, Day 50 이후 진행과 최종 종료 조건의 단일 권위 문서 |
| 상위 기준 | `VISION`, `DIFFICULTY` |
| 연계 문서 | `GAME`, `CONTENT`, `ACT`, `CORR`, `TECH` |
| 구현 | 바닐라 클라이언트 + Paper 서버 플러그인 |
| 문서 상태 | 도입 확정안 |

## 1. 핵심 결정

- Day는 세계·위협·콘텐츠 방향을 정하는 진행 축이지 회차 종료 타이머가 아니다.
- Day 50은 최종 목표를 시작할 수 있는 최초 Day다.
- Day 50이 끝나도 회차는 종료되지 않으며 Day 51 이상으로 계속 진행한다.
- 회차 성공은 최종 목표 완료 트랜잭션이 확정됐을 때만 발생한다.
- 허용된 회차에서는 플레이어 과반수 투표로 현재 Day의 남은 대기 구간을 단축할 수 있다.
- Day 스킵은 예정된 필수 보스·압박·최종 목표를 완료한 것으로 만들지 않는다.

## 2. Day 구간

| 구간 | 내부 단계 | 역할 |
|---|---|---|
| Day 1~49 | `FOUNDATION` | 시스템 도입, 발견, 성장, 부품 준비 |
| Day 50 | `FINAL_UNLOCK` | 최종 목표 최소 Day 잠금 해제, 준비 상태 검증 |
| Day 51+ | `POST_50` | 최종 목표 완료 전까지 복합 붕괴 압박 지속 |

- `currentDay`에는 50 상한을 두지 않는다.
- Day 50 도달만으로 최종 보스, 정화 성공 또는 엔딩을 확정하지 않는다.
- 최종 준비가 부족하면 누락 범주를 안내하고 다음 Day로 정상 진행한다.
- 준비를 마친 파티는 어느 `currentDay >= 50`에서도 최종 목표를 시작할 수 있다.

## 3. Day 51+ 방향

Day 51 이후는 새로운 핵심 성장 계층을 무한 추가하지 않는다. Day 1~50에 배운 시스템을 복합 조합하고 최종 목표 준비를 압박한다.

### 5-Day 순환 프로필

| 순환 위치 | 프로필 | 기본/상한 예산 | 주요 변화 |
|---:|---|---:|---|
| `day % 5 = 1` | 자원 불안정 | 90/110 | 채집 위험, 이동 경로와 가공 선택 압박 |
| `day % 5 = 2` | 변이 이동 | 94/112 | 오염 변이 조합과 지역 위험 변경 |
| `day % 5 = 3` | 시설 분산 압박 | 98/114 | 시설망·파티 중 동적 목표 선택 |
| `day % 5 = 4` | 정예 공명 | 102/116 | 적 역할·증강·브레이크 조합 강화 |
| `day % 5 = 0` | 붕괴 파동 | 108/120 | 복합 공세와 최종 장치 교정 압박 |

`cycle = floor((currentDay - 51) / 5)`, `finalBudget = min(baseBudget + 2 × cycle, budgetCap)`을 사용하며 Day 추가 HP·직접 피해 배율은 1.00이다.

- 실제 사건은 동적 후보 영역과 현재 시설·파티 위치에서 생성한다.
- Day가 증가한다는 이유만으로 HP·ATK를 무한 곱하지 않는다.
- 오염 강도, 변이 예산, 적 역할 조합, 동시 목표 수를 콘텐츠 상한 안에서 조정한다.
- Day 51+ 보상은 최종 준비 복구와 소모 보충을 제공하되 새 필수 부품을 무한 추가하지 않는다.
- 매 5-Day 순환 종료에 장기 저장 체크포인트를 만들지만 회차 완료로 처리하지 않는다.

## 4. 최종 목표와 회차 종료

### 최종 목표 준비 조건

```text
currentDay >= 50
AND boss.day10/20/30/40.state == CLEARED
AND reconstruction.parts[A,B,C,D] == BOUND
AND discovery.C27 == DISCOVERED
AND discovery.C28A/C28B/C28C/C28D/C29 == COMPLETE
AND facility.R01/R02/R03/R04 == READY
AND facility.R05.count == 3
AND facility.R06 == READY_LOCKED
AND inventoryOrLedger.finalSignalKey >= 1
AND activeBoss == NONE
AND activeSiege == NONE
AND blockingTransaction == NONE
```

조건이 충족되면 `finalObjectiveState`를 `AVAILABLE`로 전환한다. C30은 선행 조건이 아니라 완료 결과이며 시작은 FAC-R06 GUI의 명시적 상호작용과 생존·빈사 등록 인원의 과반수 찬성으로만 승인한다. 세부 전장·전투·정화는 `FINAL-001`이 담당한다.

### 상태 전이

```text
LOCKED
→ AVAILABLE
→ ACTIVATING
→ ACTIVE_STAGE_1
→ ACTIVE_STAGE_2
→ ACTIVE_STAGE_3
→ RESOLVING
→ COMPLETED
```

- `LOCKED`: 조건 미충족, 누락 범주만 표시
- `AVAILABLE`: 시작 가능, Day는 계속 흐름
- `ACTIVATING`: 투표·전장 검사·키 예약, 실패 시 자원 반환
- `ACTIVE_STAGE_1~3`: 장치 전개·붕괴 핵 제압·180초 정화와 생존자 최종 확인, Day 타이머 정지
- `RESOLVING`: 보상·세계 상태·종료 통계 원자 확정
- `COMPLETED`: 회차 성공, 재개 불가 읽기 전용 기록

최종 목표 실패가 전원 완전 사망이 아니면 저장 체크포인트에 따라 `AVAILABLE`로 복귀하고 키·임시 오브젝트·장치 출력을 복구한다. 전원 완전 사망이 확정되면 Day와 무관하게 `FAILED`가 된다.

### 금지 규칙

- Day 50 타이머 종료만으로 `COMPLETED` 또는 `FAILED`로 바꾸지 않는다.
- Day 50 이후 일반 Day 전환을 막지 않는다.
- 최종 목표가 `ACTIVATING`, `ACTIVE_STAGE_1~3`, `RESOLVING`인 동안 Day 스킵과 일반 Day 전환을 허용하지 않는다.
- 엔딩·결과 화면은 `finalObjectiveState == COMPLETED` 저장 성공 뒤에만 실행한다.

## 5. Day 스킵 목적

숙련 파티가 해당 Day에 필요한 준비와 대응을 이미 마친 뒤 남은 타이머를 기다리는 지루함을 줄인다. 스킵은 성장, 보상, 시설 생산 또는 필수 전투를 무료로 완료하는 기능이 아니다.

## 6. 사용 가능 조합

| 콘텐츠·난이도 | STANDARD | CHAOS |
|---|---:|---:|
| Story | 가능 | 불가 |
| Challenge / Easy | 가능 | 불가 |
| Challenge / Normal | 가능 | 불가 |
| Challenge / Hard | 가능 | 불가 |
| Challenge / ??? | 불가 | 불가 |

- 서버는 `difficultyId == UNKNOWN` 또는 `gameMode == CHAOS`이면 요청 생성 단계에서 거부한다.
- 금지 조합에는 스킵 GUI 버튼을 숨기되 회차 계약 화면에는 `Day 스킵 불가`를 명시한다.
- 운영자 강제 Day 변경은 Day 스킵이 아니라 감사 로그가 필요한 복구 명령으로 분리한다.

## 7. 스킵 투표권과 과반수

### 투표권 스냅샷

투표 시작 순간 다음 조건을 만족하는 플레이어를 `eligibleVoters`로 고정한다.

- 현재 회차에 등록됨
- 서버에 접속 중임
- 관전 전용 미등록 플레이어가 아님
- 운영자 복구 상태가 아님

완전 사망한 등록 멤버도 접속 중이면 투표할 수 있다. 단, 투표 개시 조건상 빈사 플레이어 또는 활성 구조 상황이 있으면 투표 자체를 시작할 수 없다.

```text
requiredYes = floor(eligibleVoters / 2) + 1
```

| 투표권자 | 필요 찬성 |
|---:|---:|
| 1 | 1 |
| 2 | 2 |
| 3 | 2 |
| 4 | 3 |

- 투표 시간은 30초다.
- 과반 찬성이 모이면 남은 시간과 무관하게 즉시 가결한다.
- 남은 미투표자가 모두 찬성해도 과반에 도달할 수 없으면 즉시 부결한다.
- 기권과 시간 초과는 찬성으로 계산하지 않는다.
- 투표 중 접속 종료해도 투표권 스냅샷과 필요 찬성 수를 낮추지 않는다.
- 투표 중 재접속한 등록 멤버는 기존 스냅샷에 있었을 때만 투표를 이어갈 수 있다.

## 8. 투표 개시 조건

다음 조건을 모두 만족해야 한다.

1. `runState == ACTIVE`
2. 스킵 허용 난이도·규칙 모드 조합
3. 현재 Day 전환 또는 다른 스킵 투표가 진행 중이지 않음
4. 최종 목표 상태가 `ACTIVATING`, `ACTIVE_STAGE_1~3`, `RESOLVING` 중 하나가 아님
5. 보스·공세·엘리트 추적·동적 사건이 전투 상태가 아님
6. 빈사자, 구조 채널링과 예약된 치명 피해가 없음
7. 보상·증강·고유 장비·발견 선택 트랜잭션이 열려 있지 않음
8. 시설 설치·철거·재건 교정 같은 핵심 채널링이 진행 중이지 않음
9. 최소 한 명의 투표권자가 존재함
10. 직전 부결·취소 후 120초 재사용 대기가 지남

조건이 깨지면 요청을 거부하고 `전투 중`, `정산 중`, `금지 난이도`, `금지 규칙 모드` 같은 범주형 원인을 표시한다.

## 9. 가결 후 처리

Day 스킵은 `SKIP_PREPARED` 트랜잭션을 사용한다.

1. 투표 결과와 대상 Day를 우선 저장한다.
2. 신규 일반 사건·채집 노드·선택 보상 생성을 잠근다.
3. 실제 경과 시간까지만 시설 작업·쿨타임·자원 재생을 정산한다.
4. 남은 시간을 시설 생산, 작물 성장, 정화 연료 처리 또는 쿨타임에 더하지 않는다.
5. 현재 Day의 미완료 필수 압박을 확인한다.
6. 필수 압박이 없으면 Day 종료 정산으로 이동한다.
7. 필수 압박이 있으면 `EXPEDITE_PENDING`으로 전환해 해당 압박을 즉시 시작하고 완료 후 Day 종료 정산으로 이동한다.
8. Day 종료 보상 중 실제 행동을 요구한 보상은 지급하지 않는다.
9. Day 시작 파이프라인으로 `currentDay`를 정확히 1 증가시킨다.
10. 새 Day 위협·오염·변이·사건 잠금을 정상 적용하고 저장한다.

### 필수 압박의 예

- 해당 Day에 아직 해결하지 않은 필수 보스
- 이미 확정된 세션 경계 전투
- 시작이 예약된 붕괴 파동
- 최종 목표 진행 중 필수 단계

스킵은 필수 압박을 `완료`로 표시하지 않는다. 대기 시간만 제거하고 필요한 콘텐츠를 즉시 앞당긴다. 필수 압박이 시작되면 Day 타이머를 정지하며, 해결 전에는 다음 Day로 넘어가지 않는다.

## 10. 스킵 정산 정책

| 항목 | 처리 |
|---|---|
| Day 번호 | 정확히 +1 |
| Day 시작 오염 | 정상 적용 |
| 신규 변이·적 역할 잠금 | 정상 적용 |
| 시설 작업 | 실제 경과 시간만 반영 |
| 작물·자원 재생 | 남은 Day 시간 소급 없음 |
| 일반 Day 생존 보상 | 미충족분 지급 없음 |
| 필수 보스·발견 | 자동 완료 금지 |
| 공세 | 이미 활성화됐으면 투표 불가, 필수 예약이면 즉시 실행 |
| 증강 마일스톤 | 실제 레벨·보스 정산 조건을 만족할 때만 제공 |
| Day 50 잠금 | `currentDay >= 50`만 만족, 나머지 조건은 별도 검증 |

- 스킵으로 새 Day에 도달해도 장비, 발견, 보스, 재건 재료가 자동 지급되지 않는다.
- 반복 스킵은 세계 압박을 계속 높이므로 준비가 부족한 파티에는 명확한 위험 선택이 된다.
- 스킵한 Day와 남긴 미완료 선택 콘텐츠는 결과 통계에 기록한다.

## 11. 취소·실패·복구

| 상황 | 처리 |
|---|---|
| 투표 부결·시간 초과 | Day 정상 진행, 120초 재사용 대기 |
| 투표 중 전투 시작 | 투표 취소, 재사용 대기 없음 |
| 가결 저장 실패 | 스킵 미실행, 기존 Day 유지 |
| `SKIP_PREPARED` 중 서버 종료 | 트랜잭션 단계와 대상 Day를 읽어 한 번만 완료 또는 취소 |
| 필수 압박 생성 실패 | 다음 Day로 전환하지 않고 `RECOVERING`, 운영 로그 생성 |
| Day 시작 저장 실패 | 이전 Day 종료 확정 상태에서 재시도, 보상·오염 중복 금지 |
| 투표권자 전원 접속 종료 | 투표 정지 후 60초 내 복귀 없으면 취소 |

같은 `runId + targetDay + voteSequence`의 가결 결과는 한 번만 적용한다.

## 13. 저장 데이터

```yaml
day-state:
  current-day: 53
  era: POST_50
  phase: ACTIVITY
  remaining-millis: 161000
  transition-sequence: 52
  final-objective-state: AVAILABLE
  skip:
    policy: ALLOWED
    vote-sequence: 7
    state: NONE
    target-day: null
    eligible-voters: []
    yes-voters: []
    required-yes: 0
    expires-at: null
    cooldown-until: null
  history:
    skipped-days: [17, 28, 46]
```

필수 추가 저장 항목:

- Day별 정상 종료·스킵 종료 구분
- 스킵 가결 투표권자·찬성자 UUID
- 가결 시 남은 시간과 실제 경과 시간
- `SKIP_PREPARED`, `EXPEDITE_PENDING`, `DAY_TRANSITION` 처리 단계
- 스킵으로 즉시 시작한 필수 압박 ID
- Day 51+ 순환 프로필과 난수 리비전
- 최종 목표 상태와 마지막 검증 실패 범주

## 14. 관리자·통계

### 관리자 검사

- 현재 스킵 허용 여부와 거부 원인
- 투표권 스냅샷, 필요 찬성 수, 만료 시각
- Day 전환 트랜잭션 단계
- 미완료 필수 압박과 최종 목표 조건
- Day 51+ 프로필·위협 예산·오염 강도

### 통계

- 회차별 스킵 요청·가결·부결 수
- 스킵한 Day와 당시 남은 시간
- 난이도·규칙 모드별 스킵 사용률
- 스킵 사용 회차와 미사용 회차의 실패율
- Day 50 도달부터 최종 목표 완료까지 걸린 Day 수
- 최종 완료 Day 분포

## 15. 검증 항목

### 투표

- 1·2·3·4명에서 필요 찬성 수가 1·2·2·3인가
- 접속 종료로 가결 기준이 투표 중 낮아지지 않는가
- 과반 도달·도달 불가 시 조기 종료하는가
- `UNKNOWN`과 모든 CHAOS 회차에서 요청·명령·GUI 우회가 차단되는가
- 전투·빈사·정산·핵심 채널링 중 투표가 열리지 않는가

### 정산

- 한 번의 가결로 Day가 정확히 1만 증가하는가
- 남은 시간을 시설·작물·쿨타임에 소급하지 않는가
- 필수 압박이 자동 완료되지 않고 즉시 실행되는가
- 보상·발견·증강이 조건 없이 지급되지 않는가
- 서버 종료 후 스킵과 Day 시작 효과가 중복되지 않는가

### Day 50+

- Day 50 타이머가 끝난 뒤 Day 51로 진행할 수 있는가
- Day 51 이상에서 위협 프로필과 오염이 정상 갱신되는가
- Day 50 도달만으로 엔딩·완료 상태가 발생하지 않는가
- 어느 Day 50+에서도 준비 조건 충족 후 최종 목표를 시작할 수 있는가
- 최종 목표 완료 저장 후에만 회차가 `COMPLETED`로 잠기는가
- 최종 목표 `ACTIVATING`·`ACTIVE_STAGE_1~3`·`RESOLVING` 중 Day 스킵과 일반 전환이 차단되는가

## 16. 완료 기준

- Day 스킵의 과반수 계산, 가능 조합, 금지 상태, 정산과 복구가 정의되어 있다.
- `???`와 CHAOS에서 모든 스킵 경로가 차단된다.
- 스킵이 필수 전투·보상·시설 생산·발견을 무료 완료하지 않는다.
- Day 50은 최종 목표 최초 해금일이며 Day 51+ 진행이 존재한다.
- 회차는 Day 번호가 아니라 최종 목표 완료 또는 전원 완전 사망으로 종료된다.
