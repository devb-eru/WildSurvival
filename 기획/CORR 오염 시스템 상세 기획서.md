# WildSurvival CORR 오염 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 ID | CORR-001~003 |
| 상위 기준 | `VISION`, `CONTENT`, `BASE`, `DISC` |
| 구현 환경 | 바닐라 클라이언트 + Paper 서버 플러그인 |
| 핵심 전제 | 고정 기지·고정 안전 지대·청크별 영구 오염 저장 없음 |

## 공통 방향

오염은 시간 경과를 단순 피해 증가로만 표현하지 않고, 탐험 경로, 시설 운영, 적 변이, 상태이상과 전투 패턴을 바꾸는 세계 압박이다. 오염은 `세계`, `시설망`, `플레이어`, `현재 지역` 네 문맥으로 분리하고 동일 원인이 여러 단계에서 중복 곱해지지 않게 한다.

# CORR-001 세계·시설망·플레이어·지역 오염

## 1. 오염 데이터

| 종류 | 내부 ID | 저장 | 역할 |
|---|---|---|---|
| 세계 오염 | `worldCorruption` | 회차 | 전체 진행 압력과 변이 풀 해금 |
| 시설망 오염 | `networkCorruption[networkId]` | 시설망 | 플레이어가 만든 각 시설망의 부식·습격 압박 |
| 플레이어 오염 | `playerCorruption[playerId]` | 플레이어 | 개인 상태이상·회복·전투 압박 |
| 지역 오염 | `localCorruption` | 파생 | 현재 위치의 실제 노출량 |

각 저장 오염은 `수치 0~100`과 `강도`를 가진다. 수치가 100인 상태에서 추가 오염을 받으면 초과분을 강도 성장으로 전환한다. 강도에는 난이도별 최소값과 콘텐츠별 상한을 둔다.

이전 저장 데이터의 `baseCorruption`은 마이그레이션 시 해당 회차의 가장 최근 활성 시설망 오염으로 옮긴다. 시설망이 없으면 폐기하지 않고 `legacyUnboundCorruption`으로 보관한 뒤 다음 생성 시설망에 한 번만 배분한다.

## 2. 세계 오염

세계 오염은 Day 구간의 콘텐츠 압력을 대표한다.

| Day 구간 | Day 시작 기본 증가 |
|---|---:|
| 1~10 | +1 |
| 11~20 | +2 |
| 21~30 | +3 |
| 31~40 | +4 |
| 41~50 | +5 |

- `CONTENT`의 특수 Day가 값을 대체할 수 있으나 같은 Day 증가를 다른 시스템에서 다시 곱하지 않는다.
- 세계 오염은 변이 후보, 자연 현상과 지역 보정의 잠금을 연다.
- 적 체력·공격력·브레이크를 세계 오염으로 일괄 곱하지 않는다. 적 템플릿이 해금된 패턴과 변이를 선택한다.
- 보스전 중 Day 시간이 멈추면 Day 시작 증가도 추가 발생하지 않는다.
- 세계 오염 감소는 핵심 발견, 대규모 정화 사건과 최종 재건 단계에서만 제한적으로 허용한다.

## 3. 시설망 오염

시설망 오염은 플레이어가 건설한 각 `facilityNetworkId`별로 계산한다.

```text
Day 시작 시설망 오염 증가 =
세계 유효 오염 압력
× 네트워크 노출 계수
× 정화 상태 보정
× 사건 보정
```

| 정화 상태 | 보정 예시 |
|---|---:|
| 정상 작동 정화기 | 0.50 |
| 손상 정화기 | 0.80 |
| 정지 정화기 | 1.25 |
| 정화기 없음 | 1.00 |

정화기가 없다는 사실만으로 미리 만들어진 기지보다 더 큰 벌을 주지 않는다. 대신 고가치·고처리량 시설망일수록 `네트워크 노출 계수`가 높아질 수 있다.

시설망 오염 증가 원인은 다음과 같다.

- 해당 시설망을 목표로 한 잔존 공세
- 시설 오염 공격과 정화기 손상
- 활성 재건 부품의 불안정한 신호
- 근처 오염 균열과 변이 사건
- 보스가 해당 시설망을 전장 목표로 선택한 상태

시설망이 파괴·철거되면 오염을 즉시 지우지 않는다. 남은 오염은 일정 시간의 지역 잔류 현상으로 바꾸고, 철거 반복을 통한 정화 악용을 막는다.

## 4. 플레이어 오염

플레이어 오염은 기본 5초마다 서버에서 계산한다.

```text
개인 오염 증가량/5초 =
기본 노출량 0.20
× 지역 오염도 / 100
× 지역 오염 강도 / 100
× 생명 상태 보정
× 사건 보정
× 장비·증강 보정
```

| 상태 | 보정 |
|---|---:|
| 생존 | 1.00 |
| 빈사 | 1.50 |
| 완전 사망·관전·오프라인 | 0 |

- 오염도 100만으로 즉시 사망하거나 회차가 실패하지 않는다.
- 빈사·부활의 보존 규칙은 `DEATH`를 따른다.
- 장비와 증강의 감소 효과에는 최종 하한을 두어 완전 면역을 일반 빌드로 만들지 않는다.
- 동일 오염 원인이 장비 단계와 최종 단계에서 두 번 감소되지 않도록 출처 ID를 기록한다.

## 5. 지역 오염

지역 오염은 청크마다 영구 저장하지 않고 현재 플레이어·시설·사건 주변에서 파생 계산한다.

```text
야생 지역 오염 = clamp(
  세계 오염
  + 생물군계·지형 보정
  + 동적 사건 보정
  + 오염 균열 보정
  - 활성 정화장 범위 보정,
  0, 100
)
```

| 문맥 | 보정 방향 |
|---|---|
| 일반 야생 | 세계 오염 기준 |
| 희귀 자원 밀집지 | +5~10 |
| 오염 생물 군락 | +10~20 |
| 동적 균열 | +15~30 |
| 보스 전장 | 보스 템플릿 지정 |
| 정상 정화기 범위 | 출력에 따라 감소, 0 가능 |
| 손상 정화기 범위 | 감소량 축소 |

- 특정 고정 좌표를 오염 진행의 필수 장소로 사용하지 않는다.
- 정화 범위는 설치한 정화기를 중심으로 계산하며 시설망 경계를 안전 지대로 간주하지 않는다.
- 정화 범위 밖의 야생은 동일하게 진행 가능해야 하며, 휴대 정화 수단을 제공한다.
- 동적 사건이 끝나면 사건 보정은 제거하되 잔류 시간 동안 완만히 감소할 수 있다.

## 6. 계산 책임과 순서

1. `CONTENT`가 Day 구간·특수 사건과 해금할 변이 풀을 제공한다.
2. CORR가 세계 오염을 한 번 갱신한다.
3. 각 활성 시설망의 오염을 한 번 갱신한다.
4. 플레이어 위치에서 지역 오염을 파생 계산한다.
5. 개인 장비·증강 보정을 적용해 플레이어 오염을 갱신한다.
6. 변화한 단계 이벤트만 `STATUS`, `ACT`, `BASE`에 발행한다.

같은 위험 원천을 세계 오염, Day 배율, 시설망 오염에서 중복 곱하지 않는다. 하위 시스템은 오염 수치를 자체적으로 다시 스케일하지 않고 전달된 단계 또는 확정 값을 사용한다.

# CORR-002 오염 단계와 효과

## 1. 단계

| 단계 | 범위 | 설계 역할 |
|---:|---:|---|
| 0 안정 | 0~19 | 기본 상태 |
| 1 노출 | 20~39 | 경고와 약한 변이 |
| 2 침식 | 40~59 | 상태이상·시설 효율 압박 |
| 3 변이 | 60~79 | 엘리트 변이와 복합 환경 위험 |
| 4 붕괴 | 80~99 | 강한 사건과 정화 비용 증가 |
| 5 포화 | 100 | 강도 성장과 최종 구간 현상 |

단계 경계에는 2%p 히스테리시스를 사용해 수치가 경계에서 오르내릴 때 효과가 반복 토글되지 않게 한다.

## 2. 세계 단계 효과

- 새로운 오염 변이 태그와 동적 사건 후보 해금
- 엘리트 등장 확률의 콘텐츠 예산 슬롯 증가
- 자연 현상 조합과 경고 정보 변화
- 보스·적의 사용 가능 패턴 풀 확장

세계 단계는 모든 적의 체력·피해·속도를 일괄 증가시키지 않는다.

## 3. 시설망 단계 효과

| 단계 | 영향 예시 |
|---:|---|
| 1 | 정화 연료 소비 경고 |
| 2 | 제작·분석 처리량 소폭 감소 |
| 3 | 시설 오작동 사건과 부식 피해 후보 |
| 4 | 일부 고급 기능 일시 잠금 가능 |
| 5 | 동적 균열 압박과 재건 시설 불안정 |

- 필수 복구 제작, 유품 회수와 정상 중단 기능은 오염으로 영구 잠그지 않는다.
- 기능 정지는 정화·수리·휴대 대안 중 하나로 해소할 수 있어야 한다.
- 여러 시설망은 각자의 오염 단계를 가진다.

## 4. 플레이어 단계 효과

- 회복 효율 감소
- AP 회복 지연 또는 비용 증가
- 오염 상태이상 후보 추가
- 적 변이의 추적·표식 대상으로 선택될 확률 증가
- 단계 5에서 주기적 오염 피해와 왜곡 현상

행동 불능 효과는 `STATUS-002`의 3초 강한 CC 체인과 면역 규칙을 반드시 따른다. 오염 단계만으로 입력을 장시간 봉쇄하지 않는다.

## 5. 오염 피해

```text
오염 피해 =
오염 템플릿 기본 피해
× 현재 오염 강도 / 100
× 난이도별 오염 피해 보정
× DEF 효율 보정
```

- `STAT`의 난이도별 오염 DEF 효율을 사용한다.
- 오염 피해는 피해 처리 서비스에서 한 번만 계산한다.
- 같은 틱의 여러 오염 원천은 출처별 피해가 아니라 짧은 집계 창으로 합친다.
- 빈사 플레이어에게는 `DEATH`의 빈사 피해 상한을 적용한다.

## 6. 알림

- 단계 상승: 타이틀 또는 액션바, 소리, 구체적인 신규 위험 요약
- 단계 하락: 정화 성공 피드백과 해제된 불이익 표시
- 색상 외에도 숫자, 단계명과 아이콘 아이템을 함께 사용
- 미발견 변이는 정확한 이름 대신 현상 단서만 표시하고 조우 후 도감에 기록

# CORR-003 플레이어 건설 정화기와 정화 자원

## 1. 핵심 전제

정화기는 시작 지점에 설치되어 있지 않다. 파티가 발견·제작·배치하는 시설이며 여러 시설망에 각각 설치할 수 있다. 정화기를 건설하지 않은 파티도 휴대 정화기와 소모품으로 진행할 수 있지만 범위, 연료 효율과 처리량에서 손해를 본다.

## 2. 해금과 제작

1. 오염 표본, 자연 정화 현상 또는 변이 적을 관찰한다.
2. `DISC`의 정화 원리 발견 노드를 충족한다.
3. 휴대 정화 도구 제작식을 먼저 해금한다.
4. 정착 시설용 정화기와 중계기 제작식을 해금한다.
5. 고급 재건 단계에서 출력·범위·개조를 확장한다.

발견 전에 필요한 표본을 획득했다면 소급 인정한다. 특정 생물군계 하나만 요구하지 않고 대체 표본 조합을 제공한다.

## 3. 정화기 성장축

| 성장축 | 상한 기준 | 효과 |
|---|---:|---|
| 시설 등급 | 5 | HP, 출력, 효율, 개조 슬롯 |
| 범위 단계 | 3 | 반경 12/24/48블록 |
| 정화 단계 | 5 | 시설망·플레이어 정화량과 강도 안정화 |

- 등급, 범위, 정화 단계는 독립적으로 강화한다.
- 모든 업그레이드는 비전투 상태에서 트랜잭션으로 수행한다.
- 정화기 중심의 수평 원기둥 범위를 사용하되 Y축 상한을 두어 과도한 청크 검색을 막는다.
- 중계기는 주 정화기와 연결되며 독립 연료 없이 주 정화 출력을 분배한다.
- 여러 정화장 중첩은 단순 합산하지 않고 가장 강한 출력 100%와 나머지 출력의 제한된 비율만 적용한다.

## 4. 정화 자원

| 자원층 | 역할 | 획득 경로 예시 |
|---|---|---|
| 불안정 표본 | 현장 분석과 응급 정화 | 변이 적, 오염 식생 |
| 정제 촉매 | 정화기 연료 | 제작, 엘리트, 자연 정화 현상 |
| 안정화 코어 | 고급 강화·과부하 | 보스 재료, 고급 발견, 희귀 제작 |

핵심 연료에는 최소 두 획득 경로를 제공한다. 정화 자원은 파티 공용 원장에 넣을 수 있으며 투입과 소비를 트랜잭션으로 기록한다.

## 5. 운전 모드

| 모드 | 출력 | 소비 | 용도 |
|---|---:|---:|---|
| 절약 | 70% | 60% | 장기 야영 |
| 표준 | 100% | 100% | 일반 운영 |
| 집중 | 140% | 180% | 높은 오염 정화 |
| 과부하 | 200% | 300%+ | 짧은 비상 대응, 손상 위험 |

- 출력과 소비는 예시 기준이며 경제 수치는 `ECONOMY`·후속 밸런스표에서 확정한다.
- 연료 고갈 시 범위 정화는 정지하지만 시설과 저장 데이터는 유지한다.
- 과부하는 지속시간 상한, 냉각, 시설 피해와 명확한 경고를 가진다.
- 공세 중 모드 변경은 잠금 또는 긴 채널링을 적용해 즉시 토글 악용을 막는다.

## 6. 휴대 정화 대안

- 개인 오염을 소량 낮추는 소모품
- 짧은 시간 작은 정화장을 만드는 휴대 장치
- 시설 복구 부품을 만드는 저효율 야전 제작
- 오염 현상을 잠시 억제하는 발견 기반 환경 상호작용

휴대 대안은 정착 시설보다 자원당 효율이 낮지만 시설 전멸이나 유목 플레이에서 핵심 진행을 보장한다.

## 7. 저장과 성능

- 정화기 ID, 시설망 ID, 좌표, 등급, 범위, 단계, HP, 연료, 운전 모드, 개조와 트랜잭션을 저장한다.
- 플레이어가 없고 시설이 비활성인 청크는 매 틱 계산하지 않고 마지막 계산 시각을 이용해 필요한 누적 처리만 수행한다.
- 정화 범위 안 플레이어와 활성 시설만 공간 인덱스로 조회한다.
- 파티클은 리소스 팩 없이도 이해 가능한 보조 표현이며 성능 저하 시 먼저 축소한다.

## 8. 예외와 복구

| 상황 | 처리 |
|---|---|
| 정화기 설치 중 서버 종료 | 트랜잭션 원장으로 자원 소비 또는 설치를 한 번만 확정 |
| 정화기 파괴 | 고유 부품은 복구 원장에 보존, 지역 잔류 오염 생성 |
| 모든 정화기 소실 | 휴대 정화·야전 제작 경로 안내 |
| 시설망 분리·병합 | 시설별 기여도와 위치를 기준으로 오염·연료를 결정론적으로 분배 |
| 월드 좌표 무효 | 시설 기능 잠금 후 가장 가까운 유효 위치에 복구 요청 제공 |
| 연료 부족 | 정화 정지, 데이터·보관품 유지, 명확한 경고 |

## 9. 테스트 항목

- 고정 기지와 초기 설치 정화기 없이 Day 1을 시작할 수 있는가
- 정화기 없이 휴대 수단만으로 핵심 진행이 가능한가
- 여러 시설망의 오염이 독립 계산되고 철거로 삭제되지 않는가
- 정화 범위 중첩이 상한과 성능 예산을 지키는가
- 세계 오염과 Day Scaling이 적 수치에 중복 곱해지지 않는가
- 시설 파괴·서버 종료·재설치로 연료와 고유 부품이 복제되지 않는가
- 리소스 팩 없이 오염 단계, 원인과 대응을 읽을 수 있는가

## 완료 기준

- 자유 야생, 유목, 다중 정착지 구조에서 동일하게 동작한다.
- 오염이 체력 배율만이 아니라 변이, 패턴, 환경, 시설 운영을 변화시킨다.
- 정화 시설이 강력한 선택지이지만 없거나 파괴되어도 회차가 영구 중단되지 않는다.
- 모든 저장·판정·UI가 바닐라 클라이언트와 서버 플러그인으로 구현 가능하다.
