# WildSurvival BASE 플레이어 시설망 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 ID | BASE-001~003 |
| 상위 기준 | `VISION`, `RULES`, `CONTENT`, `DISC`, `ECONOMY` |
| 구현 범위 | 바닐라 블록·개체·인벤토리 GUI와 Paper 플러그인 |
| 핵심 전제 | 시작부터 제공되는 고정 기지나 고정 안전 지대 없음 |

## 공통 방향

기지는 반드시 지켜야 하는 단일 고정물이 아니라 플레이어가 필요에 따라 만드는 시설망이다. 파티는 유목 생활, 소규모 야영지 여러 개, 대형 정착지 중 어느 형태도 선택할 수 있다. 시설 건설은 효율과 선택지를 늘리지만, 짓지 않았다는 이유로 핵심 진행이 막히거나 야간 위협을 피할 수 있어서는 안 된다.

# BASE-001 플레이어 건설 시설망

## 1. 시설 단계

| 단계 | 설명 | 예시 |
|---|---|---|
| 휴대 장치 | 인벤토리에서 제한적으로 사용, 항상 비효율적 | 응급 수리 키트, 야전 정화기, 휴대 연구 도구 |
| 야영 시설 | 짧은 체류를 위한 저비용 블록·상호작용점 | 간이 작업대, 침낭, 소형 보관함 |
| 정착 시설 | 위치를 등록하고 연결하는 중형 시설 | 제작·강화대, 치료소, 분석대, 정화기 |
| 재건 시설 | 최종 목표에 필요한 고급 네트워크 | 신호기, 동력 핵, 재건 조립기 |

휴대 장치는 시설 파괴나 유목 플레이 때의 최소 진행 경로를 보장한다. 정착 시설은 더 높은 처리량, 선택 잠금, 공용 대기열, 장기 보관을 제공한다.

## 2. 등록과 네트워크

- 시설은 플레이어가 설치한 블록에 PDC 기반 `facilityInstanceId`를 부여해 등록한다.
- 서로 일정 거리 안에 있거나 중계 장치로 연결된 시설을 하나의 `facilityNetworkId`로 묶는다.
- 네트워크에는 소유권, 접근 권한, 시설 목록, 저장 원장, 위협도, 오염도, 마지막 사용 시각을 저장한다.
- 하나의 파티가 여러 시설망을 가질 수 있으며 주 거점을 지정할 의무는 없다.
- 바닐라 블록 외형은 힌트일 뿐이며, 서버 등록 데이터가 실제 시설 여부를 결정한다.

## 3. 시설 배치 조건

- 월드 보더 안의 충돌 없는 지면이면 원칙적으로 설치할 수 있다.
- 다른 파티가 없는 단일 파티 콘텐츠이므로 토지 경쟁 규칙은 두지 않는다.
- 보스 동적 전장, 포탈, 파괴 불가 구조물, 월드 스폰 보호 범위에는 설치할 수 없다.
- 같은 유형 시설의 과밀 배치는 처리량 감소와 등록 상한으로 제한한다.
- 특정 생물군계나 고정 좌표를 필수 조건으로 사용하지 않는다.

## 4. 시설 기능

| 시설군 | 주요 기능 | 휴대 대안 |
|---|---|---|
| 제작 | 장비·도구·부품 제작, 공용 대기열 | 기본 제작만 가능 |
| 강화·재련 | 확정 강화, 옵션 잠금 재련 | 낮은 등급까지만 가능 |
| 분석·연구 | 발견 단서 분석, 제작식 해금 | 느린 현장 분석 |
| 치료·구조 | 부상 회복, 유품 처리, 부활 보조 | 소모품 기반 응급 처리 |
| 정화 | 지역·플레이어 오염 감소 | 소량 개인 정화 |
| 관측 | 야간 압박 예고, 위험 방향 분석 | 짧은 경고만 제공 |
| 보관 | 공용 가상 원장과 등록 보관함 | 개인 인벤토리·엔더 보관 제한 |
| 세션 | 정상 중단 요청과 체크포인트 | 안전 상태 명령으로 대체 |

## 5. 안전과 회복

- 시설 반경은 자동 안전 지대가 아니다.
- 적 탐지, 최근 피해, 공세·보스 상태가 없을 때만 시설 기능별 휴식 보너스를 적용한다.
- 침대는 바닐라 밤 넘김을 하지 못하며 개인 재접속 지점 또는 회복 보조로 대체한다.
- AP·HP 회복은 `COMBAT`, 부활은 `DEATH`, 정화는 `CORR`가 최종 계산한다.

## 6. 이동과 철거

- 시설은 비전투 상태에서 철거할 수 있다.
- 핵심 재료는 일부 회수하되 설치·철거 반복 이득을 막기 위해 소모 부품은 회수하지 않는다.
- 빠른 이동은 발견·등록된 시설망 사이에서만 제한적으로 허용하며 공세, 보스, 추적 중에는 차단한다.
- 시설을 전부 철거해도 휴대 장치와 발견 진행으로 회차를 계속할 수 있다.

## 7. UI와 저장

시설 관리 GUI는 시설 상태, 연결망, 처리 대기열, 오염, 위협, 권한을 표시한다. 리소스 팩 없이 바닐라 아이템 아이콘, 이름, 로어, 색상, 페이지 이동 아이템으로 완전하게 조작할 수 있어야 한다.

필수 저장 필드는 다음과 같다.

- `facilityInstanceId`, `facilityType`, `revision`
- `facilityNetworkId`, 월드 UUID, 좌표, 방향
- 현재 HP, 손상 단계, 기능 상태
- 소유 파티, 접근 권한, 설치자
- 대기열, 가상 원장 참조, 오염·위협 수치
- 설치·수리·철거 트랜잭션 ID

# BASE-002 동적 야간 압박과 시설 습격

## 1. 목적

야간 위협은 건축 여부와 무관하게 파티를 압박하되, 플레이 방식에 맞는 목표를 선택한다. 고정 기지 외곽 스폰 지점이나 등록 임무 구역을 사용하지 않는다.

## 2. 압박 모드 선택

경고 단계 시작 시 아래 우선순위로 하나의 주 모드를 결정한다.

| 모드 | 조건 | 주 목표 |
|---|---|---|
| `SETTLEMENT_ASSAULT` | 최근 사용된 고가치 시설망이 있고 유효 공격 경로가 존재 | 시설 방어와 파티 압박 |
| `PURSUIT` | 정착 시설이 없거나 파티가 장거리 이동 중 | 플레이어 추적과 이동 경로 차단 |
| `RIFT_PRESSURE` | 파티가 심하게 분산되었거나 지형상 직접 생성이 불안정 | 중간 지점 주변 균열과 단계적 포위 |

시설을 짓지 않으면 `PURSUIT` 또는 `RIFT_PRESSURE`가 발생하므로 공세를 회피할 수 없다. 시설이 여러 개면 최근 사용량, 시설 가치, 파티 거리, 네트워크 위협도를 합산해 목표를 고른다.

## 3. Day 단계

| 단계 | 기본 시간 | 기능 |
|---|---:|---|
| 활동 | 0~5분 | 탐험·제작·이동·시설 정비 |
| 경고 | 5~6분 | 모드·위험 방향·특수 조건 예고 |
| 압박 | 6~7분 | 동적 공세 또는 특수 사건 수행 |

정확한 Day 시간과 특수 Day 예외는 `CONTENT`와 `GAME`이 최종 결정한다.

## 4. 위협 예산

공세 예산은 `CONTENT`가 제공하는 Day 구간 기본값에 다음 보정만 한 번씩 적용한다.

```text
최종 위협 예산 = 콘텐츠 기본 예산
               × 회차 난이도 배율
               × 유효 전투 인원 배율
               × 현재 압박 모드 보정
               × 잔존 압박 보정
```

- Day 증가, 오염 단계, 엘리트 확률, 패턴 증가는 `CONTENT` 또는 적 템플릿이 이미 반영한 값을 다시 곱하지 않는다.
- 적 체력, 적 수, 엘리트 수, 스킬 수를 동시에 올리지 않고 구간별 예산 배분표를 사용한다.
- TPS가 안전선 아래면 개체 수를 줄이고 동일 예산을 패턴·정예도에 재배분한다.

## 5. 동적 생성 지점

- 목표 주변의 환형 후보 지점을 지형 검사로 생성한다.
- 시야 밖, 충돌 없는 지면, 월드 보더 내부, 보호 구조물 밖인 후보만 사용한다.
- 밝기나 플레이어 건축만으로 모든 후보를 무효화할 수 없게 하되, 몬스터를 밀폐 블록 안에 생성하지 않는다.
- 후보가 부족하면 반경을 단계적으로 넓히고, 그래도 실패하면 시각화된 균열을 예고한 뒤 안전한 위치에 생성한다.
- 같은 좌표 반복 생성은 쿨다운과 시드 난수로 방지한다.

## 6. 목표 우선순위

| 압박 모드 | 우선순위 |
|---|---|
| 정착지 습격 | 방어 중인 플레이어 → 관측·정화·재건 시설 → 기타 시설 |
| 추적 | 고립 플레이어 → 후방 지원 플레이어 → 파티 중심 |
| 균열 압박 | 파티 합류 경로 → 공용 자원 접근점 → 활성 플레이어 |

완전히 막힌 시설을 공격하기 위한 제한적 블록 파괴는 `BREAKABLE_BY_ASSAULT`로 등록된 임시 방어 블록에만 허용한다. 자연 지형과 무관한 광범위 파괴는 금지한다.

## 7. 완료와 잔존 압박

- 지정 예산의 핵심 개체 처치와 사건 목표 완료 시 압박을 종료한다.
- 시간 초과 잔존 적은 즉시 삭제하지 않고 약화·추적 표식·오염 증가 중 하나를 적용한다.
- 다음 Day 예산에는 잔존 압박을 제한적으로 반영하되 무한 누적 상한을 둔다.
- 보상은 참여 기여와 `GAME`·`EQUIP`의 공용 보상 규칙을 따른다.

# BASE-003 시설 피해·수리·진행 안전장치

## 1. 시설 상태

| 상태 | HP 비율 | 효과 |
|---|---:|---|
| 정상 | 70% 초과 | 전체 기능 |
| 손상 | 30% 초과 | 처리량·범위 감소 |
| 기능 정지 | 0% 초과 | 핵심 기능 차단, 수리 가능 |
| 파괴 | 0% | 잔해와 복구 원장 생성 |

시설 HP는 시설 등급과 난이도·인원만 반영한다. Day 증가를 HP 공식에 직접 다시 곱하지 않고 상위 콘텐츠 템플릿에서 내구 등급을 선택한다.

## 2. 피해 원칙

- 시설 피해는 서버가 지정한 공세 스킬과 상호작용만 적용한다.
- 폭발, 불, 용암 등 바닐라 연쇄 파괴는 차단하고 커스텀 시설 피해로 변환한다.
- 플레이어의 실수 클릭은 시설 피해를 주지 않는다.
- 선택형 전술 아군 피해 모드에서도 시설 고의 파괴는 별도 관리자 규칙 없이는 금지한다.

## 3. 수리와 복구

- 평시 수리는 재료와 짧은 채널링을 소비한다.
- 압박 중 긴급 수리는 효율이 낮고 공격받으면 중단된다.
- 파괴된 시설은 복구 원장과 잔해를 이용해 동일 네트워크에 재건할 수 있다.
- 유일 부품은 시설 파괴로 소실되지 않고 회차 가상 원장에 잠긴 상태로 보존된다.
- 파괴 위치가 접근 불가능하면 안전한 플레이어 위치에서 복구 요청을 생성한다.

## 4. 진행 막힘 방지

- 핵심 발견은 시설 파괴 전에 만족한 조건을 소급 유지한다.
- 필수 제작 시설이 모두 파괴되면 휴대 장치로 하위 등급 복구 부품을 만들 수 있다.
- 최종 재건 시설은 Day 50 전에는 완성 상태로 전환되지 않는다.
- 시설을 설치하지 않은 파티도 탐험·현장 분석·휴대 제작으로 핵심 진행을 이어갈 수 있으나 처리 시간과 자원 효율에서 손해를 본다.

## 5. 트랜잭션과 복구

설치, 수리, 철거, 파괴, 복구는 각각 고유 트랜잭션 ID로 기록한다. 서버 재시작 시 블록 상태와 저장 원장을 비교해 미완료 트랜잭션을 한 번만 완료하거나 롤백한다. 중복 아이템, 유령 시설, 좌표 충돌이 발견되면 시설 기능을 잠그고 관리자 검사 대상으로 전환한다.

## 6. 테스트 항목

- 시설 없이 Day 압박이 정상적으로 추적 모드로 실행되는가
- 시설을 여러 곳에 나눠 지어도 목표가 결정론적으로 선택되는가
- 지형과 건축 때문에 생성 후보가 없을 때 균열 대체 경로가 작동하는가
- 시설 전멸 후 휴대 장치만으로 핵심 복구가 가능한가
- 시설 파괴와 서버 종료가 겹쳐도 자원 복제·소실이 없는가
- 고정 좌표, 고정 기지 중심, 고정 외곽 스폰 지점 없이 동작하는가
- 리소스 팩 없이 모든 시설 상태와 경고를 확인할 수 있는가

## 완료 기준

- 유목·야영·정착 플레이가 모두 유효하다.
- 건설 여부가 야간 위협 회피 수단이 되지 않는다.
- 시설의 편의성과 위험이 명확하지만 시설 파괴가 영구 소프트락을 만들지 않는다.
- 모든 기능이 바닐라 클라이언트와 서버 플러그인만으로 구현 가능하다.
