# WildSurvival AUG 증강 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 카테고리 | 개인·파티 증강 선택, 등급 잠금, 드로우, 진화, 리롤 |
| 목록 문서 | AUG 증강 리스트 기획서 |
| 참여 규칙 | 회차 시작 멤버 고정, 신규 중도 참여 없음 |
| 최종 수정일 | 2026-08-16 |

## 1. 시스템 목적

- 레벨 진행마다 플레이어가 자신의 무기와 플레이 방식에 맞는 빌드를 구성한다.
- 무작위 선택의 변주를 유지하되 사용할 수 없는 후보와 완전한 운 나쁨을 제한한다.
- 최초 레벨 달성자의 등급 결과가 같은 회차의 해당 레벨과 적 증강에 공동 세계 규칙으로 남는다.
- 파티 증강은 전원에게 적용되는 장기 전략 선택을 제공한다.
- 서버 플러그인이 후보 생성, 투표, 저장과 발동 결과를 권위 있게 처리한다.

## 2. 증강 구분

| 구분 | 소유권 | 선택 주체 | 적용 범위 |
|---|---|---|---|
| 개인 증강 | 플레이어 | 해당 플레이어 | 개인 전투·활동·장비 빌드 |
| 파티 증강 | 회차 | 파티 투표 | 회차의 모든 등록 플레이어와 지정 파티 시스템 |
| 적 증강 | 적 개체 | 서버 시드 드로우 | 해당 적 또는 명시된 적 집단 |

## 3. 증강 등급

| 등급 | 내부 ID | 기본 역할 |
|---|---|---|
| 실버 | `SILVER` | 안정적인 수치·기초 운용 강화 |
| 골드 | `GOLD` | 조건부 발동, 태그 조합, 행동 보상 |
| 프리즘 | `PRISM` | 규칙 변화, 강한 빌드 전환, 명시적 대가 |

- 등급은 무조건적인 상하 호환이 아니라 효과 구조와 복잡도를 뜻한다.
- 프리즘도 최종 하드캡과 무한 행동 방지 규칙을 따른다.
- 모든 등급에는 범용, 무기, 방어, 상태, 브레이크, 지원 후보가 존재해야 한다.

## 4. 개인 증강 선택 레벨

개인 증강은 총 10회 제공한다.

| 선택 순서 | 레벨 | 등급 결정 |
|---:|---:|---|
| 1 | 3 | 실버 고정 |
| 2 | 6 | 골드 고정 |
| 3 | 10 | 프리즘 고정 |
| 4 | 15 | 회차 최초 달성 시 확률 결정 후 잠금 |
| 5 | 20 | 회차 최초 달성 시 확률 결정 후 잠금 |
| 6 | 25 | 회차 최초 달성 시 확률 결정 후 잠금 |
| 7 | 30 | 회차 최초 달성 시 확률 결정 후 잠금 |
| 8 | 35 | 회차 최초 달성 시 확률 결정 후 잠금 |
| 9 | 40 | 회차 최초 달성 시 확률 결정 후 잠금 |
| 10 | 45 | 회차 최초 달성 시 확률 결정 후 잠금 |

- 최대 레벨 50에서는 추가 개인 증강 선택을 제공하지 않는다.
- `n > 10`이며 `n mod 5 = 0`인 선택은 총 10회 조건에 맞춰 15~45만 사용한다.
- 레벨을 여러 단계 한 번에 올리면 미처리 선택을 레벨 순서대로 대기열에 등록한다.
- 전투 중 레벨을 달성해도 등급 잠금은 즉시 처리하지만 후보 선택 GUI는 안전 상태까지 보류할 수 있다.

## 5. 레벨별 등급 잠금

### 확률

레벨 15 이후 각 선택 레벨의 등급은 다음 확률을 사용한다.

| 등급 | 확률 |
|---|---:|
| 실버 | 50% |
| 골드 | 30% |
| 프리즘 | 20% |

### 최초 달성자 잠금

1. 해당 레벨의 등급 잠금이 존재하는지 확인한다.
2. 존재하지 않으면 가장 먼저 레벨에 도달한 플레이어의 레벨 상승 이벤트가 서버 시드로 등급을 추첨한다.
3. 결과를 `run.augment-tier-locks[level]`에 즉시 저장한다.
4. 이후 같은 레벨에 도달한 모든 플레이어는 잠긴 등급을 사용한다.
5. 각 플레이어에게 표시되는 후보 3개는 같은 등급 안에서 개별적으로 드로우한다.

- 등급 추첨은 플레이어 UUID, 접속 순서나 클라이언트 난수에 의존하지 않는다.
- 같은 틱에 여러 플레이어가 도달하면 레벨 상승 이벤트의 서버 확정 순번이 가장 낮은 플레이어를 최초 달성자로 기록한다.
- 저장 실패 시 후보 GUI를 열지 않고 등급 잠금 저장을 재시도한다.

## 6. 적 증강과 등급 잠금

- 적 증강도 회차의 개인 증강 레벨별 등급 잠금을 참조한다.
- 레벨 3·6·10의 고정 등급과 레벨 15 이후 잠금 등급을 동일하게 사용한다.
- 적은 플레이어용 증강 목록을 그대로 사용하지 않고 `eligible-for-enemy: true` 또는 전용 적 증강 목록에서 선택한다.
- 등급 잠금이 생성된 뒤 새로 생성되거나 변이되는 적만 해당 슬롯의 증강을 드로우한다.
- 이미 전투 중인 적에게 새 증강을 소급 부여하지 않는다.
- 일반 적 전체에 모든 잠금 슬롯을 부여하지 않는다. Day, 적 등급, 변이 확률과 적별 최대 증강 수를 따른다.
- 보스는 무작위 적 증강보다 보스 데이터의 허용 목록과 패턴 안전 검증을 우선한다.

### 적 증강 선택 예시

레벨 15 잠금이 실버라면:

- 모든 플레이어의 레벨 15 개인 선택은 실버 후보 3개를 사용한다.
- 이후 적 증강 슬롯 15를 받는 적은 실버 적 증강 중 하나를 선택한다.
- 플레이어 후보와 적 증강의 실제 ID는 서로 독립적으로 추첨한다.

## 7. 개인 후보 생성 파이프라인

```text
선택 레벨과 잠긴 등급 확인
→ 등급 풀 로드
→ 선행·Day·무기·소유·배타 조건 필터
→ 현재 즉시 작동 가능한 후보 판정
→ 진화 보장 슬롯 판정
→ 태그 기반 가중치 계산
→ 후보 역할 슬롯별 가중 무작위 추첨
→ 중복·무효·동일 계열 재검증
→ 최종 3개 저장 후 GUI 표시
```

후보 생성 결과는 GUI를 열기 전에 저장한다. GUI를 닫거나 재접속해도 같은 후보를 다시 표시한다.

## 8. 빌드 편향 가중치

후보는 무작위지만 현재 빌드와 무관한 후보만 연속해서 등장하지 않게 가중치를 적용한다.

### 기본 가중치

| 조건 | 가중치 배율 |
|---|---:|
| 기본 후보 | 1.00 |
| 현재 주무기 핵심 태그 일치 | 2.00 |
| 보조무기 핵심 태그 일치 | 1.30 |
| 보유 증강의 활성 핵심 태그 일치 | 태그당 +0.35, 최대 +1.05 |
| 현재 가장 높은 빌드 태그와 일치 | 1.35 |
| 파티에 부족한 생존·지원 범용 태그 | 1.15 |
| 최근 두 선택에서 같은 세부 태그 과다 | 0.65 |
| 현재 작동은 가능하지만 조건 충족 빈도가 낮음 | 0.50 |

- 가중치는 후보 자격을 만들지 않는다. 선행 조건을 만족하지 못한 증강은 가중치 계산 전에 제거한다.
- 한 무기 태그가 모든 후보를 독점하지 않도록 최종 가중치 상한을 기본값의 4배로 둔다.
- 장비를 선택 직전에 교체해 후보를 조작하는 것을 막기 위해 레벨 달성 시점의 주무기 태그와 최근 2분간 가장 오래 사용한 무기 태그를 함께 저장한다.
- 두 태그가 다르면 둘 다 인정하되 현재 무기 배율을 더 높게 적용한다.

## 9. 후보 3개의 역할 보장

세 후보는 선택 등급 안에서 다음 역할을 우선한다.

| 후보 슬롯 | 역할 |
|---:|---|
| 1 | 현재 주무기 또는 가장 강한 빌드 태그와 직접 연결되는 `ANCHOR` |
| 2 | 기존 증강을 확장하거나 진화시키는 `EXTENSION` |
| 3 | 무기 비종속 생존·지원 또는 새로운 태그를 여는 `BRIDGE/WILDCARD` |

- 최종 후보는 모두 선택된 동일 등급에 속한다.
- 최소 2개는 선택 즉시 실제 효과를 발동할 수 있어야 한다.
- `ANCHOR` 후보가 없으면 범용 공격·AP·회피·방어 후보로 대체한다.
- `EXTENSION` 후보가 없으면 두 번째 호환 후보를 사용한다.
- 후보 풀이 부족하면 등급을 바꾸지 않고 해당 등급의 안전 범용 풀을 사용한다.
- 안전 범용 풀까지 3개 미만이면 선택을 열지 않고 데이터 오류를 기록한다.

## 10. 무효 후보 방지

다음 후보는 기본적으로 등장하지 않는다.

- 현재 회차에서 사용할 수 없는 입력이나 시스템을 요구함
- 장착할 수 없는 무기군만 요구하고 범용 효과가 없음
- 이미 배타 증강을 보유함
- 선행 증강·발견·Day 조건을 충족하지 않음
- 효과가 현재 하드캡을 영구적으로 초과하며 다른 효용이 없음
- 남은 회차에서 발동할 사건이 존재하지 않음
- 같은 증강을 이미 보유했고 중첩 불가임
- 파티 인원이나 특정 직업 수를 필수 조건으로 요구함

후보 생성 시점에는 유효했지만 선택 시점에 장비가 달라진 경우에도 선택은 허용한다. 장비를 다시 사용하면 작동할 수 있기 때문이다. 단, 회차에서 영구적으로 사용할 수 없는 후보는 서버가 거부한다.

## 11. 진화 증강

### 기본 원칙

- 진화는 선행 증강을 더 강한 같은 계열 효과로 교체한다.
- 진화 선택도 개인 증강 10회 중 한 번을 소비한다.
- 진화 완료 시 선행 증강은 비활성화하고 진화 증강이 같은 계열 슬롯을 계승한다.
- 형제 진화 중 하나를 선택하면 다른 형제 진화는 배타 처리한다.
- 진화는 단순 수치 상승뿐 아니라 발동 조건, 대상, 자원 흐름 또는 파티 연계를 변경해야 한다.

### 선행 조건

진화 증강은 다음 조건을 조합할 수 있다.

- 지정 선행 증강 보유
- 선행 증강의 유효 발동 횟수 또는 누적 성과
- 지정 무기·상태·브레이크·지원 태그 사용 경험
- 최소 개인 증강 선택 순서
- 최소 Day 또는 발견 노드
- 배타 진화 미보유

### 등급 잠금과 출현 보장

등급 잠금을 위반하지 않기 위해 진화 계열은 가능한 경우 실버·골드·프리즘 변형을 각각 가진다.

```text
evolution-family: dodge-afterimage
variants:
  SILVER: dodge-afterimage-silver
  GOLD: dodge-afterimage-gold
  PRISM: dodge-afterimage-prism
```

- 진화 조건을 달성하면 `pending-evolution`에 등록한다.
- 다음 개인 증강 선택에서 잠긴 등급과 같은 진화 변형이 존재하면 후보 한 칸을 해당 계열 진화로 보장한다.
- 복수 진화가 대기 중이면 가장 먼저 조건을 달성한 계열을 우선한다.
- 해당 등급 변형이 없다면 일반 후보를 생성하고 다음 선택으로 보장을 이월한다.
- 레벨 45 선택까지 적합한 변형이 한 번도 없지 않도록 모든 핵심 진화 계열은 세 등급 변형을 제공해야 한다.
- 선택하지 않은 보장 진화는 다음 선택에서 다시 보장하지 않고 일반 가중 후보로 돌아간다. 단, 한 회차에 최초 보장 기회는 계열별 한 번 제공한다.

## 12. 중복과 중첩

| 정책 | 처리 |
|---|---|
| `UNIQUE` | 같은 플레이어가 한 번만 보유, 기본값 |
| `STACKABLE` | 명시된 최대 중첩까지 재선택 가능 |
| `EVOLUTION_REPLACE` | 선행 증강을 진화 증강으로 교체 |
| `PARTY_UNIQUE` | 회차에 하나만 적용 |

- 중첩 가능 증강은 최대 중첩 수를 필수로 가진다.
- 기본 중첩 효율은 1회차 100%, 2회차 60%, 3회차 35%를 권장하며 증강별로 명시한다.
- 규칙 변경형 프리즘 증강은 기본적으로 중첩 불가다.
- 같은 발동 사건의 여러 증강은 각각 ICD를 검사하고 전체 발동 상한을 적용한다.

## 13. 배타 조건

### 강한 배타

- 동시에 보유하면 규칙이 충돌하거나 한쪽이 완전히 무효가 되는 조합이다.
- 후보 자격 단계에서 제거한다.
- 예: AP를 모두 제거하는 증강과 최대 AP 비례 효과 전용 증강.

### 계열 배타

- 같은 진화 계열의 형제 진화, 같은 자세를 점유하는 증강에 사용한다.
- 하나를 선택하면 다른 계열 ID를 영구 차단한다.

### 약한 충돌

- 함께 사용할 수 있지만 효율이 낮은 조합이다.
- 제거하지 않고 가중치를 0.35~0.60으로 낮추며 GUI에 충돌 경고를 표시한다.

배타는 증강 ID와 배타 그룹을 모두 지원한다. 목록 문서에서 반드시 양방향 검증한다.

## 14. 리롤

- 후보 선택 전 전체 후보 3개를 한 번에 다시 추첨한다.
- 선택 레벨당 기본 최대 1회다.
- 잠긴 등급은 변경하지 않는다.
- 진화 보장 슬롯은 리롤 후에도 유지한다.
- 직전 후보 3개는 같은 리롤에서 다시 등장하지 않는다.
- 비용은 개인 소유가 아니라 파티 공용 `증강 안정화 코어` 1개를 기준안으로 사용한다.
- 비용은 리롤 확정 시 원자적으로 소비한다.
- 리롤 GUI는 현재 공용 자원과 사용 결과를 파티에 알린다.
- 정확한 획득량과 세션별 예산은 ECONOMY에서 확정한다.

## 15. 교체

- 일반 선택 실수를 복구할 수 있지만 전투마다 최적 빌드로 바꾸는 기능은 허용하지 않는다.
- 증강 공명기 시설이 정상 작동하고 전투·공세·보스 상태가 아닐 때만 가능하다.
- 교체 대상의 원래 선택 레벨과 등급을 유지한다.
- 원래 증강과 현재 배타되는 후보, 직전 교체에서 제거한 후보를 제외하고 3개를 생성한다.
- 기본 교체 비용은 `증강 안정화 코어 2개 + 오염 촉매`로 제안한다.
- 플레이어별 회차당 기본 1회만 허용하고 추가 교체는 파티 증강·희귀 발견이 명시한 경우에만 연다.
- 프리즘 증강과 진화 증강 교체는 기본 비용 2배 또는 별도 금지 정책을 증강 데이터에 명시한다.
- 교체로 제거한 증강의 누적 발동 기록은 새 증강에 이전하지 않는다.

## 16. 파티 증강 선택

파티 증강은 Day 10·20·30·40 보스 정산에서 총 4회 제공한다.

- 후보는 3개다.
- 후보 생성 시 현재 파티 증강과 강한 배타를 제거한다.
- 특정 무기군이 없으면 무효가 되는 파티 증강은 후보에서 제외한다.
- 완전 사망자도 투표할 수 있다.
- 투표 후보와 표는 정산 저장 데이터에 기록한다.

### 동률 처리

1. 생존 플레이어 표만 집계한다.
2. 생존 표 1위가 하나면 즉시 확정한다.
3. 생존 표가 동률이면 동률 후보에 한해서 완전 사망자 표를 추가한다.
4. 사망자 표로 하나의 1위가 생기면 해당 후보를 확정한다.
5. 여전히 동률이면 남은 동률 후보 중 서버 시드 무작위로 확정한다.
6. 생존 투표가 전혀 없으면 사망자 표를 1차 집계로 사용하고, 동률은 서버 시드 무작위로 처리한다.

- 사망자의 표는 생존자가 열세인 후보를 동률 후보군에 다시 진입시키지 않는다.
- 무투표는 모든 후보를 동률로 간주하고 서버 시드 무작위로 결정한다.
- 결과와 난수 시드를 저장하여 재시작으로 결과가 바뀌지 않게 한다.

## 17. 선택 보류와 시간 처리

- 개인 증강 선택 GUI가 열려 있어도 Day와 전투를 자동 정지하지 않는다.
- 전투 중에는 선택을 `PENDING`으로 저장하고 안전 상태에서 GUI를 연다.
- 플레이어는 선택 전까지 해당 마일스톤 증강 효과를 받지 않는다.
- 다음 개인 마일스톤에 도달하기 전에 이전 선택을 처리하는 것을 기본으로 한다.
- 미처리 선택이 여러 개면 낮은 레벨부터 순서대로 처리한다.
- 파티 증강 투표는 세션 정산 중 Day가 정지된 상태에서 진행한다.

```yaml
run:
  augment-tier-locks:

    15:
      tier: SILVER
      first-player: "uuid-a"

players:
  "uuid-a":

      3:
        tier: SILVER
        chosen: aug.dodge.breath
        rerolled: false

```

저장 대상:

- 레벨별 등급 잠금, 최초 달성자, 저장 순번과 시드
- 플레이어별 후보 3개, 리롤 전후 후보와 선택 결과
- 보유·진화·배타·중첩 상태
- 리롤·교체 사용 횟수와 소비 기록
- 파티 증강 후보, 생존·사망 표, 동률 단계와 최종 결과
- 적 개체의 증강 ID와 출처 마일스톤

## 20. 테스트 항목

- 레벨 3·6·10 고정 등급
- 레벨 15~45의 50%·30%·20% 분포
- 같은 회차 동일 레벨 등급 잠금
- 같은 틱 최초 달성자 결정
- 플레이어별 후보 3개 독립 드로우
- 적 증강의 같은 등급 잠금 사용과 기존 적 미소급
- 주무기·기존 증강 태그 가중치
- 최소 2개 즉시 작동 후보와 안전 범용 폴백
- 진화 보장 후보의 등급 일치
- 중복·강한 배타·약한 충돌
- 리롤 등급 유지와 이전 후보 제외
- 교체 횟수·비용·원래 등급 유지
- 생존자 우선, 사망자 후순위 동률 처리
- 재접속·재시작 후 후보와 투표 결과 유지
- 전투 중 선택 보류와 마일스톤 순서 처리

## 21. 완료 기준

- 개인 증강 10회와 파티 증강 4회의 일정이 확정되어 있다.
- 최초 달성자 기준 레벨별 등급 잠금과 적 연계가 정의되어 있다.
- 후보 3개의 필터, 가중치, 호환 보장과 폴백이 정의되어 있다.
- 진화, 중복, 배타, 리롤과 교체 규칙이 정의되어 있다.
- 사망자 투표권을 포함한 파티 동률 처리 순서가 결정적이다.
- 신규 중도 참여 보정 없이 저장·재접속이 동작한다.
