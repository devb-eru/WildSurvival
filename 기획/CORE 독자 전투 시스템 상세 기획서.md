- 등록 플레이어와 콘텐츠 개체의 체력, 피해, 방어, 사망 판정은 플러그인이 서버 권위로 처리한다.
- 마인크래프트 바닐라 체력, 방어력, 공격 피해는 실제 콘텐츠 전투 계산에 사용하지 않는다.
- 바닐라 피해 이벤트는 입력 감지와 연출에만 활용하고 실제 피해는 커스텀 피해 서비스로 실행한다.
- 일반 공격 입력은 직접 피해를 주지 않으며 `CORE-002`에서 무기별 일반 공격 스킬로 변환한다.
- 플레이어와 몬스터는 같은 커스텀 피해 계산 구조를 사용한다.
- 모든 피해는 실행 ID, 출처, 분류, 계산 과정과 실제 적용 결과를 추적할 수 있어야 한다.

# CORE-001 독자 HP·DEF·피해 계산 및 바닐라 피해 차단

## 1. 시스템 목적

CORE-001은 WildSurvival의 모든 피해와 생명 상태 판정이 통과하는 공통 전투 기반이다.

- 높은 커스텀 HP와 독자 스탯 공식을 안정적으로 사용한다.
- 바닐라 피해와 커스텀 피해가 중복 적용되는 문제를 차단한다.
- DEF, PEN, 치명타, 피해 보정, 방어, 회피, 보호막의 처리 순서를 통일한다.
- 환경 피해와 오염 피해를 커스텀 HP 규모에 맞게 환산한다.
- 치명 피해를 바닐라 사망 대신 빈사 및 완전 사망 시스템으로 연결한다.
- 공격 출처, 실제 피해, 기여도와 보상 데이터를 일관되게 기록한다.

## 2. 커스텀 전투 적용 대상

### 적용 대상

- 현재 회차에 등록된 플레이어
- 콘텐츠 태그가 있는 일반 몬스터, 엘리트, 보스
- 콘텐츠 시설, 소환수, 함정, 특수 개체
- 플러그인이 명시적으로 커스텀 전투 대상으로 등록한 개체

### 비적용 대상

- 회차 외 플레이어
- 일반 동물과 주민
- 콘텐츠 태그가 없는 바닐라 몬스터
- 운영자가 커스텀 전투 대상에서 제외한 개체

비적용 대상은 기본적으로 바닐라 체력과 피해 시스템을 유지한다. 커스텀 전투 대상과 비적용 대상이 서로 공격하면 대상별 정책에 따라 바닐라 피해를 차단하거나 허용한다.

## 3. 서버 권위 커스텀 HP

### 기본 원칙

- 실제 현재 HP와 최대 HP는 플러그인 데이터로 관리한다.
- 바닐라 체력값은 생존 상태 유지와 UI 표시에만 사용한다.
- 바닐라 체력값을 읽어 실제 커스텀 HP를 역산하지 않는다.
- 현재 커스텀 HP는 최대 커스텀 HP를 초과할 수 없다.
- 생존 중 현재 커스텀 HP는 최소 1이며, 피해로 0 이하가 되면 빈사 판정을 수행한다.
- STANDARD 커스텀 HP 계산과 저장은 `double`을 사용한다.
- STANDARD 실제 최대 HP 기술 한계는 `1,000,000,000`이다.
- CHAOS는 BigNumber HP와 보호막을 사용한다.
- STANDARD 기술 한계를 초과한 계산은 한계값으로 제한하고 원인 출처를 오류 로그에 기록한다.

### 몬스터 처리

- 콘텐츠 몬스터도 커스텀 HP만 실제 생존 판정에 사용한다.
- 바닐라 최대 체력, 방어력, 방어구 수치는 실제 피해 계산에서 제외한다.
- 커스텀 HP가 0 이하가 되면 플러그인이 처치, 드롭, 기여도, 보상을 확정한 후 개체를 제거한다.
- 일반 비콘텐츠 개체는 바닐라 생명 및 사망 처리를 유지한다.

## 4. 플레이어 바닐라 HP UI 연동

플레이어는 모드 없이 바닐라 하트 HUD로 커스텀 HP 비율을 확인한다.

### 표시 기준

- 바닐라 최대 체력 UI는 한 줄 `20 반 하트`, 즉 하트 10개로 고정한다.
- Normal 기본 최대 HP 1,000에서는 커스텀 HP 50당 반 하트 한 칸에 대응한다.
- 최대 HP가 1,000이 아닌 경우에도 한 줄 전체가 현재 최대 HP를 나타내는 비율 표시를 사용한다.

```text
표시 반 하트 수 =
ceil(
  현재 커스텀 HP / 최대 커스텀 HP
  × 20
)
```

- 현재 커스텀 HP가 1 이상이면 최소 반 하트 한 칸을 표시한다.
- 커스텀 HP가 0 이하일 때만 빈사 전환을 수행한다.
- 흡수 하트는 커스텀 보호막 표시로 사용하지 않는다.
- 정확한 현재 HP와 최대 HP는 상세 스탯 GUI 또는 보조 HUD에서 확인할 수 있다.

### 생명 상태별 표시

| 생명 상태 | 바닐라 HP UI |
|---|---|
| `ALIVE` | 커스텀 HP 비율을 한 줄에 표시 |
| `DOWNED_GRACE`, `DOWNED`, `BEING_REVIVED` | 최소 반 하트 한 칸으로 고정 |
| `DEAD` | 관전 모드이므로 HP UI 의미 없음 |

- UI 동기화 과정에서 발생한 바닐라 체력 변경은 커스텀 피해나 회복으로 처리하지 않는다.
- 바닐라 허기 자연 회복은 커스텀 HP를 회복하지 않는다.

## 5. 바닐라 전투 기능 차단

### 차단할 바닐라 피해

등록 플레이어와 콘텐츠 개체 사이에서 발생하는 다음 바닐라 피해는 실제 HP 적용 전에 취소한다.

- 근접 공격
- 화살, 삼지창과 기타 투사체
- 폭발
- 마법 및 물약 피해
- 가시 피해
- 화염 인챈트와 바닐라 연소 피해
- 늑대, 골렘 등 바닐라 소환 개체 공격
- 다른 플러그인이 일반 피해 이벤트로 발생시킨 미등록 피해

커스텀 스킬 또는 환경 피해 서비스가 허용된 API를 통해 생성한 피해만 커스텀 HP에 적용한다.

### 차단할 바닐라 능력치와 효과

- 바닐라 방어구 수치와 방어구 강도
- 보호 계열 인챈트
- 바닐라 저항 효과
- 바닐라 힘과 약화의 피해 보정
- 바닐라 흡수 하트
- 바닐라 자연 HP 회복
- 바닐라 무기 공격 피해

사용할 효과는 장비, 증강, 상태이상 또는 스킬의 커스텀 옵션으로 별도 구현한다.

### 외부 플러그인 호환

- 등록 플레이어와 콘텐츠 개체에 발생한 외부 플러그인 피해는 기본적으로 차단한다.
- 허용된 커스텀 피해 API로 등록된 피해만 적용한다.
- 차단된 외부 피해는 출처 플러그인, 대상, 원인과 수치를 운영 로그에 기록한다.
- 운영자는 신뢰 가능한 출처 플러그인을 허용 목록에 추가할 수 있다.

## 6. 바닐라 무적 틱과 피격 연출

- 커스텀 피해에는 바닐라 피격 후 무적 틱을 사용하지 않는다.
- 스킬 실행 ID, 타격 ID, 대상 ID와 공격별 내부 적중 간격으로 중복 피해를 방지한다.
- 다단 공격의 적중 간격과 최대 타격 횟수는 스킬 데이터에서 정의한다.
- 피해 적용 후 바닐라 피격 애니메이션, 붉은 효과, 사운드와 입자를 별도로 재생한다.
- 바닐라 피해 이벤트를 취소하더라도 커스텀 연출이 누락되지 않게 한다.
- 넉백과 강제 이동은 바닐라 피해 반응에 의존하지 않고 커스텀 스킬 데이터로 처리한다.
- 일반 공격 스킬에는 데이터로 작은 기본 넉백을 제공할 수 있다.

## 7. 피해 최상위 분류

| 분류 | 내부 ID | 기본 처리 |
|---|---|---|
| 일반 피해 | `NORMAL` | 계수, 치명타, DEF, PEN, 피해 보정 적용 |
| 고정 피해 | `FIXED` | DEF·PEN 무시, 기본 피해 보정 무시 |
| 환경 피해 | `ENVIRONMENT` | 공격자 없음, DEF·일반 피해 보정 무시 |
| 오염 피해 | `POLLUTION` | 난이도별 DEF 효율과 대상 피해 보정 적용 |
| 시스템 피해 | `SYSTEM` | 일반 계산을 우회하고 명시된 시스템 결과 실행 |

### 고정 피해

- 정해진 수치만큼 HP를 감소시킨다.
- DEF, PEN, `DAMAGE_DEALT`, `DAMAGE_TAKEN`은 별도 허용 태그가 없으면 적용하지 않는다.
- 보호막, 빈사 전환, 빈사 피해 상한과 보호 상태는 정상 적용한다.
- 시스템 피해와 달리 일반적으로 빈사 단계를 건너뛰지 않는다.

### 환경 피해

- 자연 화재, 용암, 낙하, 익사, 질식, 굶주림 등 공격자가 없는 위험이다.
- DEF, PEN, `DAMAGE_DEALT`, `DAMAGE_TAKEN`을 적용하지 않는다.
- 보호막과 빈사 전환 규칙은 정상 적용한다.
- 회피, 패링, 일반 방어로 막을 수 없다.

### 오염 피해

- 환경 피해와 분리된 `POLLUTION` 유형을 사용한다.
- 공격자 `DAMAGE_DEALT`는 적용하지 않는다.
- 대상 `DAMAGE_TAKEN`은 적용한다.
- 플레이어의 DEF를 난이도별 오염 DEF 효율로 보정한 뒤 적용한다.
- 오염 피해의 세부 발생량과 주기는 `CORR` 문서에서 확정한다.

### 시스템 피해

- 공허 구조 횟수 소진, 운영자 강제 사망 등 명시된 시스템 결과에만 사용한다.
- 보호막, DEF, 피해 감소, 회피, 패링을 무시할 수 있다.
- 시스템 피해만 명시적으로 빈사 단계를 건너뛸 수 있다.

## 8. 공격 효과와 자연 환경의 구분

- 자연적으로 발생한 불, 용암과 폭발은 환경 피해다.
- 플레이어 또는 몬스터 스킬이 생성한 불, 장판, 폭발은 일반 공격 또는 DOT 피해다.
- 공격자가 설치하거나 점화한 TNT는 원본 소유자가 있는 일반 공격 피해다.
- 소유자를 확인할 수 없는 TNT, 침대, 리스폰 정박기 폭발은 환경 피해다.
- 공격 출처를 잃은 투사체와 소환물은 효과 데이터의 출처 상실 정책을 따른다.

## 9. 일반 피해 계산 순서

### 우선 판정 순서

```text
1. 시스템 피해 여부
2. 대상 생명 상태와 피해 가능 여부
3. 피해 면역
4. 패링
5. 회피 무적
6. 일반 피해 수치 계산
7. 아군 공격 배율
8. 일반 방어·부분 회피·기믹 보정
9. 보호막 차감
10. HP 적용 및 빈사 판정
```

- 패링이 회피 무적보다 먼저 판정된다.
- 패링 성공 공격은 회피 성공으로 중복 기록하지 않는다.
- 피해 면역, 패링, 회피 무적으로 무효화한 공격은 피해 계산을 진행하지 않는다.

### 일반 피해 수치 계산

아래 수식은 `STANDARD` 규칙 모드의 기본 계산식이다. `CHAOS`에서는 `SKILL-001`의 BigNumber 수치 엔진, 상대 DEF 공식과 98% 일반 PEN 상한을 사용한다.

```text
계수 피해 =
스킬 기본 피해
+ 모든 허용 참조 스탯 계수

공격자 보정 피해 =
계수 피해
× DAMAGE_DEALT 및 공격별 피해 보정

치명타 피해 =
공격자 보정 피해
× 치명타 배율

유효 DEF =
max(
  0,
  대상 DEF - 적용 PEN
)

DEF 감소 후 피해 =
치명타 피해
× (1 - 유효 DEF / (100 + 유효 DEF))

대상 보정 후 피해 =
DEF 감소 후 피해
× DAMAGE_TAKEN 및 대상별 피해 보정

관계 보정 후 피해 =
대상 보정 후 피해
× 아군 공격 배율

최종 피해 =
관계 보정 후 피해
× 방어·부분 회피·기믹별 최종 배율
```

- 치명타는 DEF와 PEN 계산 전에 적용한다.
- DEF, `DAMAGE_TAKEN`, 방패 방어, 부분 회피와 기믹 감소는 각각 곱연산한다.
- 일반 PEN은 STANDARD에서 대상 DEF의 최대 90%, CHAOS에서 최대 98%까지 적용한다.
- `TRUE_PEN` 태그가 있는 공격만 DEF를 0까지 낮출 수 있다.
- 최종 적용 시 피해를 내림한다.
- 계산 결과가 양수였다면 최종 최소 피해는 1이다.
- 완전 무효화, 면역, 패링과 회피 무적은 최종 피해 0을 허용한다.

## 10. 음수 ATK와 회복 변환

- 스킬 기본 피해와 모든 공격 계수 합산 결과가 음수이면 `STAT-002`의 음수 ATK 규칙을 적용한다.
- `ALLOW_NEGATIVE_ATK_HEAL` 태그가 있으면 원래 공격 대상을 절댓값만큼 회복한다.
- 태그가 없으면 피해를 0으로 처리한다.
- 회복 변환은 일반 피해 계산, 아군 공격 30%, 보호막 피해를 발생시키지 않는다.
- 적 회복은 전투 상태, 어그로, 적중과 허용 상태이상 판정을 발생시키지만 기여도와 활동 EXP를 지급하지 않는다.

## 11. 아군 공격 처리

- 플레이어가 직접 발생시킨 커스텀 일반 공격 피해는 아군에게 30%를 적용한다.
- 아군 공격 30%는 DEF, PEN, `DAMAGE_TAKEN` 계산 이후, 방어·부분 회피·기믹 보정 이전에 한 번만 적용한다.
- 빈사 상태의 아군에게도 아군 공격 30%를 다시 중복 적용하지 않는다.
- 빈사 상태에서는 공격 유형별 빈사 피해 배율 대신 아군 공격 30% 결과와 빈사 피해 상한을 사용한다.
- 고정 피해, 환경 피해, 몬스터 공격에는 아군 공격 30% 배율을 적용하지 않는다.
- 아군 공격 상태이상 확률은 유지하며 강한 CC 지속시간은 30%다.
- 넉백, 끌어당김, 강제 이동은 원래 세기를 적용한다.
- 아군 대상 브레이크 피해는 50%다.
- 아군 공격으로 공격자 보상, 생명력 흡수와 처치 효과를 발동하지 않는다.

## 12. 피해 0과 부가 효과

| 0 피해 원인 | 적중 판정 | 상태이상·강제 이동 | 피해 보상·흡혈 |
|---|---|---|---|
| 피해 면역 | 효과별 정책 | 효과별 면역 정책 | 미발동 |
| 패링 | 적중 무효 | 무효 | 미발동 |
| 회피 무적 | 적중 무효 | 무효 | 미발동 |
| DEF·피해 감소 결과 | 적중 인정 | 공격 데이터에 따라 적용 | 피해량 기반 효과 미발동 |
| 음수 ATK 비허용 스킬 | 적중 인정 | 공격 데이터에 따라 적용 | 미발동 |

- 피해 0은 HP 피해 기여도와 생명력 흡수를 발생시키지 않는다.
- 상태이상과 강제 이동이 피해량을 요구하면 피해 0에서 적용하지 않는다.

## 13. 보호막 처리

```text
최종 피해 계산
→ 보호막 차감
→ 남은 피해를 HP에 적용
→ HP 0 이하 시 빈사 판정
```

- 보호막이 피해를 전부 흡수하면 HP 피해와 생명력 흡수는 발생하지 않는다.
- 보호막 피해도 공격 적중, 전투 상태와 AP 회복 지연을 발생시킨다.
- 구조 중단 피해량 판정에는 보호막이 흡수한 피해도 포함한다.
- 상태이상과 강제 이동은 공격 데이터에 따라 보호막을 관통하여 적용할 수 있다.
- 보호막이 흡수한 실제 피해량은 피해 기여도에 포함한다.
- 보호막별 중복과 우선 소모 규칙은 후속 스킬 및 장비 문서에서 확정한다.

## 14. 실제 피해와 과잉 피해

```text
실제 보호막 피해 =
min(적용 전 보호막, 보호막에 적용된 피해)

실제 HP 피해 =
min(적용 전 현재 HP, HP에 적용된 남은 피해)
```

- 실제 보호막과 HP에서 감소한 양만 피해 기여도로 기록한다.
- 남은 HP와 보호막을 초과한 과잉 피해는 기여도와 생명력 흡수에서 제외한다.
- 치명 피해의 원본 계산값과 과잉 피해는 사망 원인 로그에 별도로 저장한다.
- 생존 상태에는 일반적인 단일 공격 피해 상한을 두지 않는다.
- 강한 단일 공격이 현재 HP 전체를 소모할 수 있지만 일반적으로 빈사 단계를 거친다.

## 15. HP 적용과 빈사 연결

### 생존 플레이어

1. 보호막 처리 후 남은 피해를 현재 커스텀 HP에 적용한다.
2. 적용 후 HP가 1 이상이면 생존 상태를 유지한다.
3. HP가 0 이하라면 치명 피해 원인과 공격자를 기록한다.
4. 바닐라 체력을 최소 생존값으로 유지한다.
5. `DEATH-001`의 빈사 진입 가능 여부를 검사한다.
6. 빈사 가능하면 커스텀 HP 대신 빈사 체력 상태로 전환한다.
7. 빈사 불가 조건이면 완전 사망 처리를 실행한다.

- 일반 보스 패턴, 고정 피해, 환경 피해와 아군 공격은 기본적으로 빈사 단계를 건너뛰지 않는다.
- 최대 HP 감소 자체는 피해가 아니므로 빈사 상태를 발생시키지 않는다.

### 빈사 플레이어

- 일반 HP 대신 빈사 체력에 피해를 적용한다.
- 빈사 피해 공식과 1회 피해 상한은 `DEATH-001`을 따른다.
- 아군 공격 30%는 중복 적용하지 않는다.
- 빈사 체력이 0 이하가 되면 완전 사망 처리한다.
- `DOWNED_GRACE` 중에는 허용된 시스템 피해 외 모든 피해를 무효화한다.

## 16. 바닐라 사망 차단

- 일반 치명 피해에서는 실제 바닐라 사망 이벤트를 발생시키지 않는다.
- 치명 피해를 감지하면 바닐라 체력을 생존 가능한 값으로 유지하고 빈사 전환을 수행한다.
- 완전 사망도 실제 바닐라 사망 대신 관전 모드 전환으로 처리한다.
- 아이템과 경험치 드롭은 플러그인이 직접 처리한다.
- 운영자용 명시적 강제 사망만 실제 바닐라 사망을 예외적으로 허용할 수 있다.
- 실제 바닐라 사망 이벤트가 비정상 발생하면 회차 생명 상태를 기준으로 복구하고 오류를 기록한다.

## 17. 환경 피해 공통 규칙

### 난이도 배율

| 난이도 | 플레이어 환경 피해 배율 |
|---|---:|
| Easy | 75% |
| Normal | 100% |
| Hard | 110% |
| Challenge | 125% |
| ??? | 150% |

- 플레이어 환경 피해에만 적용한다.
- 콘텐츠 몬스터는 템플릿별 환경 피해 배율과 면역을 사용한다.
- 환경 피해 계산 결과가 양수이면 최소 1 피해를 적용한다.
- 시스템 피해에는 최소 피해와 난이도 환경 배율을 적용하지 않는다.

### 기본 환경 피해표

| 환경 원인 | 처리 간격 | Normal 기준 기본 공식 |
|---|---:|---|
| 화재 | 1초 | `10 + 최대 HP × 1%` |
| 용암 | 0.5초 | `25 + 최대 HP × 2%` |
| 익사 | 1초 | `20 + 최대 HP × 2%` |
| 질식 | 1초 | `20 + 최대 HP × 2%` |
| 굶주림 | 2초 | `10 + 최대 HP × 1%` |
| 선인장·열매 덤불 | 1초 | `5 + 최대 HP × 0.5%` |
| 낙하 | 착지 시 1회 | 안전 높이 초과 블록당 `10 + 최대 HP × 0.5%` |

```text
최종 환경 피해 =
floor(
  (환경 기본 고정 피해 + 최대 HP 비례 피해)
  × 난이도 환경 피해 배율
  × 개별 환경 보정
)
```

- 폭발 환경 피해는 폭발 종류, 거리와 노출도에 따라 별도 데이터로 정의한다.
- 환경 피해 수치는 `BALANCE` 테스트에서 조정할 수 있다.

### 낙하 피해

- 안전 낙하 높이는 5블록이다.
- 5블록을 초과한 낙하 거리부터 초과 블록당 피해를 계산한다.
- 낙하 피해에는 일반 상한을 두지 않는다.
- 치명적인 낙하도 기본적으로 빈사 단계를 거친다.
- 추락 방지 장비와 효과는 안전 높이 또는 최종 낙하 피해를 조정할 수 있다.

### 굶주림

- 바닐라 허기 소모와 음식 섭취를 유지한다.
- 허기 부족에 따른 질주 제한을 유지한다.
- 바닐라 자연 HP 회복은 비활성화한다.
- 굶주림 피해는 커스텀 환경 피해로 변환한다.
- 굶주림 피해로도 빈사 상태에 진입할 수 있다.

### 콘텐츠 몬스터 환경 피해

- 콘텐츠 몬스터도 화재, 용암, 낙하 등 환경 피해를 커스텀 HP로 받는다.
- 플레이어 난이도 환경 배율은 몬스터에게 적용하지 않는다.
- 몬스터 템플릿별 환경 피해 배율과 면역을 설정할 수 있다.
- 보스와 주요 공세 적은 자연 환경 함정만으로 쉽게 제거되지 않도록 개별 저항과 면역을 가질 수 있다.

## 18. 공허 시스템 처리

공허는 일반 환경 피해 틱이 아닌 시스템 처리로 분류한다.

1. 플레이어가 공허 경계에 진입한 것을 감지한다.
2. 마지막 안전 지점으로 이동시킨다.
3. 남은 공허 구조 횟수를 확인한다.
4. 구조 횟수가 남아 있으면 횟수를 소비하고 즉시 빈사 전환한다.
5. 구조 횟수를 모두 사용했다면 완전 사망 처리한다.

- 일반 보호막, DEF, 피해 감소, 회피, 패링을 무시한다.
- 공허 구조 횟수와 안전 위치는 회차 데이터에 저장한다.
- 몬스터의 공허 처리는 템플릿 정책에 따라 제거, 복귀 또는 시스템 처치로 처리한다.

## 19. 피해 출처와 소유권

### 직접 공격자와 원본 소유자

| 값 | 설명 |
|---|---|
| 직접 공격자 | 실제 투사체, 소환수, 함정, 시설 또는 공격 개체 |
| 원본 소유자 | 피해의 스탯, 팀, 기여도 귀속 주체 |

- 화살, 소환물, 함정과 시설 피해는 직접 공격자와 원본 소유자를 분리한다.
- 스탯과 기여도는 효과별 정책에 따라 원본 소유자를 기준으로 계산한다.
- 아군 판정은 원본 소유자의 팀을 기준으로 한다.
- 반사 투사체는 반사 후 직접 공격자와 현재 원본 소유자를 갱신하되 최초 소유자도 기록한다.
- 원본 소유자가 없으면 환경 또는 무소유 공격 정책을 사용한다.

## 21. 중앙 피해 처리 절차

1. 피해 요청의 출처와 대상이 커스텀 전투 대상인지 확인한다.
2. 피해 실행 ID, 타격 ID와 중복 적중 여부를 확인한다.
3. 피해 분류와 공격 태그를 검증한다.
4. 원본 소유자, 팀과 아군 여부를 판정한다.
5. 시스템 피해 및 대상 생명 상태를 확인한다.
6. 피해 면역, 패링, 회피 무적을 순서대로 확인한다.
7. 분류별 피해 공식을 계산한다.
8. 아군 공격, 방어, 부분 회피와 기믹 보정을 적용한다.
9. 보호막과 HP 또는 빈사 체력에 피해를 적용한다.
10. 전투 상태, AP 회복 지연, 상태이상과 강제 이동을 처리한다.
11. 빈사, 완전 사망 또는 몬스터 처치 여부를 처리한다.
12. 실제 피해, 기여도, 생명력 흡수와 보상을 확정한다.
13. UI와 피격 연출을 갱신한다.
14. 중요 결과와 오류를 저장 및 로그 처리한다.

## 22. 플러그인 구현 방향

- 중앙 `CustomDamageService`만 커스텀 HP를 감소시킬 수 있게 한다.
- 바닐라 피해 이벤트는 높은 우선순위에서 원인을 기록한 뒤 적용을 취소한다.
- 허용된 커스텀 피해 요청은 재귀 이벤트와 중복 변환을 막는 내부 표식을 가진다.
- UI 동기화용 바닐라 HP 변경은 커스텀 회복 또는 피해 이벤트로 변환하지 않는다.
- 피격 판정 중 동일 대상의 생명 상태 변경을 잠그고 한 번만 빈사·사망 처리한다.
- 피해 결과는 불변 결과 객체로 생성하여 기여도, 연출, 로그 시스템에 전달한다.
- CHAOS 피해 결과와 기여도는 BigNumber 값을 보존한다.
- 일반 피해 로그는 요약하고, 치명 피해, 시스템 피해, 오류와 관리자 디버그 대상은 상세 기록한다.
- 활성 대상의 환경 피해는 중앙 스케줄러에서 원인별 처리 간격으로 계산한다.
- 콘텐츠 개체 제거 전 처치와 보상 결과를 먼저 확정한다.

```yaml
    void-rescues-remaining: 1
    last-safe-location:
      world: "wild"
      x: 120.5
      y: 72.0
      z: -34.5
    shields: []
```

- 현재 및 최대 커스텀 HP, 생명 상태와 공허 구조 횟수를 저장한다.
- 보호막은 지속시간과 시스템 저장 정책에 따라 저장 여부를 결정한다.
- 일반 피해 결과는 장기 저장하지 않지만 치명 피해와 완전 사망 원인은 기록한다.
- 서버 재시작 후 바닐라 HP UI는 저장된 커스텀 HP 비율로 다시 동기화한다.

## 26. CORE-001 완료 기준

- 등록 플레이어와 콘텐츠 개체가 커스텀 HP만 실제 생존 판정에 사용한다.
- 바닐라 하트 한 줄이 커스텀 HP 비율을 정확히 표시한다.
- 바닐라 공격 피해, 방어력, 인챈트, 무적 틱과 자연 회복이 커스텀 전투에 개입하지 않는다.
- 일반, 고정, 환경, 오염, 시스템 피해가 분류별 규칙을 따른다.
- 패링, 회피, 일반 피해 계산, 아군 공격, 방어, 보호막과 HP 적용 순서가 일관된다.
- 치명타, DEF, PEN과 피해 보정이 확정된 공식으로 계산된다.
- 아군 공격 30%가 생존 및 빈사 상태에서 한 번만 적용된다.
- 환경 피해가 커스텀 HP와 난이도에 맞는 수치로 적용된다.
- 실제 피해량만 기여도와 생명력 흡수에 사용된다.
- 치명 피해가 실제 바닐라 사망 대신 빈사 또는 완전 사망 시스템으로 연결된다.
- 외부 플러그인 피해와 비정상 바닐라 피해가 차단 및 기록된다.
- 피해 데이터와 생명 상태가 서버 재시작으로 중복되거나 손실되지 않는다.

# CORE-002 일반 공격 스킬 변환 및 커스텀 공격 실행

## 1. 시스템 목적

CORE-002는 바닐라 클라이언트의 입력을 서버 권위 커스텀 스킬 실행으로 변환하는 공통 계층이다.

- 바닐라 일반 공격 피해를 무기별 일반 공격 스킬로 대체한다.
- 근접, 범위, 커스텀 투사체와 다단 공격이 같은 실행 구조를 사용하게 한다.
- 공격속도, 콤보, 입력 버퍼, 후딜레이와 행동 취소 규칙을 통일한다.
- 활과 석궁의 탄약, 석궁 탄창과 장전을 서버 데이터로 관리한다.
- 플레이어와 몬스터가 같은 스킬 실행 서비스를 사용하게 한다.
- MagicSpells 등 외부 스킬 플러그인이 안전하게 커스텀 타격을 요청할 수 있게 한다.

## 2. 일반 공격 입력

### 기본 입력

- 모든 주무기 일반 공격은 좌클릭 입력으로 실행한다.
- 검, 도끼, 활, 석궁, 지팡이와 주무기 방패가 같은 좌클릭 진입점을 사용한다.
- 좌클릭을 유지해 자동 반복하지 않으며, 입력마다 공격을 한 번 시도하는 수동 연타 방식을 사용한다.
- GUI, 채팅, 관전 상태에서는 일반 공격 입력을 받지 않는다.
- 대상이 없어도 공격 입력은 실행할 수 있다.

### 블록 파괴와의 우선순위

| 상황 | 우선 처리 |
|---|---|
| 유효한 주무기를 든 상태 | 일반 공격 |
| 맨손 또는 주무기가 아닌 아이템 | 파괴 가능한 블록의 블록 파괴 |
| 보호·파괴 불가 블록 | 가능한 경우 일반 공격 |
| 개체 또는 허공 조준 | 일반 공격 |

- 주무기를 든 상태에서 좌클릭 일반 공격이 실행되면 같은 입력으로 블록을 파괴하지 않는다.
- 유틸리티 도구를 들고 채집하는 경우에는 블록 파괴를 우선한다.
- 일반 공격과 채집 모드의 정확한 장비 분류는 `EQUIP`과 `WEAPON` 데이터에서 관리한다.

## 3. 입력 및 행동 우선순위

```text
구조·시설·GUI 상호작용
→ 패링·방어
→ 회피
→ 액티브 스킬
→ 주무기 일반 공격
→ 블록 파괴
```

- 좌클릭 일반 공격과 우클릭 문맥 행동은 별도 입력으로 처리한다.
- 우클릭은 구조, 시설, 아이템 사용, 보조무기 방어와 패링을 우선한다.
- 액티브 스킬의 구체적인 입력 배치는 `SKILL-001`에서 확정한다.
- 일반 공격과 액티브 스킬은 같은 커스텀 스킬 실행 서비스를 사용한다.

## 4. 주무기와 보조무기

### 주무기

- 주무기 슬롯에 장착된 장비의 일반 공격 스킬을 실행한다.
- 방패도 주무기 슬롯에 장착할 수 있으며 방패 타격 일반 공격을 가진다.
- 주무기 방패만 장착한 경우 일반 방어와 패링을 사용할 수 없다.

### 보조무기

- 보조무기 방패는 일반 방어와 패링에 사용한다.
- 보조무기 슬롯은 기본 일반 공격을 제공하지 않는다.
- 주무기와 보조무기에 방패를 동시에 장착할 수 있다.
- 보조무기 액티브 스킬은 후속 무기·스킬 문서에서 정의한다.

### 맨손

- 유효한 주무기가 없으면 약한 맨손 일반 공격 스킬을 사용한다.
- 맨손도 커스텀 일반 공격, 아군 공격과 실행 ID 규칙을 따른다.
- 맨손 기본 피해와 범위는 장비 무기보다 낮게 설정한다.

## 5. 일반 공격 사용 조건

다음 조건을 모두 만족해야 일반 공격 실행을 시작한다.

- 플레이어가 `ALIVE` 상태다.
- 관전, GUI, 채팅 입력 상태가 아니다.
- 강한 CC, 무장 해제 또는 공격 금지 상태가 아니다.
- 회피, 패링, 방어, 구조 등 공격 불가 행동 중이 아니다.
- 현재 일반 공격 간격이 종료되었거나 입력 버퍼를 사용할 수 있다.
- 주무기와 일반 공격 스킬 데이터가 유효하다.
- 탄약이 필요한 무기는 발사 또는 장전을 위한 탄약 조건을 만족한다.

### 실행 거부

- 조건 불충족 시 공격 실행 ID를 생성하지 않는다.
- 공격 간격, 콤보, 쿨타임과 탄약을 소비하지 않는다.
- 반복 실패 안내는 짧은 내부 재사용 대기시간으로 제한한다.
- 서버 안전상 거부 또는 데이터 오류는 원인을 로그에 기록한다.

## 6. AP와 공격 간격

- 일반 공격은 AP를 소비하지 않는다.
- 탈진 상태에서도 일반 공격을 사용할 수 있다.
- 추가 AP 비용이 필요한 특수 공격은 일반 공격이 아닌 액티브 스킬로 분류한다.
- 일반 공격에는 `SKILL_HASTE`를 적용하지 않는다.
- 일반 공격 실행 제한은 `ATTACK_SPEED`로 계산한 공격 간격을 사용한다.

```text
최종 일반 공격 간격 =
max(
  1틱,
  기본 공격 간격 × 100 / (100 + ATTACK_SPEED)
)
```

- 일반 공격 데이터에 별도 재사용 대기시간이 있다면 공격 간격과 재사용 대기시간 중 긴 값을 적용한다.
- 플레이어별 한 틱에 일반 공격 스킬을 최대 한 번 실행한다.
- 낮은 TPS에서도 실제 경과 시간을 기준으로 공격 가능 시점을 계산한다.

## 7. 입력 버퍼

- 공격 가능 시점 전 최대 3틱 동안 일반 공격 입력 하나를 저장한다.
- 여러 입력이 들어오면 가장 최근 입력 하나만 유지한다.
- 공격 가능 시점이 되면 현재 사용 조건을 다시 검증한 후 실행한다.
- 강한 CC, 빈사, 사망, 무장 해제, GUI 진입과 무기 변경 시 버퍼를 제거한다.
- 탄약 부족으로 실행할 수 없는 입력은 장전 규칙을 제외하고 버퍼에 계속 유지하지 않는다.

## 8. 일반 공격 콤보

### 공통 구조

- 일반 공격 스킬은 무기별 `1~N단` 콤보를 지원한다.
- 공격이 적중하거나 빗나가도 실행이 성립하면 다음 콤보 단계로 진행한다.
- 후속 입력이 콤보 제한시간 안에 없으면 1단으로 초기화한다.
- 정확한 콤보 수, 제한시간과 단계별 공격은 `WEAPON` 및 `SKILL-LIST`에서 확정한다.

### 기본 무기 방향

| 무기 | 기본 콤보 방향 |
|---|---|
| 검 | 다단계 근접 콤보 가능 |
| 도끼 | 다단계 또는 강한 단발 콤보 가능 |
| 주무기 방패 | 방패 타격 콤보 가능 |
| 활 | 기본 단일 단계 반복 공격 |
| 석궁 | 기본 단일 단계 반복 공격 |
| 지팡이 | 기본 단일 단계 반복 공격 |

원거리 무기도 데이터에 명시된 경우 콤보를 사용할 수 있다.

### 콤보 초기화

- 주무기 변경
- 강한 CC, 빈사 또는 완전 사망
- 콤보 제한시간 초과
- 회피로 공격 준비 취소
- 스킬이 명시적으로 콤보 초기화

일반 이동, 피격과 빗나감은 콤보를 초기화하지 않는다.

## 9. 공통 공격 실행 단계

```text
입력 수신
→ 사용 가능 조건 검증
→ 무기·스킬·탄약 데이터 확정
→ 공격 실행 ID 생성
→ 공격자 스탯 스냅샷
→ 시작 동작
→ 판정 또는 투사체 생성
→ 적중·피해·부가 효과 처리
→ 후딜레이
→ 다음 행동 허용
```

### 실행 상태

| 상태 | 설명 |
|---|---|
| `REQUESTED` | 입력을 수신하고 조건을 검증하는 단계 |
| `STARTUP` | 시작 동작 진행 중 |
| `ACTIVE` | 판정 또는 투사체가 생성된 단계 |
| `RECOVERY` | 후딜레이 단계 |
| `COMPLETED` | 실행 정상 종료 |
| `CANCELLED` | 판정 전에 취소됨 |

- 공격 실행 ID는 실행 시작이 확정될 때 생성한다.
- 다단 공격은 하나의 실행 ID 아래 여러 타격 ID를 가진다.
- 판정이 발생한 뒤 공격자가 행동을 취소해도 이미 생성된 타격과 투사체는 유지한다.

## 10. 이동, 취소와 후딜레이

### 이동

- 일반 공격 중 걷기와 질주를 허용한다.
- 무기와 공격별 이동속도 배율을 적용할 수 있다.
- 점프 허용 여부는 공격 데이터에 정의한다.
- 일반 공격이 기본적으로 플레이어 위치를 고정하지 않는다.

### 공격 취소

- `STARTUP` 중 회피를 시작하면 일반 공격을 취소한다.
- 패링 또는 방어 시작도 공격 준비를 취소한다.
- 판정 발생 전 취소된 공격은 피해와 적중 효과를 생성하지 않는다.
- AP를 소비하지 않으므로 환급은 없다.
- 탄약 소비 전 취소는 탄약을 소비하지 않는다.

### 후딜레이

- 후딜레이 중 이동과 시선 회전을 허용한다.
- 다음 일반 공격은 공격 간격 종료 전까지 제한한다.
- 회피와 패링은 기본적으로 후딜레이를 취소할 수 있다.
- 액티브 스킬과 다른 행동의 후딜레이 취소 허용 여부는 공격 데이터에 정의한다.
- 후딜레이 자체는 `ATTACK_SPEED`의 영향을 받지 않는다.

## 11. 스탯 스냅샷

- 일반 공격 실행 시작 시 공격자의 스탯, 장비, 증강과 무기 옵션을 스냅샷한다.
- 적중 순간 대상의 DEF, 상태, 보호막과 생명 상태를 조회한다.
- 투사체는 발사 시 공격자 스냅샷과 원본 소유자를 저장한다.
- 지속 공격은 스킬 데이터에 따라 시전 시 스냅샷 또는 틱별 재조회를 선택한다.
- 실행 후 무기를 변경해도 이미 생성된 공격은 기존 무기 스냅샷을 사용한다.
- `STARTUP` 중 무기 변경은 공격을 취소한다.
- 무기 변경 시 입력 버퍼와 콤보를 초기화한다.
- 전투 중 무기 변경 허용 여부는 `EQUIP-001`에서 확정한다.

## 12. 대상 선정

### 기본 유효 대상

- 적대 콘텐츠 개체
- 아군 플레이어
- 공격 가능 태그가 있는 소환수와 시설
- 공격 가능 콘텐츠 특수 개체

### 기본 제외 대상

- 완전 사망자와 관전자
- 공격 불가 시설과 시스템 표시 개체
- 일반 비콘텐츠 개체

- 개인 설정으로 아군 공격을 차단할 수 없다.
- 증강, 장비, 인챈트 또는 상태 효과의 `DISABLE_FRIENDLY_FIRE` 정책으로 제한할 수 있다.
- 해당 정책이 활성화되면 아군을 공격 대상에서 제외하고 피해, CC와 브레이크를 적용하지 않는다.
- 아군 대상 회복과 강화 효과는 정상 적용할 수 있다.

## 13. 최대 적중 수와 대상 우선순위

- 모든 공격은 최대 적중 개체 수를 필수 데이터로 가진다.
- 최대 수를 초과하면 다음 순서로 대상을 선정한다.

```text
1. 공격 판정 중심과의 거리
2. 플레이어 시선 중심과의 각도
3. 최초 감지 순서
4. 안정적인 개체 ID 순서
```

- 기본적으로 한 실행에서 같은 대상을 한 번만 적중한다.
- 다단 공격만 타격 ID별 지정 횟수까지 같은 대상을 적중할 수 있다.
- 반복 판정, 서버 지연과 개체 이동으로 같은 타격 ID가 중복 적용되지 않게 한다.
- 실제 대상 수와 선정 정책의 세부값은 `SKILL-002`에서 확정한다.

## 14. 빗나감 처리

- 공격 간격과 후딜레이를 정상 적용한다.
- 콤보 단계를 진행한다.
- 적중, 처치, 생명력 흡수, 환급과 적중 조건 효과를 발동하지 않는다.
- 공격 모션, 사운드, 궤적과 지형 충돌 연출은 정상 출력한다.
- 탄약을 발사한 원거리 공격은 빗나가도 탄약을 반환하지 않는다.

## 15. 근접·범위 공격 판정

- 바닐라 개체 공격 대상에게 직접 피해를 주지 않는다.
- 플레이어 위치와 시선을 기준으로 커스텀 히트박스를 생성한다.
- 실제 클릭 대상도 커스텀 범위 밖이면 적중하지 않는다.
- 근접 공격은 기본적으로 벽과 장애물을 관통하지 않는다.
- 범위 공격은 데이터로 시야 검사와 지형 관통 여부를 지정한다.
- 판정 시작점이 벽 내부라면 안전한 위치로 보정하고 불가능하면 실행을 취소한다.

### 지형 관통

- `PIERCE_TERRAIN` 태그가 있는 공격만 지형을 관통한다.
- 최대 관통 블록 수 또는 최대 관통 거리를 반드시 가진다.
- 기반암, 보호된 기지 핵심 블록과 시스템 경계는 관통할 수 없다.
- 관통 후 피해 감소와 부가 효과 변화는 효과 데이터에 명시한다.
- 증강, 장비, 인챈트와 상태 효과가 태그 또는 관통 한계를 부여할 수 있다.

## 16. 커스텀 투사체

활, 석궁과 지팡이는 직접적인 바닐라 피해 엔티티가 아닌 커스텀 투사체 실행을 사용한다.

### 공통 데이터

| 필드 | 설명 |
|---|---|
| 투사체 ID | 개별 투사체 식별자 |
| 실행 ID·타격 ID | 원본 공격 및 적중 식별 |
| 직접 출처·원본 소유자 | 시각 매체와 실제 귀속 주체 |
| 위치·방향·속도 | 선택 백엔드 이동값과 WildSurvival 검증 스냅샷 |
| 수명·최대 거리 | 자동 제거 조건 |
| 충돌 크기 | 선분 또는 확장 히트박스 |
| 최대 적중 수 | 관통 및 소멸 조건 |
| 지형 정책 | 충돌, 반사, 지형 관통 |
| 대상 정책 | 적, 아군, 시설 등 |
| 스탯 스냅샷 | 발사 시 공격자 수치 |

### 충돌 처리

- 실제 엔티티 존재 여부와 관계없이 선택된 실행 백엔드가 위치, 방향과 수명을 갱신하고 WildSurvival이 검증 가능한 스냅샷을 유지한다.
- `WILDSURVIVAL_NATIVE`와 `HYBRID`는 이동 전후 구간을 선분 또는 확장 히트박스로 직접 검사한다.
- `MAGICSPELLS_DRIVER`는 MagicSpells가 이동과 1차 충돌 후보를 만들고 WildSurvival이 최종 타격 요청 전에 다시 검증한다.
- 대상 또는 벽 충돌 시 커스텀 타격 요청을 생성한다.
- 동일 대상 중복 적중은 실행 ID와 타격 ID로 차단한다.
- 연출용 바닐라 개체가 존재해도 바닐라 피해는 차단한다.
- 투사체는 대상 선지정 없이 발사할 수 있다.

### MagicSpells 연동

- MagicSpells는 WildSurvival의 스킬별 실행 보조 백엔드로 사용한다.
- 단순 투사체, 유도체, 빔, 반복 연출과 범위 후보 검색은 효율이 유리할 때 MagicSpells에 맡길 수 있다.
- 복합 도형, 결정론적 최대 대상 선정, 특수 유도와 카오스 집계는 WildSurvival이 직접 처리한다.
- 어느 백엔드를 사용하더라도 실제 피해는 허용된 커스텀 공격 API를 통해 `CustomDamageService`에 요청한다.
- MagicSpells가 제공한 대상과 충돌 위치는 후보로 취급하며 WildSurvival이 관계, 생존 상태, LOS, 최대 대상 슬롯과 중복 여부를 재검증한다.
- AP, 탄약, 쿨타임, 커스텀 HP, DEF, PEN, 회피, 패링, 브레이크, 상태이상, 빈사와 기여도는 WildSurvival만 변경한다.
- 외부 플러그인이 직접 발생시킨 바닐라 피해, 폭발 피해와 포션 기반 전투 효과는 계속 차단한다.
- 연동 요청은 실행 토큰, 실행 ID, 원본 소유자, 스킬 ID, 효과 ID와 타격 ID를 반드시 전달한다.
- 하위 스펠의 `args` 및 `pass-args`를 실행 토큰 전달에 우선 사용하며 실제 엔티티 투사체는 내부 추적 키를 메타데이터에도 기록할 수 있다.
- 중복 콜백이나 바닐라 피해 재귀 변환은 실행 토큰과 타격 ID로 차단한다.
- `MAGICSPELLS_DRIVER`, `HYBRID`, `WILDSURVIVAL_NATIVE` 선택 기준과 세부 대상 판정은 `SKILL-002`를 따른다.
- 연동 실패 시 피해를 임의로 추정하지 않고 투사체를 안전하게 종료하며 로그를 기록한다.

## 17. 활 일반 공격

- 활은 좌클릭 입력으로 커스텀 투사체를 즉시 발사한다.
- 우클릭 유지, 충전과 해제 발사 방식은 사용하지 않는다.
- 활 일반 공격은 석궁보다 기본 공격 간격이 길다.
- 장전 상태와 장전 딜레이는 없다.
- 공격 실행 확정 시 화살 또는 선택 전용 탄약 한 개를 소비한다.
- 실제 공격 간격과 투사체 수치는 `WEAPON-002`에서 확정한다.

## 18. 석궁 일반 공격과 탄창

### 기본 방향

- 석궁도 좌클릭 입력으로 즉시 발사한다.
- 활보다 기본 발사 간격이 짧아 탄창이 남아 있는 동안 더 빠르게 공격한다.
- 탄창이 소진되면 장전 딜레이가 발생한다.
- 바닐라 석궁의 우클릭 장전·발사 시스템은 사용하지 않는다.

### 탄창

| 항목 | 기본 규칙 |
|---|---|
| 탄창 데이터 | 모든 석궁이 개별 보유 |
| 기본 탄창 크기 | 3발 |
| 탄창 크기 변경 | 장비·증강·커스텀 인챈트 가능 |
| 실제 무기별 수치 | `WEAPON-002`에서 확정 |

- 탄창은 석궁 아이템 개체별로 관리한다.
- 다른 동일 석궁과 탄창 상태를 공유하지 않는다.
- 장전 완료 탄약은 무기 변경, 드롭, 보관과 접속 종료 후에도 유지한다.

### 자동 장전 시작

- 탄창이 비면 자동 장전을 시작한다.
- 탄창이 남아 있을 때는 기본적으로 수동 장전할 수 없다.
- 빈 탄창 상태에서 좌클릭하면 공격 대신 장전을 시작한다.
- 장전 중 좌클릭 입력 하나를 저장하고, 완료 후 조건을 다시 검증하여 즉시 발사할 수 있다.

### 탄창 장전

1. 장전 시작 시 선택 탄약과 보유량을 확인한다.
2. 필요한 탄약 수와 최종 장전 시간을 확정한다.
3. 장전 완료 전까지 탄약을 소비하지 않는다.
4. 완료 시 탄창 최대치까지 한 번에 장전한다.
5. 탄약이 부족하면 보유량만큼만 장전한다.
6. 장전 취소 시 탄약을 소비하지 않는다.

- 장전 완료 전에는 한 발도 발사할 수 없다.
- 한 탄창에는 한 종류의 탄약만 장전한다.
- 탄창이 남아 있으면 탄약 종류를 변경할 수 없다.
- 탄창을 모두 소비한 다음 장전부터 새 선택 탄약을 사용한다.
- 탄창 강제 비우기 기능은 `WEAPON` 또는 `EQUIP` 문서에서 결정한다.

## 19. 장전속도

`RELOAD_SPEED`는 석궁과 향후 탄창형 장비의 장전 시간을 감소시키는 보조 전투값이다.

```text
최종 장전 시간 =
max(
  기본 장전 시간 × 25%,
  기본 장전 시간 × 100 / (100 + RELOAD_SPEED)
)
```

| 항목 | 규칙 |
|---|---|
| 기본 RELOAD_SPEED | 0 |
| 포인트 투자 | 불가 |
| 획득처 | 장비, 증강, 커스텀 인챈트, 효과 |
| 최종 장전 시간 최소 | 기본값의 25% |

- `ATTACK_SPEED`는 발사 간격에만 적용한다.
- `RELOAD_SPEED`는 장전 시간에만 적용한다.
- `CAST_SPEED`와 `SKILL_HASTE`는 장전에 적용하지 않는다.

## 20. 장전 행동과 취소

### 허용 행동

- 걷기, 질주, 점프
- 시선 회전
- 일반 피격

### 장전 취소

- 회피
- 강한 CC
- 빈사 또는 완전 사망
- 주무기 변경
- 방패 방어 또는 패링 시작
- 장전 불가 액티브 공격 스킬 사용
- 서버 종료 또는 회차 중단

- 일반 피격만으로 장전을 취소하지 않는다.
- 진행 중 장전이 취소되면 탄약을 소비하지 않는다.
- 장전 완료된 탄창은 유지되지만 진행 중 장전 상태는 저장하지 않는다.

## 21. 탄약 시스템

### 소비 시점

- 공격 실행과 발사가 확정되는 시점에 탄약 한 개를 소비한다.
- 공격 실행 전 거부 또는 `STARTUP` 취소 시 소비하지 않는다.
- 빗나가거나 지형에 충돌해도 반환하지 않는다.
- 발사 후 회피 등으로 후딜레이를 취소해도 반환하지 않는다.
- 서버 오류나 안전상 강제 취소가 발사 전에 발생하면 소비하지 않는다.

석궁은 장전 완료 시 탄창에 들어갈 탄약을 일괄 소비하며, 발사 시 탄창 수량만 감소시킨다.

### 탄약 선택

- 전용 탄약 GUI에서 사용할 탄약을 선택한다.
- 선택 전용 탄약이 없으면 일반 화살을 사용한다.
- 일반 화살도 없으면 활 발사를 거부하고 석궁 장전을 시작하지 않는다.
- 탄약 종류 변경은 일반 공격 간격과 콤보를 초기화하지 않는다.
- 석궁은 현재 탄창이 비었을 때만 선택 탄약 변경을 반영한다.

### 탄약 회수와 절약

- 바닐라 무한 인챈트는 사용하지 않는다.
- 발사된 일반 화살과 전용 탄약은 기본적으로 회수할 수 없다.
- 탄약 절약은 장비, 증강과 커스텀 인챈트 효과로만 제공한다.
- 절약 판정 성공 시 발사 또는 장전 완료 시점에 해당 탄약을 소비하지 않는다.
- 탄약 절약 확률과 상한은 후속 장비·인챈트 기획에서 확정한다.

## 22. 지팡이 일반 공격

- 지팡이는 좌클릭으로 즉시 발사형 마법 커스텀 투사체를 생성한다.
- 기본 일반 공격에는 탄약을 요구하지 않는다.
- 지팡이별로 투사체 속도, 궤도, 관통과 부가 효과를 변경할 수 있다.
- 실제 피해 계수와 투사체 수치는 `WEAPON-002`와 `SKILL-LIST`에서 확정한다.

## 23. 아군 공격 제한 효과

`DISABLE_FRIENDLY_FIRE` 효과는 개인 또는 파티 단위로 적용할 수 있다.

- 아군을 공격 대상 선정에서 제외한다.
- 광역 공격도 아군에게 피해, 상태이상, 강제 이동과 브레이크를 적용하지 않는다.
- 아군에게 유익한 회복과 강화 효과는 정상 적용한다.
- 효과가 없으면 기본 아군 공격 규칙을 적용한다.
- 개인 설정으로는 아군 공격을 차단할 수 없다.
- 증강, 장비, 인챈트와 상태 효과가 해당 정책을 부여할 수 있다.

## 24. 비콘텐츠 개체

- 콘텐츠 일반 공격의 기본 대상 선정에서는 일반 동물, 주민과 비콘텐츠 개체를 제외한다.
- 맨손으로 비콘텐츠 개체를 직접 공격한 경우 바닐라 피해를 허용할 수 있다.
- 보호 구역에서는 비콘텐츠 개체 공격도 차단할 수 있다.
- 주무기 커스텀 범위 공격으로 비콘텐츠 개체를 의도치 않게 공격하지 않게 한다.

## 25. 몬스터 공격 실행

- 몬스터도 플레이어와 같은 `SkillExecutionService`를 사용한다.
- 플레이어 입력 대신 AI 또는 보스 패턴이 스킬 실행 요청을 생성한다.
- 실행 ID, 타격 ID, 스냅샷, 대상 선정, 다단과 투사체 규칙을 동일하게 사용한다.
- 몬스터 AP와 쿨타임을 실행 전 서버에서 검증한다.
- 몬스터별 스킬 선택 AI와 패턴은 `ENEMY` 및 `BOSS` 문서에서 확정한다.

## 26. 서버 지연과 시간 처리

- 입력 수신 시각, 서버 틱과 실제 경과 시간을 기록한다.
- 이미 확정된 공격 결과를 늦게 도착한 입력으로 소급 변경하지 않는다.
- 공격 간격, 콤보 제한시간, 장전 시간과 투사체 수명은 실제 경과 시간을 기준으로 한다.
- 한 틱에 일반 공격 최대 한 번 규칙은 낮은 TPS에서도 유지한다.
- 같은 입력 패킷이나 연동 콜백의 중복 처리를 입력 시퀀스와 실행 ID로 차단한다.

## 27. 공통 스킬 실행 서비스

```text
InputAdapter / AI
→ SkillRequest
→ SkillEligibilityValidator
→ SkillExecutionService
→ Targeting / Projectile Service
→ CustomDamageService
→ Status / Break / Contribution Service
→ Visual Feedback
```

- 일반 공격과 액티브 스킬은 동일한 실행 객체를 사용한다.
- 일반 공격 여부, 콤보 단계, 탄약, 탄창과 무료 AP 정책은 실행 데이터로 구분한다.
- 실행 조건 검증과 자원 소비는 서버에서 원자적으로 처리한다.
- 피해와 상태이상은 실행 서비스가 직접 수치를 변경하지 않고 각 중앙 서비스에 요청한다.
- 외부 플러그인은 검증된 연동 어댑터를 통해서만 실행 또는 타격을 요청한다.

## 28. 일반 공격 데이터 최소 규격

```yaml
basic-attack:
  id: "sword.basic.1"
  weapon-type: SWORD
  input: LEFT_CLICK
  combo:
    step: 1
    next-step: 2
    timeout-ticks: 16
  timing:
    base-attack-interval-ticks: 12
    startup-ticks: 3
    active-ticks: 1
    recovery-ticks: 5
  resource:
    ap-cost: 0
    ammo-policy: NONE
  targeting:
    shape: ARC
    max-targets: 3
    requires-line-of-sight: true
    terrain-policy: BLOCK
  hit:
    max-hits-per-target: 1
    critical-allowed: true
    friendly-fire: true
  cancel:
    dodge-during-startup: true
    parry-during-recovery: true
```

- 위 수치는 데이터 구조 예시이며 실제 무기 밸런스 수치가 아니다.
- 계수, 범위, 최대 대상과 실제 타이밍 규격은 `SKILL-001`, `SKILL-002`, `WEAPON`에서 확정한다.

## 29. 저장 데이터

```yaml
players:
  "player-uuid":
    combat-input:
      buffered-basic-attack-until: null
      last-basic-attack-tick: 120400
    combo:
      weapon-instance-id: "weapon-uuid"
      step: 2
      expires-at: "2026-06-20T21:10:05+09:00"
    ammunition:
      selected-type: "STANDARD_ARROW"
items:
  "crossbow-instance-uuid":
    magazine:
      size: 3
      loaded: 2
      ammunition-type: "STANDARD_ARROW"
```

- 진행 중 일반 공격과 입력 버퍼는 서버 재시작 시 복원하지 않는다.
- 짧은 콤보 상태도 서버 재시작과 정상 중단 시 초기화한다.
- 석궁 탄창과 장전된 탄약 종류는 무기 개체에 저장한다.
- 진행 중 장전은 취소하고 탄약을 소비하지 않은 상태로 복원한다.
- 선택 탄약과 영구 입력 설정은 플레이어 데이터에 저장한다.

## 32. CORE-002 완료 기준

- 모든 주무기 일반 공격이 좌클릭 입력에서 커스텀 스킬로 실행된다.
- 주무기 상태에 따라 일반 공격과 블록 파괴 우선순위가 정확히 적용된다.
- 일반 공격이 AP 없이 공격속도 기반 간격과 3틱 입력 버퍼를 사용한다.
- 콤보, 시작 동작, 판정, 후딜레이와 취소 상태가 일관되게 처리된다.
- 실행 ID와 타격 ID가 단일, 광역, 다단과 투사체 중복 피해를 차단한다.
- 공격자 스냅샷과 대상 실시간 방어 상태가 올바르게 사용된다.
- 커스텀 투사체가 엔티티 존재 여부와 관계없이 서버 권위로 충돌을 처리한다.
- MagicSpells 연동 피해가 허용 API를 통해 한 번만 적용된다.
- 활과 석궁이 좌클릭 즉발이며 탄약을 정상 소비한다.
- 석궁이 개별 탄창, 자동 장전, 장전속도와 저장 규칙을 따른다.
- 지팡이가 즉발형 마법 투사체 일반 공격을 사용한다.
- 아군 공격 제한 효과와 기본 아군 공격 규칙이 충돌 없이 적용된다.
- 플레이어와 몬스터가 같은 커스텀 스킬 실행 서비스를 사용한다.
- 서버 재시작, 낮은 TPS와 외부 플러그인 연동으로 공격이 중복되거나 손실되지 않는다.
