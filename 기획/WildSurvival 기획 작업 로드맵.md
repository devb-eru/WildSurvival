# WildSurvival 기획 작업 로드맵

## 1. 문서 목적

이 문서는 WildSurvival의 기획 우선순위, 문서 간 권위 관계, 완료 조건을 관리한다. 구현 프로토타입을 만드는 문서가 아니라, 바닐라 Minecraft Java Edition과 서버 플러그인만으로 구현 가능한 상세 기획을 순서대로 완성하기 위한 작업표다.

## 2. 프로젝트 고정 전제

| 구분 | 확정 기준 |
|---|---|
| 장르 | 2~4인 단일 파티 협동형 하드코어 야생 생존 |
| 공간 | 고정 기지·고정 임무 구역 없는 자유 야생 |
| 진행 | 탐험 → 발견 → 재료 수집 → 제작·강화·재련 → 더 높은 위험 대응 |
| 거점 | 플레이어가 원하는 위치에 건설하는 선택적 야영지·시설망 |
| 목표 | Day 50부터 도전할 수 있고 최종 목표 완료 후 끝나는 인류 재건의 첫 단계 달성 |
| 구현 | 모드 없이 Paper 계열 서버 플러그인과 바닐라 클라이언트 사용 |
| UI | 인벤토리 GUI, 보스바, 액션바, 타이틀, 채팅 컴포넌트 중심 |
| 리소스 팩 | 초기 필수 조건 아님. 단검·둔기 외형 등은 추후 선택 적용 |
| 참여 | 회차 시작 멤버 고정, 신규 중도 참여 없음, 재접속은 허용 |
| 전투 | 기본 아군 피해 차단, 선택형 전술 모드만 제한적으로 허용 |

## 3. 문서 권위 순서

상위 문서와 하위 문서가 충돌하면 아래 순서를 따른다.

1. `VISION 콘텐츠 핵심 방향 기획서.md`
2. `RULES 바닐라 상호작용 정책 기획서.md`
3. `DIFFICULTY 난이도 및 콘텐츠 분류 상세 기획서.md`, `DAY Day 진행 및 스킵 시스템 상세 기획서.md`
4. `CONTENT Day 1-50 마스터 진행표.md`
5. 시스템별 상세 기획서
6. 목록형 콘텐츠 문서와 수치표

난이도 명칭·콘텐츠 분류는 `DIFFICULTY`, Day 스킵·Day 50+·종료 조건은 `DAY`, 발견 진행은 `DISC`, 개인·파티 증강은 `AUG`, 장비 슬롯과 보상 소유권은 `EQUIP`, 장비 경제는 `ECONOMY`를 각각 단일 기준 문서로 사용한다.

## 5. 기획 작업 순서

### 0단계 — 상위 기준 수립

- [x] 프로젝트 핵심 방향과 금지 전제 확정
- [x] 바닐라 허용·대체·잠금·차단 정책 확정
- [x] Day 1~50 마스터 진행표 확정
- [x] Story와 Challenge 콘텐츠 분류 및 난이도 단계 재매핑
- [x] Day 스킵과 Day 50 이후 연장·최종 목표 종료 기준 확정
- [x] 발견, 증강, 장비, 장비 경제의 공통 기준 확정

### 1단계 — 기존 핵심 문서 일관성 개정

- [x] `GAME`에서 신규 중도 참여와 고정 거점 전제 제거
- [x] `PROG`에 개인 증강 10회 레벨과 회차 멤버 고정 규칙 연결
- [x] `STAT`의 난이도별 HP를 전체 HP 원천에 같은 배율로 적용
- [x] `CORE`·`COMBAT`에 10개 무기군과 장비 슬롯 계약 반영
- [x] `STATUS`의 강한 CC 체인 기준을 3초로 통일
- [x] `BREAK`의 Day 전역 배율을 콘텐츠 템플릿 값으로 전환
- [x] `BASE`·`ACT`·`CORR`을 플레이어 건설 시설망과 동적 위협으로 전환
- [x] `DEATH`·`SKILL`의 고정 공간·아군 공격 예외 정리

완료 조건은 상위 기준과 충돌하는 문장이 없고, 각 시스템의 책임 경계가 명시되는 것이다.

### 2단계 — 기술 설계 명세

`TECH-001 플러그인 아키텍처 상세 기획서`를 작성한다. 현재 단계에서는 프로토타입이나 실제 플러그인 구현을 하지 않는다.

- [x] 세션·플레이어·장비·시설·발견 데이터 모델
- [x] 이벤트 차단과 커스텀 실행 우선순위
- [x] Paper 이벤트와 서버 틱 작업의 책임 분리
- [x] 인벤토리 GUI 트랜잭션과 슬롯 `0`, `-106` 동기화
- [x] 저장 원자성, 재접속 복구, 결정론적 난수 시드
- [x] PDC 식별자, 데이터 버전, 마이그레이션 및 관리자 복구 명령
- [x] 성능 예산과 개체·투사체·지속 영역 상한

기술 문서는 단일 Paper 서버·단일 활성 회차를 기본 운영 가정으로 작성했다. 운영 형태가 달라지면 세션 저장소와 동시성 계약을 먼저 개정한다.

### 3단계 — 야생 생존·발견·시설 콘텐츠

- [x] `RES-001` 자원군, 채집처, 위험도와 재생 정책
- [x] `CRAFT-001` 제작식, 해금 조건과 공용 제작 대기열
- [x] `DISC-LIST-001` 핵심·선택 발견 노드 목록과 다중 해결 경로
- [x] `FACILITY-LIST-001` 휴대·야영·정착·재건 시설 목록
- [x] `CORR-LIST-001` 오염 변이 목록
- [x] `EVENT-LIST-001` 자연 활동 문맥과 동적 사건 목록

모든 핵심 재료에는 최소 두 개의 획득 경로를 두고, 특정 생물군계·좌표·시설 파괴로 회차가 막히지 않게 한다.

### 4단계 — 성장·전투 빌드 콘텐츠

- [x] `WEAPON-001` 10개 무기군 비교표
- [x] `WEAPON-002` 무기별 일반 공격, AP, 브레이크, 상태이상, 회피 연계
- [x] `EQUIP-LIST-001` 장비 희귀도별 아이템·옵션·제작 재료
- [x] `SKILL-LIST-001` 무기별 스킬 목록
- [x] `AUG-LIST-001` 개인 증강 목록과 진화 계보
- [x] `AUG-LIST-002` 파티 증강과 협동 시너지 목록
- [x] `REWARD-001` 기여 보상, 고유 장비 투표, 귀속과 제작 해금

무기군은 검, 도끼, 활, 석궁, 단검, 둔기, 지팡이, 곡괭이, 삼지창, 권투다. 특정 무기나 역할이 파티 필수가 되지 않도록 모든 필수 패턴에 둘 이상의 대응 수단을 제공한다.

### 5단계 — Day 1~10 통합 기획 검증

프로토타입 구현이 아니라 문서와 데이터표를 이용한 수치·상태 전이 검증 단계다.

- [x] 새 월드에서 고정 좌표 없이 핵심 발견·동적 보스 전장이 가능한지 문서 검토
- [x] 시설을 짓는 파티와 유목 파티가 모두 휴대 경로와 야간 위협을 갖는지 문서 검토
- [x] 레벨 3·6·10 증강과 Day 10 파티 증강·보스 보상의 순서 검사
- [x] 10개 무기가 초반 생존·채집·전투에 참여할 수 있는지 검토
- [x] 자원 유입·제작·수리·강화 소모의 2·3·4인 세션 원장 시뮬레이션
- [x] 전멸, 재접속, 제작·보스 저장 복구 시 진행·아이템 중복 검사
- [x] `ENEMY-001` Day별 역할·변이·적 증강 예산 작성
- [x] `BOSS-001` Day 10 패턴·브레이크·보상·실패 복구 작성

## 6. 장비·증강 핵심 체크포인트

### 장비

- 모든 장비는 커스텀 GUI로 장착한다.
- 주무기는 바닐라 슬롯 `0`, 보조무기는 오프핸드 슬롯 `-106`에 서버가 동기화한다.
- 손이 비어 있으면 권투 프로필이 자동 활성화된다.
- 곡괭이는 공격 가능한 대상을 조준하면 전투 판정을 우선한다.
- 삼지창은 바닐라 투척을 차단하고 커스텀 실행기로 처리한다.
- 단검은 검, 둔기는 철퇴를 기반 아이템으로 사용하며 리소스 팩은 후속 외형 개선이다.

### 증강

- 개인 증강: 레벨 `3, 6, 10, 15, 20, 25, 30, 35, 40, 45`, 총 10회
- 레벨 3은 실버, 6은 골드, 10은 프리즘 고정
- 이후 최초 도달 시 실버 50%, 골드 30%, 프리즘 20%로 해당 마일스톤 등급을 회차에 고정
- 같은 마일스톤의 후발 플레이어와 적대 몬스터는 고정 등급을 사용
- 개인 후보 3개는 고정 등급 안에서 플레이어 빌드에 편향해 추첨
- 파티 증강: Day `10, 20, 30, 40`, 총 4회
- 사망자 표는 생존자 동률을 푸는 2차 표로만 사용하고, 최종 동률은 시드 난수로 결정

## 7. 공통 완료 기준

각 기획 항목은 다음 조건을 만족해야 완료로 본다.

- 바닐라 클라이언트와 서버 플러그인만으로 구현 가능하다.
- 리소스 팩이 없어도 판정, 정보 전달, GUI 사용이 가능하다.
- 고정 기지·고정 임무 구역·필수 고정 좌표를 요구하지 않는다.
- 2~4인 단일 파티이며 신규 중도 참여를 전제로 하지 않는다.
- 저장 필드, 실패 복구, 악용 방지, 성능 상한이 정의되어 있다.
- Day 전역 배율과 하위 시스템 배율이 같은 위험을 중복 증폭하지 않는다.
- Day 50 이전에는 최종 목표 완료 조건을 충족할 수 없다.
- Day 50 종료만으로 회차가 끝나지 않으며 최종 목표 완료 후에만 성공한다.
- `UNKNOWN`과 CHAOS에서는 Day 스킵을 사용할 수 없다.
- 정답을 숨기되 단서, 대체 경로, 소급 판정으로 진행 막힘을 방지한다.
