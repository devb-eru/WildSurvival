## 1. 결함 원인과 확정 보정

실행 로그에는 커스텀 근접 적에게 공격받은 회차 멤버가 빈사 알림 없이 실제 Minecraft 사망 처리된 기록이 남아 있었다. 원인은 적 공격력 치환과 플레이어 치명 피해 판정이 같은 `HIGHEST` 우선순위의 서로 다른 리스너에 있어 실행 순서가 보장되지 않은 것이다. 치명 판정이 먼저 낮은 바닐라 피해를 통과시킨 뒤 적 공격력이 커지면 실제 사망까지 진행될 수 있었다.

1. 플레이어·커스텀 발사체의 바닐라 공격 차단은 `HIGH`, 플레이어 최종 피해·빈사 판정은 `HIGHEST`로 분리한다.
2. 커스텀 적의 직접 공격과 해당 적이 발사한 투사체 피해를 최종 피해 경로 안에서 먼저 치환한다.
3. Test Lab 피해 배율과 DEF를 적용한 `finalDamage`가 현재 HP 이상이면 실제 피해를 취소하고 `ACTIVE → DOWNED`, HP `1`, AP `0`을 커밋한다.
4. 이미 `DOWNED` 또는 `DEAD`인 플레이어에게 Minecraft 일반 HP 피해가 들어가 실제 사망 이벤트가 발생하지 않게 차단한다.
5. 빈사·사망 플레이어의 공격, 스킬, 소모품, 블록 파괴·설치, 개체 상호작용, GUI, 아이템 획득·버리기, 질주·점프와 다른 플레이어 구조를 차단한다.
6. 기본 이동속도는 바닐라 대비 `+10%`, 블록·개체 상호작용 거리는 `+30%`를 적용한다. 회차 시작·접속·리스폰·Test Lab 런타임에 재동기화한다.
7. 증가한 개체 상호작용 거리가 구조 판정을 늘리지 않도록 구조 거리는 문서 권위값 `2.5블록`으로 고정한다. 구조 도중 월드가 달라지면 안전하게 취소한다.
8. Test Lab 백업 스키마를 `3`으로 올려 두 상호작용 거리 속성을 함께 보존·복원한다. 기존 스키마 2 백업의 누락값은 덮어쓰지 않는다.
9. 추가 감사에서 발견한 입력 누락도 함께 보정한다. `Shift+2~9` 공용 액티브·퀵 아이템은 이전 선택 슬롯이 `0`일 때만 가로채고 실행 뒤 반드시 `0`으로 복귀한다. 전투 자세의 좌클릭 블록 입력은 적중 여부와 무관하게 공격 판정을 우선하며, 빈사자의 보조 손 개체 상호작용과 웅크리기 연속 입력도 차단한다.

## 2. 자동 검증 계약

| 검증 | 통과 기준 |
|---|---|
| 생존 치명 피해 | `finalDamage == HP`, 초과 피해, 무한대 피해가 모두 `ENTER_DOWNED` |
| 빈사·사망 후속 피해 | 일반 HP 피해가 `BLOCK` |
| 비치명 피해 | `ALLOW` 유지 |
| 기본 이동속도 | 투자 0에서 `0.11` |
| 기본 블록 상호작용 거리 | `5.85` |
| 기본 개체 상호작용 거리 | `3.90` |
| 컴파일·콘텐츠 | 전체 단위 테스트와 `ws-prototype-r1` lock/hash 검증 통과 |
| 런타임 | Paper 26.1.2 활성화·L0 검증·정상 종료 |
| 전투 자세 입력 | `Shift+2~9`는 이전 슬롯 `0`에서만 실행하고 슬롯 `0` 유지, 좌클릭 블록은 공격 우선 |

## 3. 인게임 E2E 필수 매트릭스

1. HP를 `1`로 설정하고 일반 적 근접 공격, 커스텀 적 투사체, 낙하, 화재, 폭발, 익사, 공허 피해를 각각 받는다.
2. 모든 일반 치명 피해에서 Minecraft 사망 화면·아이템 드롭 없이 HP `1`, `lifeState=DOWNED`, AP `0`이 되는지 확인한다.
3. 빈사 직후 기본 공격·W/C/Q 입력, 음식·물약, 블록 파괴·설치, 상자·Craft·장비 GUI, 아이템 줍기·버리기, 질주·점프가 모두 차단되는지 확인한다.
4. 다른 생존자가 2.5블록 안에서만 구조를 시작할 수 있고, 2.5블록 초과 또는 월드 변경 시 구조가 취소되는지 확인한다.
5. `/attribute <player> minecraft:movement_speed base get`, `block_interaction_range`, `entity_interaction_range`로 각각 `0.11`, `5.85`, `3.90`을 확인한다.
6. 재접속·리스폰·서버 재시작·Test Lab 입장/종료 뒤에도 속성값과 원래 백업값이 일치하는지 확인한다.

## 5. 승인 경계

- 자동 테스트와 Paper 스모크만으로 실제 사망 방지 E2E를 승인하지 않는다.
- 위 인게임 E2E 1~6을 통과하기 전 상태는 `RUNTIME_VERIFIED_AWAITING_INGAME_E2E`다.
- P0 정식 빈사 체력 작업 전 현재 `30초 제한시간 + 후속 일반 HP 피해 차단`은 프로토타입 임시 규칙으로만 사용한다.
