## 1. 현재 정지점

- `F=짧은 패링/단기 방어` 입력 계약
- 응급 AP 자극제 `즉시 +10, 이후 5초간 초당 +3`와 기본 구조 고정대 `+10%` 권위·부분 런타임
- 연구 25개 `RCOST-*`, 시설 121개 `FCOST-*`의 중복 없는 구조화 비용 ID

## 2. 다음 목표 — 실행하지 않은 제안

### `NEXT-GOAL-S1-001 생산 구현 착수 게이트 폐쇄`

> Season 1의 부활 정책과 Story 작성 방식을 사용자 권위로 확정하고, 실제 클라이언트 검증 환경·서버 버전·후보 리비전을 잠근 뒤 Day 1~3 생산 수직 구간의 착수 조건과 합격 시나리오를 승인한다.

이 목표의 결정 입력은 다음 두 가지다.

1. 완전 사망 뒤 부활: `REVIVAL-ITEM` 권장 / `NO-REVIVAL` / `FACILITY-ONLY`
2. Story 본문 작성: `CHAPTER_REVIEW` 권장 / `ASSISTANT_DRAFT` / `USER_SUPPLY`

이 목표는 결정을 받고 게이트를 닫는 작업이다. 현재 요청에서는 선택을 간주하거나 코드를 작성하지 않는다.

완료 증거는 `AUTHOR-DECISION-REGISTER-001`의 두 ADR이 `USER_LOCKED`, 실클라이언트 E2E 서버·클라이언트 조합이 명시, `ws-content-r2-dev.1` 신규 회차 정책이 승인된 상태다.

## 4. 단계별 세부 작업

### P1 — 서버 권위 기반

1. `RunSnapshot`의 새 필드 마이그레이션 기본값과 구버전 회차 격리를 고정한다.
2. `RCOST/FCOST`를 실제 `validate→reserve→process→commit` 거래에 연결한다.
3. Lv1 시설은 제작식만 결제하고 설치 시 이중 차감하지 않는 테스트를 만든다.
4. 구조 고정대는 구조 대상·거리·AP가 유효한 첫 진행 틱에 예약을 소비하고 기본 +10%/강화 +25% 중 높은 하나만 적용한다.
5. F 입력은 패링 4틱과 단기 방어 12틱으로 연결하고 키 홀드·해제 의존을 제거한다.
6. AP 자극제의 5개 펄스가 재접속·정상 종료·강제 종료에서 중복되거나 사라지지 않는지 검증한다.

### P2 — Day 1~3 첫 생산 수직 구간

1. 아무 원목 4개로 craft GUI를 해금한다.
2. 9칸 조합, 후보 순환, 재료 예약, 취소 반환, 출력 서명까지 한 거래로 만든다.
3. 최초 획득 도감 해금과 고정 도감 인덱스·`???` 표시를 연결한다.
4. Shift+F 메뉴에서 craft·도감·스탯·장비·설정을 연다.
5. slot 0/-106 장착, slot 1~8 바닐라, slot 0 전투 입력, 빈손 권투를 함께 E2E한다.
6. 최소 적·자원·장비·레시피·연구가 Day 3까지 하나의 루프로 이어지는지 2~4인으로 확인한다.

### P3~P7 — 데이터 묶음 확장 규칙

- 새 Day 묶음을 열 때마다 그 구간의 재료, 비장비 아이템, 장비, 레시피, 스킬, 증강, 상태, 적 행동, 엔티티, 시설, 연구, loot를 함께 연다.
- 설명만 출력하는 placeholder는 등록 완료나 런타임 완료로 세지 않는다.
- 각 ID는 `HAPPY`, `REJECT`, `DUPLICATE`, `PERSIST`, `RECOVER`, `CLIENT` 여섯 증거 중 해당되는 항목을 가져야 한다.
- 파티 크기 1/2/3/4, Story/Challenge, Easy/Hard, TPS 20/15/10 행렬을 단계 종료마다 반복한다.
- 실제 클라이언트에서 블록 설치·채굴·섭취·인벤토리·숫자키가 검증되지 않은 단계는 Paper 스모크만으로 승격하지 않는다.
