## 1. 목적

이 문서는 완성형 Season 1을 한 번에 구현하지 않고, 핵심 재미와 기술 위험을 검증하는 협동 생존 프로토타입을 먼저 만든 뒤 Day·무기·성장·콘텐츠 범위를 단계적으로 확장하는 실행 순서를 고정한다.

`IMPLEMENTATION-HANDOFF-001`은 모듈·상태·최종 기능 계약을 소유하고, 이 문서는 구현 순서·프로토타입 범위·단계 승인 게이트를 소유한다. `IMP-001~017`은 최종 기능 묶음이므로 프로토타입에서 일부 기능을 사용했다고 해당 IMP 전체를 완료로 표시하지 않는다. 각 IMP는 프로토타입 조각, 확장 조각, 최종 승인 증거가 모두 합쳐진 뒤에만 완료된다.

## 2. 개발 결정

### 2.1 고정 결정

- 첫 플레이 가능 산출물은 2~4인 단일 파티용 수직 구간이다.
- 프로토타입도 바닐라 클라이언트와 Paper 플러그인만 사용한다.
- 서버 권위, 데이터 기반 판정, 회차 잠금, 멱등 보상, 재접속 복구는 프로토타입부터 적용한다.
- 프로토타입 전용 단축은 `runType: PROTOTYPE`과 별도 콘텐츠 리비전으로 격리한다.
- 프로토타입 저장은 정식 Season 1 회차로 마이그레이션하지 않는다.
- 정식 Final은 항상 Day 50부터 활성화한다. 프로토타입 보스 완료를 Final 완료로 취급하지 않는다.
- 리소스 팩은 프로토타입 필수 조건이 아니다.

### 2.2 개발 질문

프로토타입은 다음 질문에 답해야 한다.

1. 2~4인이 탐험·채집·제작·전투·성장을 서로 분리된 미니게임이 아니라 하나의 생존 루프로 느끼는가?
2. 회피·AP·상태이상·브레이크·보스 패턴이 바닐라 입력만으로 읽히고 대응 가능한가?
3. 개인 증강과 파티 증강이 실제 역할 분화와 협동 결정을 만드는가?
4. 장비 GUI와 슬롯 `0/-106`, 곡괭이 전투 우선, 빈손 권투, 커스텀 삼지창을 Paper에서 안정적으로 운영할 수 있는가?
5. 재시작·재접속·중복 이벤트에서도 장비·자원·보상이 복제되거나 소실되지 않는가?
6. 최대 4인 전투와 공세가 목표 틱 예산 안에서 동작하는가?

이 질문에 답하지 못하면 Day 11 이후 콘텐츠 양을 늘리지 않는다.

## 3. 산출물과 리비전 전략

| 산출물 | 용도 | 활성 정책 |
|---|---|---|
| `ws-content-r1` | 기존 부분 데이터와 기존 회차 보존 | 변경·마이그레이션 금지 |
| `ws-prototype-r1` | 프로토타입 전용 최소 데이터 | 개발·폐쇄 테스트 전용 |
| `ws-content-r2-dev.N` | 승인된 프로토타입에서 확장 중인 후보 | 개발 서버 신규 회차 전용 |
| `ws-content-r2-rc.N` | Season 1 전체 데이터와 테스트 증거를 가진 후보 | 폐쇄 검증·canary 전용 |
| `ws-content-r2` | `LIVE_LOCKED` 승인을 받은 정식 리비전 | 신규 정식 회차 전용 |

- 모든 리비전은 schema·manifest·lock·SHA-256을 함께 가진다.
- 개발 리비전도 부분 파일 활성화를 허용하지 않는다.
- 프로토타입 전용 가속·치트·단축 레코드는 정식 r2 manifest에서 참조할 수 없다.
- r2 목표 파일 수는 `DEV-000`에서 누락 도메인을 보정한 뒤 레지스트리의 실제 파일 목록으로부터 산출한다.

## 4. 프로토타입 범위

### 4.1 목표 경험

2~4인 파티가 새 회차를 만들고, 자유 야생에서 자원을 찾고, 최소 장비를 제작·장착하고, 전투와 증강 선택을 거쳐 협동 보스를 처치한 뒤 결과 화면까지 도달한다. 첫 내부 목표 플레이 시간은 `45~90분`이며 밸런스 확정값이 아니라 반복 검증을 위한 범위다.

프로토타입은 정식 Day 1·3·6·10 체크포인트를 개발 시간 배율로 압축한다. 레벨 3·6·10 개인 증강과 Day 10 파티 증강 규칙은 정식 규칙을 그대로 사용한다.

### 4.2 포함 범위

| 영역 | 프로토타입 포함 | 검증 목적 |
|---|---|---|
| 회차 | 2~4인 생성, 멤버 고정, 재접속, 전멸, 유일 생존자 | 회차 권위·복구 |
| Day | Day 1→3→6→10 압축 진행, Day10 보스 게이트 | 스케줄·마일스톤 |
| 야생 | 바닐라 월드 탐험, 동적 자원 노드, 한 종류 오염 위험 | 자유 야생 루프 |
| 자원·제작 | 핵심 자원 4종 이상, 휴대 제작 1종, 시설 1종, 레시피 6종 이상 | 수급→소비 폐쇄 루프 |
| 장비 | 커스텀 장착 GUI, 주무기 `0`, 보조무기 `-106`, 공용 스킬 `1~4`, 퀵 아이템 `5~8` | 원장·실제 슬롯·입력 동기화 |
| 무기 | 검·활·곡괭이·권투 플레이 가능, 삼지창 기술 스파이크 | 근접·원거리·입력 중재·가상 무기·상태기계 |
| 전투 | 일반 공격, AP, 회피, 피해 파이프라인, 상태 2종, 브레이크 | 전투 핵심 상호작용 |
| 적 | 근접·원거리·장갑 역할 각 1종, 엘리트 1종 | 역할·상태·브레이크 |
| 성장 | EXP·레벨 1~10, 개인 증강 3회, 파티 증강 1회 | 최초 도달 등급 잠금·3택 |
| 보스 | Day10 공명 추적체 축약형 2페이즈, 브레이크·협동 중단 1종 | 협동 전투·보상 1회 |
| UX | 회차·장비·증강 GUI, ActionBar, BossBar, Title, 색상 외 경고 | 정보 전달·접근성 |
| 운영 | 시작·중지·상태 검사·콘텐츠 검증·강제 종료 명령, 감사 로그 | 개발·복구 가능성 |
| 계측 | 전투 결과, AP, 다운·사망, 자원 원장, 증강 선택, 틱 시간 | 확장 승인 근거 |

삼지창은 프로토타입에서 정식 장비 풀에 넣지 않아도 된다. `HELD→THROWN→RETURNING/RECOVERABLE` 전이, 바닐라 이중 피해 차단, 청크 언로드·재접속 복구까지만 기술 승인하면 된다.

### 4.3 의도적으로 제외하는 범위

- Day 11~50 실제 진행과 Final
- 10개 무기 전체 콘텐츠와 희귀도별 완성 장비 풀
- 강화·재련·심연 장비의 전체 경제
- 전체 상태이상·적 변이·개인/파티 증강 풀
- Day20·30·40 보스와 Season 1 Story 전체
- 연구 트리·발견 C01~C30·대규모 시설망
- Story/Easy/Normal/Hard/??? 전체 난이도 튜닝과 CHAOS
- 정식 리소스 팩 모델·사운드·연출
- 공개 서버 운영, r1→r2 활성 회차 마이그레이션

제외 항목의 인터페이스와 ID 공간은 미리 예약하되 빈 기능을 사용자에게 노출하지 않는다.

## 5. 단계 지도

```text
DEV-000 계약 보정
  → DEV-100 기술 골격
    → DEV-200 전투·장착 기술 프로토타입
      → DEV-300 플레이 가능 협동 프로토타입
        → DEV-400 프로토타입 승인
          → DEV-500 Day 1~20 Alpha
            → DEV-600 Day 21~40 Beta
              → DEV-700 Day 41~50·Final·Story RC
                → DEV-800 운영·부하·릴리스
```

각 단계는 이전 단계의 완료 증거가 없으면 시작하지 않는다. 단, 같은 단계 안에서 서로 소유 상태가 겹치지 않는 작업은 병렬화할 수 있다.

## 8. 작업 보드 상태 규칙

모든 개발 작업은 다음 상태만 사용한다.

| 상태 | 의미 |
|---|---|
| `BACKLOG` | 상위 게이트 또는 입력이 준비되지 않음 |
| `READY` | Definition of Ready 충족 |
| `IN_PROGRESS` | 구현·데이터·테스트 작업 중 |
| `REVIEW` | 코드·데이터·문서 검토 중 |
| `VERIFIED` | 자동 증거와 수동 검토 통과 |
| `BLOCKED` | 원인·소유자·해제 조건이 기록된 중단 |
| `DROPPED` | 근거와 대체 경로를 남기고 범위에서 제외 |

프로토타입 조각이 `VERIFIED`여도 연결된 IMP 전체는 완료가 아니다. 단계 게이트와 IMP 완료 상태를 분리해 기록한다.

## 9. 작업 단위 Definition of Ready

- 권위 문서와 구현할 ID·상태 전이가 연결돼 있다.
- 입력·출력·오류·재시작·멱등성 fixture가 있다.
- 데이터 소유와 코드 소유가 구분돼 있다.
- Paper 이벤트 취소·허용·대체 순서가 명시돼 있다.
- 2~4인과 유일 생존자 분기가 검토돼 있다.
- 리소스 팩이 없는 표현 폴백이 있다.
- 프로토타입 전용 단축이면 정식 리비전 유입 차단 조건이 있다.

## 10. 작업 단위 Definition of Done

- 코드·schema·DATA·테스트·필요 문서가 같은 변경 세트에 있다.
- 정상·거부·재시작·중복 실행 테스트가 통과한다.
- 다른 모듈 상태를 직접 변경하지 않고 이벤트 계약을 사용한다.
- 장비·자원·보상 원장에 음수·복제·유실이 없다.
- GUI가 PENDING 중 중복 입력을 막고 서버 결과로 재렌더된다.
- 1인 생존과 2·3·4인 fixture가 있다.
- 성능 상한과 실패 시 안전 열화가 계측된다.
- 상태 메타데이터와 실제 산출물 단계가 일치한다.

## 11. 범위 변경 규칙

- `G-400` 전에는 Day 11+ 콘텐츠, 전체 Story, 정식 리소스 팩을 구현하지 않는다.
- 프로토타입 재미를 높이기 위한 새 시스템은 기존 여섯 개발 질문 중 어느 질문을 검증하는지 기록해야 한다.
- 테스트를 쉽게 하기 위한 관리자 기능은 일반 플레이 권한에서 접근할 수 없어야 한다.
- 상위 기획 수치를 바꾸는 밸런스 조정은 세션 로그·fixture·변경 이유를 함께 남긴다.
- 프로토타입에서 버린 코드는 정식 경로에서 참조하지 않으며, 재사용 가능한 인터페이스와 검증 결과만 승격한다.
