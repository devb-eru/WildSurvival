## 1. UX 불변식

- 핵심 정보는 색, 소리, 입자, 리소스 팩 중 하나에만 의존하지 않고 최소 두 경로로 전달한다.
- 서버에 저장된 상태가 권위자이며 GUI 아이템은 상태를 보여 주고 명령을 제출하는 뷰다.
- 전투 중 화면을 강제로 열어 조작을 빼앗지 않는다. 선택·보상·Story는 `PENDING`으로 큐에 넣고 안전 상태에서 연다.
- 필수 전투 판정은 인벤토리 GUI 안에서 수행하지 않는다. HUD·월드 전조·액션바로 읽을 수 있어야 한다.
- 모든 커스텀 장비는 장비 GUI에서만 장착하며 주무기 슬롯 `0`, 보조무기 오프핸드 슬롯 `-106`은 서버가 동기화한다.
- 권투는 주무기·보조무기 모두 비어 있을 때 자동 활성화되며 가짜 권투 아이템을 생성하지 않는다.
- `UNKNOWN`의 의도된 비공개 수치 외에는 실패 이유와 다음 가능한 행동을 숨기지 않는다.

### 2.1 전투 핫바·로드아웃 표시

| 영역 | 표시 | 상호작용 |
|---|---|---|
| 슬롯 `0` | 주무기 이름·기본 공격 간격, 빈 슬롯이면 `권투` | `L` 기본 공격 |
| `W1~W3` | 화면 우측 또는 액션바에 스킬명·AP·쿨다운 | `Shift+L`, `Shift+R`, `F` |
| 핫바 `1~4` | 공용 액티브 아이콘·남은 쿨다운·표시 키 `2~5` | 기본 `Shift+키`, 설정별 확인 |
| 핫바 `5~8` | 실제 퀵 아이템 수량·상태 제한·표시 키 `6~9` | 선택 후 `R` 사용 |
| 오프핸드 `-106` | 방패·보조 도구 이름과 방어 가능 상태 | `R` 사용·유지 |

- 기본 공격은 무기 액티브 3칸에 표시하지 않고 슬롯 `0`의 고정 행동으로 안내한다.
- 공용 액티브 사용·실패·퀵 아이템 종료 뒤 슬롯 `0` 복귀를 0.3초 이하의 작은 강조로 표시한다.
- `SNEAK_SELECT`, `SELECT_CONFIRM`, `DIRECT_SELECT`를 개인 설정에서 선택할 수 있다. `DIRECT_SELECT`에는 휠 오발 가능성을 확인하는 동의가 필요하다.
- 프록시 스킬 아이템은 수량을 표시하지 않고 AP·쿨다운·대상 오류를 이름·내구도 막대·로어 중 두 경로로 표현한다.
- 퀵 아이템이 0개가 되면 빈 병·장벽 등 비소비 표시로 바꾸고 자동 보충 원천이 없음을 알린다.
- 색상만으로 W/C/Q 영역을 구분하지 않고 `W1`, `C2`, `Q3` 문자 접두어와 서로 다른 바닐라 사운드를 사용한다.

## 4. 클릭·입력 공통 규칙

| 입력 | 의미 | 예외 |
|---|---|---|
| 좌클릭 | 선택·상세 보기·1단위 이동 | 파괴·영구 소비에는 사용 금지 |
| 우클릭 | 상세 옵션·5단위 이동 | 화면 로어에 명시된 경우만 |
| Shift+좌클릭 | 가능한 최대 묶음 이동 | 서버 상한·예약량 재검사 |
| Shift+우클릭 | 미리보기·출처 보기 | 부작용 없음 |
| 숫자키·더블클릭·드래그 | 기본 차단 | 장비 GUI의 명시 슬롯 이동만 서버 명령으로 변환 |
| Q·Ctrl+Q | 차단 | GUI 아이템 드롭 금지 |
| ESC·인벤토리 키 | 닫기 요청 | 임시 변경 폐기 확인 또는 안전 저장 |

- 모든 클릭은 `viewId`, `viewRevision`, `actionId`, `actorUuid`, `nonce`를 포함한다.
- 서버는 클릭 시 권한·회차·전투 상태·자원·대상 리비전을 다시 검사한다.
- 같은 `nonce`는 한 번만 처리한다. 5초 안의 동일 명령 중복 패킷은 기존 결과를 반환한다.
- 처리 중 슬롯은 시계 아이콘으로 잠그고 완료·실패 후 전체 화면을 서버 스냅샷으로 다시 그린다.

## 5. 확인·취소·되돌리기

| 위험 등급 | 예시 | 확인 |
|---|---|---|
| `R0` 읽기 | 탭·정렬·도감 | 없음 |
| `R1` 회복 가능 | 입력 예약·임시 스탯 배분 | 1회 확정, 취소 100% |
| `R2` 비용 소비 | 제작 시작·연구 처리·리롤 | 비용·결과·환불률 표시 후 확인 |
| `R3` 희소·비가역 | 프리즘 교체·고유 장비 선택·Final 시작 | 2단계 확인+파티 상태 표시 |
| `R4` 운영 | 회차 실패 확정·데이터 복구 | 일반 GUI 제공 금지, OPS 권한·감사 로그 |

- ESC는 아직 커밋되지 않은 `R1~R3` 변경을 적용하지 않는다.
- 처리 시작 뒤 취소는 각 도메인의 환불 계약을 따르며 GUI가 실제 반환량을 먼저 보여 준다.
- 장비·스탯의 무료 되돌리기 시간은 서버 시각으로 계산하고 GUI 닫힘·재접속으로 초기화하지 않는다.

## 6. 장비 GUI와 실제 슬롯 동기화

### 6.1 장비 화면 배치

| GUI 슬롯 | 장비 슬롯 | 표시·동작 |
|---:|---|---|
| 20 | `MAIN_WEAPON` | 주무기, 실제 핫바 `0`과 동기화 |
| 24 | `OFF_WEAPON` | 보조무기, 실제 오프핸드 `-106`과 동기화 |
| 29~32 | 방어구 | 서버 장비 인스턴스와 바닐라 시각 슬롯 동기화 |
| 33~35 | 장신구 | 서버 전용, 바닐라 슬롯 미사용 |
| 38 | 권투 상태 | 두 무기 슬롯이 비었을 때만 활성, 클릭 불가 |
| 40~44 | 비교·세트·태그 | 현재/후보 수치, 충돌·증강 연계 |

### 6.2 동기화 순서

1. GUI에서 장착 명령 제출.
2. 서버가 아이템 인스턴스 UUID·소유·파손·전투 상태·슬롯 호환성을 검사.
3. 장비 저장 원장에 새 슬롯 상태를 원자 커밋.
4. 슬롯 `0` 또는 `-106`의 바닐라 아이템을 서버 저장값과 동기화.
5. 스탯·스킬·증강 태그를 재계산하고 GUI 갱신.

- 플레이어가 바닐라 드래그·숫자키·F키·호퍼·사망 드롭으로 예약 슬롯을 변경하면 이벤트를 취소하고 다음 틱에 서버 상태로 복원한다.
- 곡괭이를 들고 공격 가능한 콘텐츠 대상을 조준하면 전투 판정을 채굴보다 우선한다. 블록을 조준하거나 유효 전투 대상이 없으면 바닐라 채굴 규칙으로 보낸다.
- 삼지창의 바닐라 투척·회수·충성 인챈트 실행은 차단하고 `WEAPON-002` 커스텀 실행기로 보낸다.
- 단검은 검, 둔기는 철퇴 기반 아이템을 쓰며 리소스 팩 거부 시에도 이름·로어와 무기군 태그로 판독한다.

## 7. 전투 중 GUI 정책

| 작업 | 전투 상태 | 공세·보스·Final |
|---|---|---|
| 도감·상태·설정 읽기 | 허용, 이동·피격 시 자동 닫기 선택 가능 | 허용 |
| 장비 장착·해제 | 차단 | 차단 |
| 스탯 투자·증강 선택·교체 | `PENDING` | 차단 |
| 제작·연구·시설 작업 등록 | 차단 | 차단 |
| 완료 출력 수령 | 안전 인벤토리 공간 있을 때만 | 차단 |
| 구조·회피·패링·스킬 | GUI가 열리면 입력 우선순위상 GUI 닫기 후 실행 | 월드 입력 우선 |

- 피해를 받으면 읽기 화면은 닫지만 이미 제출된 도메인 트랜잭션은 서버 결과까지 마친다.
- 개인 증강 마일스톤은 전투 중 `PENDING`만 저장하고 후보 시드는 고정한다. 안전 상태가 되면 한 번만 연다.
- 파티 증강은 보스 정산으로 Day가 정지된 상태에서만 열며, 제한 시간이 끝나면 저장된 투표와 시드로 확정한다.

## 8. GUI 중단·복귀

| 상황 | 복귀 규칙 |
|---|---|
| ESC·닫기 | 이전 화면 스택과 임시 탭을 30초 저장. 미커밋 변경은 폐기/확인 |
| 피격·강제 이동 | 즉시 닫고 `returnToken`을 60초 보존. 안전 시 채팅 버튼 제공 |
| 접속 종료 | 서버 커밋 상태만 보존. 후보·투표·작업 ID는 재접속 시 복원 |
| 서버 재시작 | 최신 저장된 `pendingUiTasks`를 낮은 우선순위부터 재개 |
| 화면 대상 소멸 | 상위 목록으로 돌아가고 `UI_TARGET_GONE` 표시 |
| 인벤토리 부족 | 출력함 유지, `UI_NO_SPACE`; 바닥 드롭 금지 |
| 리비전 불일치 | 명령 거부 후 최신 화면 재생성, 비용 미소비 |

재개 우선순위는 `Final 복구 확인 > 고유 보상 > 파티 증강 > 개인 증강 > 연구/제작 출력 > 일반 알림`이다. 한 번에 강제 화면 하나만 열고 나머지는 메뉴의 알림함에 둔다.

## 10. 전조·상태 표현 문법

| 의미 | 문자·아이콘 | 기본 색 | 바닐라 소리 | 월드 표현 |
|---|---|---|---|---|
| 회피 가능 | `◇ 회피` | 하늘색 | `ENTITY_EXPERIENCE_ORB_PICKUP` | 점선 원/방향 입자 |
| 방어 가능 | `▣ 방어` | 파랑 | `ITEM_SHIELD_BLOCK` 전조 변형 | 정면 호 |
| 패링 가능 | `✦ 패링` | 금색 | 종 고음 | 짧은 섬광+방향선 |
| 중단 가능 | `! 중단` | 노랑 | `BLOCK_NOTE_BLOCK_HAT` | 채널선+카운트다운 |
| 중단 불가 | `× 버티기` | 보라 | 저음 베이스 | 이중 테두리 |
| 강한 CC 위험 | `CC` | 자홍 | 경고음 2회 | 대상 머리 위 문자 |
| 오염 위험 | `☣ 오염` 또는 `[오염]` | 초록 | 스컬크 클릭 | 지면 얼룩+경계 입자 |
| 구조 가능 | `+ 구조` | 흰색/빨강 | 종 3연음 | 빔+남은 시간 숫자 |

유니코드 폭이나 폰트 문제가 있으면 대괄호 텍스트 폴백을 사용한다. 색각 설정은 색을 바꾸지만 문자·소리·형태는 바꾸지 않는다.

## 11. 오류 코드와 문장 규칙

| 코드 | 사용자 문장 | 다음 행동 |
|---|---|---|
| `UI_STALE_VIEW` | “정보가 갱신되었습니다.” | 최신 화면 자동 갱신 |
| `UI_COMBAT_LOCK` | “전투 중에는 변경할 수 없습니다.” | 안전 후 알림함에서 재개 |
| `UI_NO_SPACE` | “출력 공간이 없습니다. 결과는 보관 중입니다.” | 인벤토리 정리 후 수령 |
| `UI_RESOURCE_CHANGED` | “공용 자원이 변경되어 확정하지 못했습니다.” | 새 비용 확인 |
| `UI_TARGET_GONE` | “대상이 더 이상 존재하지 않습니다.” | 상위 목록 이동 |
| `UI_DAY_LOCK` | “세계 조건이 아직 충족되지 않았습니다.” | 최소 Day·선행 범주 표시 |
| `UI_PERMISSION` | “이 작업을 수행할 권한이 없습니다.” | 파티/관리 권한 표시 |
| `UI_DATA_ERROR` | “콘텐츠 데이터를 확인할 수 없습니다.” | 비용 미소비, 오류 ID 복사 |

- 한 문장은 기본 42자, 로어 한 줄은 34자, 타이틀은 18자, 액션바는 48자를 권장한다.
- “실패”만 말하지 않고 원인·손실 여부·가능한 다음 행동을 함께 쓴다.
- 내부 UUID·스택 트레이스·시드는 일반 UI에 표시하지 않고 복사 가능한 짧은 오류 ID를 제공한다.

## 12. 접근성 설정

개인 설정은 회차 난이도·판정·보상에 영향을 주지 않는다.

| 설정 | 값 | 기본 |
|---|---|---|
| 색각 팔레트 | `DEFAULT`, `DEUTERANOPIA`, `PROTANOPIA`, `TRITANOPIA`, `HIGH_CONTRAST` | DEFAULT |
| 전조 문자 | `ICON_TEXT`, `TEXT_ONLY`, `MINIMAL` | ICON_TEXT |
| 소리 경고 | 0~100%, 핵심/비핵심 분리 | 100/70 |
| 화면 흔들림 대체 | `FULL`, `REDUCED`, `OFF` | REDUCED |
| 입자량 | `FULL`, `REDUCED`, `MINIMAL` | REDUCED |
| 고어 표현 | `FULL`, `REDUCED` | REDUCED |
| Story 자동 진행 | `AUTO`, `MANUAL`, `FAST` | MANUAL |
| 채팅 반복 묶음 | `ON`, `OFF` | ON |
| 상세 수치 | `SIMPLE`, `DETAILED` | SIMPLE |

- `REDUCED` 고어는 기능적 정보와 피격 판정을 유지하고 붉은 입자·생체 명칭·잔해 밀도만 줄인다.
- 핵심 사운드가 꺼져도 화면 문자와 보스바 깜박임을 제공한다.
- 입자 최소 설정에서도 위험 경계는 블록 디스플레이/문자/보스바로 남긴다.
- 키 바인딩을 플러그인이 새로 추가할 수 없으므로 좌·우클릭, 웅크리기, 점프, 드롭, 스왑 입력 조합을 설정 화면에 설명하고 동일 기능의 채팅 버튼 또는 GUI 경로를 둔다.

## 13. Story·보스·Final 재생 정책

- Story는 전투·보상·완료 트랜잭션을 막지 않는 소비자다.
- 전투 중 장면은 타이틀 1줄+채팅 기록으로 축약하고 전체 대사는 `UI-STORY-LOG`에 보존한다.
- 스킵은 개인 표현만 건너뛰며 파티의 진행 플래그·보상·선택을 건너뛰지 않는다.
- 보스 페이즈 전환에서 대사와 패턴 전조가 충돌하면 패턴 전조가 먼저다.
- Final 완료 후 엔딩 책을 인벤토리에 넣을 공간이 없으면 가상 보관함과 다시 보기 메뉴에 저장한다.

ui-player:

  common-skill-input: SNEAK_SELECT

    - id: "ui-task:run-01:augment:uuid-a:25"

- 접근성 설정은 플레이어 계정 단위, 진행·후보·투표는 회차 리비전 단위다.
- 보안상 `InventoryHolder` 식별자와 PDC 뷰 ID를 함께 검사한다. 이름만 같은 가짜 아이템 클릭은 무시한다.

## 15. 성능·TPS 열화

| TPS | UI 처리 |
|---:|---|
| 18~20 | 기본 갱신 주기 |
| 15~17.9 | 로어 자동 갱신 10→20틱, 비핵심 입자 50% |
| 10~14.9 | 로어 40틱, 장식 입자 최소, 핵심 보스바 2틱 유지 |
| <10 | 신규 비핵심 타이틀 큐 중지, 핵심 판정·전조 실시간 유지, 운영 경고 |

GUI 전체 재생성은 플레이어당 5틱에 1회, 자동 로어 갱신은 화면당 10틱에 1회가 상한이다. 클릭 응답·핵심 오류는 이 상한보다 우선한다.
