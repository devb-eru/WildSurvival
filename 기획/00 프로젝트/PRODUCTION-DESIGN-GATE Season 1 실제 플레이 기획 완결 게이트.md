## 1. 생산 범위

별도 축소 승인이 없는 한 실제 플레이 가능 범위는 다음 전체를 의미한다.

- 2~4인 단일 협동 파티의 신규 회차 생성부터 Day 50 Final 완료까지
- Day 51+ 반복 규칙, 정상 중단·재접속·서버 재시작·실패·롤백
- 등록 아이템, 재료, 소모품, 탄약, 도구, 무기, 방어구, 보조무기, 장신구, 부적
- 모든 제작·가공·강화·수리·재련·분해·시설·보스 호출·재건 조합법
- 10개 무기군 기본 공격, 무기 액티브, 공용 액티브, 상황 스킬
- 개인 증강 50종과 파티 증강 16종, 마일스톤·등급 최초 잠금·몬스터 연동
- 일반 적, 정예, 보스, 소환체, 전투 오브젝트, 자원 노드, 시설 표현 개체
- 46종 플레이어 시설과 연구·발견·오염·사건·보스·Story 연결
- FULL/REDUCED UI, 리소스 팩 수락/거부, 관리자 복구, 텔레메트리

Day 1~10만 동작하거나 관리자 명령으로만 진행 가능한 상태는 실제 플레이 가능으로 판정하지 않는다.

## 4. slot 0 블록 파괴·내구도 확정 계약

slot 0의 블록 파괴 판정과 장비 파손 알림은 별도 계약이다. 전자는 한 스윙의 전투/채굴 중재이고, 후자는 서버 내구 원장이 `ACTIVE → BROKEN`으로 바뀌는 전이 알림이다.

### 4.1 좌클릭 판정

```text
slot != 0
→ 바닐라 블록 파괴·아이템 사용

slot == 0
→ 생명·제어·GUI 상태 검사
→ 공격 가능한 콘텐츠 대상 ray/hitbox 검사
→ 대상 있음: BASIC_ATTACK 실행, 같은 입력의 블록 손상 취소
→ 대상 없음 + PICKAXE + 허용 블록: 공격 미실행, 바닐라 채굴 허용
→ 대상 없음 + 빈 주무기 + 웅크리기 + 허용 블록: 권투 미실행, 바닐라 손 파괴 허용
→ 그 외: BASIC_ATTACK 실행, 블록 손상 취소
```

- `전투 상태`만으로 곡괭이 채굴을 전부 막지 않는다. 같은 입력에 유효 전투 대상이 있는지가 1차 기준이다.
- 공격 후보가 블록 뒤, 사거리 밖, 아군, 관전자, 사망 개체면 `대상 없음`으로 처리한다.
- 블록이 보호·등급 부족·시설 소유 블록이면 채굴을 거부하되 허공 공격으로 자동 변환하지 않는다.
- 한 번의 스윙에서 `COMBAT_HIT`와 `BLOCK_BREAK`가 동시에 커밋되면 결함이다.

### 4.2 장비 내구와 파손

- WS 장비는 영구 삭제하지 않는다. 내구 `0`은 `BROKEN`이며 아이템 인스턴스는 보존한다.
- 서버 원장의 `currentDurability/maxDurability/durabilityPolicy`가 권위다. 바닐라 damage 값은 표시 미러다.
- 커스텀 기본 공격·스킬은 실행 데이터의 내구 비용을 서버가 직접 차감한다.
- 곡괭이의 허용 채굴은 `PlayerItemDamageEvent`를 입력으로 받아 정확히 한 번만 원장에 반영한다.
- 원장 내구가 0이 되는 타격은 바닐라 삭제를 차단하고 권위 이벤트 `EquipmentBrokenEvent`와 감사 이벤트 `EQUIPMENT_BROKEN`을 정확히 한 번 발행한다.
- 다른 Bukkit 플러그인의 slot 0 파손 관찰 호환을 위해 같은 전이에서 합성 `PlayerItemBreakEvent`를 한 번 추가 발행한다. 이 이벤트의 `brokenItem`은 전이 직전 ItemStack 복사본이며, 실제 장착 ItemStack 삭제·드롭·통계 증가의 권위로 사용하지 않는다.
- 합성 `PlayerItemBreakEvent`를 다시 WS 내구 차감 입력으로 해석하지 않는다. 외부 리스너가 장비 슬롯을 수정해도 다음 틱에 서버 원장의 `BROKEN` 미러로 복구한다.
- `BROKEN` 장비는 장착 미러는 유지하되 공격·옵션을 비활성화하고 수리 GUI로 안내한다.
- 바닐라 아이템은 기존 `PlayerItemDamageEvent/PlayerItemBreakEvent`를 그대로 사용한다.

### 4.3 파손 완료 판정

- slot 0 WS 장비 내구 `1`에서 커스텀 공격, 스킬, 허용 채굴을 각각 실행하면 원장 차감·두 파손 이벤트·미러 복구가 모두 1회다.
- 이미 `BROKEN`인 같은 인스턴스에서는 두 파손 이벤트가 다시 발생하지 않는다.
- slot 1~8의 바닐라 도구는 합성 이벤트 대상이 아니며 실제 바닐라 파괴 이벤트만 발생한다.
- 실제 클라이언트 검증 전 자동 테스트는 전이 정책과 이벤트 발행 명령의 단일성만 증명한다. 채굴 입력 자체는 `BLOCKED_E2E`를 유지한다.

## 7. 구현 착수 판정

다음 조건을 모두 만족해 상태를 `IMPLEMENTATION_READY`로 변경했다. 이는 코드·번들 완성을 뜻하지 않으며 생산 구현 착수만 허용한다.

1. 별도 목록 10종의 상태가 `DATA_LOCKED`다.
2. 와일드카드·표시명 참조·중복 ID·고아 ID가 0이다.
3. 모든 craftable item에 최소 하나의 recipe, 모든 non-craftable item에 최소 하나의 loot/reward source가 있다.
4. 모든 스킬·증강·장비 효과가 해석 가능한 trigger/effect/cap ID를 가진다.
5. 모든 엔티티가 spawn/despawn/reward owner와 리소스 팩 없는 폴백을 가진다.
6. Day 1 무보급 시작부터 Day 50 Final까지 1~4인 소프트락 정적 시뮬레이션이 통과한다.
7. slot 0 채굴·전투·내구 E2E가 구현 인계 계약에 추가된다.

2026-08-24 재감사에서 설계 게이트는 유지하되 실행 의미 완료를 별도로 판정하도록 분리했다. r2의 스텁·축약·생성기 추론은 기획 목록 누락으로 숨기지 않고 `PRODUCTION-COMPLETION-PLAN-001`의 `STUB/STRUCTURED_ONLY/PARTIAL_RUNTIME` 상태로 추적한다.
