## 1. 판정과 원칙

Season 1의 게임 디자인 원장과 개별 콘텐츠 ID 목록은 작성되어 있다. 남은 핵심은 이를 실제 r2 레코드와 Paper 런타임으로 옮기고, 각 ID의 정상·거부·복구 경로를 증명하는 일이다.

다음 원칙을 고정한다.

1. 목록의 각 고정 ID를 하나의 완료 단위로 취급한다. 같은 유형의 다른 ID가 동작한다는 사실로 대체 통과시키지 않는다.
2. 문서의 표시명, 와일드카드, “현재 무기군”, 자유 서술을 런타임이 직접 해석하지 않는다.
3. 생성기가 ID 접두사 또는 문장 속 숫자로 수치·비용·효과를 추론하지 않는다. 권위 레코드에 명시된 필드만 사용한다.
4. L0 스키마·합계 통과와 실제 의미 실행을 구분한다. 스텁, 범용 opcode, 단일 행동 축약은 `STRUCTURED_ONLY`이며 완료가 아니다.
5. 한 레코드의 완료에는 데이터, 런타임, 저장·복구, 거부 폴백, 자동 테스트, 필요 시 실제 클라이언트 E2E가 모두 포함된다.
6. 프로토타입 회차와 `ws-content-r2` 회차를 섞지 않는다. 정식 리비전은 승격 전 신규 일반 회차에 연결하지 않는다.
7. 모드나 클라이언트 설치를 요구하지 않는다. 선택 리소스 팩이 없을 때도 판정과 핵심 전조를 읽을 수 있어야 한다.

## 6. 개별 레코드 상태 행렬

각 목록 레코드는 다음 상태 열을 가진 검증 보고서로 추적한다.

| 열 | 통과 조건 |
|---|---|
| `DATA` | 필수 필드·고정 참조·수치가 schema를 통과 |
| `RUNTIME` | 전용 또는 명시 조합 opcode가 정상 실행 |
| `REJECT` | 조건 불충족·오발·중복 실행이 안전하게 거부 |
| `PERSIST` | 재접속·재시작·청크 언로드 후 권위 상태 일치 |
| `RECOVER` | 취소·실패·롤백·관리 복구가 멱등 |
| `AUTO_TEST` | ID별 정상·경계 fixture 통과 |
| `CLIENT_E2E` | 실제 입력·표현이 필요한 경우 수동 증거 통과 |

허용 상태는 `NOT_STARTED`, `IN_PROGRESS`, `VERIFIED`, `BLOCKED`다. 집계 수와 목록 수가 일치해야 하며 `VERIFIED`가 아닌 행을 숨기지 않는다.

## 7. 커밋과 검증 단위

- 목록·schema·런타임·테스트를 가능한 한 같은 도메인 커밋에 둔다.
- 한 커밋은 다른 도메인의 상태 원장을 직접 변경하지 않는다.
- 기계적 대량 전개는 생성기와 결과 합계 검증을 함께 커밋한다.
- Java 변경마다 `gradlew check`, JSON 변경마다 L0·참조 그래프·해시 검증을 수행한다.
- Paper 수명주기·명령·리스너 변경은 서버 부팅·정상 종료 스모크를 추가한다.
- 실제 클라이언트가 필요한 블록 설치·slot0 채굴·동일 슬롯 숫자 입력은 BLOCKER를 유지하고 콘솔 명령으로 대체 승인하지 않는다.
