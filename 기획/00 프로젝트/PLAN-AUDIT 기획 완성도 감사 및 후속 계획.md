## 1. 감사 목적과 판정 경계

이 감사는 “문서가 많고 완료 기준이 적혀 있는가”가 아니라 다음 질문에 답한다.

> 구현자가 추가 게임 디자인 판단 없이 Season 1 전체를 데이터와 코드로 옮길 수 있는가?

다음은 서로 구분한다.

- **기획 공백**: 값, 상태 전이, 콘텐츠 목록, 선택 정책 또는 책임 문서가 없어 구현자가 새 규칙을 결정해야 하는 상태
- **데이터화 공백**: 상위 개념은 있으나 실제 ID·수치·참조·스키마가 없어 실행 데이터로 만들 수 없는 상태
- **검증 공백**: 정적 수치는 있으나 2~4인·난이도·빌드·TPS 조건에서 목표 범위를 증명하지 못한 상태
- **구현 공백**: 기획 계약은 충분하지만 코드·DB·자동화 테스트가 아직 없는 상태

플러그인 코드가 골격뿐인 사실은 구현 공백이다. 아래 `P0` 기획·데이터화 공백은 §0의 산출물로 닫혔고, 다음 단계는 `IMPLEMENTATION-HANDOFF-001`의 구현 작업이다.

## 2. 최초 감사 방법과 기준 증거

1. 색인에 등록된 기존 기획 문서 54개의 책임·상태·후속 문구를 검사했다.
2. `미정`, `후속`, `별도 확정`, `실측`, `EMPTY`와 같은 미완료 표지를 저장소 전체에서 교차 검색했다.
3. 본문이 직접 요구하는 후속 문서 ID가 실제 문서로 존재하는지 확인했다.
4. Day 1~20의 개별 사건·적·자원·장비 데이터와 Day 21~50 통합표의 상세도를 비교했다.
5. `plugins/wsplugin/src/main/resources/content/ws-content-r1/`의 실제 도메인 범위를 확인했다.
6. 현재 `wsplugin` 코드는 `Main.java` 수명주기 골격뿐이고 자동 테스트가 없음을 확인했다.

## 4. P0 — 구현 전 반드시 보완할 기획 · 해소 기록

### GAP-P0-01 — 연구 시스템 책임 문서 부재

**근거**

- `ACT-001`은 `RESEARCH_FOCUS`, 연구 트리와 요구 샘플을 `RESEARCH-001`에 위임한다.
- `DISC`는 정확한 연구 제작식·자원 비용을 `RESEARCH`에 위임한다.
- `FACILITY-LIST-001`에는 연구 단말이 있지만 분석 시간·대기열·비용·해금 충돌 규칙이 없다.

**필요 산출물: `RESEARCH-001 연구·분석·대응책 시스템 상세 기획서`**

- 표본 제출, 비교, 분석, 해금, 도감의 상태 전이
- 개인 발견과 파티 공용 연구의 소유권
- 연구 대기열, 시설 처리량, 취소·환불·재접속
- Day 1~50 연구 노드·요구 샘플·비용·대체 경로
- `ACT`, `DISC`, `CRAFT`, `FACILITY`, `ECONOMY`, Story 기록과의 경계

**완료 증거**: 모든 `RESEARCH` 참조가 실제 ID·비용·상태로 해결되고 시설 없이 가능한 휴대 복구 경로가 존재한다.

### GAP-P0-02 — Day 11~50 사건 실행 데이터 부족

**근거**

- `EVENT-DATA-001`은 Day 1~10만 실제 웨이브·노드·보상 원장을 가진다.
- 로드맵도 Day 11~20 사건 데이터와 Day 11+ 사건 풀 확장을 미완료 조치로 남긴다.
- `CONTENT-DATA-D50-001`의 적 예산은 Day별 총량이지 사건 선택·전조·웨이브·실패·정산 데이터가 아니다.

**필요 산출물**

- `EVENT-DATA-D20-001`: Day 11~20 상태·구조·환경 사건
- `EVENT-DATA-D50-001`: Day 21~50 정화·공성·분산·재건 사건
- 각 사건의 후보 조건, 공간 검사, 웨이브 비용, 목표, 실패 후 상태, 보상, 복구, 성능 상한

**완료 증거**: 보스 Day를 제외한 Day 11~50마다 최소 한 개의 유효 사건 편성이 있고 2·3·4인 예산 합계가 정확히 닫힌다.

### GAP-P0-03 — Day 21~50 도메인별 실제 콘텐츠 부족

**근거**

- 후반 통합 문서에는 적 16종의 요약 수치와 무기군별 모듈 방향은 있으나, Day 1~20 데이터와 같은 스킬 ID·전조·쿨다운·드롭·제작·옵션·노드 단위가 없다.
- `ws-content-r1`에는 Day 21+ 적·자원·장비·사건·보스 데이터가 없다.

**필요 산출물**

- `ENEMY-DATA-D50-001`: Day 21~50 적·정예·공성·소환체
- `RESOURCE-DATA-D50-001`: 전문 자원 노드·처리·대체 경로
- `EQUIP-DATA-D50-001`: EPIC·LEGENDARY·ABYSSAL 실제 템플릿·대가·옵션 풀
- `FACILITY-DATA-D50-001`: Day 11~50 시설 업그레이드·처리량·유지·이전 비용
- Day 30·40 보스와 `FINAL-001`의 실행 데이터

**완료 증거**: Day 21~50 표의 모든 ID가 도메인 데이터에서 해석되고, 상한만 있고 실제 후보가 없는 희귀도·시설·적 역할이 없다.

### GAP-P0-04 — Challenge·CHAOS 라이브 예산 프로필 부재

**근거**

- `BUDGET-001`은 허용 범위와 `AUTHORED/SEEDED/SEASONAL` 출처를 정의하지만 라이브에서 어느 출처와 분포를 쓰는지 정하지 않는다.
- 도메인별 배율의 상관관계, 0% 활동 EXP와 성장 속도, 10배 위협을 Day 시간 안에 분할하는 실제 프로필이 없다.
- `BREAK`가 요구하는 CHAOS 전용 성장률 문서가 없다.

**필요 산출물**

- `BUDGET-PROFILE-001`: 난이도·Day·도메인별 라이브 선택 정책과 공개 범위
- `BALANCE-CHAOS-001`: 0배·상한·혼합 극단 시나리오와 BigNumber 경계
- 자원·EXP·위협을 서로 독립 또는 연동할지에 대한 상관 정책
- 소프트락 검사와 선택 불가 프로필 목록

**완료 증거**: 같은 시드가 같은 프로필을 재현하고 모든 허용 프로필이 Day 50 게이트·필수 자원·동시 개체 상한을 지킨다.

### GAP-P0-05 — 통합 GUI·UX 계약 부재

**근거**

- 장비, 증강, 스킬, 시설, 연구, Story, 난이도 문서가 각각 GUI를 정의하지만 전체 화면 구조·공통 입력·우선순위·복귀 규칙을 소유하는 문서가 없다.
- 사용자 요구의 핵심인 커스텀 GUI/UI가 구현자별 화면 설계로 갈라질 위험이 있다.

**필요 산출물: `UX-001 통합 GUI·HUD·접근성 기획서`**

- 회차 생성부터 완료까지 화면 지도와 진입점
- 전투 중 GUI 차단·큐·복귀, ESC·접속 종료·인벤토리 부족 처리
- 슬롯 예약, 클릭 종류, 확인·취소·되돌리기 공통 규칙
- 보스바·액션바·채팅·타이틀 우선순위와 정보 예산
- 색각·소리·고어 `REDUCED`·키 입력 대체·텍스트 길이 기준

**완료 증거**: 모든 GUI 소비자가 공통 컴포넌트·상태·오류 코드로 연결되고 핵심 판정 정보가 색이나 소리 하나에만 의존하지 않는다.

### GAP-P0-06 — Season 1 Story 런타임 데이터 부재

**근거**

- `STORY-001`의 실제 장면은 작성됐지만 `ws-content-r1`은 `storyRevision: EMPTY`다.
- 장면 ID, 트리거, 대사 큐, 재생 여부, 선택 기록, 엔딩 책, 고어 설정과 이관 스냅샷이 실행 데이터로 분리되지 않았다.

**필요 산출물: `STORY-DATA-S1-001`**

- 프롤로그·Day 1~50+·보스·최종전 장면 JSON
- 도메인 이벤트→장면 트리거 참조표
- 다시 보기·재접속·스킵·실패 연출·`EMPTY` 폴백
- `FULL/REDUCED` 표현 자산 매핑
- `seasonBridgeSnapshot` 스키마와 완료 후 재생성 규칙

**완료 증거**: 모든 Story 장면이 기존 시스템 ID만 참조하고 Story 소비자 실패가 전투·보상·완료 트랜잭션을 되돌리지 않는다.

### GAP-P0-07 — 전체 콘텐츠 리비전 r2 계약 미완성

**근거**

- `DATA-REVISION-001`은 다음 리비전에 budget, Story, season bridge를 추가하라고 요구하지만 Day 21~50 전체 도메인과 통합 스키마·검증 합계를 아직 열거하지 않는다.
- 현재 번들만으로는 Season 1 전체 회차를 시작부터 끝까지 같은 리비전으로 실행할 수 없다.

**필요 산출물: `DATA-REVISION-002 Season 1 전체 콘텐츠 번들 계약`**

- Day 1~50+, 사건, 적, 자원, 장비, 시설, 보스, Story, 예산 정책의 manifest
- 도메인별 스키마, 참조 그래프, 합계 검증, SHA-256, 마이그레이션
- 활성 회차의 `content/story/budget` 리비전 원자 잠금
- r1 활성 회차 보존과 r2 신규 회차 정책

**완료 증거**: 빈 참조·중복 ID·합계 불일치 없이 하나의 후보 레지스트리를 만들 수 있고 활성 r1을 변형하지 않는다.

## 7. Season 2 확장 기획의 위치

Season 2는 현재 `STORY-S2-001`의 L1~L2 기반만 존재한다. 이는 의도된 상태이며 Season 1 구현 착수를 막지 않는다. 다만 Season 2 제작 승인 전에는 다음을 별도 확정해야 한다.

1. `SEASON-001`: 시즌 이관·연대기·마이그레이션
2. `FACTION-001`: 세력 관계·약속·증거 출처·재건 노선
3. `REGION-001`: 타 권역 비동기 상태·경쟁·대체 협상
4. `CORRIDOR-001`: 자원 회랑·신호망·대표권 경제
5. `STORY-DYNAMIC-001`: 행동 사실 기반 장면·문장 조합
6. `S2-CONTENT-MASTER-001`: Day·난이도·CHAOS·최종 목표
7. 다중 파티나 PvP를 실제 도입할 때만 별도 소유권·동기화·괴롭힘 방지 계약

Season 2 세부 기획은 Season 1의 `seasonBridgeSnapshot` 스키마가 확정된 뒤 시작한다. Season 1의 완료 기록을 추정해서 먼저 설계하지 않는다.

## 8. 후속 작업 순서

```text
Phase 0 문서 권위 정리
→ Phase 1 누락 시스템 계약
→ Phase 2 Season 1 실제 콘텐츠 데이터
→ Phase 3 통합 밸런스·UX·QA
→ Phase 4 전체 리비전 r2·구현 인계
→ Phase 5 Paper 구현·플레이테스트
→ Phase 6 Season 2 상세 기획
```

### Phase 0 — 문서 권위 정리

1. `PLAN-AUDIT-001`을 로드맵의 현재 기준으로 등록한다.
2. 존재하지 않는 후속 문서 ID 네 종류를 공식 백로그로 등록한다.
3. 문서 ID·상태·수정일과 오래된 `다음 기획 작업`을 정리한다.

**종료 게이트 G0**: 모든 직접 위임 문서가 실제 문서 또는 로드맵 백로그 한 곳으로 해석된다.

### Phase 1 — 누락 시스템 계약

1. `RESEARCH-001`
2. `UX-001`
3. `PARTY-SYNERGY-001`
4. 리소스 팩 없이 유지되는 공통 정보 표현 계약

**종료 게이트 G1**: 연구·GUI·파티 효과 구현에 새 규칙 판단이 필요하지 않다.

### Phase 2 — Season 1 실제 콘텐츠 데이터

1. Day 11~50 사건 데이터
2. Day 21~50 적·자원·장비·시설 데이터
3. Day 30·40 보스와 Final 데이터
4. Season 1 Story 데이터

**종료 게이트 G2**: Day 1부터 최종 완료까지 모든 Day·보스·보상·Story 참조가 실제 ID로 닫힌다.

### Phase 3 — 통합 밸런스·UX·QA

1. `BUDGET-PROFILE-001`, `BALANCE-CHAOS-001`
2. `BALANCE-WEAPON-001`, `PARTY-SYNERGY-001` 검증 원장
3. `BALANCE-D50-001`
4. 전 난이도·인원·사망·TPS 테스트 매트릭스
5. Story 실패율 10%와 접근성·가독성 계측 계획

**종료 게이트 G3**: 정적 시뮬레이션의 모든 목표 범위가 닫히고 플레이테스트에서 조정할 변수와 순서가 고정된다.

### Phase 4 — 전체 리비전과 구현 인계

1. `DATA-REVISION-002` 스키마·manifest·검증기 계약
2. 콘텐츠 작성·검토·승인·롤백 흐름
3. TECH 모듈별 구현 순서와 테스트 픽스처 매핑

**종료 게이트 G4**: Season 1 전체 후보 레지스트리를 기계 검증할 수 있고 구현 티켓이 문서 ID·테스트 ID를 직접 참조한다.

### Phase 5 — 구현·플레이테스트

구현 순서는 로더·회차 저장 → 전투 코어 → 성장·장비 → 세계·사건 → 보스·Final → Story·운영 순으로 진행한다. 각 단계는 단위 테스트, 재시작·중복·복구 통합 테스트와 함께 인계한다.

### Phase 6 — Season 2 상세 기획

Season 1 스냅샷과 실제 플레이 결과를 입력으로 세력·지역·경쟁·동적 Story·Day 콘텐츠를 작성한다.
