# WildSurvival REWARD 통합 보상 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 ID | `REWARD-001` |
| 상태 | `BASELINE_LOCKED` |
| 상위 기준 | `VISION-001`, `RULES-001`, `GAME-003`, `PROG-001`, `BUDGET-001`, `ECONOMY-001`, `EQUIP-001`, `DEATH-003` |
| 연계 데이터 | `ACT-001`, `RES-001`, `DISC-001`, `ENEMY-001`, `EVENT-LIST-001`, `BOSS-001`, `EQUIP-LIST-001`, `BALANCE-D10-001`, `TECH-001` |
| 적용 범위 | 전투·탐험·지원 기여, EXP 자격, 공용·개인 보상, 고유 장비 투표·귀속, 제작식 해금 |
| 구현 | 바닐라 클라이언트 + Paper 서버 플러그인 + 인벤토리 GUI |
| 기준 리비전 | `reward-schema-v1` |
| 최종 수정일 | 2026-08-24 |

이 문서는 보상 금액 자체가 아니라 보상을 받을 자격, 소유권, 분배, 중복 방지와 실패 복구의 단일 기준이다. 자원별 실제 공급량은 `ECONOMY`, 적별 기본 드롭은 `ENEMY`, 사건별 품목은 `EVENT-DATA`, 보스 고정 수량은 `BOSS`가 소유한다.

## 1. 설계 목표

- 막타와 순수 피해량이 보상 독점 수단이 되지 않게 한다.
- 피해, 브레이크, 상태 제어, 회복·보호, 구조, 방어, 시설 작업, 탐험과 목표 수행을 서로 대체 가능한 기여 경로로 인정한다.
- 파티의 필수 진행 보상과 고유 제작식은 개인 성과 순위 때문에 줄어들지 않게 한다.
- 개인 기여 보상은 경쟁형 분배가 아니라 참여 자격과 선택 폭을 제공하는 방식으로 사용한다.
- 접속 종료, 완전 사망, 인벤토리 부족과 서버 종료로 보상이 사라지거나 중복되지 않게 한다.
- 고유 장비 최초 완제품은 투표, 필요·양보, 수령 이력과 자동 귀속을 거쳐 한 번만 생성한다.
- 모든 판정과 GUI는 리소스 팩 없이도 완전하게 작동해야 한다.

## 2. 권위와 책임 경계

| 항목 | 단일 기준 |
|---|---|
| 진행·활동·보정 EXP의 의미와 사망 후 지급 여부 | `PROG-001` |
| Challenge 야생 활동 EXP 범위와 CHAOS 전 예산 상한 | `BUDGET-001` |
| 자원 계층, 공급 예산과 공용·개인 소유권 | `ECONOMY-001` |
| 장비 인스턴스, 장착 슬롯, 필요·양보와 귀속 | `EQUIP-001` |
| 완전 사망 시 기여 확정, 유품과 부활 | `DEATH-003` |
| 인원별 공용 재료 보상 배율 | `GAME-003` |
| 적 템플릿별 기본 활동 EXP와 드롭 | `ENEMY-001` |
| 보스별 고정 보상과 정산 순서 | 각 `BOSS` 문서 |
| 보상 자격·통합 기여·분배·원장·복구 | `REWARD-001` |

충돌 시 상위 문서의 수치와 생명 상태 규칙을 우선한다. `REWARD-001`은 다른 문서가 정의한 보상량을 임의로 증식시키지 않고, 같은 결과가 누구에게 어떤 방식으로 한 번 지급되는지를 확정한다.

## 3. 핵심 용어

| 용어 | 설명 |
|---|---|
| 보상 원천 | 적, 사건, 공세, 발견, Day 정산 또는 보스처럼 보상을 발생시키는 단위 |
| 보상 인스턴스 | 하나의 원천에서 실제로 생성된 `rewardId` 단위 |
| 유효 참여 | 해당 원천의 참여 규칙을 만족하여 EXP 또는 개인 보상 판정을 받을 수 있는 상태 |
| 기여 사건 | 피해, 구조, 목표 상호작용 등 중복 방지 ID를 가진 한 번의 유효 행동 결과 |
| 기여 축 | 서로 다른 역할을 비교하기 위한 전투·지원·목표 범주 |
| 공용 보상 | 회차 진행 원장 또는 파티 원장으로 직접 들어가는 보상 |
| 개인 기여품 | 유효 참여자 본인에게만 지급되는 비고유 보급 선택권 |
| 고유 보상 | 보스 재건 부품, 최초 고유 장비와 공유 제작식처럼 회차별 횟수가 제한된 보상 |
| 지급 대기함 | 인벤토리 부족·접속 종료·사망 상태에서 결과를 보존하는 가상 저장소 |

## 4. 보상 소유권 분류

| 분류 | 대표 보상 | 소유·전달 규칙 |
|---|---|---|
| `RUN_PROGRESSION` | 재건 부품, 보스 핵, 필수 진행 플래그 | 회차 원장, 버리기·거래·호퍼 이동 불가 |
| `PARTY_RESOURCE` | 공세 재료, 적 보상 재료, 시설 대응 부품 | 파티 원장 또는 등록 시설 보관함 |
| `PERSONAL_EXP` | 진행 EXP, 활동 EXP | 플레이어 데이터에 직접 반영, 아이템화 불가 |
| `PERSONAL_SUPPLY` | 탄약·수리·정화 등 동가치 보급 선택 | 개인 지급 대기함, 선택 후 인벤토리 또는 유품 정책 적용 |
| `EQUIPMENT_UNBOUND` | 일반 제작·드롭 장비 | 회차 귀속, 허용 범위 안에서 전달 가능 |
| `EQUIPMENT_BOUND` | 보스 최초 완제품 | 지정 플레이어 자동 귀속, 일반 거래·공용 이동 불가 |
| `PARTY_UNLOCK` | 제작식, 발견·시설 기능 | 회차 공유 플래그, 멤버 사망과 무관하게 유지 |

- 자연 채집한 일반 원물은 `RES`와 `ACT`에 따라 최초 획득자의 인벤토리로 들어갈 수 있다.
- `ENEMY` 표에서 공용 재료로 지정한 전투 전리품은 바닥에 드롭하지 않고 파티 원장으로 직접 지급한다.
- 핵심 진행·보스 고유 보상은 월드 아이템 엔티티로 생성하지 않는다.
- 미등록 플레이어는 어떤 분류의 보상도 생성·수령·투표할 수 없다.

## 6. 기여 기록 수명주기

```text
원천 활성화
→ 참여 스냅샷 생성
→ 기여 사건 검증·집계
→ 완료·이탈·사망 시 개인 스냅샷 고정
→ 보상 자격과 기여 등급 계산
→ 공용·개인·고유 보상 단계별 지급
→ 원장 COMMITTED
```

### 6.1 참여 스냅샷

원천 시작 시 다음 값을 고정한다.

- `runId`, `encounterId`, `rewardId`, Day와 콘텐츠 리비전
- 등록 멤버, 생명 상태, 접속 상태와 전투 스케일 인원
- 난이도, 규칙 모드, `budgetPolicyRevision`, Day·도메인별 잠긴 예산과 특수 사건 보정
- 적 유효 HP·보호막 합, 유효 브레이크 예산과 목표 진행량
- 플레이어별 최대 HP, 장착 무기군과 역할 태그
- 개인 기여품 풀과 고유 장비 후보 풀 리비전

전투 중 재접속으로 스케일 인원이 증가하면 적 수치 스냅샷과 동일하게 보상 스케일 인원도 증가시킨다. 접속 종료나 사망으로 현재 원천의 공용 보상 배율을 낮추지 않는다.

### 6.2 기여 사건 공통 조건

기여 사건은 다음을 모두 만족해야 한다.

1. 원본 소유자가 같은 회차의 등록 플레이어다.
2. 대상이나 목표가 현재 보상 원천에 소속되어 있다.
3. 결과가 서버 권위 파이프라인에서 실제로 적용되었다.
4. `ALLY`, `TRAINING_TARGET`, `NO_REWARD`, 운영자 시험 대상이 아니다.
5. 같은 `executionId + resultIndex + contributionType`이 아직 처리되지 않았다.
6. 원천별 거리·시간·생명 상태 조건을 만족한다.

## 7. 기여 축과 원시값

| 기여 축 | 코드 | 인정 원시값 | 인정하지 않는 값 |
|---|---|---|---|
| 피해 | `DAMAGE` | 적 HP·보호막에 실제 적용된 피해 | 과잉 피해, 아군 피해, 무효·회복 결과 |
| 브레이크 | `BREAK` | `BREAK` 공식의 유효 브레이크 기여 | 아군 브레이크, 막타 보너스, 이미 찬 게이지 |
| 제어·상태 | `CONTROL` | 실제 행동 방해 시간, 유효 약화·취약 활용량, 패턴 중단 | 면역 대상 적용, 같은 상태 무의미 갱신 |
| 회복·보호 | `SUPPORT` | 실제 회복, 보호막 흡수, 유효 해제, 타인 AP 제공 | 과잉 회복, 자기 회복 반복, 사용되지 않은 보호막 |
| 방어·위협 | `DEFENSE` | 적 공격을 막아낸 피해, 목표 대신 받은 피해, 유효 도발 유지 | 위험 없는 자해, 피격 없는 F 반복 입력 |
| 구조·부활 | `RESCUE` | 실제 구조 진행도, 구조 완료, 희귀 부활 실행 | 실패 후 되돌아간 진행도, 자기 부활 대상 이득 |
| 목표·시설 | `OBJECTIVE` | 목표 채널링, 유효 수리·보강, 운반·호위, 기믹 입력 | 설치·파괴 반복, 손상 없는 시설 수리 |
| 탐험·물류 | `EXPLORATION` | 최초 발견, 고유 표본 조사, 공용 주문·분석 완료 | 버리기·재획득, 기본 제작 반복, 이미 본 증거 |

### 7.1 피해

```text
유효 피해 = 실제 HP 피해 + 실제 보호막 피해
```

- 지속 피해는 상태를 최초 적용한 원본 소유자에게 귀속한다.
- 소환물·투사체·지속 영역은 실행 데이터의 원본 소유자에게 귀속한다.
- 대상의 남은 HP와 보호막을 넘는 피해는 기록하지 않는다.
- 적을 회복한 결과는 전투 상태를 유지할 수 있지만 기여로 기록하지 않는다.

### 7.2 브레이크

```text
브레이크 원시 기여 =
유효 브레이크 피해
× 대상 브레이크 중요도
× 0.40
```

일반 적 `0.25`, 정예 `0.60`, 보스 `1.00`의 중요도는 `BREAK`를 그대로 사용한다. 고정 기믹 브레이크는 피해량이 아니라 해당 기믹의 `OBJECTIVE` 또는 전용 `BREAK` 진행률로 한 번만 기록한다.

### 7.3 제어·상태

- 제어 환산 시간은 `실제 적용 시간 × 템플릿 효력 계수`로 계산한다. 강한 행동 불능은 `1.00`, 약한 둔화·약화는 기본 `0.25`, 보스 변환 효과는 보스 데이터 값을 사용한다.
- 강한 CC는 대상이 실제로 행동하지 못한 서버 틱만 인정한다.
- 둔화·약화·취약·방어력 감소는 효과가 없었으면 기여를 만들지 않는다.
- 취약·방어력 감소로 증가한 아군의 실제 피해는 상태 기여자에게 보조 기여로 기록하되, 증가분 전체를 피해 기여로 복제하지 않는다.
- 같은 계열 상태가 중첩되면 각 인스턴스가 만든 추가 효력과 추가 지속시간만 분리한다.
- 보스 면역 변환이나 패턴 중단으로 바뀐 상태는 보스 템플릿의 변환값을 사용한다.

### 7.4 회복·보호·방어

- 회복은 대상의 실제 HP 증가량만 인정한다.
- 보호막은 생성 시점이 아니라 실제 적 피해를 흡수한 시점에 보호막 원본 소유자에게 귀속한다.
- 해제는 실제 해로운 효과의 남은 강도·시간을 제거한 경우에만 인정한다.
- 타인 AP 제공은 실제 최대 AP 아래에서 증가한 양만 인정하며, 같은 발동의 AP 순환은 한 번만 기록한다.
- Day 1~10 기본 환산은 `타인 AP 1 = 참여자 평균 최대 HP의 0.25%`, 유효 약한 해제 1회는 `10%`로 둔다. 강한 해제·특수 자원은 스킬 데이터가 별도 환산값을 가진다.
- 자기 회복·자기 보호·정확 회피는 생존 행동으로 기록할 수 있지만 `SUPPORT` 단독 보상 자격을 만들지 않는다.
- `DEFENSE` 단독 자격은 아군·시설·기믹을 보호하거나 적의 명시적 공격 대상이었던 구간에서만 만들 수 있다.
- 가드·패링·정확 회피의 방어량은 적 공격 실행기가 계산한 `회피·방어 판정 직전 예상 최종 피해`를 상한으로 사용한다.

### 7.5 구조·목표·탐험

- 구조는 `DEATH-002`가 기록한 구조자별 실제 진행량을 사용한다.
- 두 구조자가 참여하면 각자의 실제 진행량만 기록하며 구조 완료 보너스를 중복 생성하지 않는다.
- 시설 수리는 현재 원천의 적 공격이나 환경 위험으로 잃은 내구도만 인정한다.
- 호위는 보호 대상이 유효 경로를 실제로 진행한 시간 또는 거리로 계산한다.
- 공용 주문·분석은 결과가 정상 완료된 작업에서만 인정하며 재료를 회수한 취소 작업은 제외한다.
- 최초 발견과 획득은 회차·출처 원장의 고유 증거 ID를 사용한다.

## 8. 기여 정규화

기여 점수는 역할 순위를 만드는 값이 아니라 개인 기여품의 자격과 선택 폭을 판정하는 값이다. 공용 재료, 진행 EXP, 고유 장비 후보 투표에는 점수를 배율로 곱하지 않는다.

### 8.1 기준량

| 축 | 원천별 기본 기준량 |
|---|---|
| `DAMAGE` | 원천 적 유효 HP·보호막 합의 15% |
| `BREAK` | 중요도와 0.40 가중치를 적용한 원천 유효 브레이크 기여 예산의 15% |
| `CONTROL` | 유효 제어 8초 또는 중요 패턴 중단 1회 |
| `SUPPORT` | 참여자 평균 최대 HP의 35%에 해당하는 유효 회복·보호 |
| `DEFENSE` | 참여자 평균 최대 HP의 30%에 해당하는 유효 방어 |
| `RESCUE` | 구조 진행도 50% 또는 유효 부활 1회 |
| `OBJECTIVE` | 전체 목표 진행량의 20% 또는 중요 기믹 1회 |
| `EXPLORATION` | 고유 증거 1개 또는 사건 조사·물류 진행량 20% |

- 해당 축이 존재하지 않는 원천은 계산에서 제외한다.
- 1인 잔존 상황에서는 비율 기준을 유지하고 필수 협동 행동의 요구 인원만 하위 시스템 규칙대로 낮춘다.
- 콘텐츠 템플릿은 목표 성격에 맞게 기준량을 바꿀 수 있지만 변경 이유와 리비전을 저장해야 한다.

### 8.2 계산식

```text
축 달성률 = min(1.0, 개인 유효 원시값 / 축 기준량)

기여 점수 = floor(
  80 × 가장 높은 축 달성률
  + 15 × 두 번째 축 달성률
  + 5 × 세 번째 축 달성률
)
```

한 역할에 집중해도 최대 80점에 도달할 수 있다. 여러 역할을 동시에 수행하면 최대 20점의 폭넓은 기여가 추가되지만, 순수 공격·지원·구조 빌드가 기본 개인 보상에서 제외되지는 않는다.

### 8.3 등급

| 등급 | 조건 | 효과 |
|---|---|---|
| `INELIGIBLE` | 원천별 유효 참여 조건 미충족 | 개인 EXP·기여품 없음 |
| `ELIGIBLE` | 유효 참여 충족 | 해당 원천의 기본 EXP와 기본 보상 자격 |
| `CONTRIBUTOR` | 개인 기여품 원천에서 40점 이상 | 동가치 후보 2개 중 1개 선택 |
| `PIVOTAL` | 80점 이상 | 동가치 후보 3개 중 1개 선택 |

- `CONTRIBUTOR`와 `PIVOTAL`은 인원 제한이 없다. 한 전투에서 모두가 같은 등급을 받을 수 있다.
- 등급은 보상의 양이나 희귀도를 직접 증가시키지 않고 선택 폭만 넓힌다.
- 고유 장비 수령 우선순위에 기여 점수·피해량·막타를 사용하지 않는다.

## 9. 원천별 유효 참여 판정

| 원천 | 시간·거리 | 최소 유효 행동 | 특례 |
|---|---|---|---|
| 야생 일반 적 | 최근 15초, 32블록 | 피해·브레이크·상태·피격·유효 지원 중 1개 | `PROG-001`과 동일, 점수 등급 미사용 |
| 정예·선택 목표 | 최근 15초, 48블록 | 전투 또는 목표 기여 1개 | 템플릿이 전장 반경을 명시하면 그 값을 사용 |
| 탐험·채집 사건 | 사건 활성 구역·완료 전 | 조사·채집·운반·호위·위험 대응 | 단순 구역 체류는 제외 |
| 야간 공세 | 공세 시작~완료 | 전투·지원·시설·목표 축 중 하나의 달성률 10% 이상 | 마지막 15초 조건을 요구하지 않음 |
| 보스 | 보스 시작~사망 | 한 축 달성률 10% 이상 또는 중요 기믹 1회 | 사망 전 스냅샷과 이탈 전 기록 보존 |
| Day 진행 EXP | Day 완료 시 등록·생존·빈사 | 개인 행동 조건 없음 | 생존 접속 종료자 포함 |

- 피해 한 번만 주고 떠나는 태그 행위는 야생 적 활동 EXP의 기존 최소 참여는 충족할 수 있지만 공세·보스 개인 기여품 자격은 만들지 않는다.
- 60초 이상 무활동한 플레이어는 새 활동·목표 기여를 누적하지 않는다. 실제로 발생한 피격·구조 대상 상태만으로 AFK 보상을 생성하지 않는다.
- 원천 완료 직전 접속을 종료해도 이미 고정된 기여와 개인 기여품 권리는 유지한다.

## 10. EXP 지급 계약

### 10.1 진행 EXP

- 등록된 생존자·빈사자와 생존 상태의 접속 종료자에게 같은 기본값을 지급한다.
- 개인 기여 점수, 인원수, EXP 스탯과 개인 보너스를 적용하지 않는다.
- 완전 사망 이후 발생한 진행 EXP는 지급하지 않는다.
- 같은 목표의 `rewardId + playerUuid + PROGRESSION_EXP`를 한 번만 처리한다.

### 10.2 활동 EXP

- 야생 적·정예·선택 활동의 유효 참여자마다 기본 활동 EXP 전체를 지급하며 참여자 수로 나누지 않는다.
- EXP 스탯·장비·증강과 반복 처치 감쇠는 `PROG-001` 공식을 적용한다.
- 공세 적 개별 처치, 보스 피해·반복 패턴과 보스 하수인은 활동 EXP를 지급하지 않는다.
- 접속 종료 중이거나 보상 발생 전에 완전 사망한 플레이어에게는 활동 EXP를 지급하지 않는다.
- 기여 점수 등급으로 EXP를 증폭하지 않는다.

### 10.3 완전 사망과 비EXP 기여품의 분리

완전 사망 처리 시 현재 전투의 기여 스냅샷을 먼저 고정한다. 이후 원천이 완료되면 다음처럼 처리한다.

| 결과 | 사망 중 지급 |
|---|---|
| 진행 EXP | 지급하지 않음 |
| 활동 EXP | 지급하지 않음 |
| 사망 전 확정한 개인 기여품 | 개인 지급 대기함에 보존 |
| 공용 재료·진행 부품 | 파티 원장에 정상 지급 |
| 고유 장비 후보 투표·필요 선택 | 접속 중인 완전 사망자 참여 가능 |
| 귀속 장비 실물 | 사망자 지급 대기함에 보존, 부활 전 장착 불가 |

이 분리는 `PROG`의 사망 후 EXP 금지와 `DEATH`·`GAME`의 사망 전 기여 보상 권리 보존을 동시에 만족한다.

## 11. 공용 보상 스케일링

### 11.1 적용 대상

이 절의 인원·난이도 배율은 일반 공용 재료에만 적용한다. EXP 예산은 이 배율을 사용하지 않고 `BUDGET-001`을 따른다.

적용하지 않는 항목:

- 진행·활동·보정 EXP
- 재건 부품과 최종 진행 플래그
- 보스 핵과 분해 불가 고유 재료
- 최초 고유 장비 수량
- 제작식·발견·시설 해금
- 개인 기여품의 가치와 후보 수

위 제외는 “EXP와 개인 기여품이 어떤 예산 변동도 받지 않는다”는 뜻이 아니다. Challenge 야생 활동 EXP와 CHAOS 예산은 `BUDGET-001`의 독립 도메인 배율로 계산하며 공용 재료 배율과 중복 곱하지 않는다.

### 11.2 인원 배율

| 전투 스케일 인원 | 공용 재료 배율 |
|---:|---:|
| 1인 | 0.75 |
| 2인 | 1.00 |
| 3인 | 1.25 |
| 4인 | 1.50 |

### 11.3 난이도 배율

| 난이도 | 일반 공용 재료 배율 |
|---|---:|
| Story | 1.00 |
| Easy | 1.00 |
| Normal | 1.05 |
| Hard | 1.10 |
| ??? | 해당 회차에 고정된 비공개 데이터 값 |

`???`의 실제 값은 시작 전 정보 제한 정책에 따라 UI에 표시하지 않지만 서버 데이터에는 리비전과 함께 고정한다. Challenge는 콘텐츠 분류이므로 별도 배율을 곱하지 않는다.

### 11.4 계산과 반올림

```text
일반 공용 재료 기대량 =
원천 기본량
× 인원 배율
× 난이도 배율
× 명시된 사건 보정
```

- 같은 축의 배율을 하위 시스템에서 다시 곱하지 않는다.
- 소수점은 자원 그룹별 `rewardRemainder`에 누적하고, 1 이상이 될 때 정수 1개로 전환한다.
- 나머지 값은 `runId + rewardProfileId + resourceGroup`에 저장하여 재시작으로 초기화하지 않는다.
- 보스 문서가 2·3·4인 최종 수량을 직접 명시하면 인원 배율 대신 그 표를 사용한다. 일반 재료의 난이도 배율만 추가 적용할 수 있다.
- 난수 드롭은 먼저 결정론적 후보를 확정하고 이후 배율·나머지를 적용한다.

### 11.5 EXP·CHAOS 예산 경계

- Challenge Normal·Hard·??? STANDARD의 야생 활동 EXP 예산은 기준 대비 각각 `50~150%`, `0~200%`, `0~300%`다.
- CHAOS는 진행 EXP, 야생 활동 EXP, 일반 자원, 개인 보급 가치, 위협·변이·환경·시설·보스 패턴 예산의 상한을 기준 `1000%`까지 허용한다.
- 재건 부품, 발견·보스 플래그, 고유 장비 최초 수량, 증강 횟수, Day 잠금, 멱등키와 안전 상한은 배율 대상이 아니다.
- 보상 정산은 잠긴 `budgetProfileId`와 도메인 잔여 예산을 읽기만 하며 지급 순간 배율을 재추첨하지 않는다.

## 12. 개인 기여품

개인 기여품은 파티 공용 자산을 경쟁적으로 나누지 않는다. 원천에 미리 편성된 개인 보급 예산에서 동가치 후보 하나를 선택한다.

| 원천 | 기본 자격 | 지급 | Day 상한 |
|---|---|---|---:|
| 야생 일반 적 | 해당 없음 | 없음 | 0 |
| 정예 | 유효 참여 + 기여 점수 20 이상 | 개인 회수품 1회 | 플레이어당 2회 |
| 탐험·위험 사건 | 유효 참여 + 기여 점수 20 이상 | 사건 보급 1회 | 플레이어당 2회 |
| 야간 공세 | 유효 참여 + 기여 점수 20 이상 + 공세 완료 | 공세 보급 1회 | 플레이어당 1회 |
| 보스 | 유효 참여 + 기여 점수 20 이상 | 상급 보급 1회 | 보스별 1회 |

### 12.1 Day 1~10 동가치 후보

| 보급군 | 후보 예시 | 1회 가치 |
|---|---|---|
| 유지 | 야전 수리 키트 | 1개 |
| 응급 | 붕대 | 2개 |
| 정화 | 정화 앰풀 | 1개 |
| 탄약 | 일반 화살 16발 또는 관통 볼트 4발 | 무기 호환 묶음 1개 |
| 가공 | 현재 해금된 BASIC 가공 재료 | 원장 3단위 이하 |

- 후보는 현재 해금된 제작식과 플레이어 장비 호환성을 만족해야 한다.
- Day 1~10의 보급 1회는 `SUPPLY_VALUE 1`이며 일반 재료 약 3단위의 원장 가치를 기준으로 한다. 정화 촉매처럼 희소도가 다른 재료는 `EVENT-DATA-001`의 환산값을 사용한다.
- 서로 다른 후보는 `ECONOMY` 원장 가치가 같아야 한다.
- 개인 기여품 자격을 충족한 20~39점은 서버가 현재 부족도가 높은 유효 후보 1개를 제시한다.
- 40~79점은 서로 다른 후보 2개, 80점 이상은 3개를 제시한다.
- 선택하지 않으면 30초 뒤 첫 번째 후보를 자동 확정한다. 후보와 순서는 보상 시드로 고정한다.
- 개인 기여품은 희귀 장비, 재건 자원, 증강 재료와 미해금 제작 결과를 포함할 수 없다.
- 개인 기여품은 기존 Day 자원 유입에 더하는 무상 보너스가 아니다. `EVENT-DATA-001`은 같은 원천의 공용 원재료 보상에서 동가치 예산을 개인 보급으로 배정하여 `BALANCE-D10-001`의 Day별 총 유입을 유지한다.

## 14. 보스 고유 장비 후보 생성

### 14.1 후보 검증

1. 보스 사망 시점의 장비 후보 풀 리비전을 고정한다.
2. 미해금·Day 초과·회차 희귀도 상한 위반 템플릿을 제거한다.
3. 등록 플레이어 누구에게도 호환되지 않는 템플릿을 제거한다.
4. 현재 권투 사용자가 없으면 권투 전용 후보를 제거한다.
5. 후보 3개 중 최소 2개가 서로 다른 플레이어 또는 역할에 즉시 유효하도록 편향한다.
6. 후보가 3개 미만이면 같은 희귀도·역할의 안전 대체 풀을 사용하고, 그래도 부족하면 정산을 자동 확정하지 않는다.

후보 추첨 시드는 다음을 사용한다.

```text
hash(runSeed, "UNIQUE_EQUIPMENT", bossMilestone, rewardRevision)
```

후보 ID, 순서, 시드 키와 추첨 리비전을 투표 GUI를 열기 전에 저장한다.

### 14.2 템플릿 투표

| 항목 | 규칙 |
|---|---|
| 투표자 | 회차 등록 플레이어 전체, 접속 중인 완전 사망자 포함 |
| 투표 시간 | 접속 플레이어가 있는 동안 30초 |
| 선택 | 후보 3개 중 1개 또는 기권 |
| 접속 종료 | 이미 낸 표 유지, 새 표는 없음 |
| 최다표 | 해당 템플릿 선택 |
| 동률 | 동률 후보만 고유 보상 시드로 결정 |
| 전원 기권·무투표 | 유효 후보 전체에서 고유 보상 시드로 결정 |

- 기여 점수, 생존 여부와 이전 고유 장비 수령 횟수는 템플릿 투표의 표 가중치를 바꾸지 않는다.
- 서버에 등록 플레이어가 한 명도 접속하지 않으면 투표 시간을 정지한다.
- 투표 확정 후 재접속·재시작으로 후보나 결과를 다시 뽑지 않는다.

## 15. 필요·양보와 최초 완제품 분배

템플릿 선택 뒤 EPIC iLv 10 최초 완제품 1개를 생성하고 별도 30초 동안 필요·양보를 받는다.

### 15.1 선택 정책

| 선택 | 처리 |
|---|---|
| `NEED` | 호환 검증과 자동 귀속에 동의하고 경쟁 참여 |
| `PASS` | 최초 완제품 경쟁에서 제외 |
| 시간 초과 | 저장된 자동 필요 설정이 없으면 `PASS` |

- 플레이어는 안전 상태의 장비 GUI에서 템플릿 태그별 `NEED_IF_COMPATIBLE`을 미리 설정할 수 있으며 기본값은 `PASS`다.
- 접속 중 선택은 저장된 자동 설정보다 우선한다.
- 완전 사망자는 저장된 장착 무기군·장비 슬롯과 부활 가능 상태를 기준으로 `NEED`할 수 있다.
- 무기군 전용 장비는 현재 또는 보스 시작 스냅샷에서 사용한 무기군과 일치해야 한다.
- 범용 방어구·장신구·보조무기는 슬롯 충돌과 고유 배타 조건만 검증한다.

### 15.2 수령자 결정

1. 유효 `NEED` 플레이어를 모은다.
2. 한 명이면 해당 플레이어를 선택한다.
3. 복수면 회차 내 `최초 고유 완제품 수령 횟수`가 적은 플레이어를 우선한다.
4. 여전히 동률이면 `hash(runSeed, rewardId, "RECIPIENT")`로 결정한다.
5. 선택 즉시 `BOUND_PLAYER`와 `boundPlayerUuid`를 기록한다.
6. 전원이 `PASS`이면 미귀속 상태로 파티 지급 대기함에 저장한다.

- 제작한 복제품, 일반 장비와 개인 기여품은 최초 고유 완제품 수령 횟수를 증가시키지 않는다.
- 기여 점수와 피해 순위는 수령자 결정에 사용하지 않는다.
- 파티 지급 대기함의 미귀속 최초 완제품은 생존자가 재분배를 열 수 있으며 같은 필요·양보와 수령 횟수 규칙을 다시 사용한다.
- 사망자나 접속 종료자가 수령자로 확정되면 해당 플레이어의 지급 대기함에 귀속 상태로 보존한다.

### 15.3 귀속 제한

- 귀속 장비는 일반 거래, 바닥 버리기, 공용 보관함, 호퍼·디스펜서와 다른 플레이어 장착을 차단한다.
- 장착은 장비 GUI를 통해서만 가능하며 주무기 `0`, 보조무기 `-106` 동기화 계약을 따른다.
- 사망과 유품 회수로 귀속이 풀리지 않는다.
- 최초 고유 완제품은 분해할 수 없다.
- 귀속 해제는 기본 제공하지 않으며 별도 희귀 기능이 생기면 새 트랜잭션과 명시적 확인을 요구한다.

## 16. 제작식·발견 해금

- 선택된 고유 장비 템플릿의 제작식은 최초 완제품 수령자와 무관하게 회차 전체에 해금한다.
- 전원 양보, 수령자 완전 사망, 인벤토리 부족으로도 제작식 해금을 취소하지 않는다.
- 선택되지 않은 두 후보의 제작식은 해금하지 않는다.
- 고유 장비의 진행 필수 기능은 개인 귀속에만 의존하지 않으며 공유 제작식·발견·시설 기능으로 대체 가능해야 한다.
- 발견 증거와 제작식 해금은 `rewardId + unlockId`로 멱등 처리하고 소급 검사 대상에 포함한다.
- 미해금 고등급 장비가 다른 경로로 들어오면 완제품 사용을 막고 손상 장비·설계 단서·분해 재료 정책을 적용한다.

## 19. 보상 트랜잭션

### 19.1 상태

```text
CREATED
→ CONTRIBUTION_LOCKED
→ PUBLIC_GRANTED
→ PERSONAL_GRANTED
→ UNIQUE_CANDIDATES_LOCKED
→ UNIQUE_TEMPLATE_SELECTED
→ UNIQUE_ITEM_CREATED
→ UNIQUE_RECIPIENT_SELECTED
→ UNIQUE_ITEM_DELIVERED
→ UNLOCKS_GRANTED
→ FOLLOWUP_READY
→ COMMITTED
```

해당 단계가 없는 원천은 건너뛴다. `CANCELLED`는 원천 자체가 보상 확정 전에 안전 취소된 경우에만 사용한다. 보스 사망·완전 사망·고유 보상 확정처럼 되돌릴 수 없는 결과는 일반 체크포인트 롤백으로 취소하지 않는다.

### 19.2 중복 방지 키

| 결과 | 키 |
|---|---|
| 공용 자원 | `rewardId + resourceId + PARTY` |
| 진행·활동 EXP | `rewardId + playerUuid + expType` |
| 개인 기여품 | `rewardId + playerUuid + supplyPoolId` |
| 후보 목록 | `rewardId + UNIQUE_CANDIDATES + drawRevision` |
| 템플릿 선택 | `rewardId + UNIQUE_TEMPLATE` |
| 최초 완제품 | `rewardId + FIRST_UNIQUE_ITEM` |
| 귀속 | `itemInstanceId + BIND + playerUuid` |
| 제작식·발견 해금 | `rewardId + unlockId` |

### 19.3 실패 복구

- `CREATED` 이전 실패는 아무 보상도 지급하지 않고 원천별 재시도 정책을 따른다.
- 기여 스냅샷이 손상되었지만 원천 미완료면 마지막 전투 스냅샷으로 재개한다.
- 공용 지급 뒤 개인 지급 중 종료되면 공용 지급을 반복하지 않고 미완료 플레이어만 처리한다.
- 최초 완제품이 생성됐으나 수령자가 미확정이면 같은 인스턴스를 지급 대기함에 잠그고 필요·양보를 재개한다.
- 귀속 확정 뒤 월드 아이템이 사라졌으면 원장과 서명을 확인해 같은 인스턴스를 대기함에 복원한다. 새 UUID를 만들지 않는다.
- 스냅샷과 원장이 서로 달라 어느 결과가 권위 있는지 판정할 수 없으면 `ADMIN_RECOVERY_REQUIRED`로 동결한다.
- 운영 복구는 원래 `rewardId`, 이전·이후 값, 사유와 운영자 UUID를 감사 로그에 남긴다. 새 후보 추첨은 허용하지 않는다.

## 21. GUI와 피드백

### 21.1 활동·전투 HUD

- 현재 참여 원천, 유효 참여 여부와 주요 기여 축 최대 3개를 표시한다.
- 정확한 실시간 순위는 표시하지 않는다. 경쟁 유도와 불필요한 틱별 정렬을 피한다.
- 자격 미충족 시 `거리 이탈`, `유효 행동 없음`, `사망 후 발생`, `반복 감쇠`처럼 원인을 짧게 표시한다.
- 색상만으로 등급을 구분하지 않고 아이콘, 문자와 사운드를 함께 사용한다.

### 21.2 정산 GUI

정산 GUI는 다음 순서로 연다.

1. 공용 진행·재료 결과
2. 개인 EXP와 기여 축 요약
3. 개인 기여품 선택
4. 고유 장비 후보 투표
5. 필요·양보와 귀속 확인
6. 제작식·발견 해금
7. 보스인 경우 파티 증강 선택

- 완료된 앞 단계를 뒤 GUI에서 다시 실행할 수 없다.
- 개인 기여도는 절대량과 행동 범주로 설명하고 파티원 순위를 기본 표시하지 않는다.
- 완전 사망자에게는 지급 대기함 보존과 부활 전 사용 불가를 명확히 안내한다.
- 리소스 팩이 없어도 바닐라 아이템 아이콘, 로어, 페이지와 채팅 컴포넌트로 모든 선택이 가능해야 한다.

## 22. 성능과 구현 안전선

- 피해 틱마다 DB에 쓰지 않고 메모리 누적 후 1초 주기·중요 상태 전환·사망·정산 때 저장한다.
- `executionId` 단위로 다단 히트·상태·흡혈·기여 중복을 제거한다.
- 활성 원천당 플레이어 4명 × 기여 축 8개의 고정 크기 누적기를 사용한다.
- HUD 갱신은 기본 10틱보다 빠르게 하지 않는다.
- 상세 기여 사건의 메모리 보관은 원천당 최근 2,000건을 상한으로 두고, 초과 시 검증된 축별 합계로 압축한다.
- 비동기 DB 저장은 가능하지만 Bukkit 개체·인벤토리·GUI 변경은 메인 스레드에서 수행한다.
- 낮은 TPS에서도 보상량·후보·투표 결과를 줄이거나 다시 뽑지 않는다. 표시 갱신 빈도만 낮춘다.

## 23. 텔레메트리

| 지표 | 목적 |
|---|---|
| 원천별 유효 참여율·무자격 사유 | 거리·시간·최소 행동 기준 과도 여부 |
| 무기군·역할별 최고 기여 축과 개인 기여품 자격률 | 특정 역할 불이익 탐지 |
| 피해 단독·지원 단독·구조 단독 자격률 | 대체 경로 성립 검증 |
| 개인 기여품 후보 선택률과 Day별 가치 | 자원 원장 영향 검증 |
| 고유 장비 후보별 투표율·전원 양보율 | 후보 유효성·귀속 거부 원인 확인 |
| 플레이어별 최초 고유 완제품 수령 횟수 | 장기 분배 편향 확인 |
| 사망·접속 종료 상태의 지급 대기 건수 | 복구와 권리 보존 검증 |
| `PREPARED`·동결·운영 복구 건수 | 트랜잭션 신뢰성 확인 |
| reward remainder 누적·전환량 | 소수 배율의 장기 손실 여부 |

역할별 개인 기여품 자격률이 같은 Day·난이도에서 15%p 이상 차이 나면 보상량보다 해당 축 기준량과 유효 행동 판정을 먼저 조정한다.

## 24. 테스트 항목

### 기여

- 막타 없이 피해·브레이크·지원·구조·시설 기여만 한 플레이어의 유효 참여
- 순수 피해, 순수 브레이크, 순수 지원, 순수 목표 빌드가 각각 80점에 도달 가능
- 과잉 피해·과잉 회복·미사용 보호막·면역 상태 기여 0
- 아군 공격, 훈련 대상, 소환체와 공세 적 개별 보상 차단
- 60초 AFK, 거리 이탈, 마지막 순간 태그의 자격 분리
- 구조자 2명의 실제 진행량 분리와 완료 보너스 중복 방지

### EXP·소유권

- 야생 적 유효 참여자마다 활동 EXP 전체 지급과 반복 감쇠
- 공세·보스 개별 적 활동 EXP 차단
- 생존 접속 종료자의 진행 EXP와 활동 EXP 차이
- 전투 중 완전 사망자의 EXP 미지급, 사망 전 개인 기여품 보존
- 자연 채집 개인 원물과 적 공용 전리품의 소유권 분리
- 1·2·3·4인과 Story·Easy·Normal·Hard 공용 재료 배율·나머지 누적

### 고유 장비

- Day 10 후보 3개, 최소 2개 역할 유효성과 권투 후보 제외
- 후보 동률·무투표 결정론과 재시작 후 결과 유지
- 필요자 1명·복수·전원 양보·자동 필요·시간 초과
- 수령 횟수 우선과 최종 시드 동률 처리
- 완전 사망자·접속 종료자 당첨 시 지급 대기함과 귀속 보존
- 최초 완제품 1개, 선택 제작식 1개만 해금
- 거래·버리기·호퍼·공용 보관함·타인 장착·분해 차단

### 복구

- 공용 지급 직후 종료, 개인 지급 중 종료, 투표 중 종료와 귀속 직후 종료
- 같은 `rewardId` 재요청 시 기존 결과 반환
- 인벤토리 가득 참, 유품 미회수와 장비 슬롯 동기화 실패
- 원장·PDC 불일치 시 자동 재생성 금지와 `ADMIN_RECOVERY_REQUIRED`
- Story 데이터가 없어도 모든 보상과 GUI 정상 동작

## 25. 완료 기준

- 피해·브레이크·상태·지원·방어·구조·목표·탐험이 구현 가능한 원시값과 중복 방지 규칙을 가진다.
- 한 가지 역할에 집중한 플레이어도 개인 기여품 최고 선택 폭에 도달할 수 있다.
- 기여 점수가 공용 진행 보상, EXP 양과 고유 장비 수령 우선순위를 왜곡하지 않는다.
- 진행 EXP, 활동 EXP, 개인 기여품과 고유 보상의 사망·접속 종료 규칙이 서로 구분된다.
- Day 1~10 EXP 총량과 적·보스 보상 프로필이 기존 원장과 일치한다.
- 고유 장비 후보 3개, 필요·양보, 수령 이력, 자동 귀속과 제작식 공유 해금이 결정적이다.
- 보상과 해금은 바닥 드롭이나 고정 기지 상자 없이 가상 원장·지급 대기함으로 처리할 수 있다.
- 서버 종료·재접속·인벤토리 부족으로 중복 지급·유실·재추첨이 발생하지 않는다.
- 바닐라 클라이언트와 플러그인 GUI만으로 모든 정보와 선택을 제공할 수 있다.
