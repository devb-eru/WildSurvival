# WildSurvival EQUIP 장비 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 카테고리 | 장비 슬롯, 인스턴스, 희귀도, 장착, 고유 장비 보상 |
| 연계 문서 | CORE, COMBAT, ECONOMY, REWARD, RULES |
| 기본 UI | 리소스팩 없는 커스텀 인벤토리 GUI |
| 최종 수정일 | 2026-08-16 |

## 1. 기본 원칙

- 모든 콘텐츠 장비는 커스텀 장비 GUI를 통해 장착·해제한다.
- 바닐라 인벤토리에서 직접 슬롯을 바꿔 장비 효과를 활성화할 수 없다.
- 서버에 저장된 장착 상태가 권위자이며 실제 인벤토리 슬롯은 표시·입력 동기화 대상으로 사용한다.
- 장비 효과는 개별 장비 인스턴스 UUID를 기준으로 계산한다.
- 무기군마다 강점은 다르지만 특정 무기군이 핵심 진행의 필수 조건이 되지 않는다.
- 기본 기능과 정보 표시는 리소스팩 없이 이해할 수 있어야 한다.

## 2. 장비 슬롯

| 슬롯 | 내부 ID | 바닐라 동기화 | 기본 역할 |
|---|---|---:|---|
| 주무기 | `MAIN_WEAPON` | `0` | 일반 공격과 주무기 스킬 |
| 보조무기 | `OFF_WEAPON` | `-106` | 방패, 보조 도구, 보조 스킬 |
| 머리 | `ARMOR_HEAD` | 서버 설정 슬롯 | 방어구 |
| 가슴 | `ARMOR_CHEST` | 서버 설정 슬롯 | 방어구 |
| 다리 | `ARMOR_LEGS` | 서버 설정 슬롯 | 방어구 |
| 발 | `ARMOR_FEET` | 서버 설정 슬롯 | 방어구 |
| 장신구 1 | `ACCESSORY_1` | 가상 | 보조 스탯·조건부 효과 |
| 장신구 2 | `ACCESSORY_2` | 가상 | 보조 스탯·조건부 효과 |
| 부적 | `CHARM` | 가상 | 희귀 규칙 효과·부활 가능성 |

`0`과 `-106`은 WildSurvival 내부 슬롯 설정값이 아니라 마인크래프트 장비 동기화 대상으로 고정한다. 저장 데이터는 `MAIN_WEAPON`, `OFF_WEAPON` 같은 의미 ID를 함께 보존한다.

## 3. 장비 GUI 처리

### 장착

1. 플레이어 생명·전투·GUI 사용 가능 상태를 확인한다.
2. 대상 아이템의 장비 서명, UUID, 템플릿과 리비전을 검증한다.
3. 슬롯 호환, 레벨·발견·배타 조건을 검증한다.
4. 변경 전·후 장착 상태를 불변 스냅샷으로 만든다.
5. 서버 장착 데이터를 원자적으로 변경한다.
6. 실제 슬롯 `0`, `-106`과 방어구 표시를 동기화한다.
7. 스탯·스킬·증강 후보 태그를 재계산한다.
8. 성공 결과를 저장하고 GUI를 갱신한다.

### 직접 조작 차단

- 숫자 키, 드래그, 쉬프트 클릭, F키, 사망 드롭, 호퍼, 디스펜서로 콘텐츠 장비 슬롯을 우회하지 못하게 한다.
- 서버 장착 데이터와 실제 슬롯이 다르면 서버 데이터를 기준으로 복원한다.
- 전투 중 자의 장비 교체는 기본 차단한다.
- GUI가 비정상 종료되면 미확정 변경을 폐기하고 기존 장착 상태를 복원한다.

## 4. 권투 상태

- 주무기 슬롯 `MAIN_WEAPON`과 실제 슬롯 `0`이 모두 비어 있으면 `UNARMED_COMBAT`을 자동 활성화한다.
- 권투는 아이템 인스턴스가 아니라 플레이어의 가상 무기 프로필이다.
- 권투 프로필은 일반 공격 스킬, 공격 범위, 콤보 단계, 태그와 기본 계수를 가진다.
- 주무기를 장착하면 권투 프로필을 즉시 비활성화한다.
- 주무기 데이터가 손상됐지만 실제 아이템이 남은 경우 권투로 자동 대체하지 않고 장비를 격리한 뒤 오류를 표시한다.
- 권투 중 블록 파괴 입력은 RULES의 웅크리기 또는 별도 채굴 도구 우선순위를 따른다.

| 도끼 | 도끼 | 높은 단일 비용·브레이크 |
| 활 | 활 | 바닐라 피해 차단, 커스텀 투사체 |
| 석궁 | 석궁 | 커스텀 탄창·장전 |
| 단검 | 검 계열 아이템 | 표시명·로어로 구분, 이후 리소스팩 모델 적용 |
| 둔기 | 철퇴 | 표시명·로어로 구분, 이후 리소스팩 모델 적용 |
| 지팡이 | 막대·블레이즈 막대 계열 | 커스텀 투사체·광역·지원 |
| 곡괭이 | 곡괭이 | 전투 판정 우선, 채굴 입력 분리 |

- 리소스팩 적용 전에도 장비 이름, 무기군 태그, 로어와 GUI 슬롯으로 구분 가능해야 한다.
- 리소스팩 적용 후에도 템플릿 ID와 성능 데이터는 변경하지 않고 시각 모델만 교체한다.
- 방패는 주 무기군이 아니라 보조무기 방어 장비다.

## 6. 장비 인스턴스 데이터

모든 콘텐츠 장비는 최소한 다음 데이터를 가진다.

| 필드 | 역할 |
|---|---|
| `instance-id` | 전 세계 고유 장비 UUID |
| `template-id` | 장비 원형 |
| `revision` | 템플릿·직렬화 버전 |
| `owner-run-id` | 회차 귀속과 외부 반입 방지 |
| `bound-player` | 개인 귀속 시 대상 UUID |
| `equipment-type` | 무기·방어구·장신구·부적 |
| `weapon-class` | 10개 무기군 또는 없음 |
| `slot-policy` | 장착 가능 슬롯 |
| `rarity` | 일반~심연 |
| `item-level` | 장비 기준 성장 단계 |
| `enhancement-level` | 강화 단계 |
| `reforge-options` | 재련 옵션과 잠금 상태 |
| `durability-policy` | 내구도 처리 방식 |
| `source-id` | 제작·보스·적 드롭 등 획득 출처 |
| `signature` | 핵심 필드 위변조 검증값 |

- 스택 가능한 재료와 장비 인스턴스를 분리한다.
- 서로 다른 인스턴스 UUID 장비는 같은 아이템 스택으로 합칠 수 없다.
- PDC가 사라지거나 서명이 맞지 않으면 장착과 거래를 차단하고 격리한다.

## 7. 희귀도

| 희귀도 | 내부 ID | 설계 역할 |
|---|---|---|
| 일반 | `COMMON` | 기본 성능과 0~1개 단순 옵션 |
| 고급 | `UNCOMMON` | 역할 방향을 선택하는 기초 옵션 |
| 희귀 | `RARE` | 무기·상태·브레이크 태그 연계 |
| 영웅 | `EPIC` | 빌드 엔진이 되는 조건부 효과 |
| 전설 | `LEGENDARY` | 고유 효과, 증강·발견 진화 연결 |
| 심연 | `ABYSSAL` | 규칙 변화와 오염·자원·운용 대가 |

- 희귀도는 단순 공격력 배율만 의미하지 않는다.
- 같은 세션의 고등급 장비가 모든 저등급 장비의 완전한 상위 호환이 되지 않게 한다.
- 심연 장비는 명시적인 대가와 위험 표시가 없으면 제작·드롭할 수 없다.
- 희귀도별 옵션 예산과 정확한 수치는 BALANCE에서 확정한다.

## 8. 제작·강화·재련 연계

- 장비 제작은 발견한 템플릿, 재료와 사용 가능한 제작 시설을 검증한다.
- 강화는 장비를 파괴하거나 강화 단계를 하락시키지 않는 누적 성장으로 설계한다.
- 재련은 정해진 옵션 예산 안에서 선택지를 바꾸며 잠금 옵션 수에 따라 비용이 증가한다.
- 장비 복구와 강화 재료에는 휴대 설비로 만들 수 있는 최소 복구 경로를 둔다.
- 고급 제작과 재련은 설치형 시설을 요구할 수 있다.
- 정확한 비용, 천장과 재료 예산은 ECONOMY를 따른다.

## 9. 적 장비 드롭

- 일반 적은 장비보다 재료·부품·표본 드롭을 중심으로 한다.
- 직접 장비 드롭은 적 등급, Day, 발견 진행과 드롭 테이블을 모두 만족해야 한다.
- 미해금 템플릿 장비가 드롭되면 즉시 장착 가능한 완제품이 아니라 분석 가능한 손상 장비 또는 설계 단서로 변환할 수 있다.
- 직접 드롭 장비의 아이템 레벨과 희귀도는 현재 세션 상한을 넘지 않는다.
- 같은 적 반복 처치의 장비 드롭에는 회차·Day·템플릿별 감쇠와 천장을 둔다.
- 보스 고유 장비는 일반 적 드롭과 분리한다.

## 10. 보스 고유 장비 흐름

### 후보 선택

1. 보스 처치 정산에서 고유 장비 템플릿 후보 3개를 생성하고 저장한다.
2. 후보는 현재 파티가 사용할 수 있는 서로 다른 역할을 우선한다.
3. 등록 플레이어가 후보 1개에 투표한다.
4. 최다표 후보를 선택하며 동률은 서버 시드 무작위로 결정한다.
5. 선택된 템플릿의 최초 완제품 1개를 생성한다.
6. 동시에 같은 템플릿의 파티 공용 제작식을 해금한다.

- 최초 지급 후 생존 파티는 재료와 시설 조건을 만족하면 동일 장비를 추가 제작할 수 있다.
- 제작식 해금은 회차 공유이며 완전 사망자의 상태와 무관하게 유지한다.
- 후보 생성과 제작식 해금은 보스 보상 ID로 한 번만 처리한다.

### 필요·양보와 자동 귀속

선택된 최초 완제품은 다음 절차로 배분한다.

| 선택 | 의미 |
|---|---|
| 필요 | 직접 사용할 의사가 있으며 자동 귀속에 동의 |
| 양보 | 최초 완제품 경쟁에서 제외 |

1. 모든 등록 플레이어에게 필요·양보 선택을 제공한다.
2. 필요를 선택한 플레이어 중 장비 슬롯·무기군 호환을 검증한다.
3. 유효 필요자가 한 명이면 해당 플레이어에게 귀속한다.
4. 복수면 같은 회차의 고유 장비 수령 횟수가 적은 플레이어를 우선한다.
5. 여전히 동률이면 서버 시드 무작위로 결정한다.
6. 전원이 양보하면 최초 완제품을 가상 파티 보상 보관함에 미귀속 상태로 저장한다.

- 완전 사망자도 향후 부활 가능성이 있으므로 필요를 선택할 수 있다.
- 자동 귀속 장비는 일반 거래와 공용 보관함 이동을 제한한다.
- 귀속 해제는 기본 제공하지 않으며 명시된 희귀 기능만 허용한다.
- 결과와 시드를 저장하여 재접속·재시작으로 다시 추첨할 수 없게 한다.

## 11. 사망과 유품

- 장착 장비와 인벤토리 장비는 DEATH의 유품 스냅샷에 포함한다.
- 귀속 상태는 사망으로 해제되지 않는다.
- 유품을 파티원이 회수해도 귀속 장비는 원래 소유자가 부활하기 전까지 장착할 수 없다.
- 파티 진행에 필수인 고유 기능은 장비 개인 귀속에만 의존하지 않고 제작식·발견·시설 해금으로 공유한다.
- 장비 손실보다 플레이어 전력 이탈과 제한된 소모품 손실을 하드코어 결과의 중심으로 유지한다.

- 장착·해제
- 제작
- 강화
- 재련
- 귀속·귀속 확인

트랜잭션에는 작업 ID, 이전·이후 소유자, 이전·이후 슬롯, 소비 재료, 생성·삭제 인스턴스와 저장 순번을 기록한다.

## 14. 완료 기준

- 커스텀 GUI와 실제 슬롯 동기화 규칙이 확정되어 있다.
- 10개 무기군과 방패 분류, 권투 자동 상태가 반영되어 있다.
- 장비 인스턴스·희귀도·제작·강화·재련의 공통 기준이 있다.
- 적 직접 드롭이 제작·발견 진행을 우회하지 않는다.
- 보스 최초 1개, 제작식 해금, 후보 투표와 필요·양보 자동 귀속이 정의되어 있다.
