## 2. Craft 해금

- 신규 회차는 `CRAFT_LOCKED`로 시작한다.
- 플레이어 메뉴의 Craft를 열면 해금 3×3 화면을 먼저 표시한다. 요청자가 개인 인벤토리의 임의 원목 태그 `minecraft:logs ×4`를 중앙 십자 슬롯에 놓고 확인하면 파티 전체가 `CRAFT_UNLOCKED`가 된다.
- 원목은 `validate→reserve→commit`의 commit에서만 소비한다. 중복 클릭·접속 종료·서버 종료는 같은 `unlockTransactionId`로 멱등 처리한다.
- 해금은 공용 물류고나 공용 자원을 요구하지 않는다. 최초 기여자와 시간을 기록하되 별도 능력 보상은 주지 않는다.
- 해금 전에는 조합법 도감 열람만 가능하며 결과 수령, 자동 채우기, 시설 가공 등록을 모두 거부한다.

## 3. 3×3 조합 실행

모든 WS 제작은 바닐라 제작대가 아니라 `CRAFT GUI`의 9칸 입력에서만 실행한다.

```text
OPEN → PLACE/REMOVE → MATCHED → CONFIRM
     → RESERVE → PROCESSING → OUTPUT_READY → CLAIMED
```

- 기본 레시피는 입력 목록 순서대로 좌상단부터 빈칸 없이 배치하는 `ORDERED_3X3`를 사용한다. 장비·시설은 아래 shape profile을 사용한다.
- 한 칸은 한 item/resource ID만 담으며 그 칸의 수량까지 일치해야 한다. 태그 입력은 허용된 후보 아이콘을 실제 선택해야 한다.
- 개인 원장 자원은 GUI 재료 팔레트에서 가상 스택으로 꺼내 놓는다. 이는 예약 표현이며 결과 commit 전에는 원장에서 차감하지 않는다.
- FAC-S16 전에는 요청자의 개인 원장·인벤토리만 입력 원천이다. 다른 플레이어는 `CONTRIBUTE` 화면에서 자기 입력을 별도 승인할 수 있다.
- FAC-S16 ACTIVE 뒤에는 개인 또는 공용 원장을 명시적으로 선택한다. 획득 즉시 공용 입금은 하지 않는다.
- 결과 칸 클릭만으로 서버가 재료를 찾아 즉시 제작하는 이전 프로토타입 방식은 제거한다.
- 스택 overflow는 출력함에 보존하며 바닥 드롭으로 우회하지 않는다.

| profile | 고정 배치 | 대상 |
|---|---|---|
| `ORDERED_3X3` | 입력 순서대로 0→8 | 소모품·가공·탄약 |
| `WEAPON_FRAME` | 중심에 기반 장비, 상/좌/우에 금속·신호·전문, 하단에 연료/촉매 | 장비 개조 |
| `ARMOR_FRAME` | 중심에 기반 부위, 네 모서리에 구조/천, 좌우에 전문 | 방어구 |
| `FACILITY_FRAME` | 0 건설, 2 생존, 4 금속, 6 신호, 8 전문 | 시설 키트 |
| `CALL_FRAME` | 중심에 핵/증명, 네 모서리에 호출 재료 | 보스 호출 |
| `REBUILD_FRAME` | 중심에 비소각 WSP 증명, 나머지에 지정 재료 | FAC-R01~R05·Final |

- 회전·반전 허용은 기본 `false`다. 접근성 자동 채우기는 정답 배치를 대신 수행하지만 확인 버튼은 생략하지 않는다.

## 8. 장비 레시피 생성 규칙

- 기존 `WSRCP-W01~W09/E01~E07`은 완제품 신규 생성이다.
- 그 외 `WSRCP-EQ-<equipmentId>`는 정의 원장에 기반 장비가 적혀 있으면 instance 개조, 없으면 같은 슬롯·무기군의 직전 단계 장비를 중심 칸에 요구한다.
- EQL Day1~10과 D20은 각 정의 원장 표의 재료를 §4 ID로 치환한다.
- D20 세트 4부위는 세트 공통 재료에 HEAD/CHEST/LEGS/FEET 계수 `0.7/1.4/1.1/0.6`을 곱해 각 항목 올림한다.
- D50 일반 모듈은 원장의 EP21/LG25/LG31/AB35/AB41 프로필을 사용한다. 기반 장비를 중심에 두고 가치 태그의 실제 자원을 선택한다.
- D10/D20/D30/D40 최초 보상 1개는 reward로 생성한다. 같은 템플릿의 추가 제작만 해당 장비 recipe를 사용하며 보스 잔류물과 완료 증명을 검사한다.
- 결과 장비는 기반 instance의 강화, 내구 비율, 귀속, 허용 재련 옵션과 원본 UUID 계보를 원자적으로 계승한다.

## 9. 도감·해금

- 아이템 발견과 recipe 실행 권한은 별도다.
- outputId를 최초 획득하면 그 아이템의 현재 리비전 recipe 3×3 위치, 정확 수량, 시설, 처리시간, 입력 원천과 결과 귀속을 도감에서 공개한다.
- 연구·Day·시설·보스 선택 조건이 남아 있으면 recipe는 열람만 가능하고 실행 버튼에 잠금 이유를 표시한다.
- 보스 후보는 선택해 완제품을 받은 템플릿만 최초 획득으로 처리한다. 선택하지 않은 후보는 이름 노출만으로 도감·조합 배열을 해금하지 않는다.
- 시설 파괴는 이미 배운 recipe를 지우지 않지만 해당 시설이 없으면 작업 시작을 막는다.

## 10. 트랜잭션·취소

- `RESERVED` 전 취소 100%, `PROCESSING` 25% 미만 75%, 이후 50% 반환이라는 기존 시설 정책은 시간 작업에만 적용한다. 즉시 Craft는 confirm 전 100%, commit 뒤 취소 불가다.
- 입력 장비·고유 증명은 수량 재료와 다른 잠금 테이블을 사용한다. 환불률로 장비나 증명을 부분 반환하지 않는다.
- 서버 재시작 시 RESERVED는 해제하고 PROCESSING은 저장된 경과시간부터 재개한다. OUTPUT_READY는 동일 transaction 결과만 수령한다.
- 같은 `recipeTransactionId`에서 output을 두 번 생성하거나 입력을 두 번 반환하면 치명 결함이다.
