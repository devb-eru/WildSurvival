# WildSurvival DISC 발견형 목표 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 카테고리 | 발견, 연구 단서, 비선형 목표 진행 |
| 문서 목적 | 고정 임무 구역과 정답형 퀘스트 없이 파티가 다음 진행을 발견하게 함 |
| 진행 소유권 | 핵심 발견은 회차·파티 공유 |
| 기본 UI | 리소스팩 없는 인벤토리 GUI·채팅·타이틀 |
| 최종 수정일 | 2026-08-16 |

## 1. 시스템 목적

발견형 목표 시스템은 Stoneblock·SkyFactory 계열의 단계적 목표 구조가 제공하는 방향성과 성취감을 사용하되, 퀘스트 목록이 모든 정답과 순서를 처음부터 노출하는 문제를 피한다.

- 플레이어의 관찰과 실험이 실제 진행을 만든다.
- 고정 좌표와 임무 구역 없이 어떤 월드 시드에서도 진행 가능하게 한다.
- 핵심 시스템의 사용법을 직접 발견하되 장시간 소프트락은 방지한다.
- 파티원이 서로 다른 활동을 해도 발견 결과를 공유한다.
- 이미 수행한 행동을 나중에 다시 반복하도록 강요하지 않는다.

## 2. 발견 흐름

```text
미관측
→ 단서 관측
→ 가설 생성
→ 실험 가능
→ 발견 완료
→ 제작·시설·정보·대응책 해금
→ 후속 발견 분기
```

### 상태

| 상태 | 내부 ID | 플레이어 표시 |
|---|---|---|
| 미관측 | `HIDDEN` | 표시하지 않음 |
| 단서 관측 | `CLUE_FOUND` | 모호한 현상과 관련 범주 표시 |
| 가설 생성 | `HYPOTHESIS` | 시험 가능한 행동 범주 표시 |
| 진행 중 | `EXPERIMENTING` | 일부 조건과 관찰 결과 표시 |
| 발견 완료 | `DISCOVERED` | 이름, 효과, 제작·시설 정보 표시 |
| 숙련 완료 | `MASTERED` | 효율 개선 또는 고급 분기 해금 |

`HIDDEN` 상태의 노드는 일반 퀘스트 목록에서 빈 칸으로 표시하지 않는다. 플레이어는 존재 자체를 알 수 없다.

## 3. 발견 노드 종류

| 종류 | 역할 | 예시 |
|---|---|---|
| 생존 발견 | 기본 생존과 휴대 설비 | 오염 샘플 보관, 현장 수리 |
| 자원 발견 | 재료의 성질과 가공법 | 오염 광석 정제, 촉매 추출 |
| 제작 발견 | 아이템과 부품 | 강화 코어, 정화 필터 |
| 시설 발견 | 설치형 설비와 모듈 | 분석대, 정화기, 증강 공명기 |
| 생물 발견 | 적 역할, 약점, 변이 | 중장갑의 브레이크 취약 구간 |
| 세계 발견 | Day·오염·붕괴 현상 | 균열 신호, 붕괴 핵의 위치 원리 |
| 대응 발견 | 상태·패턴 대응책 | 해제제, 방해파 차단 모듈 |
| 재건 발견 | 최종 진행 | 정화 프레임, 재건 신호기 |

## 4. 발견 조건 데이터

각 노드는 다음 필드를 가진다.

| 필드 | 설명 |
|---|---|
| `id` | 저장용 고유 ID |
| `revision` | 데이터 변경 버전 |
| `category` | 발견 노드 종류 |
| `visibility` | 현재 표시 단계 |
| `prerequisite-expression` | 선행 발견 논리식 |
| `clue-triggers` | 단서 관측 사건 목록 |
| `experiment-triggers` | 실험 진행 사건 목록 |
| `completion-expression` | 완료 조건 논리식 |
| `retroactive` | 선행 행동 소급 인정 여부 |
| `shared` | 파티 공유 여부 |
| `hint-profile` | 시간·실패별 힌트 단계 |
| `unlock-actions` | 제작식·시설·정보·드롭 해금 |
| `alternative-groups` | 대체 완료 경로 |
| `minimum-day` | 조기 완료 방지 Day 하한 |
| `maximum-stall-time` | 다음 힌트 검토 기준 시간 |

## 5. 트리거

### 관찰 트리거

- 특정 종류의 아이템 최초 획득
- 오염 단계 또는 지역 현상 경험
- 특정 적의 공격·패턴 관측
- 시설 또는 바닐라 블록 상호작용
- 특정 피해·상태이상·브레이크 결과 경험
- 구조물·생물·생물군계 범주 발견
- 공세와 보스 결과
- 제작 실패 또는 불완전 조합 시도

### 실험 트리거

- 재료 조합을 분석대에 투입
- 특정 도구로 특정 재료 처리
- 장비 태그와 상태이상의 상호작용 발생
- 시설 모듈 조합 및 가동
- 같은 현상을 서로 다른 방법으로 해결
- 연구 표본을 기준 수량만큼 비교

좌표 자체는 핵심 발견 조건으로 사용하지 않는다. 구조물이나 생물군계가 필요한 경우 `구조물 범주 관측`으로 처리하고 대체 경로를 둔다.

## 6. 소급 인정

- 노드가 `HIDDEN`이어도 서버는 핵심 진행 사건의 요약 카운터를 기록한다.
- 후에 선행 조건이 열리면 저장된 사건을 완료 조건에 재적용한다.
- 고유 아이템 획득·보스 처치·시설 건설처럼 복구가 어려운 사건은 반드시 소급 인정한다.
- 일반 반복 채집은 무제한 사건 로그를 남기지 않고 재료 범주별 최고 기록과 누적값만 저장한다.
- 리비전 변경으로 조건이 바뀌면 마이그레이션 규칙에 따라 재평가한다.

## 7. 힌트 정책

힌트는 답을 직접 제공하기보다 탐색 범위를 줄인다.

| 단계 | 제공 정보 | 예시 |
|---:|---|---|
| 0 | 현상만 표시 | “금속 표면에 오염이 달라붙는다.” |
| 1 | 필요한 활동 범주 | “가열보다 분리·여과가 필요해 보인다.” |
| 2 | 필요한 재료 태그 | “정화 성질과 다공성 재료를 함께 시험할 수 있다.” |
| 3 | 필요한 설비 범주 | “휴대 도구가 아니라 분석 설비가 필요하다.” |
| 4 | 최소 조합 구조 | 정확한 수량 없이 핵심 재료군과 처리 순서 표시 |

- 기본적으로 단계 0~2를 사용한다.
- 핵심 진행이 장시간 멈췄거나 같은 실패가 반복될 때만 다음 단계를 연다.
- 선택 콘텐츠와 숨겨진 고유 장비는 자동 힌트 단계 상승 대상에서 제외할 수 있다.
- 파티는 GUI에서 힌트 강도를 `기본`, `최소`, `직접 요청만` 중 하나로 선택할 수 있다.
- 최종 Day 잠금이나 미도달 Day 때문에 진행할 수 없는 경우 실패 힌트를 주지 않고 `아직 세계 조건이 부족함`을 표시한다.

## 8. 비선형 진행과 핵심 경로

### 노드 관계

| 관계 | 처리 |
|---|---|
| `ALL_OF` | 모든 선행 노드 필요 |
| `ANY_OF` | 대체 노드 중 하나 필요 |
| `COUNT_OF` | 후보 중 지정 수 이상 필요 |
| `OPTIONAL_BOOST` | 없어도 진행 가능, 있으면 비용·위험 감소 |
| `MUTUALLY_EXCLUSIVE` | 한 회차에서 한 분기만 활성화 |

### 핵심 경로 규칙

- 핵심 경로 노드는 대체 해결 경로를 최소 2개 갖는다.
- 특정 무기, 개인 증강 또는 희귀 무작위 장비를 필수 선행 조건으로 사용하지 않는다.
- 특정 생물군계 하나만 요구하지 않는다.
- 핵심 시설이 파괴돼도 저등급 휴대 설비로 복구 재료를 만들 수 있어야 한다.
- 무작위 드롭을 요구하면 누적 보정 또는 확정 대체 제작식을 제공한다.
- 최종 재건 노드는 Day 하한과 보스 진행 기록을 함께 검증한다.

## 9. 파티 공유

- 핵심 발견은 회차 단위로 저장하고 접속 중인 모든 파티원에게 즉시 반영한다.
- 개인이 먼저 관측한 단서는 발견자 이름과 함께 파티 기록에 남긴다.
- 개인 도감 UI는 파티 공유 상태를 표시하되 개인 관측 기록도 별도로 볼 수 있다.
- 완전 사망자도 파티 기록과 새 발견 알림을 볼 수 있다.
- 발견 막타나 최초 발견자에게 독점 전투 보너스를 주지 않는다.
- 선택적 외형·수집 도감은 개인 진행으로 둘 수 있지만 핵심 제작식과 시설은 공유한다.

## 10. 발견 기록 UI

인벤토리 GUI 기반 `생존 기록 장치`를 사용한다.

### 기본 탭

- 최근 관측
- 실험 가능한 가설
- 완료한 발견
- 적·오염 기록
- 설비·제작 지식
- 재건 진행

### 표시 규칙

- 정확한 좌표를 기본 표시하지 않는다.
- 아이콘은 바닐라 아이템을 사용하고 이름·로어로 상태를 구분한다.
- 리소스팩이 없어도 등급과 상태를 색상·문자·아이템 종류로 구분한다.
- 진행 수치를 숨겨야 하는 노드는 `관찰 부족`, `반응 있음`, `거의 안정됨` 같은 구간 표현을 사용한다.
- 핵심 경로가 장시간 정체되면 GUI 첫 화면에 관련 현상 카테고리를 강조한다.

## 11. 필요한 장치와 설비

| 장치·설비 | 계층 | 핵심 기능 |
|---|---|---|
| 생존 기록 장치 | 휴대 | 단서·가설·발견 GUI |
| 휴대 분석 도구 | 휴대 | 기본 표본 분류, 낮은 정확도 |
| 야영 작업대 | 야영 | 기본 부품·수리·표본 보관 |
| 분석대 | 거점 | 복합 실험, 제작·적 대응 발견 |
| 오염 분리기 | 거점 | 오염 자원 정제와 정화 재료 생산 |
| 증강 공명기 | 거점 | 증강 리롤·교체·진화 관리 |
| 신호 탐지기 | 휴대·거점 | 자원·균열·보스 신호의 방향·강도 탐지 |
| 정화 설비 | 거점 | 지역·플레이어·시설 오염 제어 |

## 12. 보스와 발견형 소환

- 보스는 고정 임무 구역에서 대기하지 않는다.
- 보스 Day에 세계 신호가 발생하고 파티가 신호 탐지·소환·차단 절차를 발견한다.
- 핵심 보스는 Day 종료 시 자동으로 진행 불가능 상태가 되지 않도록 강제 접근 경로를 가진다.
- 소환 장치는 현재 파티와 활성 시설망 주변의 안전한 공간을 검증해 전투 영역을 만든다.
- 부적합한 지형이면 후보 위치를 다시 탐색하고, 실패 시 임시 전투 지형 보호 규칙을 적용한다.
- 보스전 시작 후 시설 철거·차원 이동·장거리 도주로 전투를 무효화할 수 없다.

## 13. 저장 데이터 예시

```yaml
discoveries:
  shared:
    disc.purification.filter:
      state: EXPERIMENTING
      revision: 2
      first-clue-player: "uuid-a"
      observed-tags: [CORRUPTED_METAL, POROUS_MATERIAL]
      counters:
        analysis-attempt: 2
      hint-level: 1
      retroactive-events-applied: true
  history:
    - event-id: "run-event-1842"
      type: BOSS_PATTERN_OBSERVED
      tags: [BREAKABLE_CAST, CORRUPTION]
```

## 14. 예외 및 악용 방지

| 상황 | 처리 |
|---|---|
| 조건 달성 직후 서버 종료 | 발견 이벤트 ID로 한 번만 재처리 |
| 제작 결과와 발견 해금 동시 발생 | 아이템 지급 후 발견 저장, 중복 제작식 지급 차단 |
| 미해금 제작식을 외부에서 습득 | 장착·사용 제한, 분석 단서로만 인정 |
| 같은 표본 반복 투입 | 고유 표본·출처·회차 카운터로 감쇠 |
| 파티원이 서로 다른 분기 선택 | 공유 분기 규칙과 투표를 먼저 적용 |
| 월드에 필수 자원 없음 | 대체 제작식 또는 보정 획득 경로 활성화 |
| Day 하한 전 모든 재료 확보 | 실험은 가능하나 최종 발견 완료를 잠금 |
| 완전 사망자가 단서 관측 | 관전으로 새 월드 단서를 생성하지 않음 |

## 15. 완료 기준

- 고정 좌표 없이 핵심 발견을 진행할 수 있다.
- 우연히 먼저 수행한 핵심 행동이 소급 인정된다.
- 파티 공유와 개인 관측 기록이 분리 저장된다.
- 정답을 처음부터 공개하지 않으면서 장기 정체를 방지한다.
- 무작위 월드 시드와 자원 부족으로 핵심 진행이 소프트락되지 않는다.
- 고정 임무 구역 없이 보스와 최종 진행을 시작할 수 있다.
- 리소스팩 없이 모든 발견 상태와 조작을 이해할 수 있다.
