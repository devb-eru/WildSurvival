## 1. 성공 정의

최종 목표는 다음 세 단계를 모두 완료하고 `finalObjectiveState == COMPLETED`가 저장됐을 때만 성공이다.

1. 첫 재건 장치와 교정 말뚝을 동적 전장에 전개한다.
2. 이동하는 세계 붕괴 핵을 제압해 `CORE_SUBDUED` 상태로 만든다.
3. 정화 출력을 180초 유효 유지하고 생존자가 마지막 협동 확정을 완료한다.

- 보스 HP 0, Day 50 도달, 장치 제작, 180초 타이머 중 어느 하나만으로 회차가 끝나지 않는다.
- 엔딩·결과 화면·완료 통계는 완료 트랜잭션 저장 성공 뒤에만 실행한다.
- 전원 완전 사망은 어느 단계에서든 하드코어 회차 실패다.

## 2. 준비 조건

```text
currentDay >= 50
AND boss.day10.state == CLEARED
AND boss.day20.state == CLEARED
AND boss.day30.state == CLEARED
AND boss.day40.state == CLEARED
AND reconstruction.parts[A,B,C,D] == BOUND
AND discovery.C27 == DISCOVERED
AND discovery.C28A == COMPLETE
AND discovery.C28B == COMPLETE
AND discovery.C28C == COMPLETE
AND discovery.C28D == COMPLETE
AND discovery.C29 == COMPLETE
AND facility.R01 == READY
AND facility.R02 == READY
AND facility.R03 == READY
AND facility.R04 == READY
AND facility.R05.count == 3
AND facility.R06 == READY_LOCKED
AND inventoryOrLedger.finalSignalKey >= 1
AND activeBoss == NONE
AND activeSiege == NONE
AND blockingTransaction == NONE
```

- C30은 최종 목표 자체이므로 시작 선행이 아니라 완료 결과다.
- 세계 오염 수치, 특정 무기, 특정 장비·증강, 정착 정화기, 전원 Lv50은 선행 조건이 아니다.
- 조건이 하나라도 없으면 `LOCKED`를 유지하고 `DAY`, `BOSS`, `PART`, `DISCOVERY`, `FACILITY`, `CALIBRATION`, `KEY`, `ACTIVE_CONTENT` 범주만 공개한다.
- 관리자 Day 복구 명령도 위 독립 원장을 대신할 수 없다.

## 3. 상태 전이

```text
LOCKED
→ AVAILABLE
→ ACTIVATING
→ ACTIVE_STAGE_1
→ ACTIVE_STAGE_2
→ ACTIVE_STAGE_3
→ RESOLVING
→ COMPLETED
```

| 상태 | 의미 | Day 타이머·스킵 |
|---|---|---|
| `LOCKED` | 준비 조건 미충족 | Day 정상 진행 |
| `AVAILABLE` | 시작 가능 | Day 정상 진행 |
| `ACTIVATING` | 투표·최종 전장 검사·TX 준비 | 일시 정지, 60초 내 실패 시 복귀 |
| `ACTIVE_STAGE_1~3` | 최종 실행 | Day 타이머·일반 공세·스킵 정지 |
| `RESOLVING` | 세계 상태·C30·완료 기록 원자 확정 | 정지 |
| `COMPLETED` | 읽기 전용 성공 회차 | 재개 불가 |

- 자동 복구 불가 시 `ADMIN_RECOVERY_REQUIRED`, 전원 사망 시 `FAILED`로 별도 전환한다.
- 활성화 실패가 전원 사망이 아니면 가능한 경우 `AVAILABLE`로 돌아간다.

## 4. 시작 승인

1. 생존·접속 중인 등록 플레이어가 FAC-R06 GUI에서 시작 요청을 한다.
2. 서버가 준비 조건과 콘텐츠 리비전을 다시 검사한다.
3. Day 스킵과 같은 투표권 스냅샷을 만들고 과반수 찬성을 요구한다.
4. 가결 뒤 전장 후보를 검사하되 최종 신호 키를 아직 소비하지 않는다.
5. `FinalArenaManifest`, 플레이어·시설·자원 스냅샷을 저장한다.
6. 최종 신호 키를 예약하고 `ACTIVATING`을 커밋한다.
7. Stage 1 오브젝트 생성 성공 뒤 키를 소비 확정하고 `ACTIVE_STAGE_1`로 전환한다.

- 투표권자는 요청 시점 생존·빈사 등록 멤버다. 완전 사망자는 투표권이 없다.
- 동률은 실패이며 Day는 계속된다. 60초 뒤 재요청할 수 있다.
- 서버 오류로 Stage 1이 생성되지 않으면 키 예약을 취소하고 전량 반환한다.

## 13. Stage 3 — 180초 정화 유지

### 13.1 유효 출력

```text
effectiveOutput =
FAC-R06 base 40
+ activeCalibrationStakes × 20
+ playerChannelCount × 10
- activeJammer × 20
```

- 유효 출력 70 이상인 실제 경과 틱만 정화 시간에 더한다.
- 40~69는 진행 정지, 0~39는 마지막 체크포인트까지 초당 0.5초 후퇴한다.
- 체크포인트는 0·60·120·180초이며 그 아래로 후퇴하지 않는다.
- 플레이어 채널은 1명당 10, 최대 20이다. 전원이 채널할 필요가 없다.

### 13.2 정화 공세

| 구간 | 위협 | 핵심 선택 |
|---|---|---|
| 0~60초 | 상태·이동 압박 | 말뚝 보호와 개인 상태 대응 |
| 60~120초 | 오염·시설 방해 | 방해자 우선 또는 출력 채널 보충 |
| 120~180초 | 브레이크·공성 정예 | 공격 중단, 말뚝 재가동, 구조 우선순위 |

- 동시 활성 적 10, 정예 1, 지원 1, 공성 1, 강한 전조 3을 넘지 않는다.
- 적·핵·말뚝 행동은 EXP·자원·장비 드롭을 생성하지 않는다.
- 1인 잔존은 세 말뚝 기본 100 출력으로 채널 없이 유지 가능하지만 방해 대응이 더 어렵다.

## 14. 마지막 협동 확정

정화 180초 달성 뒤 생존·빈사 등록 플레이어 수에 맞춰 상호작용 슬롯을 만든다.

| 생존 상태 | 요구 |
|---|---|
| 생존 | 45초 안에 FAC-R06에서 2초 확정 상호작용 1회 |
| 빈사 | 구조 성공 후 남은 시간 안에 상호작용, 또는 다른 생존자의 구조 대리 기록 |
| 완전 사망 | 요구 대상 제외, 성공 기록에는 사망자로 남음 |
| 접속 종료 90초 이내 | 전투 참여 상태 유지, 90초 유예 |
| 1인 잔존 | 그 한 명의 상호작용 1회로 충족 |

- 상호작용 중 일반 적은 새로 생성되지 않고 남은 적은 45초 동안 약화된다.
- 45초 실패 시 정화 진행 120초 체크포인트로 돌아가며 보스는 부활하지 않는다.
- 무한 재시도를 막는 추가 자원 소모는 없지만 남아 있는 전투 손실은 복구하지 않는다.

## 19. 검증 항목

- Day 49 이하 명령·GUI·아이템·관리자 일반 권한의 활성화 우회 차단
- 독립 준비 원장과 C30 비선행·완료 결과 구분
- 1~4인 Stage 1 예산, Stage 2 HP·브레이크, Stage 3 출력

- RESOLVING 저장 성공 전 엔딩·완료 통계 미실행
- Story EMPTY에서도 완료·읽기 전용 회차 전환

## 20. 완료 기준

- Day 50은 최초 시작 가능일이고 Day 51+ 어느 날에도 준비 후 시작할 수 있다.

- 고정 던전·모드·바닐라 보스 AI 없이 자유 야생과 Paper 플러그인으로 구현 가능하다.
