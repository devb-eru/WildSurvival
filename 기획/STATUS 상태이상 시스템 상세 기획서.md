# STATUS-001 상태이상 공통 규칙

## 1. 시스템 목적

상태이상 시스템은 피해량 외의 전투 전략을 제공하고 적과 플레이어의 행동을 일시적으로 변화시킨다.

- 무기, 스킬, 증강이 서로 다른 전투 역할을 가지게 한다.
- 파티가 상태이상 연계와 해제를 통해 협력하게 한다.
- 일반 적, 엘리트, 보스에 적합한 적용 규칙을 제공한다.
- 무한 CC와 반복적인 행동 봉쇄를 방지한다.
- 모든 효과의 적용, 중첩, 저항, 해제, 저장 방식을 통일한다.

## 2. 상태이상 용어

| 용어 | 정의 |
|---|---|
| 상태 효과 | 대상에게 일정 시간 또는 조건 동안 적용되는 모든 효과 |
| 상태이상 | 대상에게 불리한 상태 효과 |
| 강화 효과 | 대상에게 유리한 상태 효과 |
| 약화 효과 | 능력치 또는 행동 효율을 낮추지만 직접 행동을 봉쇄하지 않는 효과 |
| 제어 효과(CC) | 이동, 공격, 스킬, 시점 또는 위치를 제한하는 효과 |
| 지속 피해(DOT) | 일정 주기마다 피해를 주는 효과 |
| 강제 이동 | 넉백, 끌어오기, 공중 띄움처럼 위치를 변경하는 효과 |
| 해제 | 불리한 상태이상을 제거하는 행동 |
| 정화 | 특정 분류의 상태이상을 제거하거나 저항을 부여하는 강한 해제 |
| 면역 | 상태이상 적용 자체를 거부하는 상태 |

## 3. 상태이상 분류

모든 상태이상은 하나 이상의 분류 태그를 가진다.

| 분류 | 설명 | 예시 |
|---|---|---|
| `DEBUFF` | 능력치 또는 행동 효율 감소 | 공격력 감소, 방어력 감소 |
| `DOT` | 주기적 피해 | 화상, 독, 출혈 |
| `SOFT_CC` | 행동 일부를 제한 | 둔화, 침묵, 무장 해제 |
| `HARD_CC` | 행동 대부분 또는 전부를 봉쇄 | 기절, 수면, 공중 띄움 |
| `ROOT` | 위치 이동 제한 | 속박 |
| `FORCED_MOVE` | 대상 위치 강제 변경 | 넉백, 끌어오기 |
| `TAUNT` | 공격 대상 강제 또는 위협 변경 | 도발 |
| `SPECIAL` | 일반 분류로 처리하기 어려운 효과 | 오염 변이, 보스 표식 |

- 하나의 상태이상이 여러 태그를 가질 수 있다.
- 중복 규칙, 저항, 해제, 보스 적용 정책은 태그와 상태이상 고유 설정을 함께 사용한다.
- `HARD_CC`와 강한 `ROOT`는 연속 제어 방지 규칙의 영향을 받는다.

## 4. 포인트 투자 스탯과 보조 전투값

플레이어가 스탯 포인트로 성장시키는 스탯은 `HP`, `AP`, `ATK`, `DEF`, `HIT`, `EVA`, `SPD`, `EXP`다.

상태이상 시스템은 다음 보조 전투값을 별도로 사용한다.

| 보조 전투값 | 역할 | 주요 획득처 |
|---|---|---|
| 상태 적중 보정 | 저항 가능한 상태이상의 적용 확률 증가 | HIT, 스킬, 장비, 증강 |
| `RES` 상태이상 저항 | 약화 효과와 지속 피해의 적용 확률 감소 | 장비, 증강, 대상 템플릿 |
| `TENACITY` 강한 CC 저항 | 제어 효과 지속시간 감소 | 장비, 증강, 대상 템플릿 |
| 상태 면역 태그 | 특정 상태이상 적용 불가 | 보스, 엘리트 특성, 특수 효과 |

- 보조 전투값은 기본적으로 스탯 포인트 투자 대상이 아니다.
- HIT 5당 상태 적중 보정 +1%p를 제공하며 HIT 기반 보정은 최대 +20%p다.
- RES의 최종 하드캡은 90, TENACITY의 최종 하드캡은 80이다.
- 보조 전투값이 최종 플레이어 스탯 GUI에 표시될지는 `UX-001`에서 확정한다.

## 5. 상태이상 필수 데이터

모든 상태이상은 최소한 다음 데이터를 가진다.

| 필드 | 설명 |
|---|---|
| 상태 ID | 저장과 구현에 사용하는 고유 ID |
| 표시 이름 | 플레이어에게 표시하는 이름 |
| 분류 태그 | `DOT`, `SOFT_CC`, `HARD_CC` 등 |
| 출처 ID | 스킬, 장비, 증강, 환경 등 적용 원인 |
| 적용자 ID | 상태이상을 적용한 주체 |
| 대상 ID | 상태이상이 적용된 대상 |
| 기본 지속시간 | 저항 계산 전 지속시간 |
| 남은 지속시간 | 현재 남은 시간 |
| 적용 확률 정책 | 확정, 저항 가능, 조건부 |
| 중첩 방식 | 갱신, 연장, 강도 중첩, 개별 중첩 등 |
| 최대 중첩 | 허용되는 최대 스택 |
| 틱 간격 | 지속 피해나 주기 효과 처리 간격 |
| 해제 분류 | 일반 해제, 정화, 해제 불가 등 |
| 보스 적용 정책 | 정상, 감소, 브레이크 변환, 면역 |
| 시각 우선순위 | HUD와 파티클 표시 우선순위 |
| 저장 정책 | 저장, 재접속 시 제거, 회차 중단 시 제거 |

## 6. 상태이상 적용 처리 순서

상태이상은 다음 순서로 적용한다.

1. 대상과 생명 상태가 유효한지 확인한다.
2. 공격 또는 스킬이 실제로 적중했는지 확인한다.
3. 회피, 패링, 방어 등 전투 대응 결과를 적용한다.
4. 대상의 상태 면역 태그를 확인한다.
5. 상태이상의 보스·엘리트 적용 정책을 확인한다.
6. 저항 가능한 효과라면 최종 적용 확률을 계산한다.
7. 적용 성공 시 최종 지속시간을 계산한다.
8. 중첩 및 교체 규칙을 처리한다.
9. 효과를 등록하고 최초 적용 효과를 실행한다.
10. UI, 파티클, 사운드와 전투 로그를 갱신한다.

이 순서를 통해 회피나 패링으로 무효화된 공격의 상태이상이 별도로 적용되는 문제를 방지한다.

## 7. 적용 확률과 저항

### 적용 정책

| 정책 | 설명 |
|---|---|
| `GUARANTEED` | 면역이 아니라면 확정 적용 |
| `RESISTIBLE` | 상태 적중 보정과 대상 `RES`로 적용 확률 계산 |
| `CONDITIONAL` | 약점 적중, 중첩 수, 대상 상태 등 별도 조건 충족 시 적용 |
| `SCRIPTED` | 보스 기믹 등 콘텐츠 규칙으로 적용 |

### 저항 가능한 상태이상 공식

```text
최종 적용 확률 =
기본 적용 확률
+ 적용자의 상태 적중 보정
- 대상의 RES
```

- 모든 값은 퍼센트포인트로 계산한다.
- 일반 `RESISTIBLE` 효과의 최종 적용 확률은 최소 10%, 최대 95%다.
- 기본 적용 확률이 0%인 효과는 조건을 충족하기 전까지 적용되지 않는다.
- `GUARANTEED` 효과는 대상 `RES`로 실패하지 않지만 면역과 보스 정책의 영향을 받는다.
- 동일 스킬의 다단 공격은 상태이상 적용 시도를 스킬별 지정 횟수만 수행한다.
- 광역 공격은 각 대상에게 개별적으로 적용 확률을 계산한다.

### 예시

기본 적용 확률 70%, 상태 적중 보정 15%, 대상 RES 20인 경우:

```text
70 + 15 - 20 = 65%
```

## 8. 지속시간과 제어 저항

### 일반 지속시간

- 약화 효과와 지속 피해는 상태이상별 지속시간을 사용한다.
- 제어 효과는 TENACITY에 따라 지속시간이 감소한다.
- RES는 적용 확률에 영향을 주고, TENACITY는 적용된 제어 효과의 지속시간에 영향을 준다.

### 제어 효과 지속시간 공식

```text
최종 제어 지속시간 =
기본 지속시간
× 대상 등급 배율
× (1 - TENACITY 기반 지속시간 감소율)
× 연속 제어 배율
```

| 대상 | 기본 등급 배율 |
|---|---:|
| 플레이어 | 1.00 |
| 일반 몬스터 | 1.00 |
| 엘리트 몬스터 | 0.50 |
| 보스 | 직접 적용하지 않고 보스 정책 사용 |

- TENACITY 기반 지속시간 감소율은 `TENACITY / (100 + TENACITY)` 공식을 사용한다.
- 장비·증강의 별도 감소를 포함한 최종 제어 지속시간 감소율은 최대 60%다.
- 최종 `HARD_CC` 지속시간은 적용 성공 시 최소 0.25초다.
- `SOFT_CC`와 약화 효과의 최소 지속시간은 상태이상별로 설정한다.
- 상태이상 자체가 지속시간 감소 면역이면 TENACITY를 적용하지 않을 수 있다.

## 9. 대상 등급별 적용 정책

### 플레이어

- 상태이상 고유 규칙에 따라 정상 적용한다.
- 아군 공격으로도 공격에 포함된 상태이상이 적용될 수 있다.
- 아군 공격의 상태이상 적용 확률은 유지하되 강한 CC 지속시간은 원래 지속시간의 30%를 적용한다.
- 반복적인 강한 CC는 연속 제어 방지 규칙의 영향을 받는다.

### 일반 몬스터

- 대부분의 상태이상을 정상 적용한다.
- 일부 개체 특성은 특정 상태 면역을 가질 수 있다.
- 강한 CC가 전투를 지나치게 무력화하지 않도록 최대 지속시간을 설정할 수 있다.

### 엘리트 몬스터

- 약화 효과와 지속 피해는 상태이상별 규칙에 따라 적용한다.
- `HARD_CC`와 강한 위치 제어 지속시간은 기본 50%로 감소한다.
- 연속 제어 방지 규칙을 적용한다.
- 특정 엘리트 특성은 일부 상태에 면역일 수 있다.

### 보스

모든 상태이상은 다음 보스 적용 정책 중 하나를 가진다.

| 정책 | 처리 |
|---|---|
| `FULL` | 정상 적용 |
| `REDUCED` | 효과 강도 또는 지속시간 감소 후 적용 |
| `BREAK_CONVERT` | 직접 적용하지 않고 브레이크 피해로 변환 |
| `SCRIPTED` | 보스 패턴과 페이즈가 정의한 방식으로 적용 |
| `IMMUNE` | 적용하지 않음 |

- `HARD_CC`, `ROOT`, 강한 `FORCED_MOVE`는 기본적으로 `BREAK_CONVERT`를 사용한다.
- 둔화, 공격력 감소, 방어력 감소 등 약한 효과는 `REDUCED`를 사용할 수 있다.
- 지속 피해는 적용할 수 있지만 보스별 초당 피해 상한을 가진다.
- 보스에게 적용되지 않는 효과도 적중 및 변환 결과를 명확히 표시한다.

## 10. 중첩 방식

상태이상은 다음 중첩 방식 중 하나를 사용한다.

| 중첩 방식 | 처리 |
|---|---|
| `REFRESH` | 동일 효과 재적용 시 지속시간을 기본값으로 갱신 |
| `EXTEND` | 남은 지속시간에 추가 지속시간을 더함 |
| `STACK_INTENSITY` | 중첩 수에 따라 효과 강도 증가 |
| `STACK_INDEPENDENT` | 각 중첩이 독립된 지속시간과 틱을 가짐 |
| `REPLACE_STRONGER` | 더 강한 효과만 적용하고 약한 효과는 무시 |
| `UNIQUE_SOURCE` | 적용자별로 하나씩 독립 적용 |
| `NO_REFRESH` | 활성 중에는 다시 적용할 수 없음 |

### 공통 중첩 제한

- 모든 상태이상은 최대 중첩 수를 가진다.
- `EXTEND` 효과의 남은 지속시간은 기본 지속시간의 최대 200%까지만 늘릴 수 있다.
- `STACK_INDEPENDENT`는 성능 부담 때문에 일반적으로 최대 5중첩으로 제한한다.
- 같은 이름의 강한 CC는 일반적으로 강도를 중첩하지 않는다.
- 여러 출처의 동일 상태이상이 충돌하면 상태이상 고유 우선순위를 따른다.

## 11. 연속 제어 방지

강한 CC를 반복 적용하여 대상이 계속 행동하지 못하는 상황을 막기 위해 제어 감소 단계를 사용한다.

### 적용 대상

- `HARD_CC`
- 강한 `ROOT`
- 행동을 완전히 봉쇄하는 특수 상태

### 기본 연속 제어 단계

| 연속 적용 단계 | 지속시간 배율 |
|---:|---:|
| 첫 번째 | 100% |
| 두 번째 | 50% |
| 세 번째 이후 | 면역 |

- 강한 제어 효과가 종료되면 대상에게 연속 제어 단계가 기록된다.
- 마지막 강한 제어 종료 후 6초 동안 새로운 강한 제어가 없으면 단계를 초기화한다.
- 면역된 강한 제어는 적용되지 않으며 시각적으로 `제어 면역`을 표시한다.
- 강한 제어가 보스에게 브레이크 피해로 변환된 경우 연속 제어 단계를 증가시키지 않는다.
- 서로 다른 강한 CC도 같은 연속 제어 단계 그룹을 기본적으로 공유한다.

## 12. 상태이상 충돌과 우선순위

- 같은 종류의 이동속도 감소는 기본적으로 가장 강한 효과만 적용한다.
- 같은 능력치의 강화와 약화는 각각 합산 후 최종 계산 단계에서 서로 적용한다.
- 기절과 수면처럼 행동을 완전히 봉쇄하는 효과가 동시에 적용되면 남은 지속시간은 각각 유지하되 강한 효과 하나만 UI 최우선으로 표시한다.
- 수면처럼 피해로 해제되는 효과는 피해 처리 후 즉시 제거한다.
- 무장 해제와 침묵은 서로 다른 행동군을 제한하므로 동시에 적용할 수 있다.
- 강제 이동은 지속 상태가 아니라 즉시 효과로 처리하되 연속 제어 방지 태그를 가질 수 있다.

## 13. 해제와 정화

### 해제 분류

| 분류 | 설명 |
|---|---|
| `DISPELLABLE` | 일반 해제로 제거 가능 |
| `CLEANSE_ONLY` | 정화 효과로만 제거 가능 |
| `CONTROL_BREAK` | 제어 해제 전용 효과로 제거 가능 |
| `UNDISPELLABLE` | 지속시간 종료 또는 기믹으로만 제거 |
| `DEATH_ONLY` | 사망 또는 회차 종료로만 제거 |

### 해제 처리

- 해제 효과는 제거 가능한 상태이상 중 우선순위가 높은 효과부터 제거한다.
- 해제 우선순위는 강한 CC, 위험 DOT, 약화 효과 순서를 기본으로 한다.
- 하나의 해제가 제거할 수 있는 개수와 분류를 명시한다.
- 상태이상 해제 시 남은 피해나 효과를 소급하여 되돌리지 않는다.
- 연속 제어 단계는 강한 CC를 해제해도 유지한다.
- 해제 불가 상태는 UI에 자물쇠 표시를 제공한다.

## 14. 면역

- 면역은 특정 상태 ID, 분류 태그 또는 출처 태그를 대상으로 한다.
- 면역 상태에서도 상태이상 적용 시도 여부를 전투 로그에 기록할 수 있다.
- 면역된 상태이상은 중첩, 지속시간, 연속 제어 단계에 영향을 주지 않는다.
- 일시 면역은 시작과 종료를 명확히 표시한다.
- 모든 상태이상에 대한 장시간 완전 면역은 매우 제한적으로 제공한다.
- 보스 면역은 상태이상 빌드의 효과를 완전히 제거하지 않도록 브레이크 변환 또는 약화 효과를 우선 고려한다.

## 15. 지속 피해 공통 규칙

- 지속 피해는 상태이상별 틱 간격을 사용한다.
- 기본 권장 틱 간격은 1초다.
- 일반 모드의 실제 DOT 처리 간격은 최소 0.25초인 5틱이다.
- 카오스 모드의 실제 DOT 처리 간격은 최소 1틱이다.
- 카오스에서 논리 간격이 1틱보다 짧으면 1틱 동안의 피해량을 합산하고 공간 검색과 부가 판정은 틱당 한 번만 수행한다.
- 각 틱은 적용자의 스킬 실행 ID와 상태이상 출처를 유지한다.
- DOT는 치명타, 방어력, 방어 관통 적용 여부를 상태이상별로 명시한다.
- DOT로 플레이어의 커스텀 HP가 0이 되면 정상적으로 빈사 상태에 진입한다.
- DOT 피해는 방패 일반 방어와 패링으로 막을 수 없다.
- 회피는 이미 적용된 DOT를 제거하거나 무효화하지 않는다.
- 한 대상에 적용 가능한 전체 DOT 개수와 처리량에는 서버 성능 상한을 둔다.

## 16. 빈사·사망·부활 연계

### 빈사 진입

- `DEATH-001`에 따라 기절, 속박, 침묵, 무장 해제 등 행동 제한 상태이상을 제거한다.
- 화상, 독, 출혈 등 지속 피해는 유지하며 빈사 피해로 변환한다.
- 빈사 상태에서는 새로운 강한 행동 제한 CC를 적용하지 않는다.
- 둔화는 빈사 기본 이동속도에 추가 적용하지 않는다.

### 완전 사망

- 일반적인 전투 상태이상은 제거한다.
- 회차 단위 특수 표식이나 부활 관련 상태는 저장 정책에 따라 유지할 수 있다.
- 관전 상태에는 전투 상태이상을 적용하지 않는다.

### 부활

- 부활 완료 시 사망 전 일반 상태이상을 복원하지 않는다.
- 부활 보호와 부상 스택은 DEATH 시스템 규칙을 따른다.
- 회차 단위 특수 상태는 부활 후 다시 적용할 수 있다.

## 17. 아군 공격 및 소유권

- 아군 공격이 허용되므로 공격 스킬에 포함된 상태이상도 기본적으로 아군에게 적용될 수 있다.
- 아군 대상 넉백, 끌어당김, 강제 이동은 원래 세기를 적용하며 강한 CC 지속시간만 30%로 제한한다.
- 지원 스킬과 강화 효과는 명시적으로 아군 대상 정책을 가진다.
- 아군에게 상태이상을 적용해도 적 대상 전용 AP 환급, 증강 발동, 기여도 보상을 제공하지 않는다.
- 상태이상의 적용자와 원래 소유자를 기록하여 처치, 기여도, 해제 효과를 계산한다.
- 반사된 투사체와 소환물은 최종 소유자와 원래 소유자를 모두 기록할 수 있다.

## 18. 상태이상 시간 처리

- 상태이상 시간은 서버가 관리하는 남은 지속시간을 기준으로 처리한다.
- 회차가 정상 중단되거나 서버에 생존 플레이어가 없어 콘텐츠가 정지하면 상태이상 시간도 정지한다.
- 접속 종료한 플레이어의 상태이상 시간은 회차가 진행 중이면 상태별 저장 정책에 따라 계속 흐르거나 정지한다.
- 공세와 보스 AI 정지 중에는 해당 개체의 상태이상 시간도 정지한다.
- 낮은 TPS에서도 실제 지속시간이 과도하게 늘어나지 않도록 경과 시간 기반 처리를 우선 검토한다.

## 19. 저장 정책

상태이상은 다음 저장 정책 중 하나를 가진다.

| 정책 | 처리 |
|---|---|
| `PERSIST` | 남은 시간, 중첩, 출처를 저장하고 복원 |
| `CLEAR_ON_LOGOUT` | 접속 종료 시 제거 |
| `CLEAR_ON_PAUSE` | 회차 정상 중단 또는 서버 종료 시 제거 |
| `CLEAR_ON_DEATH` | 완전 사망 시 제거 |
| `SESSION_PERSIST` | 세션 종료까지 유지 |
| `RUN_PERSIST` | 회차 종료까지 유지 |

- 짧은 전투 CC는 기본적으로 `CLEAR_ON_PAUSE`를 사용한다.
- DOT와 장시간 약화 효과는 필요에 따라 `PERSIST`를 사용한다.
- 저장한 상태이상의 출처가 존재하지 않아도 효과 자체는 남은 시간 동안 복원할 수 있다.
- 중복 적용과 보상 악용을 방지하기 위해 상태 인스턴스 ID를 저장한다.

# STATUS-002 개별 상태이상 및 연속 CC 방지

## 1. 작업 범위

`STATUS-002`는 실제 전투에서 사용될 개별 상태이상의 기본값과 충돌 규칙을 정의한다.

- 상태이상 기본 목록은 `기절`, `속박`, `침묵`, `무장 해제`, `공중 띄움`, `수면`, `공포`, `도발`, `둔화`, `화상`, `독`, `출혈`, `약화`, `취약`, `방어력 감소`, `받는 회복 감소`로 한다.
- `빙결`, `실명`, `탈진`, `표식`은 이번 문서에서 확장 템플릿만 정의하고, 실제 사용 여부와 수치는 스킬 목록 작업에서 확정한다.
- 각 상태는 기본 지속시간과 기본 강도를 가지되, 스킬 데이터에서 지속시간, 강도, 적용 확률, 보스 정책, 중첩 방식을 오버라이드할 수 있다.
- 모든 상태의 최종 적용은 `STATUS-001`의 공통 적용 파이프라인을 따른다.
- 이 장의 연속 CC 규칙은 `STATUS-001` 11장의 기본안을 대체하는 상세 규칙이다.

## 2. 상태 데이터 공통 필드

개별 상태 데이터는 다음 필드를 가진다.

| 필드 | 설명 |
|---|---|
| `id` | 상태 고유 ID |
| `display-name` | 플레이어에게 표시되는 이름 |
| `tags` | `DOT`, `HARD_CC`, `ROOT`, `DEBUFF` 등 분류 태그 |
| `mode-values.standard` | 일반 모드 기본값 |
| `mode-values.chaos` | 카오스 모드 기본값 |
| `base-duration-sec` | 기본 지속시간 |
| `max-pre-resist-duration-sec` | RES, TENACITY, 방어, 연속 CC 감소 전 최대 지속시간 |
| `base-strength` | 피해량, 감속률, 감소율 등 상태의 기본 강도 |
| `resist-policy` | `RESISTIBLE`, `GUARANTEED`, `CONDITIONAL`, `SCRIPTED` |

| `boss-policy` | `FULL`, `REDUCED`, `BREAK_CONVERT`, `SCRIPTED`, `IMMUNE` |

기본값은 데이터 누락 방지를 위한 기준이며, 특정 스킬은 스킬 데이터에 더 강한 제한을 명시할 수 있다.

### 4.5 공중 띄움 `AIRBORNE`

| 항목 | 값 |
|---|---|
| 분류 | `HARD_CC`, `FORCED_MOVE`, `CONTROL` |
| 일반 모드 기본 지속시간 | 0.5초 |
| 일반 모드 저항 전 최대 지속시간 | 4초 |
| 카오스 모드 기본 지속시간 | 0.7초 |
| 카오스 모드 저항 전 최대 지속시간 | 5초 |
| 저항 | 가능 |
| TENACITY | 행동 제한 시간에만 적용 |
| 보스 정책 | 기본 `BREAK_CONVERT` |
| 중첩 | `REFRESH`, 더 강한 수직 벡터와 긴 행동 제한 우선 |
| 해제 | `CONTROL_BREAK` |
| 시각 표시 | 위쪽 화살표, 공중 고정 링 |

공중 띄움은 `물리 이동`과 `행동 제한`을 분리해서 처리한다.

- 물리 이동은 스킬이 지정한 수직·수평 벡터를 즉시 적용한다.
- TENACITY는 물리 이동 세기를 줄이지 않고, 공중 띄움으로 인해 공격·스킬·회피·방어가 막히는 행동 제한 시간만 줄인다.
- 이유는 마인크래프트 물리와 충돌 판정상 벡터를 매번 줄이면 지형, 천장, 넉백 저항, 서버 TPS에 따라 결과가 크게 흔들리기 때문이다.
- 대상이 천장에 부딪히거나 지면에 빨리 닿아도 행동 제한은 계산된 최종 지속시간까지 유지된다.
- 아군에게 적용된 공중 띄움은 이동 벡터를 원래 세기로 적용하되 행동 제한 시간은 아군 강한 CC 규칙에 따라 30%만 적용한다.

## 5. 둔화와 능력 약화 상태

### 5.1 둔화 `SLOW`

| 항목 | 값 |
|---|---|
| 분류 | `DEBUFF`, `SOFT_CC` |
| 기본 지속시간 | 3초 |
| 기본 강도 | 이동속도 -30% |
| 최대 감속률 | 80% |
| 저항 | 가능 |
| 보스 정책 | 기본 `REDUCED` |
| 중첩 | 강도 우선 대기열 |
| 시각 표시 | 파란 발자국, 느려진 발밑 파티클 |

둔화는 가장 강한 효과를 우선 적용하고, 같은 강도라면 남은 지속시간이 긴 효과를 우선한다. 약한 둔화는 사라지지 않고 대기한다.

예시:

1. 20% 둔화 5초가 적용된다.
2. 1초 뒤 30% 둔화 2초가 적용된다.
3. 실제 적용은 20% 1초, 30% 2초, 남은 20% 2초가 된다.

최종 이동속도는 기존 `SPD` 규칙에 따라 최소 1%를 유지한다.

### 5.4 방어력 감소 `ARMOR_BREAK`

| 항목 | 값 |
|---|---|
| 분류 | `DEBUFF` |

| 기본 강도 | 고정 DEF -20 |
| 기본 방식 | 고정 DEF 감소 |
| 선택 방식 | 최종 DEF 비율 감소 |
| 일반 모드 비율 감소 상한 | 80% |
| 카오스 모드 비율 감소 상한 | 98% |

| 보스 정책 | 기본 `REDUCED` |

방어력 감소는 기본적으로 고정 DEF 감소를 사용한다. 고정 감소와 비율 감소가 함께 있을 경우 고정 감소를 먼저 적용한 뒤 비율 감소를 적용한다. 상태이상으로 인한 DEF 감소는 대상을 0 미만의 DEF로 만들 수 없다.

| 기본 강도 | 받는 회복량 -30% |
| 상한 | -99% |
| 저항 | 가능 |
| 보스 정책 | 기본 `REDUCED` |
| 중첩 | `REPLACE_STRONGER`, 같은 강도는 긴 지속시간 우선 |
| 시각 표시 | 갈라진 십자가 또는 검은 회복 아이콘 |

받는 회복 감소는 보호막 획득량에 영향을 주지 않는다. 보호막 효율 감소는 별도 상태로 분리한다.

## 6. DOT 상태

### 6.1 DOT 공통 처리

- 기본 DOT는 피해 보정, 받는 피해 보정, DEF, PEN, 보호막, 빈사 전환을 적용한다.
- 기본 DOT는 치명타를 적용하지 않는다.
- DOT 생명력 흡수는 지속 피해 효율인 40%를 적용한다.
- DOT의 공격자 스탯, 피해 계수, 원본 스킬 데이터는 적용 순간 스냅샷한다.
- 대상의 DEF, Damage Taken, 보호막, 면역, 빈사 상태는 각 틱마다 실시간 값을 사용한다.
- 최대 HP 비례 DOT는 상태 기본 기능과 스킬 옵션 양쪽에서 허용한다.
- 보스에게 최대 HP 비례 DOT를 적용할 경우 보스별 개별 1회 상한과 초당 상한을 반드시 가진다.
- 피해가 0인 공격은 기본적으로 상태를 적용하지 않는다. 단, 상태 효과에 `APPLY_STATUS_ON_ZERO_DAMAGE`가 있으면 적용할 수 있다.
- 보호막이 피해를 전부 흡수해도 공격이 적중했다면 상태이상은 적용된다. 단, 상태에 `requires-hp-damage: true`가 있으면 실제 HP 피해가 있을 때만 적용된다.

### 6.2 화상 `BURN`

| 항목 | 값 |
|---|---|
| 분류 | `DOT`, `DEBUFF` |
| 기본 지속시간 | 5초 |
| 틱 간격 | 1초 |
| 중첩 | `STACK_INTENSITY` |
| 최대 중첩 | 5 |
| 재적용 | 전체 지속시간 갱신 |
| 저항 | 가능 |
| 보스 정책 | `REDUCED`, DPS 상한 적용 |
| 시각 표시 | 불꽃 아이콘, 약한 불 파티클 |

화상은 중첩 수에 따라 틱 피해 강도가 증가한다. 새 화상이 적용되면 중첩을 올리고 모든 화상 중첩의 지속시간을 기본 지속시간으로 갱신한다.

### 6.3 독 `POISON`

| 항목 | 값 |
|---|---|
| 분류 | `DOT`, `DEBUFF` |
| 기본 지속시간 | 6초 |
| 틱 간격 | 1초 |
| 중첩 | `UNIQUE_SOURCE` |
| 출처당 중첩 | 1 |
| 전체 최대 출처 | 5 |
| 저항 | 가능 |
| 보스 정책 | `REDUCED`, DPS 상한 적용 |
| 시각 표시 | 초록 방울 아이콘, 독 입자 |

독은 적용자 또는 원본 스킬 출처별로 하나씩 유지된다. 같은 출처의 독은 갱신하고, 다른 출처의 독은 최대 출처 수까지 별도로 유지한다.

### 6.4 출혈 `BLEED`

| 항목 | 값 |
|---|---|
| 분류 | `DOT`, `DEBUFF` |
| 기본 지속시간 | 6초 |
| 틱 간격 | 1초 |
| 중첩 | `STACK_INDEPENDENT` |
| 최대 중첩 | 5 |
| 저항 | 가능 |
| 보스 정책 | `REDUCED`, DPS 상한 적용 |
| 시각 표시 | 붉은 물방울 아이콘 |

출혈은 각 중첩이 독립적인 남은 시간을 가진다. 기본 출혈은 이동 여부에 따른 추가 피해를 주지 않는다. 이동 연동 출혈은 별도 상태 변형 또는 스킬 옵션으로 정의한다.

## 7. 확장 상태 템플릿

| 상태 | 임시 ID | 기본 방향 | 실제 사용 확정 |
|---|---|---|---|
| 빙결 | `FREEZE` | 기절과 둔화를 결합한 강한 제어, 보스는 기본 `BREAK_CONVERT` | 스킬 목록에서 확정 |
| 실명 | `BLIND` | 시야 방해와 원거리 명중 보정 감소, 보스 전조는 가리지 않음 | 스킬 목록에서 확정 |
| 탈진 | `EXHAUSTION` | AP 회복 감소 또는 AP 비용 증가 | 스킬 목록에서 확정 |
| 표식 | `MARK` | 후속 스킬 조건, 추가 피해, 추적, 기믹 연결용 상태 | 스킬 목록에서 확정 |

확장 상태는 기본 시스템에 등록 가능하지만, 초기 밸런스에서는 실제 스킬이 참조하기 전까지 등장하지 않는다.

## 8. 연속 CC 방지

### 8.1 강한 CC 그룹

다음 효과는 같은 강한 CC 그룹을 공유한다.

- 기절
- 수면
- 공포
- 빙결
- 공중 띄움
- 강한 속박
- 행동을 사실상 모두 막는 특수 상태

### 8.2 2초 체인 기준

강한 CC는 짧은 단발 제어와 장시간 행동 봉쇄를 분리해서 처리한다.

- 강한 CC가 끊기지 않고 누적 2초 미만으로 이어지는 동안에는 연속 CC 단계가 증가하지 않는다.
- 강한 CC가 끊기지 않고 2초 이상 이어진 뒤, 추가 강한 CC가 적용 또는 연장에 성공하면 그 시점부터 연속 CC 단계를 증가시킨다.
- 연속 CC 단계는 상태 종료 시점이 아니라 적용 성공 즉시 증가한다.
- 같은 상태의 갱신이나 연장도 실제 지속시간이 늘어났다면 연속 CC 단계 증가 대상으로 본다.

### 8.3 단계별 지속시간

| 단계 | 조건 | 지속시간 배율 |
|---:|---|---:|
| 0 | 2초 체인 기준 도달 전 | 100% |
| 1 | 2초 이상 체인 후 첫 추가 강한 CC | 100% |
| 2 | 두 번째 추가 강한 CC | 50% |
| 3 이상 | 세 번째 이후 추가 강한 CC | 면역 |

- 면역된 강한 CC 시도는 적용되지 않으며, 초기화 시간을 연장하지 않는다.
- 보스에게 강한 CC가 브레이크 피해로 변환된 경우 연속 CC 단계를 증가시키지 않는다.
- 같은 틱에 여러 강한 CC가 들어오면 상태 우선순위, 적용 시각, 실행 ID 순서로 처리하고, 후순위 효과에는 이미 증가한 단계를 적용한다.

### 8.4 초기화와 과제어 보호

- 강한 CC가 모두 종료된 뒤 6초 동안 새 강한 CC가 없으면 체인 누적 시간과 연속 CC 단계를 초기화한다.
- 강한 CC가 끊기지 않고 2초 체인 기준을 넘기면 별도의 과제어 감시 타이머 6초를 시작한다.
- 과제어 감시 타이머가 끝나는 시점에도 대상이 여전히 강한 CC 상태라면 `ANTI_CHAIN_ALL_STATUS_IMMUNITY`를 6초 부여한다.
- `ANTI_CHAIN_ALL_STATUS_IMMUNITY` 발동 시 현재 활성화된 강한 CC와 강한 속박은 제거한다.
- 이 면역은 모든 신규 상태이상 적용, 갱신, 연장을 막는다.
- 기존 DOT와 일반 약화 상태는 즉시 제거하지 않지만, 면역 시간 동안 갱신되거나 연장되지 않는다.

이 규칙은 플레이어가 장시간 아무 행동도 하지 못하는 상황을 막기 위한 안전장치다. 단발 제어기는 그대로 살리고, 2초 이상 이어지는 제어 사슬부터 강하게 제한한다.

### 8.5 제어 해제 후 면역

제어 해제 스킬 또는 아이템으로 강한 CC를 해제하면 해당 강한 CC 그룹에 대해 0.5초 면역을 부여한다. 이 면역은 신규 강한 CC만 막고 DOT나 일반 약화 상태에는 영향을 주지 않는다.

## 9. 침묵·무장 해제 연속 방지

침묵과 무장 해제는 강한 CC와 별도의 행동 제한 그룹을 사용한다.

| 단계 | 지속시간 배율 |
|---:|---:|
| 1 | 100% |
| 2 | 70% |
| 3 | 40% |
| 4 이상 | 면역 |

- 마지막 행동 제한 종료 후 6초 동안 새 침묵 또는 무장 해제가 없으면 단계를 초기화한다.
- 침묵과 무장 해제는 같은 그룹을 공유한다.
- 같은 틱에 들어온 침묵과 무장 해제는 우선순위와 실행 ID 순서로 처리한다.

## 10. 강제 이동 내성

넉백, 끌어당김, 밀쳐내기처럼 즉시 위치를 바꾸는 효과는 별도 이동 내성을 사용한다.

| 단계 | 이동 세기 |
|---:|---:|
| 1 | 100% |
| 2 | 70% |
| 3 | 40% |
| 4 이상 | 20% |

- 마지막 적대 강제 이동 후 3초가 지나면 단계를 초기화한다.
- 아군 강제 이동은 기존 규칙대로 원래 세기 100%를 적용한다.
- 아군 강제 이동은 기여도, 활동 EXP, 공격 보상에 영향을 주지 않는다.

## 11. 아군 상태이상 규칙

아군 공격은 허용되지만, 보상 악용과 장시간 방해를 막기 위해 별도 배율을 적용한다.

| 항목 | 처리 |
|---|---|
| 아군 커스텀 공격 피해 | 최종 피해 30% |
| 아군 강한 CC 지속시간 | `기본시간 × 30% × TENACITY × 연속 CC 배율` |
| 아군 강한 CC 최소 지속시간 | 1틱 |
| 아군 넉백·끌어당김·강제 이동 | 원래 세기 100% |
| 아군 브레이크 피해 | 50% |
| 아군 회복 | 100% |
| 아군에게 적용한 상태 보상 | 기여도, 활동 EXP, 공격 보상 미지급 |

적대 강한 CC의 최소 지속시간은 0.25초다. 아군 강한 CC는 30% 배율을 적용한 뒤 1틱을 최소값으로 사용한다.

## 12. 방어, 회피, 패링과 상태이상

| 상황 | 상태이상 처리 |
|---|---|
| 회피 무적 성공 | 공격에 포함된 피해, 상태, 강제 이동 모두 무효 |
| 패링 성공 | 공격에 포함된 피해, 상태, 강제 이동 모두 무효 |
| 일반 방어 성공 | 피해는 방어 규칙대로 감소, 상태 지속시간 50% 감소 |
| 일반 방어 성공과 저항 가능 상태 | 적용 확률은 감소하지 않음 |
| 보호막이 피해 전부 흡수 | 명중했다면 상태 적용 가능 |
| `requires-hp-damage: true` | 실제 HP 피해가 1 이상일 때만 상태 적용 |
| 피해 0 | 기본 상태 적용 불가, `APPLY_STATUS_ON_ZERO_DAMAGE`가 있을 때만 가능 |

일반 방어의 상태이상 50% 감소는 지속시간 감소로만 처리한다. 적용 확률에는 영향을 주지 않는다.

## 13. 보스와 엘리트 정책

- 엘리트의 `HARD_CC` 지속시간 50% 감소 규칙을 유지한다.
- 보스에게 적용되는 둔화, 약화, 취약, 방어력 감소는 기본 강도 50%, 지속시간 50%로 제한한다.
- 보스의 강한 CC, 강한 속박, 강한 강제 이동은 기본적으로 `BREAK_CONVERT`를 사용한다.
- 브레이크 변환의 실제 수치와 공식은 `BREAK-001 브레이크 게이지 및 피해`의 상태 변환 브레이크 피해 규칙을 따른다.
- 이번 문서에서는 변환 계수 필드만 정의한다.

### 브레이크 변환 필드

```yaml
boss-conversion:
  policy: BREAK_CONVERT
  break-damage-base: 0
  break-damage-scaling: []
  convert-duration-to-break: true
  convert-strength-to-break: true
  notes: "BREAK-001 상태 변환 브레이크 피해 공식 참조"
```

## 14. 접속 종료와 저장

- 접속 종료 시 짧은 CC는 제거한다.
- DOT와 일반 약화 상태는 세션 시간이 흐르는 동안 남은 시간이 감소한다.
- 오프라인 상태에서는 DOT 피해를 실제로 누적 적용하지 않는다.
- 재접속 시 오프라인 누적 피해를 한 번에 적용하지 않는다.
- 서버에 아무도 없어 Day가 정지한 경우 상태 시간도 콘텐츠 시간 기준으로 정지한다.
- 보스전 정지, 세션 중단, 서버 종료는 상태별 저장 정책을 따른다.

## 15. 활성 상태 상한

| 모드 | 대상당 전체 상태 인스턴스 상한 | 대상당 DOT 인스턴스 상한 |
|---|---:|---:|
| 일반 모드 | 64 | 32 |
| 카오스 모드 | 128 | 64 |

- 상한에 도달하면 시각 우선순위가 낮고 전투 영향이 낮은 상태부터 신규 적용을 거부한다.
- 강한 CC, 위험 DOT, 보스 기믹 상태는 일반 약화보다 우선한다.
- 같은 상태의 갱신은 신규 인스턴스 생성이 아니므로 상한을 추가로 소모하지 않는다.

## 16. UI 표시 규칙

상태이상 UI는 플레이어 설정에 따라 간단 표시와 상세 표시를 제공한다.

| 표시 방식 | 표시 정보 |
|---|---|
| 간단 표시 | 아이콘, 남은 시간, 중첩 수, 위험도 색상 |
| 상세 표시 | 아이콘, 이름, 출처, 남은 시간, 중첩, 저항 여부, 해제 가능 여부, 보스 변환 여부 |

표시 우선순위는 강한 CC, 위험 DOT, 일반 약화 순서다. 같은 우선순위에서는 남은 시간이 짧고 즉시 대응이 필요한 상태를 먼저 보여준다.

| 테스트 | 확인 목적 |
|---|---|
| 기절, 속박, 침묵, 무장 해제 행동 차단 | 상태별 차단 범위 검증 |
| 공중 띄움 벡터와 행동 제한 분리 | TENACITY가 물리 이동 세기를 줄이지 않는지 검증 |
| 수면 중 DOT 피해 | DOT가 수면을 해제하지 않는지 검증 |
| 도발 대상 제한 | 같은 팀 미적용과 플레이어 대상 검증 방식 확인 |
| 둔화 대기열 | 강한 둔화 종료 후 약한 둔화가 남은 시간만큼 복귀하는지 검증 |
| 화상, 독, 출혈 중첩 | 세 DOT 중첩 방식 차이 검증 |
| 2초 이상 하드 CC 체인 | 2초 전에는 미증가, 이후 단계 증가 검증 |
| 6초 과제어 보호 | 장시간 하드 CC 시 모든 상태이상 면역 6초 부여 검증 |
| 침묵·무장 해제 연속 방지 | 100%, 70%, 40%, 면역 단계 검증 |
| 일반 방어 상태 지속시간 감소 | 적용 확률은 유지되고 지속시간만 50% 감소하는지 검증 |
| 보호막 전부 흡수 | `requires-hp-damage` 여부에 따른 상태 적용 검증 |
| 접속 종료와 재접속 | 오프라인 피해 미누적, 남은 시간 감소 검증 |
| 활성 상태 상한 | 일반 모드 64/32, 카오스 128/64 상한 검증 |

## 19. STATUS-002 완료 기준

- 기본 상태 목록의 지속시간, 저항 여부, 보스 정책, 중첩 규칙, 시각 표시가 정의되어 있다.
- 기절, 속박, 침묵, 무장 해제, 공중 띄움, 수면, 공포, 도발의 행동 제한 범위가 구분되어 있다.
- 화상, 독, 출혈의 DOT 중첩 방식과 피해 보정 규칙이 분리되어 있다.
- 둔화, 약화, 취약, 방어력 감소, 받는 회복 감소의 상한과 계산 방향이 명시되어 있다.
- 2초 이상 하드 CC 체인 감지와 6초 과제어 보호가 정의되어 있다.
- 아군 공격, 방어, 패링, 회피, 보호막, 0 피해 상황에서 상태이상 적용 규칙이 충돌하지 않는다.
- 보스와 엘리트에 대한 약화, DOT, CC 정책이 후속 브레이크 기획과 연결되어 있다.
- 접속 종료, 저장, UI, 성능 상한이 구현 가능한 형태로 정리되어 있다.
