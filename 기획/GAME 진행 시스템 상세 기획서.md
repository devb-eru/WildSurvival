# WildSurvival GAME 진행 시스템 상세 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 프로젝트 | WildSurvival |
| 콘텐츠 형태 | 2~4인 협동 하드코어 야생 생존 RPG |
| 구현 환경 | Minecraft Java Edition, 바닐라 + 서버 플러그인 |
| 모드 사용 | 없음 |
| 카테고리 | GAME 진행 및 난이도 시스템 |
| 문서 상태 | GAME 카테고리 상세 기획 진행 중 |
| 최종 수정일 | 2026-06-23 |

## 확정된 핵심 방향

- 플레이어 전원은 하나의 팀으로 협력한다.
- 자유 야생에서 탐험, 발견, 자원 수집, 제작, 연구를 진행하고 필요한 시설망을 선택적으로 건설한다.
- 전체 콘텐츠는 Day 1~50으로 구성한다.
- Day 하나는 현실 시간 7분이며, 서버에 생존 플레이어가 없으면 진행하지 않는다.
- 한 번의 권장 플레이 단위는 Day 10개이며, 중단 후 이어서 진행할 수 있다.
- Day 10, 20, 30, 40, 50에는 보스가 등장한다.
- 보스를 처치하기 전까지 다음 Day로 진행하지 않는다.
- 전원 완전 사망 시 해당 회차는 즉시 실패하며 일반적인 방법으로 재개할 수 없다.
- 회차 시작 멤버를 고정하며 신규 중도 참여는 허용하지 않는다. 기존 멤버의 접속 종료와 재접속은 허용한다.
- 기본 아군 피해는 차단한다. 회차 시작 시 선택한 전술 모드에서만 비치명·악용 방지 규칙과 함께 제한적으로 허용한다.
- 회차 생성 시 `Easy`, `Normal`, `Hard`, `Challenge`, `???` 중 하나의 난이도를 선택하며 진행 중 변경할 수 없다.

## 회차 난이도 공통 규칙

| 표시 난이도 | 내부 ID | 투자 전 표시 HP | HP 배율 |
|---|---|---:|---:|
| Easy | `EASY` | 1,800 | 1.80 |
| Normal | `NORMAL` | 1,000 | 1.00 |
| Hard | `HARD` | 800 | 0.80 |
| Challenge | `CHALLENGE` | 500 | 0.50 |
| ??? | `UNKNOWN` | 100 | 0.10 |

- 난이도는 회차 생성 단계에서 파티가 확정한다.
- 활성 회차에서는 난이도를 변경할 수 없다.
- 표의 수치는 `Normal 기준 HP 1,000`에 난이도 배율을 적용한 표시 예시다. 실제로는 기본·투자·고정 장비 보너스 합계 전체에 동일 난이도 배율을 적용한다.
- 몬스터 난이도 보정은 플레이어 HP 배율과 분리하여 관리한다.
- 난이도별 오염 피해 DEF 효율과 추천 스탯 분배는 `STAT-001`을 따른다.
- 선택 난이도는 저장 데이터, 종료 기록, 통계에 기록한다.

## 회차 규칙 모드

| 표시명 | 내부 ID | 핵심 방향 |
|---|---|---|
| 일반 모드 | `STANDARD` | 기존 수치 한계와 5틱 채널링 최소 간격 |
| 카오스 모드 | `CHAOS` | BigNumber 전투 수치와 1틱 채널링 최소 간격 |

- 규칙 모드와 난이도는 서로 독립적으로 선택한다.
- 회차 생성 시 확정하고 진행 중 변경할 수 없다.
- 카오스 모드에서도 기존 난이도 중 하나를 별도로 선택한다.
- 규칙 모드는 저장 데이터, 종료 기록과 통계에 기록한다.

# GAME-001 Day 타이머 시스템

## 1. 시스템 목적

Day 시스템은 콘텐츠 전체의 진행 속도와 긴장도를 통제한다.

- 전체 콘텐츠 진행도를 표시한다.
- 탐험, 정비, 귀환, 방어 시점을 안내한다.
- 시간이 흐를수록 세계 오염도와 적 난이도를 증가시킨다.
- 정해진 Day마다 보스전을 시작한다.
- 플레이어가 안전한 상태에서 무기한 성장하는 것을 방지한다.

## 2. 기본 진행 규칙

| 항목 | 규칙 |
|---|---|
| 전체 진행 기간 | Day 1~50 |
| Day당 시간 | 현실 시간 7분 |
| 기본 전체 플레이 시간 | 약 5시간 50분 + 보스전 |
| 권장 1회 플레이 분량 | Day 10일 |
| Day 진행 방식 | 서버 공용 타이머 |
| 침대 사용 | 밤 건너뛰기 불가 |
| 서버 무인 상태 | 타이머 및 콘텐츠 진행 정지 |
| 보스전 진행 중 | 타이머 정지 |
| 콘텐츠 중단 | 현재 상태를 저장하고 재개 가능 |
| 패배 조건 | 모든 플레이어 완전 사망 |
| 최종 승리 조건 | Day 50 보스 처치 및 세계 붕괴 핵 정화 |

Day 타이머는 마인크래프트 월드 시간과 별도로 관리한다. 월드의 태양과 달은 연출 목적으로 Day 타이머에 맞출 수 있지만, 월드 시간 자체를 콘텐츠 진행 기준으로 사용하지 않는다.

## 3. Day 내부 단계

| 단계 | 남은 시간 | 주요 목적 |
|---|---:|---|
| 활동 단계 | 07:00~03:00 | 야생 탐험, 채집·광질, 제작, 연구, 시설 건설 |
| 경고 단계 | 03:00~01:30 | 동적 압박 모드와 위험 방향 예고, 방어·이동 준비 |
| 공세 단계 | 01:30~00:00 | 정착지 습격·파티 추적·균열 압박 중 하나 실행 |

### 활동 단계

- 플레이어가 자유롭게 야생을 탐험한다.
- 제작 재료와 정화 자원을 확보한다.
- 아이템, 몬스터, 오염, 시설과 관련된 연구 단서를 확보하거나 분석한다.
- 플레이어 시설을 건설하거나 수리한다.
- 수집, 제작, 연구 성과를 바탕으로 다음 공세의 방어 전략을 조정한다.
- 일반 몬스터와 소규모 오염 무리가 등장한다.
- 더 위험한 자연 환경과 동적 사건에서 높은 보상을 획득할 수 있다.
- Day 번호의 일의 자리가 3, 6, 9인 경우 파티 활동 전략을 선택한다.
- Day 1에는 활동 전략을 선택하지 않는다.
- 보스 Day에는 일반 활동 전략 대신 보스 전용 전략을 선택한다.
- Hard 이상에서는 일정 Day에 일반 적군 전략이 등장하며, 보스 Day와 겹치면 보스 전용 적군 전략과 함께 적용한다.
- 전략 선택, 지속, 목표, 적군 전략과 연구 정보는 `ACT-001`을 따른다.

### 경고 단계

- 화면과 사운드로 공세 접근을 알린다.
- 현재 압박 모드와 위험 방향을 안내한다.
- 목표 파티 또는 활성 시설망 주변의 유효 지형에 적 선발대가 등장한다.
- 야생의 몬스터 생성률과 오염 노출 위험이 증가한다.
- 플레이어는 계속 탐험할 수 있지만 귀환하지 않을 위험을 감수해야 한다.

### 공세 단계

- 공세 적은 `BASE-002`의 동적 압박 모드에 따라 플레이어, 이동 경로 또는 활성 시설망을 공격한다.
- 공세 적은 일반 야생 몬스터보다 강한 전용 개체로 구성한다.
- 공세 시간이 끝나도 남은 주요 공세 적은 사라지지 않는다.
- 보스 Day가 아니라면 남은 공세 적이 있어도 시간 흐름에 따라 다음 Day로 넘어간다.
- 남은 공세 적은 잔존 압박 상태로 약화되며 목표 시설망 또는 주변 지역에 오염 압박을 남긴다.

## 4. Day 종료 조건

### 일반 Day

다음 조건을 만족하면 다음 Day로 진행한다.

1. Day 타이머가 `00:00`에 도달한다.

타이머가 끝났지만 공세 적이 남았다면 해당 적은 `잔존 공세 상태`로 전환된다.

- 다음 Day는 정상적으로 시작한다.
- 잔존 주요 공세 적의 위치를 10초마다 표시한다.
- 잔존 공세 상태가 길어질수록 해당 지역 또는 목표 시설망 오염도가 증가한다.
- 일반 잡몹은 약화된다.
- 일반 시설 이용은 가능하지만, 잔존 적을 이용한 무한 파밍을 방지하기 위해 추가 보상은 제한한다.

### 보스 Day

보스 Day는 `Day 10`, `20`, `30`, `40`, `50`이다.

보스 Day의 타이머가 `00:00`에 도달하면 다음 순서로 진행한다.

1. 일반 밤 공세를 생성하지 않고 보스전 전환을 준비한다.
2. 보스 등장 경고 연출을 시작한다.
3. Day 타이머를 정지한다.
4. 보스를 소환하고 보스전을 시작한다.
5. 보스를 처치할 때까지 다음 Day로 진행하지 않는다.

보스전에는 제한 시간을 두지 않는다. 무한 대치와 안전한 파밍을 방지하기 위해 보스전 중에는 다음 규칙을 적용한다.

- 보스의 동적 전장과 연결된 지역·시설망 오염도가 서서히 증가한다.
- 보스는 전투 이탈로 체력을 자연 회복하지 않는다.
- 야생 탐험 보상과 일반 몬스터 보상을 크게 제한한다.
- 보스가 일정 시간 동안 전투 대상을 찾지 못하면 가장 가까운 생존 파티원 또는 활성 재건 시설을 추적한다.
- 등록 멤버가 보스전 도중 재접속하면 기존 캐릭터 상태로 복귀한다.

## 5. Day 10 단위 세션 구조

한 세션의 기본 타이머 진행 시간은 약 70분이며, 보스전과 세션 정산 시간은 별도로 추가된다.

| 세션 | 진행 구간 | 최종 목표 |
|---|---|---|
| 세션 1 | Day 1~10 | 첫 번째 보스 처치 |
| 세션 2 | Day 11~20 | 상태이상 보스 처치 |
| 세션 3 | Day 21~30 | 오염 보스 처치 |
| 세션 4 | Day 31~40 | 브레이크 보스 처치 |
| 세션 5 | Day 41~50 | 세계 붕괴 핵 정화 |

보스 처치 후에는 `세션 정산 단계`로 진입한다.

- Day 타이머를 정지한다.
- 보스 공용 보상을 지급한다.
- 개인 기여도 보상을 지급한다.
- Day 10·20·30·40 정산에서만 파티 증강을 선택한다. Day 50에는 추가 파티 증강 없이 최종 정산한다.
- 현재 상태를 자동 저장한다.
- 다음 세션 시작 여부를 투표한다.

다음 세션 시작 투표는 접속 중인 생존 플레이어 과반수의 동의로 결정한다. 부결되면 콘텐츠를 정상 중단한다. Day 50 보스 처치 후에는 최종 정산과 엔딩으로 진행한다.

## 6. 서버 접속 상태 처리

### 서버에 생존 플레이어가 없는 경우

- Day 타이머를 정지한다.
- 공세 및 보스 AI를 정지한다.
- 오염도 증가를 정지한다.
- 시설 작동과 자원 생산을 정지한다.
- 현재 상태를 자동 저장한다.

### 생존 플레이어가 다시 접속한 경우

- 저장된 진행 상태를 불러온다.
- 첫 생존 플레이어 접속 후 10초의 준비 시간을 제공한다.
- 준비 시간 종료 후 Day와 콘텐츠 AI를 재개한다.

### 관전자만 남은 경우

- 회차에 등록된 생존 가능 플레이어가 모두 완전 사망했다면 콘텐츠 실패로 처리한다.
- 아직 생존한 접속 종료 플레이어가 있다면 실패로 처리하지 않고 진행만 정지한다.
- 관전자 존재 여부와 관계없이 Day는 진행하지 않는다.

## 7. 콘텐츠 정상 중단

### 중단 가능 조건

- 보스전 진행 중이 아니다.
- 공세 또는 잔존 공세 상태가 아니다.
- 빈사 상태인 플레이어가 없다.
- 파티원 및 사용하려는 세션 시설 주변에 적이 없다.

### 중단 방식

- 등록된 세션 시설 GUI 또는 전용 명령어를 통해 중단 투표를 시작한다.
- 접속 중인 생존 플레이어 과반수의 동의가 필요하다.
- 승인 후 10초 카운트다운을 진행한다.
- 카운트다운 중 중단 가능 조건이 깨지면 취소한다.
- 완료 시 현재 상태를 저장하고 콘텐츠를 `PAUSED` 상태로 전환한다.

중단 기능은 위험한 상황에서 저장 후 이탈하는 수단으로 사용할 수 없다. 플레이어가 단순히 접속 종료하는 것은 자유지만, 콘텐츠는 남은 생존 플레이어가 존재하는 동안 계속 진행된다.

## 8. Day 시작 이벤트

새로운 Day는 다음 순서로 시작한다.

1. 현재 Day를 증가시킨다.
2. `CONTENT`의 Day 구간 위협 프로필과 신규 패턴·변이 잠금을 갱신한다.
3. 세계 오염도를 증가시킨다.
4. 활성 지역·시설망 오염도 변화를 계산한다.
5. 몬스터 능력치와 변이 확률을 갱신한다.
6. 해당 Day의 특수 이벤트를 결정한다.
7. 공세 구성을 결정한다.
8. 플레이어에게 Day 시작을 안내한다.
9. 자동 저장한다.
10. Day 타이머를 시작한다.

### 기본 세계 오염도 증가안

| Day 구간 | Day당 세계 오염도 증가 |
|---|---:|
| Day 1~10 | +1 |
| Day 11~20 | +2 |
| Day 21~30 | +3 |
| Day 31~40 | +4 |
| Day 41~50 | +5 |

세계 오염도 수치는 100%까지 상승하며, 100% 이후의 추가 오염은 `오염 강도`로 전환되어 최대 150%까지 상승할 수 있다. 세계 오염도는 기본적으로 감소하지 않으며, 콘텐츠 전체의 난이도 진행도를 나타낸다. 구체적인 수치와 효과는 `CORR` 문서를 따른다.

## 9. 특수 Day 이벤트

| 이벤트 | 효과 |
|---|---|
| 짙은 안개 | 야생 시야 감소, 원거리 적 증가 |
| 오염 폭풍 | 플레이어 오염도 축적 속도 증가 |

# GAME-002 세션 저장 및 회차 상태 관리

## 1. 시스템 목적

저장 시스템은 장시간 진행되는 회차를 안전하게 중단하고 재개할 수 있게 하며, 서버 충돌이나 플러그인 오류로 인한 진행 손실을 최소화한다.

동시에 하드코어 규칙을 보호하기 위해 플레이어가 저장 데이터를 이용해 사망이나 불리한 결과를 되돌릴 수 없도록 해야 한다.

## 2. 핵심 용어

| 용어 | 정의 |
|---|---|
| 회차(Run) | Day 1부터 승리 또는 실패까지 이어지는 하나의 전체 게임 |
| 세션(Session) | 권장 플레이 단위인 Day 10개의 구간 |
| 활성 저장본 | 현재 회차를 재개할 때 사용하는 최신 상태 |
| 체크포인트 | Day 10 단위 보스 처치 후 생성되는 장기 보관용 기록 |
| 백업 저장본 | 데이터 손상 복구를 위한 최근 저장 기록 |
| 실패 기록 | 전원 완전 사망으로 종료되어 재개할 수 없는 회차 기록 |

체크포인트는 일반적인 되돌리기 기능이 아니다. 운영자가 데이터 손상이나 명확한 서버 오류를 복구할 때만 사용한다.

## 3. 회차 상태

회차는 반드시 다음 상태 중 하나를 가진다.

| 상태 | 설명 | 재개 가능 여부 |
|---|---|---|
| `CREATED` | 회차 생성 후 시작 대기 | 가능 |
| `ACTIVE` | Day 타이머 또는 전투 진행 중 | 가능 |
| `PAUSED` | 정상 중단되어 안전하게 정지 | 가능 |
| `INTERMISSION` | Day 10 단위 보스 처치 후 정산 중 | 가능 |
| `RECOVERING` | 비정상 종료 후 데이터 검증 및 복구 중 | 검증 후 가능 |
| `FAILED` | 전원 완전 사망으로 종료 | 불가능 |
| `COMPLETED` | Day 50 최종 목표 달성 | 불가능 |
| `CORRUPTED` | 자동 복구할 수 없는 데이터 손상 | 운영자 확인 필요 |

`FAILED`와 `COMPLETED` 상태의 회차는 읽기 전용 기록으로 보존한다. 같은 회차 ID를 다시 `ACTIVE`로 변경할 수 없다.

## 4. 저장 원칙

### 서버 권위 저장

- 모든 회차 진행 데이터는 서버가 관리한다.
- 클라이언트 또는 플레이어가 저장 시점을 선택하여 이전 상태를 불러올 수 없다.
- `/reload`를 통한 플러그인 재시작은 지원하지 않는다.
- 회차 데이터에는 고유 회차 ID와 저장 순번을 부여한다.

### 최신 상태 우선

- 재개 시 저장 시각이 아니라 가장 높은 저장 순번을 가진 정상 저장본을 사용한다.
- 실패 기록이 존재하면 그보다 이전 저장본으로 재개하지 않는다.
- 각 저장본에는 무결성 검사값을 기록하여 일부 파일 손상을 감지한다.

### 월드와 플러그인 데이터 분리

- 블록, 상자, 지형 등 바닐라 월드 정보는 마인크래프트 월드 저장을 사용한다.
- Day, 오염도, 플레이어 상태, 장비, 증강, 시설 상태, 특수 몬스터 등 콘텐츠 정보는 플러그인이 별도로 저장한다.
- 시설과 특수 몬스터에는 고유 ID를 부여하여 월드 개체와 플러그인 데이터를 연결한다.
- 저장 시 플러그인 데이터 기록 후 월드 저장을 요청하고, 두 작업의 완료 상태를 기록한다.

## 5. 저장본 종류

### 활성 저장본

- 회차당 하나만 존재한다.
- 정상 재개에 사용하는 최신 상태다.
- 자동 저장 성공 후에만 기존 활성 저장본을 교체한다.
- 저장 중 오류가 발생하면 이전 활성 저장본을 유지한다.

### 순환 백업

- 최근 정상 저장본 5개를 순환 보관한다.
- 새 저장본 생성 시 가장 오래된 백업을 제거한다.
- 일반 플레이어는 백업을 선택하거나 불러올 수 없다.
- 활성 저장본 손상 시 가장 최신의 정상 백업부터 자동 검증한다.

### 세션 체크포인트

- Day 10, 20, 30, 40 보스 처치와 정산 완료 후 생성한다.
- 회차의 주요 진행 결과를 장기 보존한다.
- 일반적인 사망, 자원 손실, 장비 손실을 되돌리는 용도로 사용하지 않는다.
- 운영상 복구 시 사용 여부와 사유를 별도 기록한다.

### 종료 기록

- 실패 또는 최종 승리 시 생성한다.
- 참여 플레이어, 도달 Day, 플레이 시간, 사망 기록, 보스 처치 기록, 최종 장비와 증강을 저장한다.
- 종료 기록 생성 후 활성 저장본은 재개 불가 상태로 잠근다.

## 6. 저장 시점과 우선순위

| 우선순위 | 저장 시점 | 목적 |
|---:|---|---|
| 1 | 전원 완전 사망 판정 직후 | 실패 결과 확정 |
| 1 | 보스 처치 직후 | 핵심 진행 결과 확정 |
| 1 | 플레이어 완전 사망 직후 | 하드코어 사망 상태 확정 |
| 2 | Day 시작 및 종료 | 진행 경계 저장 |
| 2 | 공세 시작 및 종료 | 전투 상태 저장 |
| 2 | 정상 중단 및 세션 정산 | 안전한 재개 지점 생성 |
| 3 | 플레이어 접속 종료 | 개인 상태 손실 방지 |
| 3 | 매 30초 | 일반 진행 손실 최소화 |
| 3 | 서버 정상 종료 | 종료 직전 상태 저장 |

우선순위 1 저장은 다른 일반 저장보다 먼저 처리하며, 완료 전에는 회차 상태 변경이나 서버 재개를 허용하지 않는다.

## 7. 저장 처리 절차

저장은 다음 순서로 처리한다.

1. 현재 저장 순번을 증가시킨다.
2. 메모리상의 회차 상태를 불변 스냅샷으로 생성한다.
3. 임시 저장본에 스냅샷을 기록한다.
4. 필수 데이터 존재 여부와 무결성을 검증한다.
5. 마인크래프트 월드 저장을 요청한다.
6. 기존 활성 저장본을 백업 목록으로 이동한다.
7. 검증된 임시 저장본을 새로운 활성 저장본으로 교체한다.
8. 저장 성공 시각과 결과를 로그에 기록한다.

저장 도중 오류가 발생하면 임시 저장본을 활성화하지 않고 기존 활성 저장본을 유지한다. 연속 저장 실패 시 플레이어와 운영자에게 경고한다.

## 8. 저장 대상 데이터

### 회차 공통 데이터

- 회차 ID, 생성 시각, 저장 순번, 현재 상태
- 선택 난이도와 적용 중인 난이도 규칙 버전
- 선택 규칙 모드와 수치 엔진 버전
- 현재 Day, Day 단계, 남은 시간
- 현재 세션 구간과 세션 정산 상태
- 세계, 현재 지역 및 각 시설망 오염도
- 활성 특수 Day 이벤트
- 공세와 보스 진행 상태
- 플레이어가 건설한 시설망 및 정화 시설 상태
- 공용 보관함과 공용 재화
- 파티 증강
- 난이도 산정에 사용하는 인원 기준

### 플레이어 데이터

- 플레이어 UUID와 회차 참여 여부
- 생존, 빈사, 완전 사망, 관전 상태
- 현재 HP, AP, 오염도와 상태이상
- 인벤토리와 GUI 가상 장비 슬롯
- 개인 증강과 개인 성장 정보
- 현재 위치와 마지막 안전 위치
- 기여도와 보상 수령 상태
- 특수 부활 가능 여부

### 활성 전투 개체 데이터

- 주요 공세 적과 보스의 고유 ID
- 종류, 현재 체력, 브레이크 게이지, 페이즈
- 위치와 대상
- 활성 패턴 및 기믹 진행 상태
- 이미 지급된 보상 여부

일반 야생 몬스터는 개별 저장하지 않는다. 재개 시 제거하거나 바닐라 방식으로 처리하여 저장량과 복구 복잡도를 줄인다.

## 9. 정상 중단과 재개

### 정상 중단

1. `GAME-001`의 정상 중단 조건을 확인한다.
2. 중단 투표와 카운트다운을 완료한다.
3. 모든 플레이어의 행동과 콘텐츠 AI를 정지한다.
4. 우선순위 2 저장을 실행한다.
5. 저장 성공 후 회차를 `PAUSED`로 변경한다.
6. 플레이어를 회차 외 대기 공간으로 이동한다.

저장에 실패하면 중단을 완료하지 않으며 회차는 `ACTIVE` 상태를 유지한다.

### 정상 재개

1. 활성 저장본과 월드 상태의 무결성을 확인한다.
2. 회차를 `RECOVERING` 상태로 변경한다.
3. 시설, 공용 데이터, 플레이어 데이터를 복원한다.
4. 주요 공세 적과 보스를 필요한 경우 복원한다.
5. 접속한 생존 플레이어를 검증된 마지막 위치로 복원하고, 위치가 위험하거나 유효하지 않을 때만 가장 가까운 등록 시설 또는 파티원 주변 안전 지점으로 이동한다.
6. 10초 준비 시간을 제공한다.
7. 검증 완료 후 회차를 `ACTIVE`로 변경한다.

## 10. 비정상 종료 복구

서버 충돌이나 강제 종료 후에는 다음 규칙을 적용한다.

- 마지막 활성 저장본을 우선 사용한다.
- 활성 저장본이 손상됐다면 가장 최신의 정상 백업을 사용한다.
- 월드 상태와 플러그인 데이터가 충돌하면 중복 보상 방지를 우선한다.
- 보스 처치 여부가 불명확하면 보상 지급 기록을 확인한다.
- 플레이어 완전 사망 여부가 불명확하면 가장 최근의 우선순위 1 기록을 따른다.
- 자동 복구가 불가능하면 회차를 `CORRUPTED`로 변경하고 진행하지 않는다.

복구로 인해 최대 30초의 일반 진행이 되돌아갈 수 있다. 단, 완전 사망, 보스 처치, 보상 지급과 같은 핵심 결과는 즉시 저장하여 일반 진행보다 우선 보존한다.

## 11. 실패 처리와 되돌리기 방지

전원 완전 사망이 확정되면 다음 절차를 즉시 실행한다.

1. Day 타이머와 모든 콘텐츠 AI를 정지한다.
2. 회차 상태를 메모리에서 `FAILED`로 변경한다.
3. 실패 기록을 우선순위 1로 저장한다.
4. 활성 저장본과 모든 백업에 실패 잠금 정보를 기록한다.
5. 종료 통계와 실패 원인을 생성한다.
6. 회차 재개 메뉴에서 해당 회차를 제거한다.

서버가 실패 저장 중 종료되더라도 별도의 실패 잠금 기록을 먼저 남긴다. 실패 잠금이 존재하는 회차는 과거 백업이 남아 있어도 자동 재개하지 않는다.

## 12. Day 10 세션 정산 저장

보스 처치 후 정산은 다음 순서로 처리한다.

1. 보스 처치와 보상 지급 가능 상태를 즉시 저장한다.
2. 공용 보상을 한 번만 지급한다.
3. 개인 기여도 보상을 계산하고 플레이어별 수령 상태를 저장한다.
4. 파티 증강 투표를 진행하고 결과를 저장한다.
5. 시설망과 월드 상태를 정리한다.
6. 세션 체크포인트를 생성한다.
7. 회차를 `INTERMISSION` 상태로 저장한다.
8. 다음 세션 시작 투표를 활성화한다.

정산 도중 서버가 종료되면 완료된 단계부터 다시 수행하지 않는다. 각 정산 단계와 보상에는 완료 여부를 별도로 저장한다.

## 13. 등록 멤버 및 접속 종료 저장 규칙

### 등록 멤버 고정

- 회차 시작 트랜잭션에서 2~4명의 UUID를 확정하고 즉시 저장한다.
- 시작 완료 후 등록되지 않은 플레이어는 관전만 가능하며 참여 슬롯에 추가할 수 없다.
- 이미 완전 사망한 등록 멤버는 재접속해도 관전 상태를 유지한다.

### 접속 종료와 재접속

- 접속 종료 직전 플레이어 상태를 저장한다.
- 생존 플레이어가 남아 있으면 회차는 계속 진행한다.
- 접속 종료한 플레이어의 캐릭터는 월드에서 제거한다.
- 보스전 인원 배율은 보스 시작 시점 기준을 유지한다.
- 접속 종료 중 발생한 공세와 Day 진행 결과는 복귀한 플레이어에게 그대로 적용한다.

- 일반 플레이어가 백업이나 체크포인트를 선택하여 불러올 수 없다.

# GAME-003 참여 인원 및 난이도 스케일링

## 1. 시스템 목적

참여 인원 및 난이도 스케일링 시스템은 2~4인 파티에서 다음 목표를 달성한다.

- 인원수와 관계없이 각 플레이어가 전투, 탐험과 시설 방어에 의미 있게 기여한다.
- 인원이 많아졌을 때 적의 체력만 과도하게 증가하는 현상을 방지한다.
- 접속 종료를 이용해 보스와 공세 난이도를 낮추는 행위를 방지한다.
- 시작 멤버를 고정하고 접속 종료로 전투 난이도를 일방적으로 낮추지 못하게 한다.
- 완전 사망자가 발생해도 남은 플레이어가 이론적으로 회차를 계속 진행할 수 있게 한다.

난이도 스케일링은 `완벽하게 동일한 난이도`보다 `인원이 많을수록 더 복잡하고 바빠지는 협동 경험`을 목표로 한다.

## 2. 참여자 분류

회차에 관여하는 플레이어는 다음 상태 중 하나로 분류한다.

| 분류 | 설명 | 난이도 산정 참여 |
|---|---|---|
| 미등록 플레이어 | 회차 시작 명단에 없는 플레이어 | 관전만 가능, 제외 |
| 활성 생존자 | 회차에 등록되었으며 접속 중이고 완전 사망하지 않은 플레이어 | 포함 |
| 이탈 생존자 | 회차에 등록되었으며 생존 중이지만 접속 종료한 플레이어 | 현재 전투에서는 감소 사유가 되지 않음 |
| 빈사 플레이어 | 접속 중이며 빈사 상태인 플레이어 | 생존자로 포함 |
| 완전 사망자 | 완전 사망 후 관전 상태인 플레이어 | 다음 전투부터 제외 |
| 관전자 | 회차에 직접 참여하지 않는 관전 전용 플레이어 | 제외 |

빈사는 구조 가능한 전투 상태이므로 난이도 산정에서 생존자로 취급한다.

## 3. 회차 참여 인원 규칙

### 회차 시작

- 최초 회차 시작에는 최소 2명의 플레이어가 필요하다.
- 한 회차에 등록 가능한 최대 인원은 4명이다.
- 시작 시 등록한 플레이어는 회차 참여 슬롯 하나를 차지한다.
- 회차 시작과 동시에 명단을 잠그며 빈 슬롯이 있어도 새로운 플레이어를 추가하지 않는다.

### 참여 슬롯

- 완전 사망하거나 접속 종료해도 해당 플레이어의 참여 슬롯은 유지된다.
- 완전 사망한 플레이어를 내보내고 새로운 플레이어로 교체할 수 없다.
- 기존 등록 플레이어는 재접속 시 자신의 기존 상태로 복귀한다.
- 참여 슬롯 규칙은 사망자를 신규 인원으로 계속 교체하는 방식의 하드코어 규칙 우회를 방지한다.

### 1인만 남은 상황

- 시작은 반드시 2인 이상이어야 하지만, 진행 중 사망 또는 접속 종료로 활성 생존자가 1명만 남아도 회차는 계속 진행한다.
- 활성 생존자 1명만 접속 중이어도 Day 타이머는 계속 진행한다.
- 마지막 생존자는 구조를 받을 수 없으므로 빈사 상태에서 추가 피해를 받으면 완전 사망할 위험이 매우 크다.
- 마지막 생존자가 완전 사망하고 다른 생존 가능 등록 플레이어도 없다면 회차는 실패한다.
- 생존 중인 이탈 플레이어가 있다면 마지막 접속 플레이어의 사망만으로 즉시 전원 실패 처리하지 않는다.

## 4. 회차 명단 잠금과 재접속

- 회차 시작 전 모든 등록 플레이어가 참여에 동의해야 한다.
- 회차 시작 완료 후 명단 추가·교체·성장 보정은 제공하지 않는다.
- 미등록 플레이어는 관전 전용이며 전투, 보상, 투표와 발견 공유에 관여할 수 없다.
- 등록 플레이어의 재접속은 신규 참여가 아니다. 저장된 레벨, 장비, 증강, 생명 상태와 위치를 검증해 복원한다.
- 접속 종료로 현재 공세·보스의 잠금 인원은 감소하지 않는다.

## 5. 난이도 산정 인원

난이도 계산에는 `전투 스케일 인원`을 사용한다.

### 일반 활동 단계

- 야생 일반 몬스터는 생성 시점의 주변 활성 생존자 수를 기준으로 조정한다.
- 주변 플레이어는 동일 몬스터로부터 일정 거리 이내에 있는 생존자로 판정한다.
- 몬스터 생성 후 플레이어가 멀어져도 해당 몬스터의 난이도는 낮아지지 않는다.
- 여러 플레이어가 합류하면 필요 시 체력과 브레이크 수치를 상향하지만 낮추지는 않는다.

### 공세 및 보스전

- 전투 시작 시 활성 생존자 수를 `전투 스케일 인원`으로 고정한다.
- 전투 중 접속 종료, 빈사, 완전 사망이 발생해도 현재 전투의 스케일 인원은 감소하지 않는다.
- 전투 시작 시 이탈했던 등록 플레이어가 재접속해 현재 전투에 참여하면 스케일 인원을 등록 명단 상한까지 증가시킨다.
- 한 번 증가한 현재 전투의 스케일 인원은 전투 종료 전까지 감소하지 않는다.
- 다음 공세 또는 보스전 시작 시 현재 활성 생존자 수를 기준으로 새로 계산한다.

### 전투 참여 판정

다음 중 하나를 만족하면 현재 전투에 참여한 것으로 간주한다.

- 동적 공세 개체 또는 보스의 활성 전투 반경에 진입한다.
- 해당 전투 적에게 피해, 상태이상 또는 브레이크 피해를 준다.
- 전투 참여 플레이어를 회복하거나 구조하거나 강화한다.
- 전투 적에게 직접 공격받는다.

활성 전투와 떨어진 곳에서 재접속한 플레이어는 실제로 관여하기 전까지 현재 전투 스케일 인원을 증가시키지 않는다.

## 6. 기본 난이도 배율

모든 배율은 2인을 기준값 `1.00`으로 사용한다. 1인 배율은 회차 시작용이 아니라 진행 중 인원 손실 상황을 위한 예외값이다.

| 전투 스케일 인원 | 적 체력 | 적 직접 피해 | 브레이크 게이지 | 주요 적 수 | 공세 예산 | 공용 재료 보상 |
|---:|---:|---:|---:|---:|---:|---:|
| 1인 | 0.72 | 0.90 | 0.75 | 0.75 | 0.70 | 0.75 |
| 2인 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |
| 3인 | 1.32 | 1.06 | 1.25 | 1.20 | 1.30 | 1.25 |
| 4인 | 1.60 | 1.12 | 1.50 | 1.40 | 1.60 | 1.50 |

### 배율 적용 원칙

- 적 체력은 파티 총 피해량 증가보다 낮은 비율로 증가시켜 전투 시간이 지나치게 길어지지 않게 한다.
- 적 직접 피해 증가는 작게 제한하여 인원 증가가 갑작스러운 즉사 위험 증가로 이어지지 않게 한다.
- 인원이 많을수록 주요 적 수, 동시 패턴, 역할 분담 요구를 늘린다.
- 브레이크 게이지는 인원수에 따라 증가하지만 체력보다는 낮은 부담으로 조정한다.
- 공용 재료 보상은 인원수에 따라 증가하되 인원수와 정확히 비례하지 않는다.
- 개인 기여 보상은 인원수 배율과 별개로 개인별 지급한다.

수치는 최초 밸런스 기준안이며, Day 1~10 플레이 테스트 후 조정한다.

## 7. 공세 스케일링

### 공세 예산

각 공세는 `공세 예산`을 사용하여 적 구성을 결정한다.

```text
최종 공세 예산 =
기본 Day 공세 예산
× 전투 스케일 인원 배율
× 세계 오염 배율
× 특수 Day 이벤트 배율
```

각 적은 강함과 역할에 따라 서로 다른 비용을 가진다.

| 적 유형 | 예시 비용 |
|---|---:|
| 일반 근접 적 | 1 |
| 일반 원거리 적 | 2 |
| 특수 역할 적 | 3 |
| 엘리트 적 | 8 |
| 공성 특화 적 | 10 |

### 인원별 공세 구성 방향

| 인원 | 구성 방향 |
|---:|---|
| 1인 | 한 방향 중심 공격, 동시 특수 적 제한 |
| 2인 | 최대 두 방향 압박, 기본 역할 조합 |
| 3인 | 다방향 압박 또는 지원형 적 추가 |
| 4인 | 다방향 압박과 역할 조합 강화, 엘리트 추가 가능 |

인원수에 따른 추가 난이도는 단순 몬스터 밀집보다 공격 방향과 적 역할 조합으로 제공한다. 서버 성능과 전투 가독성을 위해 한 영역의 동시 활성 공세 적 수에는 상한을 둔다.

### 공세 적 수 상한

| 인원 | 권장 동시 활성 일반·특수 적 상한 | 권장 동시 활성 엘리트 상한 |
|---:|---:|---:|
| 1인 | 12 | 1 |
| 2인 | 18 | 1 |
| 3인 | 24 | 2 |
| 4인 | 30 | 2 |

공세 예산이 상한을 초과하면 적을 한 번에 생성하지 않고 다음 웨이브로 나누어 생성한다.

## 8. 보스 스케일링

### 기본 배율

- 보스 최대 체력은 전투 스케일 인원의 적 체력 배율을 적용한다.
- 보스 직접 피해량은 적 직접 피해 배율을 적용한다.
- 보스 브레이크 게이지는 브레이크 게이지 배율을 적용한다.
- 보스전 중 소환되는 하수인 수는 주요 적 수 배율을 참고하되 개별 상한을 둔다.

### 인원별 패턴 변화

보스는 인원수에 따라 단순 수치 외에도 일부 패턴이 변화한다.

| 인원 | 패턴 변화 방향 |
|---:|---|
| 1인 | 동시 대상 패턴 최소화, 기믹 요구 인원 1명으로 조정 |
| 2인 | 기본 패턴 구성 |
| 3인 | 동시 지정 대상 증가, 추가 위험 구역 생성 |
| 4인 | 역할 분담형 패턴 강화, 일부 패턴 연계 사용 |

어떤 인원수에서도 현재 생존자 수보다 많은 플레이어가 동시에 필수 행동을 해야 하는 기믹은 만들지 않는다.

### 보스전 중 인원 증가

보스전 도중 이탈했던 등록 플레이어가 재접속하여 전투 스케일 인원이 증가하면 다음 처리를 한 번 수행한다.

- 보스 최대 체력과 현재 체력을 같은 비율로 증가시킨다.
- 브레이크 게이지 최대치와 현재치를 같은 비율로 증가시킨다.
- 다음 패턴부터 증가한 인원수의 패턴 구성을 적용한다.
- 이미 시작된 패턴과 기믹은 변경하지 않는다.
- 증가 사실을 모든 플레이어에게 안내한다.

예를 들어 최대 체력 10,000 중 50%가 남은 2인 보스가 3인으로 조정되면, 3인 최대 체력 13,200과 현재 체력 6,600으로 변경한다.

### 보스전 중 인원 감소

- 접속 종료 또는 완전 사망으로 인원이 감소해도 보스의 체력, 브레이크, 패턴 단계는 현재 전투 동안 낮아지지 않는다.
- 현재 생존자 수로 수행 불가능해진 협동 기믹은 자동으로 요구 인원을 낮춘다.
- 요구 인원만 조정하며 보스 수치와 일반 패턴 난이도는 유지한다.

이를 통해 접속 종료 악용을 막으면서도 기믹 자체가 진행 불가능해지는 상황을 방지한다.

## 9. 플레이어 대상 패턴 규칙

### 대상 선정

- 보스와 엘리트는 같은 플레이어를 연속 지정하지 않도록 기본 보정을 적용한다.
- 빈사 플레이어는 일반적으로 강한 지정 패턴의 대상에서 제외한다.
- 구조 중인 플레이어는 공격 대상이 될 수 있으나, 구조 위치에 즉사급 패턴을 직접 생성하지 않는다.
- 완전 사망자와 전투 영역 밖 플레이어는 대상에서 제외한다.

### 동시 지정 대상 수

| 활성 전투 참여자 | 일반 동시 지정 | 강한 동시 지정 |
|---:|---:|---:|
| 1인 | 1 | 1 |
| 2인 | 1~2 | 1 |
| 3인 | 2 | 1~2 |
| 4인 | 2~3 | 2 |

강한 동시 지정 패턴은 회피, 패링, 엄폐 등 명확한 대응 방법을 제공해야 한다.

## 10. 시설망 스케일링

인원수가 많다고 플레이어 시설의 기본 성능을 낮추지는 않는다. 대신 압박 예산, 적 역할과 동시 패턴을 조정한다.

- 시설 체력과 수리 비용은 참여 인원수에 따라 변경하지 않는다.
- 정화탑의 기본 정화 효율은 참여 인원수에 따라 변경하지 않는다.
- 공세 중 파티 또는 목표 시설망을 공격하는 적의 수와 역할 구성을 조정한다.
- 공용 자원 보상은 인원수에 따라 완만하게 증가한다.
- 시설 상호작용에 필수 인원수를 요구하지 않는다.

시설 성능까지 인원수에 따라 낮추면 플레이어가 늘었을 때 성장 성취감이 약해지고 계산이 불명확해지므로 사용하지 않는다.

## 11. 보상 스케일링

### 공용 보상

- 공세 및 보스 공용 재료는 기본 공용 재료 보상 배율을 적용한다.
- 보스 최초 처치의 고유 장비 완제품은 1개만 지급하고, 동시에 해당 장비 제작식을 파티에 해금한다.
- 고유 장비 템플릿 후보 3개를 먼저 파티 투표로 선택한 뒤 `필요·양보`를 받아 수령자를 정한다.
- 복수 필요자는 회차 내 고유 장비 수령 횟수가 적은 플레이어를 우선하고, 동률은 회차 시드 난수로 결정한다.
- 수령 즉시 자동 귀속한다. 전원 양보 시 가상 파티 보상 보관함에 미귀속으로 저장한다.
- 세부 트랜잭션과 사망자 참여 규칙은 `EQUIP-001`을 따른다.

### 개인 보상

- 개인 기여 보상은 각 플레이어에게 별도로 지급한다.
- 피해량, 브레이크, 구조, 회복, 피해 방어, 시설 수리 등을 기여도로 계산한다.
- 접속 시간만으로 개인 보상을 반복 획득할 수 없게 한다.
- 등록 멤버는 실제 참여한 전투와 Day에 대해서만 개인 기여 보상을 받는다.
- 완전 사망자도 사망 전 기여한 전투의 정산 보상을 받을 수 있다.

### 1인 잔존 보상

진행 중 1인만 남은 경우 난이도는 감소하지만 보상 효율도 함께 감소한다.

- 다음 전투부터 1인 공용 재료 보상 배율을 적용한다.
- 개인 보상은 정상적으로 지급한다.
- 이미 시작한 전투의 공용 보상 배율은 시작 시점 값을 유지한다.

## 12. 접속 종료 및 재접속 악용 방지

- 현재 공세와 보스전의 스케일 인원은 접속 종료로 감소하지 않는다.
- 전투 시작 직전 반복적인 접속 종료로 난이도를 낮추는 행위를 막기 위해, 최근 90초 내 접속 종료한 생존자를 다음 전투의 스케일 인원에 포함한다.
- 접속 종료한 플레이어가 90초 내 재접속하면 기존 전투 참여 상태를 그대로 복구한다.
- 재접속으로 시작 지급품이나 개인 보상을 다시 받을 수 없다.
- 보상 지급 직전 접속 종료해도 이미 기록된 기여도와 수령 권한은 유지한다.

### 최근 이탈자 규칙

공세 또는 보스전 시작 시 다음 값을 사용한다.

```text
전투 시작 스케일 인원 =
현재 활성 생존자 수
+ 최근 90초 내 접속 종료한 생존자 수
```

최댓값은 해당 회차의 등록 인원수이며, 최소값은 1이다.

## 13. 전투 불가능 상황 방지

- 모든 협동 기믹은 현재 접속 중인 생존자 수를 기준으로 필수 인원을 조정한다.
- 혼자 남은 플레이어도 모든 문, 장치, 정화 기믹을 느리지만 수행할 수 있어야 한다.
- 인원이 적을수록 상호작용 시간 또는 수행 횟수를 줄일 수 있다.
- 전투 수치는 이미 시작한 전투 동안 감소시키지 않지만, 필수 기믹 요구 인원은 즉시 조정한다.
- 특정 무기나 역할이 없으면 진행 불가능한 패턴을 만들지 않는다.

## 14. UI 및 안내

### 기본 표시

파티 UI 또는 스코어보드에 다음 정보를 표시한다.

```text
등록 인원 4 / 4
활성 생존자 3
빈사 1
완전 사망 0
현재 전투 스케일 4인
```

### 변경 안내

다음 상황에서는 전체 플레이어에게 알림을 표시한다.

- 회차 시작 명단 잠금
- 공세 또는 보스전 스케일 인원 확정
- 등록 멤버 재접속 참여로 현재 전투 스케일 증가
- 완전 사망자로 인해 다음 전투 스케일 감소 가능
- 마지막 활성 생존자 상태 진입

## 16. 밸런스 테스트 항목

동일한 Day와 장비 수준에서 다음 조합을 각각 테스트한다.

| 테스트 | 확인 목적 |
|---|---|
| 2인 정상 파티 | 기준 전투 시간과 기본 난이도 확인 |
| 3인 정상 파티 | 체력보다 역할 압박이 적절히 증가하는지 확인 |
| 4인 정상 파티 | 전투 가독성과 서버 성능 확인 |
| 2인 시작 후 1인 잔존 | 회차 지속 가능성과 하드코어 긴장감 확인 |
| 보스전 도중 등록 멤버 재접속 | 체력 및 패턴 전환 오류 확인 |
| 보스전 도중 접속 종료 | 난이도 감소 악용 방지 확인 |
| 공세 중 등록 멤버 재접속 | 공세 예산 및 보상 중복 여부 확인 |

### 목표 전투 시간 예시

동일 Day의 보스는 적정 장비 파티 기준으로 인원수와 관계없이 비슷한 처치 시간을 목표로 한다.

| 전투 | 목표 시간 |
|---|---:|
| 일반 엘리트 | 45~90초 |
| 일반 Day 공세 | 1분 30초, 잔존 적 정리는 다음 Day와 병행 |
| Day 10 보스 | 8~12분 |

인원수 증가로 목표 시간이 크게 늘어난다면 적 체력 배율을 낮추고, 너무 짧아진다면 패턴 압박과 역할 적 구성을 먼저 조정한다.

## 17. GAME-003 완료 기준

- 2~4인으로 회차를 시작하고 참여 슬롯을 정상적으로 관리할 수 있다.
- 빈 슬롯이 있어도 시작 후 새로운 플레이어가 참여할 수 없다.
- 완전 사망자를 새로운 플레이어로 교체하여 하드코어 규칙을 우회할 수 없다.
- 접속 종료로 현재 공세와 보스 난이도를 낮출 수 없다.
- 이탈했던 등록 멤버가 현재 전투에 관여하면 전투 스케일이 증가한다.
- 인원수에 따라 적 체력뿐 아니라 공세 구성, 패턴, 브레이크가 함께 조정된다.
- 인원이 감소해도 모든 필수 기믹을 수행할 수 있다.
- 1인만 남은 상황에서도 회차를 계속 진행할 수 있다.
- 공용 보상과 개인 보상이 인원수 및 기여도 기준으로 정상 지급된다.
- 난이도 및 참여 상태가 저장 후 재개되어도 유지된다.
- 회차 생성 시 선택한 난이도가 진행 중 변경되지 않고 플레이어의 기본·투자·고정 보너스 HP 합계에 적용된다.
