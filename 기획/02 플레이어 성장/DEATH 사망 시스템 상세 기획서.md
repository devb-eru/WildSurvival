# DEATH-001 빈사 상태 시스템

## 1. 시스템 목적

빈사 시스템은 플레이어가 한 번의 실수로 즉시 회차에서 제외되는 상황을 완화하면서, 동료 구조와 전장 통제의 중요성을 높인다.

- 치명적인 피해 이후 동료가 개입할 구조 기회를 제공한다.
- 빈사 플레이어를 보호할지 전투 목표를 우선할지 선택하게 한다.
- 오염과 적대 환경을 포함한 모든 피해에 긴장감을 유지한다.
- 반복 구조를 통한 무한 생존을 방지한다.
- 플러그인만으로 안정적으로 상태와 행동을 통제할 수 있게 한다.

## 2. 생명 상태

플레이어는 회차 진행 중 다음 생명 상태 중 하나를 가진다.

| 상태 | 설명 | 일반 조작 |
|---|---|---|
| `ALIVE` | 정상적으로 활동 가능한 상태 | 가능 |
| `DOWNED_GRACE` | 빈사 전환 직후의 짧은 보호 상태 | 이동 불가 |
| `DOWNED` | 이동과 도움 요청만 가능한 빈사 상태 | 제한 |
| `BEING_REVIVED` | 동료가 구조를 진행 중인 빈사 상태 | 제한 |
| `DEAD` | 완전 사망하여 관전하는 상태 | 불가능 |

`DOWNED_GRACE`, `DOWNED`, `BEING_REVIVED`는 모두 빈사 상태로 취급한다.

## 3. 빈사 진입 조건

### 기본 진입

`ALIVE` 상태인 플레이어의 HP가 피해로 인해 0 이하가 되면 해당 피해로 즉시 완전 사망하지 않고 빈사 상태로 전환한다.

빈사 진입 시 다음 순서로 처리한다.

1. 치명 피해의 원인과 공격자를 기록한다.
2. 일반 HP를 1로 고정한다.
3. AP를 0으로 변경한다.
4. 현재 사용 중인 스킬, 회피, 패링, 구조 행동을 취소한다.
5. 모든 해제 가능한 상태이상을 제거한다.
6. 플레이어를 `DOWNED_GRACE` 상태로 변경한다.
7. 빈사 체력을 최대치로 설정한다.
8. 빈사 전환 연출과 파티 알림을 출력한다.
9. 빈사 상태를 즉시 저장한다.

### 빈사 진입 불가 상황

다음 상황에서는 빈사 단계를 거치지 않고 즉시 완전 사망할 수 있다.

- 이미 빈사 상태에서 빈사 체력이 0이 됨
- 관리자 또는 시스템에 의한 강제 완전 사망
- 회차 외부에서 발생한 일반 마인크래프트 사망

일반 보스 패턴, 낙사, 용암, 공허와 폭발은 빈사 진입을 건너뛰지 않는다. 전술 아군 피해는 HP 1에서 정지하므로 빈사 원인이 되지 않는다. 대응 실패 한 번으로 즉시 회차에서 제외되는 예외 패턴은 사용하지 않는다.

## 4. 빈사 체력

빈사 상태에서는 일반 HP 대신 별도의 `빈사 체력`을 사용한다.

| 항목 | 기본값 |
|---|---:|
| 최대 빈사 체력 | 부상 스택에 따라 최종 최대 HP의 70%·52.5%·35% |
| 빈사 전환 직후 체력 | 현재 부상 스택의 최대 빈사 체력 |
| 자연 감소 | 없음 |
| 일반 적 공격 피해 배율 | 원래 피해의 50% |
| 엘리트 및 보스 공격 피해 배율 | 원래 피해의 75% |
| 전술 아군 피해 | 빈사 상태에는 적용하지 않음 |
| 환경 및 지속 피해 배율 | 원래 피해의 50% |
| 한 번에 받을 수 있는 최대 빈사 피해 | 현재 최대 빈사 체력의 50% |

### 빈사 피해 계산

```text
최종 빈사 피해 =
원래 최종 피해
× 공격 유형별 빈사 피해 배율
× 빈사 피해 보정
```

- 일반 방어력과 피해 감소는 `원래 최종 피해` 계산 단계에서 적용한다.
- 빈사 상태에서는 회피와 패링을 사용할 수 없다.
- 한 번의 공격으로 현재 최대 빈사 체력의 50%까지만 감소하도록 제한한다.
- 서로 다른 공격이 동시에 적중한 경우 각각 피해를 적용할 수 있다.
- 빈사 체력이 0 이하가 되면 즉시 완전 사망 처리한다.

### 빈사 체력 회복

- 일반 회복 아이템, 음식, 재생 효과로 빈사 체력을 회복할 수 없다.
- 구조 완료 외의 방법으로 `ALIVE` 상태로 복귀할 수 없다.
- 빈사 체력 회복 전용 장비 또는 증강은 추후 추가할 수 있다.
- 빈사 체력 회복 효과가 존재하더라도 최대 빈사 체력을 넘을 수 없다.

## 5. 빈사 전환 보호

빈사 진입 직후 `1.5초` 동안 `DOWNED_GRACE` 상태가 된다.

- 모든 피해를 받지 않는다.
- 이동, 공격, 아이템 사용, 도움 요청을 할 수 없다.
- 적의 직접 공격 대상으로 새롭게 지정되지 않는다.
- 기존 발사체와 범위 공격이 빈사 직후 즉시 완전 사망을 유발하는 것을 방지한다.
- 보호 종료 후 `DOWNED` 상태로 전환한다.

보호 시간은 빈사 전환 애니메이션과 상태 변경을 안정적으로 처리하기 위한 시간이며, 위치를 안전하게 이동시키는 효과는 제공하지 않는다.

## 6. 빈사 상태 행동 제한

### 허용 행동

- 느린 속도로 이동
- 시점 회전
- 도움 요청 신호 사용
- 파티 채팅 사용
- 구조 진행 상황 확인
- 자신의 빈사 체력과 위험 상태 확인

### 금지 행동

- 기본 공격 및 무기 스킬 사용
- 회피, 패링, 방어 사용
- 블록 설치 및 파괴
- 상자, 제작대, 시설 GUI 사용
- 아이템 줍기, 버리기, 교환하기
- 음식, 물약, 소모품 사용
- 다른 플레이어 구조
- 탈것 탑승
- 순간이동 및 귀환

### 이동 규칙

| 항목 | 규칙 |
|---|---|
| 기본 이동 속도 | 정상 기본 이동 속도의 20% |
| 질주 | 불가능 |
| 점프 | 불가능 |
| 수영 | 수면 방향의 느린 이동만 허용 |
| 사다리 오르기 | 불가능 |
| 넉백 | 일반 넉백의 50% 적용 |
| 강제 이동 | 적용 가능 |

마인크래프트에서는 완전한 기어가기 자세를 안정적으로 강제하기 어렵기 때문에, 기본 구현은 이동속도 감소와 행동 차단을 사용한다. 리소스팩 또는 표시 엔티티를 사용한다면 시각적인 빈사 연출을 추가할 수 있다.

## 7. 빈사 상태 적 대상 선정

빈사 플레이어는 전투에서 완전히 안전하지 않지만, 모든 적이 빈사자를 집중 공격하지도 않는다.

| 적 유형 | 빈사 플레이어 공격 규칙 |
|---|---|
| 일반 야생 적 | 주변에 살아 있는 대상이 없을 때만 공격 |
| 일반 공세 적 | 기지 시설과 살아 있는 플레이어를 우선 |
| 처형자 특성 적 | 빈사 플레이어를 우선 공격 가능 |
| 엘리트 적 | 패턴별 규칙 적용 |
| 보스 | 일반 지정 패턴에서는 제외, 광역 피해는 적용 |

- 빈사 플레이어는 기존 범위 공격과 환경 피해를 받을 수 있다.
- 처형자 특성을 가진 적은 등장 전에 명확한 시각 표시를 제공한다.
- 보스가 빈사 플레이어만을 대상으로 강한 지정 패턴을 새로 사용하지 않는다.
- 빈사자를 보호하는 것은 파티의 책임이지만, 빈사 직후 피할 수 없는 처형은 방지한다.

## 8. 도움 요청

빈사 플레이어는 재사용 대기시간이 있는 도움 요청 신호를 사용할 수 있다.

| 항목 | 규칙 |
|---|---|
| 입력 | 웅크리기 입력 또는 빈사 전용 아이템 우클릭 |
| 재사용 대기시간 | 10초 |
| 파티 알림 | 이름, 거리, 방향 표시 |
| 위치 표시 지속시간 | 3초 |
| 사운드 | 파티원에게만 재생 |

- 도움 요청은 적의 주의를 끌지 않는다.
- 반복 입력으로 채팅과 사운드를 방해할 수 없도록 재사용 대기시간을 적용한다.
- 구조 가능한 동료가 없을 때도 도움 요청은 사용할 수 있다.

## 9. 상태이상 및 오염 처리

### 상태이상

- 빈사 진입 시 기절, 속박, 침묵, 무장 해제 등 행동 제한 상태이상을 제거한다.
- 화상, 독, 출혈 등 지속 피해 효과는 유지하며 빈사 피해로 변환한다.
- 빈사 상태에서는 새로운 강한 행동 제한 CC를 적용하지 않는다.
- 둔화는 빈사 이동속도에 추가 적용하지 않는다.

### 플레이어 오염도

- 빈사 상태에서도 주변 오염에 노출된다.
- 빈사 상태에서는 플레이어 오염도 축적 속도가 기본의 150%가 된다.
- 오염도 단계에 따른 빈사 피해 또는 구조 방해 효과는 오염 시스템 기획에서 확정한다.
- 빈사 상태에서 오염도가 최대가 되어도 즉시 완전 사망하지 않는다.

## 10. 환경별 예외 처리

### 낙사

- 치명적인 낙하 피해로 빈사가 되면 착지 위치에서 빈사 상태가 된다.
- 빈사 전환 직후 보호 시간으로 같은 낙하 피해의 중복 처리를 막는다.
- 접근 불가능한 위치에 떨어진 경우 자동 이동시키지 않는다.

### 공허

- 공허 피해로 HP가 0이 되면 마지막 안전 지점으로 이동한 후 빈사 상태가 된다.
- 마지막 안전 지점은 최근 10초 내 지상에 정상적으로 서 있었던 위치를 사용한다.
- 공허 구조는 회차당 플레이어별 1회만 허용한다.
- 공허 구조 횟수를 모두 사용한 상태에서 다시 공허에 빠지면 완전 사망한다.

### 용암과 화재

- 용암과 화재는 빈사 전환 보호 종료 후 빈사 피해를 준다.
- 빈사 플레이어는 스스로 물이나 소모품을 사용할 수 없다.
- 동료가 환경을 정리하거나 신속히 구조해야 한다.

### 질식 및 익사

- 질식과 익사 피해는 빈사 피해로 적용한다.
- 빈사 플레이어는 느리게 수면 방향으로 이동할 수 있다.
- 구조 완료 시에도 위험 환경에서 자동 이동시키지 않는다.

### 접속 종료

- 빈사 플레이어가 접속 종료해도 빈사 상태와 위치를 저장한다.
- 회차에 다른 생존 접속 플레이어가 남아 있다면 빈사 체력은 월드에서 계속 피해받을 수 있는 대리 개체로 유지하는 것을 원칙으로 한다.
- 대리 개체 구현이 불안정하다면 빈사 접속 종료 시 해당 플레이어를 완전 사망 처리하는 대체 규칙을 사용한다.
- 최종 구현 방식은 플러그인 기술 검증 후 확정한다.

빈사 중 자유로운 접속 종료가 안전한 회피 수단이 되어서는 안 된다.

## 11. 아군 공격

- 기본 모드에서는 아군 피해와 해로운 효과를 전부 차단한다.
- 전술 모드에서도 아군 피해는 HP 1에서 멈추고 빈사 체력에는 적용하지 않으므로 팀킬할 수 없다.
- 구조 입력과 공격 입력은 분리하고, 전술 모드의 아군 공격 기록은 악용·분쟁 진단용으로만 저장한다.
- 아군 공격으로 빈사·완전 사망·구조 방해 보상을 만들 수 없다.

## 12. 빈사 반복 제한

반복 구조를 통한 무한 생존을 막기 위해 `부상 스택`을 사용한다.

### 부상 스택 기본 규칙

- 빈사 상태에 진입할 때 부상 스택이 1 증가한다.
- 구조에 성공해도 부상 스택은 유지된다.
- 부상 스택은 Day 종료 또는 지정된 기지 치료 시설을 통해 감소한다.
- 부상 스택은 기본 최대 3이다.
- 부상 스택이 최대인 상태에서 다시 치명 피해를 받으면 빈사 없이 즉시 완전 사망한다.

### 부상 스택 효과

| 부상 스택 | 빈사 진입 시 빈사 체력 | 구조 완료 후 복귀 HP | 추가 효과 |
|---:|---:|---:|---|
| 1 | 최종 최대 HP의 70% | 최대 HP의 30% | 없음 |
| 2 | 최종 최대 HP의 52.5% | 최대 HP의 25% | 구조 시간 증가 |
| 3 | 최종 최대 HP의 35% | 최대 HP의 20% | 구조 시간 크게 증가 |
| 최대 상태에서 재치명 피해 | 빈사 진입 불가 | 해당 없음 | 즉시 완전 사망 |

구체적인 구조 시간 증가는 `DEATH-002 구조 행동 시스템`에서 확정한다.

### 부상 스택 감소

- 일반 Day 종료 시 모든 생존 플레이어의 부상 스택을 1 감소시킨다.
- 보스전과 잔존 공세 상태에서는 감소하지 않는다.
- 기지 치료 시설은 비용을 소비하여 추가로 감소시킬 수 있다.
- 부상 스택 감소 직후 상태를 즉시 저장한다.

Day가 7분으로 짧기 때문에 매 Day 완전 초기화하지 않고 1씩만 감소시켜 부상 관리의 의미를 유지한다.

## 13. UI 및 시각 표시

### 빈사 플레이어 화면

- 화면 중앙에 `빈사 상태`를 표시한다.
- 빈사 체력을 보스바 또는 액션바로 표시한다.
- 현재 부상 스택을 표시한다.
- 도움 요청 입력과 재사용 대기시간을 안내한다.
- 구조 진행 중에는 구조자와 남은 시간을 표시한다.

```text
빈사 상태 | 빈사 체력 320 / 525 | 부상 2 / 3
도움 요청 가능 | 구조 중: PlayerB
```

### 파티원 표시

- 빈사 발생 시 이름과 방향을 전체 파티에 표시한다.
- 빈사 플레이어 머리 위에 식별 가능한 표시를 출력한다.
- 빈사 체력이 25% 이하가 되면 경고 표시와 사운드를 강화한다.
- 부상 스택이 최대인 생존 플레이어를 파티 UI에서 별도로 표시한다.

## 14. 플러그인 구현 방향

빈사 상태는 실제 마인크래프트 사망 이벤트가 발생하기 전에 치명 피해를 가로채 구현한다.

- 치명 피해 감지 시 실제 사망을 취소하고 HP를 1로 고정한다.
- 플레이어 UUID별 생명 상태와 빈사 체력을 플러그인 데이터로 관리한다.
- 이동속도 속성과 이벤트 차단으로 행동을 제한한다.
- 피해 이벤트를 빈사 체력 피해로 변환한다.
- 빈사 체력은 액션바 또는 보스바로 표시한다.
- 완전 사망 시 실제 사망 처리 대신 관전 모드로 전환하고 회차 데이터를 저장한다.

### 기술 검증 필요 항목

- 빈사 플레이어의 안정적인 점프 및 상호작용 차단
- 수영과 용암 환경에서의 이동 처리
- 빈사 접속 종료 시 피해 가능한 대리 개체 구현
- 다른 플러그인의 피해 및 회복 이벤트와 충돌 여부
- 공허 이동과 마지막 안전 위치 판정

## 18. DEATH-001 완료 기준

- 모든 일반적인 치명 피해가 플레이어를 빈사 상태로 전환한다.
- 빈사 진입 직후 다단 피해로 즉시 완전 사망하지 않는다.
- 빈사 플레이어가 제한된 이동과 도움 요청만 사용할 수 있다.
- 빈사 상태에서 추가 피해를 받아 완전 사망할 수 있다.
- 일반 적, 보스, 아군 공격, 환경 피해가 정의된 규칙대로 처리된다.
- 부상 스택이 반복 구조를 통한 무한 생존을 방지한다.
- 빈사 상태와 관련 데이터가 서버 재시작 후 정상 복원된다.
- 빈사 중 접속 종료를 안전한 회피 수단으로 사용할 수 없다.
- 플러그인 환경에서 행동 제한과 빈사 체력 UI가 안정적으로 동작한다.

# DEATH-002 구조 행동 시스템

## 1. 시스템 목적

구조 행동은 빈사 플레이어를 다시 전투에 복귀시키는 기본 협동 수단이다.

- 빈사 상태가 즉시 전력 이탈로 이어지지 않게 한다.
- 구조자가 전투와 구조 사이에서 의미 있는 판단을 하게 한다.
- 동료들이 함께 구조하면 더 빠르게 복귀시킬 수 있게 한다.
- 구조 시도에는 위치 선정과 전장 확보가 필요하게 한다.
- 짧은 반복 입력이나 접속 종료를 이용한 구조 악용을 방지한다.

## 2. 기본 구조 규칙

| 항목 | 기본 규칙 |
|---|---|
| 구조 대상 | `DOWNED` 또는 `BEING_REVIVED` 상태 플레이어 |
| 구조 가능 상태 | `ALIVE` 상태 플레이어 |
| 기본 입력 | 빈사 플레이어를 바라보며 웅크리기 + 우클릭 유지 |
| 빈손 요구 | 없음 |
| 기본 상호작용 거리 | 2.5블록 |
| 기본 구조자 수 상한 | 2명 |
| 구조 진행도 | 대상 빈사 플레이어별 공유 |
| 구조 중 AP 소모 | 초당 5 AP |
| AP 부족 시 | 해당 구조자의 기여 중단 |
| 구조 완료 결과 | 빈사 플레이어를 `ALIVE` 상태로 복귀 |

구조 입력은 공격 입력과 분리한다. 구조자는 무기를 들고 있어도 구조할 수 있으며, 구조 중 우클릭으로 발생할 수 있는 무기 스킬과 아이템 사용은 취소한다.

## 3. 구조 시작 조건

구조자는 다음 조건을 모두 만족해야 구조를 시작할 수 있다.

- 구조자가 `ALIVE` 상태다.
- 구조 대상이 `DOWNED` 또는 `BEING_REVIVED` 상태다.
- 구조자와 대상 사이의 거리가 2.5블록 이하다.
- 구조자가 대상을 일정 범위 안에서 바라보고 있다.
- 구조자와 대상 사이에 완전히 막힌 블록이 없다.
- 구조자가 웅크리기 상태에서 대상에게 우클릭을 유지한다.
- 구조자의 현재 AP가 5 이상이다.
- 구조자가 기절, 속박, 공중 띄움 등 구조 불가능 상태가 아니다.
- 대상이 완전 사망 처리 중이 아니다.

구조 조건을 만족하면 대상의 상태를 `BEING_REVIVED`로 변경하고 구조 진행도를 표시한다.

## 4. 구조 시간

기본 구조 시간은 빈사 대상의 현재 부상 스택에 따라 결정한다.

| 대상 부상 스택 | 기본 구조 시간 | 구조 완료 후 복귀 HP |
|---:|---:|---:|
| 1 | 5초 | 최대 HP의 30% |
| 2 | 7초 | 최대 HP의 25% |
| 3 | 9초 | 최대 HP의 20% |

- 구조 시간은 대상 플레이어의 부상 정도를 기준으로 한다.
- 구조자의 장비, 증강, 상태이상에 따라 구조 속도가 변경될 수 있다.
- 최종 구조 시간은 최소 2.5초보다 짧아질 수 없다.
- 구조 시간 증가 효과를 포함한 최종 구조 시간은 최대 15초로 제한한다.

### 구조 진행 계산

```text
초당 구조 진행도 =
기본 진행 속도
× 구조자별 구조 속도 배율의 합
× 대상 구조 수용 배율
```

기본 진행 속도는 `1 / 기본 구조 시간`이다. 구조 진행도가 100%가 되면 구조에 성공한다.

## 5. 복수 구조자

한 빈사 플레이어에게 최대 2명까지 동시에 구조에 기여할 수 있다.

| 구조자 순서 | 기본 구조 속도 기여 |
|---:|---:|
| 첫 번째 구조자 | 100% |
| 두 번째 구조자 | 60% |
| 세 번째 이후 | 구조 참여 불가 |

- 두 번째 구조자는 구조 시간을 단축하지만 완전히 절반으로 줄이지 않는다.
- 구조자 판정 순서는 구조 입력을 시작한 시각을 기준으로 한다.
- 기존 구조자가 중단하면 대기 중인 세 번째 구조자가 자동으로 참여할 수 있다.
- 복수 구조자도 각각 AP를 소모한다.
- 구조 보조 기여도는 실제 구조 진행도 기여량에 따라 기록한다.

예를 들어 부상 스택 1의 대상은 한 명이 구조하면 5초, 두 명이 기본 속도로 함께 구조하면 약 3.1초가 걸린다.

## 6. 구조 진행도 유지 및 감소

구조 진행도는 빈사 대상별로 공유한다.

### 구조자 존재 시

- 유효한 구조자가 한 명 이상이면 구조 진행도가 증가한다.
- 구조자가 바뀌어도 현재 진행도를 유지한다.
- 복수 구조자의 기여량을 각각 기록한다.

### 구조자 부재 시

- 유효한 구조자가 없어지면 0.5초의 유예 시간을 제공한다.
- 유예 시간 안에 다시 구조를 시작하면 기존 진행도를 유지한다.
- 유예 시간이 끝나면 구조 진행도가 초당 20%씩 감소한다.
- 구조 진행도가 0%가 되면 대상 상태를 `DOWNED`로 되돌린다.

구조 시도가 잠깐 끊겼다고 즉시 모든 진행도를 잃지는 않지만, 전장을 확보하지 않은 채 짧은 입력만 반복해서 구조를 완성할 수는 없다.

## 7. 구조자 행동 제한

구조에 기여하는 동안 구조자는 다음 제한을 받는다.

### 허용 행동

- 아주 느린 위치 보정
- 시점 회전
- 구조 입력 해제
- 파티 채팅

### 금지 행동

- 기본 공격과 무기 스킬
- 회피, 패링, 방어
- 아이템 사용과 교체
- 블록 설치 및 파괴
- 시설 및 GUI 상호작용
- 다른 대상과 상호작용
- 질주와 점프

### 이동 제한

- 구조자는 구조 시작 위치에서 최대 0.75블록까지 움직일 수 있다.
- 구조 대상이 움직여 거리가 2.5블록을 초과하면 해당 구조자의 기여를 중단한다.
- 구조자가 대상을 일정 각도 이상 벗어나 바라보면 해당 구조자의 기여를 중단한다.
- 넉백과 강제 이동은 정상 적용한다.

## 8. 구조 중 AP 처리

- 구조자는 구조에 기여하는 동안 초당 5 AP를 소비한다.
- AP는 0.25초 단위로 나누어 차감한다.
- AP가 부족하면 해당 구조자의 기여를 즉시 중단한다.
- AP가 회복되어도 입력을 다시 수행해야 구조에 재참여한다.
- 구조 중에는 기본 AP 자연 회복이 정지한다.
- 구조 속도가 빨라져도 초당 AP 소비량은 변하지 않는다.

구조 시작 시 AP를 한 번에 지불하지 않으므로 중단된 구조 시도에 과도한 손실이 발생하지 않는다. 구조를 끝까지 수행하려면 부상 스택에 따라 기본적으로 25~45 AP가 필요하다.

## 9. 구조 중 피해 및 방해

### 구조자 피해

구조자는 구조 중에도 모든 피해를 정상적으로 받는다.

| 상황 | 처리 |
|---|---|
| 한 번에 최대 HP의 5% 미만 피해 | 구조 유지 |
| 한 번에 최대 HP의 5% 이상 피해 | 해당 구조자의 기여 중단 |
| 기절, 속박, 공중 띄움 | 해당 구조자의 기여 중단 |
| 강제 이동으로 거리 이탈 | 해당 구조자의 기여 중단 |
| 구조자가 빈사 상태 진입 | 즉시 기여 중단 |

지속 피해처럼 작은 피해가 반복되는 상황에서는 구조를 유지할 수 있지만, 강한 공격을 맞으면서 구조를 강행하기는 어렵게 한다.

### 빈사 대상 피해

- 구조 중인 빈사 대상도 빈사 피해를 정상적으로 받는다.
- 빈사 피해를 받아도 구조 진행도는 직접 감소하지 않는다.
- 대상이 완전 사망하면 구조를 즉시 실패 처리하고 진행도를 제거한다.
- `DOWNED_GRACE` 상태에서는 구조를 시작할 수 없다.

### 아군 공격

- 기본 모드와 전술 모드 모두 빈사 대상에 대한 아군 피해를 차단한다.
- 전술 모드에서 구조자가 아군 피해를 받아도 구조 진행을 중단하지 않아 고의 방해를 막는다.
- 구조 입력 자체는 공격으로 판정하지 않는다.

## 10. 구조 완료 처리

구조 진행도가 100%에 도달하면 다음 순서로 처리한다.

1. 대상의 완전 사망 처리 여부를 다시 확인한다.
2. 대상에게 적용 중인 빈사 지속 피해를 제거한다.
3. 대상 상태를 `ALIVE`로 변경한다.
4. 부상 스택에 따른 복귀 HP를 적용한다.
5. AP를 최대 AP의 20%로 설정한다.
6. 구조 후 회복 보호 상태를 적용한다.
7. 구조자와 대상에게 성공 연출을 출력한다.
8. 구조 기여도를 구조자별로 기록한다.
9. 구조 결과와 생명 상태를 즉시 저장한다.

구조 완료는 대상의 부상 스택을 감소시키지 않는다.

## 11. 구조 후 회복 보호

구조 직후 플레이어가 같은 장판이나 다단 공격으로 즉시 다시 빈사 상태가 되는 것을 방지하기 위해 짧은 회복 보호를 제공한다.

| 항목 | 규칙 |
|---|---|
| 기본 지속시간 | 2초 |
| 피해 처리 | 모든 피해 80% 감소 |
| 상태이상 | 강한 CC 면역, 지속 피해 면역 |
| 공격 및 스킬 | 사용 불가 |
| 회피 및 패링 | 사용 불가 |
| 이동 | 가능 |
| 시설 상호작용 | 불가 |

- 회복 보호는 완전 무적이 아니며 위험 지역에서 계속 버티는 용도로 사용할 수 없다.
- 공허 피해와 시스템 강제 사망은 보호 대상에서 제외한다.
- 보호 종료 시 1초 동안 받는 피해 30% 감소 효과를 추가 적용한다.
- 회복 보호 중 다시 치명 피해를 받으면 정상적으로 빈사 또는 완전 사망 처리한다.

구조 직후 공격 행동을 금지하여 보호 시간을 공격 기회로 사용하는 것을 막는다.

## 12. 구조 속도 변경 효과

장비, 증강, 상태이상은 구조 속도를 변경할 수 있다.

### 구조 속도 증가

- 장비 및 개인 증강의 구조 속도 증가 합계는 최대 50%로 제한한다.
- 파티 증강과 특수 시설 효과는 개인 증가 제한 이후 별도로 적용할 수 있다.
- 두 번째 구조자의 효율은 구조 속도 증가와 별개로 기본 60%를 유지한다.
- 최종 구조 시간은 최소 2.5초 제한을 적용한다.

### 구조 속도 감소

- 플레이어 오염도와 특정 적 디버프가 구조 속도를 감소시킬 수 있다.
- 구조 속도 감소는 최대 50%로 제한한다.
- 구조 불가 디버프는 보스 패턴 또는 명확히 표시된 특수 효과에만 사용한다.
- 구조 속도 감소 효과는 구조 시작 전과 진행 중 모두 반영한다.

### 효과 예시

| 효과 | 예시 |
|---|---|
| 응급 처치 장신구 | 구조 속도 +20% |
| 구조 전문 개인 증강 | 구조 AP 소모 -30% |
| 결속 파티 증강 | 복수 구조자의 두 번째 기여 효율 +20% |
| 고오염 상태 | 구조 속도 -20% |
| 처형자의 공포 | 일정 시간 구조 불가 |

## 13. 자력 구조

기본적으로 빈사 플레이어는 스스로 구조할 수 없다.

자력 구조는 일부 희귀 부적, 장비 능력 또는 증강을 통해서만 허용한다.

### 자력 구조 공통 규칙

- 자력 구조 효과는 명시된 횟수 또는 재사용 대기시간을 가진다.
- 발동 중 빈사 피해를 받으면 취소될 수 있다.
- 발동 시간은 최소 5초 이상이어야 한다.
- 자력 구조 후에도 현재 부상 스택에 따른 복귀 HP와 회복 보호를 적용한다.
- 자력 구조는 부상 스택을 감소시키지 않는다.
- 부상 스택이 최대인 상태에서 발생한 즉시 완전 사망에는 사용할 수 없다.

마지막 생존자의 빈사는 기본적으로 회차 종료 직전의 매우 위험한 상태다. 자력 구조 효과가 없다면 다른 생존자가 재접속하거나 특수 외부 효과가 적용되기 전까지 스스로 복귀할 수 없다.

## 14. 특수 구조 효과

추후 장비와 증강에서 사용할 수 있는 구조 관련 효과는 다음 규칙을 따른다.

| 효과 유형 | 규칙 |
|---|---|
| 원거리 구조 | 직접 구조보다 느리며 시야가 차단되면 중단 |
| 즉시 구조 | 매우 희귀한 일회성 효과로 제한 |
| 구조 완료 시 보호막 | 복귀 HP와 별도 적용하되 상한 설정 |
| 구조 중 피해 감소 | 구조자 본인에게만 적용 |
| 구조 시 광역 밀쳐내기 | 보스와 엘리트에는 브레이크 피해로 변환 |
| 자동 구조 시설 | 해당 플레이어 건설 시설의 작동 범위 안에서만 작동하고 재사용 대기시간 적용 |

어떤 효과도 완전 사망한 플레이어를 일반 구조 행동으로 되살릴 수 없다. 완전 사망 부활은 `DEATH-003 완전 사망 및 부활 시스템`에서 별도로 다룬다.

## 15. UI 및 피드백

### 구조자 화면

- 대상 이름과 구조 진행도를 표시한다.
- 남은 예상 구조 시간을 표시한다.
- 현재 AP와 예상 총 AP 소모량을 표시한다.
- 구조 중단 원인을 짧게 안내한다.

```text
PlayerB 구조 중 | 62% | 약 2.4초 | AP 38
```

### 빈사 대상 화면

- 구조자의 이름과 현재 구조 진행도를 표시한다.
- 복수 구조자가 참여하면 인원수를 표시한다.
- 구조가 끊기고 진행도가 감소하는 상태를 표시한다.

```text
구조 진행 중 | 62% | 구조자 2명
```

### 파티 표시

- 구조 시작과 성공은 가까운 파티원에게만 사운드로 알린다.
- 구조 실패와 대상 완전 사망은 전체 파티에 알린다.
- 구조 중인 대상은 파티 UI에서 별도 색상으로 표시한다.

## 16. 플러그인 구현 방향

- `PlayerInteractEntityEvent` 계열 이벤트로 빈사 플레이어 우클릭을 감지한다.
- 웅크리기 상태, 거리, 시야, 생명 상태를 서버에서 검증한다.
- 우클릭 유지 여부는 짧은 주기의 반복 입력 또는 구조 세션 유지 조건으로 판정한다.
- 대상 UUID별 구조 진행도와 구조자 목록을 관리한다.
- 구조 진행 계산은 모든 플레이어를 매 틱 검사하지 않고 활성 구조 세션만 처리한다.
- 구조 중 아이템 사용과 무기 스킬 이벤트를 취소한다.
- 구조 완료와 중단은 서버 권위 상태로 처리한다.

### 입력 기술 검증

바닐라 클라이언트의 플레이어 대상 우클릭 유지 이벤트가 환경에 따라 반복 전달되지 않을 수 있으므로 다음 방식을 우선 검증한다.

1. 웅크리기 + 최초 우클릭으로 구조 세션 시작
2. 웅크리기 유지, 거리, 시야 조건으로 구조 유지
3. 웅크리기 해제 또는 조건 이탈 시 구조 중단

이 방식이 가장 안정적이면 실제 조작 안내는 `웅크린 상태로 대상 우클릭 후 유지`로 제공한다.

## 17. 저장 데이터

구조 진행도는 짧은 전투 행동이므로 일반 자동 저장 대상에서는 제외한다. 서버 재시작 또는 회차 중단 시 진행 중인 구조는 취소하고 대상은 기존 빈사 상태로 복원한다.

```yaml
players:
  "downed-player-uuid":
    life-state: DOWNED
    downed-hp: 320.0
    downed-max-hp: 525.0
    injury-stacks: 2
    revive-progress: 0.0
    recovery-protection-until: null
statistics:
  "reviver-player-uuid":
    revives-completed: 3
    revive-progress-contributed: 2.45
```

구조 완료 결과와 구조 기여 통계는 즉시 저장한다.

## 20. DEATH-002 완료 기준

- 웅크리기와 대상 우클릭으로 구조를 안정적으로 시작할 수 있다.
- 거리, 시야, 상태, AP 조건에 따라 구조 참여가 검증된다.
- 부상 스택에 따라 구조 시간과 복귀 HP가 달라진다.
- 최대 2명의 구조자가 대상별 공유 진행도에 기여할 수 있다.
- 구조가 잠시 끊기면 유예 후 진행도가 서서히 감소한다.
- 강한 피해, CC, 거리 이탈, AP 부족이 구조를 정상적으로 중단한다.
- 구조 중인 빈사 대상이 추가 피해로 완전 사망할 수 있다.
- 구조 완료 후 복귀 HP, AP, 회복 보호가 정상 적용된다.
- 구조 기여도와 완료 결과가 중복 없이 기록된다.
- 구조 중 서버 재시작으로 구조가 자동 완료되거나 대상 상태가 손상되지 않는다.

# DEATH-003 완전 사망 및 부활 시스템

## 1. 시스템 목적

완전 사망은 해당 회차에서 플레이어 한 명의 일반적인 참여가 종료되는 하드코어 결과다. 부활은 이 결과를 예외적으로 되돌리는 매우 희귀하고 명확한 자원으로만 제공한다.

- 완전 사망에 충분한 긴장감과 손실을 부여한다.
- 사망자가 관전으로 파티를 지원하거나 정보를 과도하게 제공하지 못하게 한다.
- 유품과 장비를 생존 파티가 회수할 수 있게 한다.
- 희귀 부활 효과가 하드코어 규칙을 무력화하지 않게 한다.
- 전원 사망과 회차 실패를 명확하고 복구 불가능하게 확정한다.

## 2. 완전 사망 조건

플레이어는 다음 조건 중 하나를 만족하면 완전 사망한다.

- 빈사 체력이 0 이하가 된다.
- 부상 스택이 최대인 상태에서 다시 치명 피해를 받는다.
- 공허 구조 기회를 이미 사용한 상태에서 다시 공허에 빠진다.
- 시스템 또는 운영자 기능이 명시적으로 완전 사망을 확정한다.
- 빈사 접속 종료 대리 개체가 파괴되는 등 기술적으로 완전 사망 조건이 확정된다.

일반 보스 패턴과 환경 피해는 `DEATH-001`의 빈사 단계를 기본적으로 건너뛰지 않는다.

## 3. 완전 사망 처리 절차

완전 사망 조건이 확정되면 다음 순서로 처리한다.

1. 진행 중인 구조, 스킬, 상호작용을 즉시 취소한다.
2. 해당 플레이어의 생명 상태를 메모리에서 `DEAD_PENDING`으로 변경한다.
3. 사망 원인, 공격자, 위치, Day, 전투 ID를 기록한다.
4. 플레이어 인벤토리와 가상 장비 상태의 불변 스냅샷을 생성한다.
5. 유품 생성 및 보존 가능 여부를 판정한다.
6. 플레이어를 관전 모드로 전환한다.
7. 생명 상태를 `DEAD`로 확정하고 우선순위 1 저장을 수행한다.
8. 파티와 사망자에게 완전 사망을 알린다.
9. 현재 전투 기여도를 확정한다.
10. 전원 사망 여부를 판정한다.

`DEAD_PENDING` 상태에서는 접속 종료나 서버 오류가 발생해도 생존 상태로 되돌리지 않는다.

## 4. 완전 사망자의 상태

| 항목 | 규칙 |
|---|---|
| 기본 게임모드 | 관전 모드 |
| 전투 참여 | 불가능 |
| 아이템 및 장비 사용 | 불가능 |
| 기지 시설 이용 | 불가능 |
| 보상 획득 | 사망 전 확정한 기여 보상만 가능 |
| 파티 참여 슬롯 | 계속 점유 |
| 회차 재접속 | 관전 상태로 복귀 |
| 일반 구조 | 불가능 |
| 부활 | 명시된 특수 부활 효과로만 가능 |

- 완전 사망자를 신규 플레이어로 교체할 수 없다.
- 사망 전 획득한 개인 증강과 성장 데이터는 부활 가능성을 위해 유지한다.
- 완전 사망자는 회차 종료 전까지 파티 구성원으로 기록한다.

## 5. 관전 규칙

관전자는 살아 있는 플레이어에게 과도한 정찰 정보를 제공하지 못하도록 제한한다.

### 허용

- 살아 있는 파티원의 시점을 선택하여 관전
- 살아 있는 파티원 또는 활성 파티 시설 주변의 제한된 자유 관전
- 파티 채팅 사용
- 자신의 사망 기록, 장비, 기여도 확인
- 세션 정산 및 파티 증강 투표 참여

### 제한

- 살아 있는 플레이어와 일정 거리 이상 떨어진 야생 지역 이동
- 미발견 지역과 미발견 적 위치 정찰
- 적, 상자, 자원, 기믹과 상호작용
- 도움 요청 위치 표시 및 전투 핑 생성
- 아이템 이동, 보상 수령, 시설 조작

### 관전 영역

- 기본적으로 살아 있는 파티원 시점 관전을 사용한다.
- 자유 관전은 선택한 생존 파티원 반경 48블록 또는 활성 파티 시설 반경 32블록 안에서만 허용한다.
- 보스전 중에는 동적으로 생성된 보스 전투 반경 안에서만 자유 관전을 허용한다.
- 허용 영역을 벗어나면 가장 가까운 생존 플레이어 시점 또는 활성 파티 시설 시점으로 이동시킨다.

관전자 채팅을 제한하지는 않지만, 시스템이 미발견 정보를 직접 제공하지 않게 한다.

## 6. 유품 생성

완전 사망 시 플레이어의 소지품은 기본적으로 `유품 보관함`에 저장한다.

### 유품 보관 대상

- 일반 인벤토리 아이템
- 핫바 아이템
- 바닐라 방어구 및 보조 손 아이템
- GUI 가상 장비 슬롯의 장비
- 개인 소지 재료와 소모품

개인 증강, 레벨, 기여도, 부활 권한은 아이템으로 떨어뜨리지 않고 플레이어 데이터에 유지한다.

### 유품 생성 위치

- 기본적으로 완전 사망 위치에 생성한다.
- 용암, 공허, 블록 내부 등 보관함을 생성할 수 없는 위치에서는 마지막 안전 위치에 생성한다.
- 보스 전투 영역에서 접근 불가능한 위치라면 지정된 전투 영역 유품 지점에 생성한다.
- 안전 위치를 찾지 못하면 기지의 유품 회수 시설에 전송한다.

### 유품 보관함 규칙

| 항목 | 규칙 |
|---|---|
| 파괴 가능 여부 | 파괴 불가 |
| 폭발 및 화재 | 면역 |
| 접근 권한 | 같은 회차의 생존 플레이어 |
| 아이템 회수 | 자유롭게 회수 가능 |
| 자동 소멸 | 없음 |
| 회차 종료 후 | 종료 기록에 포함 후 제거 |

- 유품 보관함은 일반 블록 상자가 아니라 플러그인 관리 개체 또는 가상 보관함으로 구현한다.
- 유품 내용물과 회수 상태를 즉시 저장한다.
- 같은 아이템이 월드 드롭과 유품에 동시에 존재하지 않도록 사망 처리 중 인벤토리 드롭을 차단한다.

## 7. 사망 손실 규칙

완전 사망은 파티 전체 자산을 무작위로 파괴하기보다 해당 플레이어의 전력 이탈과 제한된 개인 손실에 초점을 둔다.

| 대상 | 손실 규칙 |
|---|---|
| 장비 | 유품으로 회수 가능 |
| 공용 핵심 재료 | 공용 보관함에 있다면 손실 없음 |
| 개인 일반 재료 | 유품으로 회수 가능 |
| 개인 소모품 | 기본 25% 소실 후 나머지 유품 보관 |
| 개인 증강 | 데이터에 유지, 부활 시 복원 |
| 개인 레벨 및 스탯 | 데이터에 유지, 부활 시 복원 |
| 기여 보상 권한 | 사망 전 기여분 유지 |

### 소모품 소실

- 완전 사망 시 회복, 정화, 전투 소모품의 각 아이템 스택에서 25%를 제거한다.
- 제거량은 내림 처리하며 한 개짜리 희귀 소모품은 기본적으로 보존한다.
- 부활 전용 아이템과 보스 핵심 아이템은 소실 대상에서 제외한다.
- 장비와 핵심 진행 아이템에는 무작위 소실을 적용하지 않는다.

이 규칙은 완전 사망에 개인 자원 손실을 부여하면서도 생존 파티가 장비를 이어받아 회차를 계속 진행할 수 있게 한다.

## 8. 전원 사망 및 회차 실패

### 실패 판정 대상

전원 사망은 회차에 등록된 플레이어 중 `향후 일반 또는 보유 효과로 생존 복귀 가능한 플레이어`가 한 명도 없는 상태로 정의한다.

다음 플레이어가 하나라도 존재하면 즉시 실패하지 않는다.

- `ALIVE` 상태 플레이어
- `DOWNED_GRACE`, `DOWNED`, `BEING_REVIVED` 상태 플레이어
- 생존 상태로 접속 종료한 등록 플레이어
- 사망 시 자동 부활 효과가 이미 발동되어 복귀 처리 중인 플레이어

완전 사망자에게 인벤토리 또는 파티 자원으로 사용할 수 있는 수동 부활 아이템이 남아 있다는 이유만으로 실패 판정을 보류하지 않는다. 부활을 실행할 살아 있는 플레이어가 없다면 회차는 실패한다.

### 실패 확정 절차

1. 모든 등록 플레이어의 생명 상태를 다시 검증한다.
2. 진행 중인 자동 부활 효과가 있는지 확인한다.
3. 조건을 만족하면 Day 타이머와 콘텐츠 AI를 정지한다.
4. 회차 상태를 `FAILED`로 변경한다.
5. 실패 잠금 기록을 우선 저장한다.
6. 사망 위치, 도달 Day, 기여도, 장비, 보스 기록을 정산한다.
7. 회차 종료 연출 후 모든 플레이어를 대기 공간으로 이동한다.

회차 실패가 확정되면 부활 아이템이나 장비 효과를 사용해 해당 회차를 재개할 수 없다.

## 9. 부활 체계

부활은 완전 사망한 플레이어를 다시 `ALIVE` 상태로 되돌리는 예외 시스템이다. 부활 방법은 발동 시점에 따라 구분한다.

| 유형 | 발동 시점 | 실행 주체 | 기본 희귀도 |
|---|---|---|---|
| 자동 부활 | 완전 사망 확정 직전 또는 직후 | 사망자의 장비·부적 | 매우 희귀 |
| 현장 부활 | 완전 사망 후 전투 또는 탐험 중 | 살아 있는 동료 | 매우 희귀 |
| 세션 부활 | 보스 처치 후 세션 정산 단계 | 파티 공용 선택 | 극히 희귀 |

일반 제작, 반복 파밍, 저등급 플레이어 시설을 통한 무제한 부활은 제공하지 않는다.

## 10. 공통 부활 제한

- 회차당 플레이어별 기본 부활 가능 횟수는 1회다.
- 모든 부활 유형은 동일한 플레이어별 부활 횟수를 공유한다.
- 부활 횟수는 회차가 끝날 때까지 회복되지 않는다.
- 부활한 플레이어의 참여 슬롯과 기존 성장 데이터는 그대로 유지한다.
- 부활은 완전 사망자의 유품을 자동 회수하지 않는다.
- 회차가 `FAILED` 또는 `COMPLETED` 상태가 되면 부활할 수 없다.
- 부활 직후 부상 스택은 최대치인 3으로 설정한다.
- 부활 후 다시 치명 피해를 받으면 빈사 없이 즉시 완전 사망한다. 부상 스택을 낮춘 이후에는 다시 빈사 상태에 진입할 수 있다.
- 부활은 보스 체력, 공세 상태, Day 시간을 되돌리지 않는다.

## 11. 자동 부활

자동 부활은 사망자가 미리 장착한 매우 희귀한 부적 또는 장비 능력으로 발동한다.

### 기본 절차

1. 완전 사망 조건 발생 시 사용 가능한 자동 부활 효과를 확인한다.
2. 효과를 즉시 소비하고 플레이어를 `REVIVING_AUTO` 상태로 변경한다.
3. 5초 동안 부활 대기 상태를 유지한다.
4. 대기 중 플레이어는 전투에 참여하지 않으며 피해를 받지 않는다.
5. 대기 종료 후 사망 위치 또는 마지막 안전 위치에서 부활한다.

### 자동 부활 결과

| 항목 | 규칙 |
|---|---|
| 복귀 HP | 최대 HP의 30% |
| 복귀 AP | 최대 AP의 20% |
| 부상 스택 | 3 |
| 보호 시간 | 3초 |
| 유품 생성 | 생성하지 않음 |
| 장비 효과 소비 | 즉시 저장 |

- 자동 부활 발동 중인 플레이어는 전원 사망 판정에서 복귀 가능 플레이어로 취급한다.
- 자동 부활 소비 기록은 발동 즉시 저장하여 서버 종료로 되돌릴 수 없게 한다.
- 자동 부활은 공허에서 마지막 안전 위치를 사용한다.

## 12. 현장 부활

현장 부활은 살아 있는 동료가 희귀 부활 아이템을 소비하여 완전 사망자를 복귀시키는 방식이다.

### 사용 조건

- 부활 대상이 `DEAD` 상태다.
- 대상의 플레이어별 부활 횟수가 남아 있다.
- 사용자가 `ALIVE` 상태다.
- 회차가 실패 또는 완료 상태가 아니다.
- 대상의 유품 보관함 또는 사망 표식과 상호작용할 수 있다.
- 필요한 부활 아이템을 보유하고 있다.

### 현장 부활 의식

| 항목 | 기본값 |
|---|---:|
| 기본 시전 시간 | 15초 |
| 최대 참여자 | 2명 |
| 시전자 AP 소모 | 초당 8 AP |
| 피해 중단 기준 | 한 번에 최대 HP의 5% 이상 |
| 이동 허용 거리 | 시작 위치 기준 0.75블록 |
| 부활 아이템 소비 | 의식 시작 시 |

- 의식 진행 중 공격, 스킬, 회피, 패링을 사용할 수 없다.
- 시전자가 피해, CC, 거리 이탈, AP 부족으로 중단되면 의식은 실패한다.
- 실패 시 부활 아이템은 반환하지 않는다.
- 두 번째 참여자는 의식 시간을 단축할 수 있지만 최소 8초보다 짧아지지 않는다.
- 의식 대상은 관전 상태로 진행 상황을 확인할 수 있다.

### 현장 부활 결과

| 항목 | 규칙 |
|---|---|
| 복귀 위치 | 유품 보관함 또는 사망 표식 위치 |
| 복귀 HP | 최대 HP의 20% |
| 복귀 AP | 최대 AP의 10% |
| 부상 스택 | 3 |
| 보호 시간 | 3초 |
| 유품 | 그대로 유지, 직접 회수 필요 |

현장 부활 아이템은 보스 고유 보상, 일회성 특수 이벤트 등 제한된 경로에서만 획득할 수 있게 한다.

## 13. 세션 부활

세션 부활은 Day 10 단위 보스 처치 후 정산 단계에서만 가능한 파티 공용 선택이다.

- 세션 부활 기회는 항상 제공하지 않는다.
- 특정 보스 보상, 파티 증강 또는 극히 희귀한 공용 자원을 통해서만 선택할 수 있다.
- 한 번의 세션 정산에서 최대 한 명만 부활시킬 수 있다.
- 살아 있는 플레이어의 투표로 대상을 결정한다.
- 부활 대상이 없으면 해당 선택지를 보존하거나 다른 보상으로 변경할 수 없다.

### 세션 부활 결과

| 항목 | 규칙 |
|---|---|
| 복귀 위치 | 기지 안전 지점 |
| 복귀 HP | 최대 HP의 100% |
| 복귀 AP | 최대 AP의 100% |
| 부상 스택 | 2 |
| 유품 | 기지 유품 회수 시설로 이동 |
| 복귀 시점 | 다음 세션 시작 직전 |

세션 부활은 강력하지만 보스 처치까지 생존한 파티만 사용할 수 있다. 전원 완전 사망으로 실패한 회차에는 적용할 수 없다.

## 14. 부활 아이템 및 효과 설계 원칙

- 부활 효과는 설명에 사용 조건, 소비 시점, 복귀 HP, 부상 스택을 명시한다.
- 부활 아이템은 공용 보관함에 보관할 수 있다.
- 부활 아이템은 사망 시 소모품 소실 대상에서 제외한다.
- 동일한 자동 부활 효과를 여러 개 장착해도 한 번의 사망에 하나만 발동한다.
- 발동 우선순위는 플레이어가 장비 GUI에서 지정할 수 있다.
- 부활 횟수가 없는 플레이어에게 자동 부활 장비를 장착해도 발동하지 않는다.
- 부활을 취소하거나 거래하여 소비 기록을 되돌릴 수 없다.

### 예시 효과

| 이름 | 유형 | 효과 |
|---|---|---|
| 불씨 부적 | 자동 부활 | 회차당 1회, 5초 후 마지막 안전 위치에서 부활 |
| 정화자의 심장 | 현장 부활 아이템 | 15초 의식으로 완전 사망자 한 명 부활 |
| 생명의 잔향 | 파티 증강 | 다음 세션 정산에서 완전 사망자 한 명 부활 가능 |

예시 이름과 수치는 추후 장비 및 증강 기획에서 변경할 수 있다.

## 15. 부활 후 처리

부활이 완료되면 다음 순서로 처리한다.

1. 플레이어 생명 상태를 `ALIVE`로 변경한다.
2. 사용한 부활 유형과 플레이어별 부활 횟수를 기록한다.
3. 유형별 HP, AP, 부상 스택을 적용한다.
4. 모든 빈사·사망 전용 상태이상을 제거한다.
5. 부활 보호를 적용한다.
6. 관전 제한을 제거하고 생존 UI를 복원한다.
7. 현재 공세 또는 보스의 전투 참여자로 등록한다.
8. 현재 전투 스케일 인원을 필요한 경우 증가시킨다.
9. 부활 결과를 즉시 우선 저장한다.

### 부활 보호

- 기본 지속시간은 3초다.
- 모든 피해를 80% 감소시키고 강한 CC와 지속 피해에 면역을 부여한다.
- 보호 중 공격, 스킬, 회피, 패링은 사용할 수 없다.
- 공허 피해와 시스템 강제 사망은 보호 대상에서 제외한다.
- 보호 종료 후 추가 피해 감소는 제공하지 않는다.

## 16. 보상 및 기여도 처리

- 완전 사망자는 사망 전 완료한 전투의 개인 기여 보상을 받을 수 있다.
- 사망 후 관전 시간은 기여도로 계산하지 않는다.
- 부활 후 새롭게 수행한 행동은 다시 기여도로 기록한다.
- 부활 자체를 실행한 플레이어에게 지원 기여도를 부여한다.
- 부활 대상은 사망해 있던 기간의 자동 보상이나 접속 보상을 받지 않는다.
- 파티 증강 투표는 완전 사망자도 참여할 수 있지만, 세션 부활 대상 투표에서는 자신에게 투표할 수 없다.

## 17. 저장 데이터

```yaml
players:
  "player-uuid":
    life-state: DEAD
    death:
      day: 17
      cause: DOWNED_DAMAGE
      killer-id: "elite-executor-01"
      location:
        world: "wild"
        x: 84.5
        y: 63.0
        z: -120.5
      encounter-id: "ASSAULT-DAY-17"
    resurrection:
      used-count: 0
      max-count: 1
      pending-type: null
    remains-id: "remains-player-uuid-01"
remains:
  "remains-player-uuid-01":
    owner: "player-uuid"
    location-type: DEATH_LOCATION
    recovered: false
    contents: []
```

완전 사망, 유품 생성, 부활 효과 소비, 부활 완료는 모두 일반 자동 저장보다 우선하여 기록한다.

## 18. 예외 처리

| 상황 | 처리 |
|---|---|
| 완전 사망 처리 중 서버 종료 | `DEAD_PENDING` 기록을 기준으로 사망 처리 재개 |
| 유품 생성 중 서버 종료 | 저장된 스냅샷으로 유품 한 번만 생성 |
| 자동 부활 발동 중 서버 종료 | 소비 기록을 유지하고 남은 대기 후 부활 |
| 현장 부활 의식 중 서버 종료 | 의식 실패, 소비 아이템 반환 안 함 |
| 부활 완료 순간 전원 사망 판정 | 부활 완료를 우선 검증 후 실패 여부 재판정 |
| 부활 위치가 위험하거나 막힘 | 가장 가까운 안전 위치 사용 |
| 완전 사망자 접속 종료 | 사망 상태 유지 |
| 유품이 이미 모두 회수됨 | 빈 유품 표식을 유지하거나 현장 부활 후 제거 |
| 회차 실패 직후 부활 사용 시도 | 실패 상태를 우선하여 부활 거부 |
| 동일 플레이어 대상 동시 부활 시도 | 최초 승인된 하나만 진행 |

## 19. 밸런스 테스트 항목

| 테스트 | 확인 목적 |
|---|---|
| 빈사 피해와 최대 부상 상태 사망 | 완전 사망 조건 검증 |
| 완전 사망 중 서버 종료 | 사망 롤백 방지 검증 |
| 일반 위치·용암·공허 사망 | 유품 안전 위치 생성 검증 |
| 관전자 자유 이동 | 정찰 제한 검증 |
| 자동 부활 발동 | 소비 기록과 전원 사망 판정 검증 |
| 현장 부활 성공 및 실패 | 의식, AP, 아이템 소비 검증 |
| 세션 부활 | 정산 투표 및 다음 세션 복귀 검증 |
| 동일 플레이어 두 번째 부활 시도 | 회차당 횟수 제한 검증 |
| 마지막 생존자 사망과 자동 부활 | 실패 판정 순서 검증 |
| 유품 회수와 서버 재시작 | 아이템 중복 및 손실 검증 |

## 20. DEATH-003 완료 기준

- 모든 완전 사망 조건이 일관되게 `DEAD` 상태로 전환된다.
- 완전 사망 결과를 서버 종료나 과거 저장본으로 되돌릴 수 없다.
- 완전 사망자의 유품이 안전하게 생성되고 중복되지 않는다.
- 완전 사망자는 제한된 관전만 가능하며 전투와 정찰에 직접 개입할 수 없다.
- 전원 사망 조건이 접속 종료자와 자동 부활 상태를 포함해 정확히 판정된다.
- 자동·현장·세션 부활이 각각 정의된 조건과 비용으로 작동한다.
- 플레이어별 회차당 부활 횟수를 초과할 수 없다.
- 부활 직후 상태, 전투 스케일, 저장 데이터가 정상적으로 갱신된다.
- 회차 실패 확정 후에는 어떤 부활 효과도 사용할 수 없다.
- 완전 사망 및 부활 관련 보상과 기여도가 중복 처리되지 않는다.
