# WildSurvival 파티 증강·생존 인원 보정 기획서

## 문서 정보

| 항목 | 내용 |
|---|---|
| 문서 ID | `PARTY-SYNERGY-001` |
| 상태 | `BASELINE_LOCKED` |
| 역할 | 16개 파티 증강의 1~4인·빈사·사망·부활·접속 종료 보정과 순환 차단 |
| 상위 기준 | `AUG-001`, `AUG-LIST-002`, `GAME-003`, `DEATH-001~003` |
| 연계 | `REWARD-001`, `STATUS-001~002`, `BREAK-001~002`, `FACILITY-LIST-001`, `FINAL-001` |
| 적용 | 회차 시작 2~4인, 신규 중도 참여 없음, 모든 플레이어 하나의 협동팀 |
| 최종 수정일 | 2026-08-21 |

## 1. 인원 용어와 판정

| 값 | 포함 | 용도 |
|---|---|---|
| `registeredSize` | 회차 시작 명단 2~4명 | 절반·고유 횟수·보상 기준, 변경 불가 |
| `survivableSize` | `ALIVE`, `DOWNED`, `BEING_REVIVED`, `AUTO_REVIVE_PENDING` | 파티가 아직 되살릴 수 있는 인원 |
| `activeSize` | 온라인이며 `ALIVE`, 관전·빈사·완전 사망 제외 | 전투·거리·서로 다른 플레이어 조건 |
| `combatScaleSize` | `GAME-003`의 전투 잠금 인원 | 적 HP·웨이브·패턴. 증강 보정과 별도 |
| `contributorSet` | 같은 사건에 유효 참여한 고유 UUID | 기여 범주·협동 트리거 |

- `activeSize`가 1이어도 회차는 계속된다. 아래 단독 폴백 외에 새 동료·가짜 분신을 만들지 않는다.
- 빈사자는 버프 수신·거리 조건·서로 다른 플레이어 조건에서 제외하되 구조 대상이 되는 트리거에는 포함한다.
- 완전 사망자가 부활하면 다음 안전 틱에 `survivableSize`, 다음 전투 락 갱신 시 `activeSize`에 다시 포함한다.
- 접속 종료는 버프 수신에서 즉시 제외한다. 전투 중 인원 축소 악용을 막기 위해 `activeSize`의 하향 재계산은 20초 유예하고 상향은 즉시 반영한다. `combatScaleSize`는 `GAME-003` 규칙을 그대로 쓴다.

## 2. 공통 스케일 원칙

1. 파티 증강의 기본 수치는 `activeSize >= 2`에서 목록 문서 값 그대로다.
2. 3·4인이라고 수치를 추가 증폭하지 않는다. 협동 조건을 만족할 기회만 자연스럽게 늘어난다.
3. 1인 잔존 폴백은 원 효과의 50% 이하이거나 다른 자기완결 조건을 요구한다.
4. 고유 재료, 진행 플래그, 파티 증강 횟수, 보스 보상은 인원 보정을 받지 않는다.
5. 트리거를 만든 효과는 같은 `effectChainId`에서 자신 또는 다른 파티 증강을 다시 발동하지 않는다.
6. 훈련 대상·아군 피해·소환체·분열체·보상 없음 태그는 기여·보상·증강 발동에서 제외한다.

```text
effectiveValue = baseValue × aliveProfileMultiplier
→ 도메인 소프트캡
→ 시스템 하드캡
```

`aliveProfileMultiplier`는 임의 전역 배율이 아니라 §4의 증강별 프로필이다. 퍼센트포인트 효과는 곱하지 않고 증강별 표에 적힌 값으로 직접 치환한다.

## 3. 상태 전환 시 재계산

| 사건 | 처리 시점 | 현재값 처리 |
|---|---|---|
| `ALIVE → DOWNED` | 빈사 트랜잭션 커밋 다음 틱 | 거리·공격 버프 제거, 구조 트리거 활성 |
| `DOWNED → ALIVE` | 구조 완료 뒤 보호 상태 적용 후 | 버프 재평가, 같은 구조 사건 중복 발동 금지 |
| `* → DEAD` | 완전 사망 커밋 다음 틱 | 사망 임계 증강 평가, 사망자에게 전투 버프 없음 |
| `DEAD → ALIVE` | 부활 커밋 다음 안전 틱 | 신규 선택 없이 기존 파티 증강 재수신 |
| 접속 종료 | 즉시 수신 해제, 하향 조건 20초 유예 | HP·AP를 새 최대치 아래로만 절삭 |
| 재접속 | 등록 멤버·생명 상태 확인 후 즉시 | 종료 전 임시 ICD 복원 |

최대 HP 증가가 생기거나 사라질 때 현재 HP 비율을 맞춰 회복하지 않는다. 현재 HP는 유지하고 새 최대치를 넘는 값만 절삭한다. 이 절삭으로 `ALIVE`가 빈사가 되지 않는다.

### 4.1 등록 인원별 `PAUG-015` 임계

| 등록 인원 | 발동 survivableSize | 예시 |
|---:|---|---|
| 2 | 1 이하 | 한 명 완전 사망 |
| 3 | 2 이하 | 한 명 완전 사망부터 |
| 4 | 2 이하 | 두 명 완전 사망부터 |

빈사는 구조 가능 상태이므로 임계 인원을 줄이지 않는다. `PAUG-015`를 받기 위해 동료 구조를 일부러 포기하는 전략이 보상·진행 이득이 되지 않도록 사망 페널티와 보상 효율은 그대로다.

## 5. 거리·동시성·고유 참여 판정

- 거리 조건은 같은 월드의 서버 좌표 중심 간 3D 거리 제곱으로 판정한다.
- 다른 차원, 관전, 안전 복구 위치의 플레이어는 거리 조건을 만족하지 않는다.
- 거리 조건은 5틱마다 재평가하고 10틱의 이탈 유예를 둔다. 경계에서 버프가 깜빡이지 않게 진입 12블록, 이탈 13블록 히스테리시스를 쓴다.
- “서로 다른 플레이어”는 UUID 고유 수다. 소환물·투사체는 원소유자 UUID로 합친다.
- 발동 창 안에서 부활·재접속한 플레이어의 과거 사건은 새 고유 참여로 재사용하지 않는다.

## 6. 순환·중첩 차단

### 6.1 효과 사슬

모든 증강 발동은 다음 문맥을 가진다.

```yaml
effect-chain-id: "combat-event-uuid"
root-event: REVIVE_COMPLETED
source-augment: PAUG-004
depth: 1
flags: [NO_AUGMENT_RETRIGGER, NO_REWARD, NO_CONTRIBUTION]
```

- `depth > 4`이면 파생 효과를 중단하고 진단 로그를 남긴다.
- `NO_AUGMENT_RETRIGGER`가 있는 회복·AP·정화·상태·브레이크는 다른 증강의 조건 카운터를 올리지 않는다.
- 같은 `sourceAugmentId + target + effectChainId`는 한 번만 적용한다.
- 개인 증강·장비·스킬과 결합할 때 각 도메인의 전체 하드캡을 마지막에 적용한다.

### 6.2 공통 상한

| 축 | 파티 증강 합산 상한 | 전체 상한 원천 |
|---|---:|---|
| 받는 브레이크 증가 | 일반 +12%, 보스 +8% | `BREAK` 전체 보스 +10% |
| 피해 증가 | 파티 증강 합 +12% | STAT/장비/개인 증강 뒤 전체 하드캡 |
| 피해 감소 | 파티 증강 합 20% | 방어·패턴별 전체 하드캡 |
| AP 직접 회복 | 초당 12 | `COMBAT` AP 직접 회복 상한 |
| 오염 추가 정화 | 사건당 1%p, 8초 | `CORR` 정화 상한 |
| 재건 작업속도 | +12% | 시설 전체 작업속도 상한 |
| 일반 자원 보너스 | +10% | `REWARD`·예산 원장 |

## 7. 후보 유효성 재판정

파티 증강 후보 3개 중 최소 2개가 현재 파티에서 즉시 기능해야 한다.

| 후보 | 제외·감쇠 규칙 |
|---|---|
| `PAUG-009` | 탄약 무기·특수 탄약 제작식이 모두 없으면 가중치 0 |
| `PAUG-013` | 남은 제작 가능한 고유 템플릿이 0이면 가중치 0 |
| `PAUG-014` | Day 30 이전 후보 제외, Day 30 정산부터 허용 |
| `PAUG-016` | 현재 생존 1인이어도 단독 폴백이 있으므로 유효성 0.50 |
| 구조 계열 | 회차에서 부활·구조 기능이 영구 차단된 경우 가중치 0 |
| 시설 계열 | 시설이 없어도 유목 폴백이 있으면 최소 0.50 유지 |

후보 생성 뒤 인원이 변해도 후보를 재추첨하지 않는다. 선택 결과가 1인 잔존에서 어떻게 작동하는지는 §4로 고정돼 있다.

## 8. 보상·기여 경계

- 파티 증강이 만든 추가 피해·회복·브레이크·정화는 원래 행동자의 전투 기여로만 귀속하며 새 기여 항목을 만들지 않는다.
- `PAUG-005`의 보너스는 `COMMON_RESOURCE`에만 적용하고 전문·고유·보스·재건 부품·최종 신호 키에는 적용하지 않는다.
- `PAUG-013`은 비용 할인이지 재료 생성 보상으로 기록하지 않는다.
- 1인 폴백과 `PAUG-015`는 보상 배율·드롭률·투표권을 높이지 않는다.
- 사망자 투표는 `AUG-001`의 동률 보조 규칙만 따르며 전투 시너지 수신과 무관하다.

## 9. 저장 계약

```yaml
party-synergy:
  revision: party-synergy-r1
  registered-size: 4
  survivable-size: 2
  active-size: 2
  active-size-lower-at: null
  augments:
    PAUG-003:
      selected-day: 10
      per-target-icd:
        enemy-uuid: 1724220008000
    PAUG-015:
      threshold: 2
      active: true
  processed-events:
    - "augment:PAUG-004:revive-event-uuid"
```

- 영구 저장은 선택 ID·임계·긴 ICD·멱등 이벤트만 한다.
- 4초 이하의 거리·적중 창은 정상 종료 저장 대상이 아니며 재시작 시 비활성으로 복원한다.
- 재시작으로 `PAUG-015` 최대 HP가 중복 적용되지 않게 출처 ID 기반으로 스탯을 재구성한다.

## 10. UI

- 파티 화면은 `등록 / 생존 가능 / 전투 가능` 인원을 서로 다른 문자로 표시한다.
- 각 증강 로어에 `2~4인 효과`, `1인 잔존 효과`, `현재 활성 조건`, `ICD`를 표시한다.
- 조건 충족은 초록 점 하나가 아니라 `활성`, `대기 6초`, `조건 부족: 다른 생존자 필요` 문자를 함께 쓴다.
- `PAUG-015` 발동·해제 시 최대 HP가 바뀌는 이유를 액션바 1회와 상세 스탯 출처에 남긴다.
- 리소스 팩·색각 설정과 무관하게 `UX-001`의 아이콘+문자 규칙을 따른다.
